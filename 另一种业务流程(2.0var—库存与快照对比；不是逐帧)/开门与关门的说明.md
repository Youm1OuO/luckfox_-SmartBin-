# 开门与关门的会话流程（2.0）

> 本文件是《另一个版本.md》和《track的说明.md》的外层流程。
> 一次“开门 → 关门”是一个 Session。

## 1. 光线状态

```text
环境较暗 → 冰箱灯亮、画面持续变亮：认为开门；
环境较亮 → 冰箱灯灭、画面持续变暗：认为关门。
```

不能只凭单帧亮度变化判断。应使用两个阈值和连续帧确认，避免自动曝光、灯光闪烁造成误判：

```python
if 连续 open_confirm_frame_count 帧的亮度 > open_light_threshold:
    door_state = OPEN

if 连续 close_confirm_frame_count 帧的亮度 < close_light_threshold:
    door_state = CLOSED
```

通常应满足：

```text
open_light_threshold > close_light_threshold
```

这样会形成迟滞，避免亮度处在临界值时反复开门、关门。


## 2. 开门

开门只执行一次初始化，不能在门已打开时反复初始化。

```python
def on_door_open():
    if session_active:
        return

    session_active = True
    initial_snapshot_settled = False

    # 后台返回完整库存状态，而不只是商品数量。
    # 每个库存物品至少需要：
    # item_id、cls_id、box、base_box、status、block_ids。
    inventory = 向后台申请库存列表()

    # item_by_id 从开门后一直保留到关门；Track 和库存结算都会使用它。
    item_by_id.clear()
    for A in inventory:
        item_by_id[A.item_id] = A

    track_buffer.clear()
    frozen_tracks.clear()
    no_hand_buffer.clear()
    track_session_is_ambiguous = False
    operation_pending = False
```

### 2.1 首个稳定快照

开门后先等待连续 N 帧无手，然后用这 N 帧投票合成首个稳定快照。

快照的完整生成规则见《快照的说明.md》。

```python
if session_active and not initial_snapshot_settled \
   and 已累计连续 N 帧无手:
    initial_snapshot = 生成投票快照()

    # 首个快照也使用《另一个版本.md》的同一套库存结算流程。
    # 此时没有手操作，因此 frozen_tracks 为空，不能凭 Track 判整理。
    settle_inventory(
        inventory=inventory,
        snapshot=initial_snapshot,
        frozen_tracks=[]
    )

    initial_snapshot_settled = True
```

正常情况下，开门前后物品没有变化，这次结算应主要得到严格匹配或局部匹配。

首个稳定快照结算完成后：

```python
track_buffer.clear()
frozen_tracks.clear()
track_session_is_ambiguous = False
operation_pending = False
```

注意：这里**不能**清空 `item_by_id`，因为门仍然开着，后续 Track 仍需要它。


## 3. 开门期间

开门期间按《track的说明.md》逐帧处理：

```python
if door_state == OPEN:
    process_frame(item_detections, hand_detections)
```

当手离开后，累计到连续 N 帧无手时，生成投票快照并结算：

```python
if door_state == OPEN \
   and operation_pending \
   and 已累计连续 N 帧无手:
    snapshot = 生成投票快照()

    settle_inventory(
        inventory=inventory,
        snapshot=snapshot,
        frozen_tracks=frozen_tracks
    )

    # 这是一次手操作的结算结束；库存和 item_by_id 保留。
    track_buffer.clear()
    frozen_tracks.clear()
    track_session_is_ambiguous = False
    operation_pending = False
```

`settle_inventory()` 就是《另一个版本.md》中的完整流程：

```text
严格匹配
→ 局部匹配
→ Track 唯一整理配对
→ 遮挡 / 出库 / 入库
→ 隐藏物品恢复判断
```


## 4. 关门

关门后画面变暗，不能再依靠暗帧生成稳定快照或补做库存判断。

```python
def on_door_close():
    if not session_active:
        return

    if operation_pending:
        # 最后一次手操作还没有得到“连续 N 帧无手”的投票快照。
        # 暗帧没有可靠视觉信息，不能在这里猜测最后的入库、出库或整理。
        记录本次存在未结算操作

    # 上传的始终是最后一次已经完成结算的库存。
    将当前 inventory 发送给后台()

    # 清理整个开门 Session。
    item_by_id.clear()
    track_buffer.clear()
    frozen_tracks.clear()
    no_hand_buffer.clear()
    track_session_is_ambiguous = False
    operation_pending = False
    initial_snapshot_settled = False
    session_active = False
```

### 4.1 关门前仍未结算的操作

```text
若用户刚移动物品就立刻关门，系统没有机会获得“连续 N 帧无手、明亮”的最终投票快照。
此时视觉上无法可靠判断最终库存。
```

因此本版本的规则是：

```text
不使用关门后的暗帧补算；
后台收到的是最后一次已确认结算后的库存；
同时记录“本次有未结算操作”，供日志、提示或后续业务处理使用。
```

若未来希望关门也能可靠结算，需要在门完全关上前保留连续 N 帧明亮、无手的最终投票快照；这属于后续扩展，不改变当前 2.0 的库存对比逻辑。
