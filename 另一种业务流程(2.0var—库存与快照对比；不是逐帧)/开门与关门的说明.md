# 开门与关门的会话流程（2.0）

> 本文件是《另一个版本.md》《track的说明.md》和《快照的说明.md》的外层流程。
> 一次“开门 → 关门”是一个 Session；但本地 `inventory` 与 `item_by_id` 不会在关门时清空。


## 1. 持久状态与会话状态

```text
跨关门持续保留的本地状态：
inventory
→ 每个物品的 item_id、cls_id、box、base_box、status、block_ids。

has_local_inventory
→ 本地 inventory 是否已经完成过初始化；即使 inventory 当前为空，也可以为 True。

item_by_id
→ `item_id -> inventory 中对应物品对象` 的持久索引；必须始终与 inventory 同步。

next_item_id
→ 下一个从未使用过的 item_id；跨关门持续递增，不能因当前 inventory 为空或删除了最大 ID 而回退。

needs_reconciliation
→ 上一次关门前是否存在尚未得到稳定快照的操作。

仅在当前开门 Session 中使用的状态：
track_buffer、frozen_tracks、no_hand_buffer、
track_session_is_ambiguous、operation_pending、initial_check_state。
```

`item_by_id` 与 `inventory` 指向同一批持久物品：新物品入库时插入映射，物品出库时删除映射。它不保存第二份库存数据，只提供按 `item_id` 的快速查找。

`initial_check_state` 用于说明本次开门后，第一个可用无手快照应该做什么：

```text
WAITING         # 已从后台取得初始库存，尚未完成首次校验
DONE            # 已完成首次校验或补结算，不再因会话开始而收集快照
SKIPPED         # 第一帧就是手，没有可用无手帧，直接采用后台初始库存
NOT_NEEDED      # 本地 inventory 已存在，不需要会话开始时的首次校验
RECONCILE_LOCAL # 本地 inventory 存在，但上次有未结算操作；等待首个正常 N 帧快照补结算
```


## 2. 光线状态与图像处理开关

门状态分为四种：

```text
CLOSED
→ 已确认关门；低频原始图像亮度检测，不运行 YOLO。

OPENING
→ 已发现开门亮度候选；立刻恢复正常取帧率，只做原始图像亮度确认。

OPEN
→ 已确认开门；正常帧率运行 YOLO、手检测、Track 和需要时的快照。

CLOSING
→ 已发现高置信关门暗帧；立即暂停 YOLO、Track、快照和库存结算，等待确认关门或恢复 OPEN。
```

所有亮度判断都直接使用原始图像；不需要先缩放、裁剪或输入 YOLO。

### 2.1 高置信的“可能正在关门”暗帧

不能因为画面稍微变暗，就进入 `CLOSING`。只有同时满足下列三项时，才认为当前帧是高置信关门暗帧：

```python
def is_high_confidence_closing_dark(light_features):
    return (
        light_features.mean_brightness <= closing_guard_threshold
        and light_features.mean_brightness
            <= open_brightness_reference * closing_drop_ratio
        and light_features.dark_pixel_ratio >= closing_dark_pixel_ratio_threshold
    )
```

其中：

```text
mean_brightness
→ 原始画面的整体平均亮度。

open_brightness_reference
→ 已确认 OPEN 时的稳定亮度基准，例如近期正常亮帧亮度的中位数；
  CLOSING 候选帧和偏暗帧都不能更新它。

dark_pixel_ratio
→ 亮度低于 dark_pixel_threshold 的像素占全图比例。
```

阈值关系应满足：

```text
closing_guard_threshold < opening_candidate_threshold < open_light_threshold
open_reference_update_threshold >= open_light_threshold
closing_drop_ratio < 1
```

也就是说，进入 `CLOSING` 要求“绝对很暗、相对开门亮度明显下降、而且画面大部分像素都变暗”。局部阴影、手挡住一部分画面、自动曝光的小幅变化，都不应满足这三个条件。

实际部署时，应采集同一摄像头下的“正常开门最暗画面”与“正常关门最亮画面”，再设置安全边距；不要把具体数值写死在业务逻辑中。

更新 `open_brightness_reference` 时，只把“明显处于正常开门亮度”的帧放入近期窗口，再取中位数；不能让逐渐变暗的帧把基准一路拉低。例如：

```python
def update_open_brightness_reference(light_features):
    if (
        light_features.mean_brightness >= open_reference_update_threshold
        and light_features.dark_pixel_ratio <= open_dark_pixel_ratio_limit
    ):
        recent_open_brightness.append(light_features.mean_brightness)
        recent_open_brightness 只保留最近 open_reference_window_size 个值
        open_brightness_reference = median(recent_open_brightness)
```

`open_reference_update_threshold` 应从正常开门亮帧中标定，并高于“只是略暗”的区域；它只决定哪些帧可更新基准，不替代上面的三项关门判断。

### 2.2 状态转换与 CLOSING 保护

```python
def process_raw_camera_frame(raw_frame):
    light_features = 从原始图像计算亮度、暗像素比例等特征(raw_frame)

    if door_state == CLOSED:
        # 此分支以 closed_light_check_fps 运行；建议先从约 10 FPS 调试。
        if light_features.mean_brightness >= opening_candidate_threshold:
            door_state = OPENING
            opening_confirm_count = 1
            恢复正常取帧率()
        return

    if door_state == OPENING:
        if light_features.mean_brightness >= open_light_threshold:
            opening_confirm_count += 1
            if opening_confirm_count >= open_confirm_frame_count:
                door_state = OPEN
                # 用已确认的亮帧建立本次开门的初始基准，避免刚开门就关门时基准为空。
                open_brightness_reference = light_features.mean_brightness
                on_door_open()
        else:
            # 亮度没有持续变亮，只是一次误触发。
            door_state = CLOSED
            降低到 closed_light_check_fps()
        return

    if door_state == CLOSING:
        if is_high_confidence_closing_dark(light_features):
            closing_confirm_count += 1
            if closing_confirm_count >= close_confirm_frame_count:
                on_door_close()
                door_state = CLOSED
                降低到 closed_light_check_fps()
        else:
            # 只是一次误暗帧；库存没有被修改，恢复正常 OPEN 即可。
            door_state = OPEN
            closing_confirm_count = 0
        return

    # door_state == OPEN
    if is_high_confidence_closing_dark(light_features):
        # 第一个高置信暗帧就停止把暗画面混入快照。
        # 注意：该候选暗帧不能参与 open_brightness_reference 的更新。
        door_state = CLOSING
        closing_confirm_count = 1
        clear_snapshot_buffer()
        return

    更新 open_brightness_reference(light_features)
    yolo_result = 正常尺寸预处理后输入 YOLO(raw_frame)
    process_open_frame(yolo_result.item_detections, yolo_result.hand_detections)
```

进入 `CLOSING` 后，即使尚未正式确认关门，也不再运行 YOLO、不更新 Track、不收集快照、不执行库存结算。若误判而恢复 `OPEN`，最多只是丢弃一段尚未完成的快照缓存；库存与 Track 证据不会被错误修改。

### 2.3 关门后的低消耗模式与快速唤醒

当 `door_state == CLOSED` 时，当前画面没有可靠的库存信息，因此不需要执行：

```text
不缩放 / 不裁剪成 YOLO 输入尺寸；
不把图片输入 YOLO；
不更新 Track；
不收集快照帧；
不执行库存结算。
```

只保留低频、低成本的原始图像亮度检测。`closed_light_check_fps` 不应低到影响响应；建议先从约 `10 FPS` 开始调试。检测到一次明显变亮的 `OPENING` 候选后，立即恢复正常帧率确认开门，因此最坏延迟主要是一帧低频检测间隔加少量确认帧，而不是长时间等待。


## 3. 开门：优先使用本地库存

开门只执行一次会话初始化，不能在门已打开时反复初始化。

```python
def on_door_open():
    if session_active:
        return

    session_active = True

    track_buffer.clear()
    frozen_tracks.clear()
    clear_snapshot_buffer()
    track_session_is_ambiguous = False
    operation_pending = False

    if has_local_inventory:
        # 本地 inventory 是上次结算后持续保存的库存，直接使用它。
        if needs_reconciliation:
            initial_check_state = RECONCILE_LOCAL
        else:
            initial_check_state = NOT_NEEDED
    else:
        # 只有冷启动、本地从未维护过库存时，才向后台申请初始库存。
        inventory = 向后台申请库存列表()
        保存为本地 inventory
        has_local_inventory = True

        item_by_id.clear()
        for A in inventory:
            item_by_id[A.item_id] = A

        # next_item_id 一旦使用就绝不回退；空库存按最大 ID 为 -1 处理。
        max_existing_item_id = inventory 中所有 item_id 的最大值，空库存时为 -1
        next_item_id = max(next_item_id, max_existing_item_id + 1)

        initial_check_state = WAITING
```

后台库存是本地库存结算后上传得到的。因此本地库存存在时，不需要每次开门都把后台库存与本地库存重新做视觉匹配。


## 4. 冷启动时的首次库存校验

只有 `initial_check_state == WAITING` 时需要首次校验。它的目的只是验证“快照中已经看见的物品”能否在后台初始库存中找到对应的【可见】物品；它不是普通的库存结算。

```text
快照中看见 B
→ 库存中应存在一个【可见】A 与 B 对应。

库存中有 A、但首次快照没有看见 A
→ 不能据此判 A 出库；不修改库存。
```

若快照中的 B 找不到对应可见 A，只记录“首次校验不一致”；不凭这一次校验直接入库、出库或修改 `block_ids`。

### 4.1 正常得到 N 帧首次快照

如果开门后先连续得到 N 帧无手，快照模块会正常返回 `initial_snapshot`：

```python
if initial_check_state == WAITING and initial_snapshot 已生成:
    只验证每个 B 能否对应 inventory 中的一个【可见】A
    initial_check_state = DONE
```

同一个库存 A 在首次校验中最多对应一个快照 B，避免两个快照物品同时“验证”同一个 A。
这里可复用严格匹配 / 局部匹配的候选与双向唯一规则，但它们只用于只读校验，不能写入 `affirm`、`item_id`、`box`、`base_box` 或 `block_ids`。

### 4.2 手先出现时，强行使用已有 k 帧

若首次 N 帧尚未凑满就检测到手，先在清空缓存前处理已有无手帧：

```python
def finalize_initial_check_before_hand():
    if initial_check_state != WAITING:
        return

    if no_hand_buffer 为空:
        # 第一帧就是手；没有可用画面，直接采用后台初始库存。
        initial_check_state = SKIPPED
        return

    # 此时实际只有 k 帧，1 <= k < N。
    # 以实际 k 帧进行投票、平均框和最终小框过滤，不能假装有 N 帧。
    short_snapshot = generate_snapshot_from_frames(no_hand_buffer)
    clear_snapshot_buffer()

    只验证 short_snapshot 中每个 B 能否对应 inventory 中的一个【可见】A
    initial_check_state = DONE
```

这项“用 k < N 帧生成快照”的特例只允许用于冷启动的首次校验。普通手操作结束后的快照仍必须使用连续 N 帧无手。

无论首次校验完成还是跳过，都不能再让之后的正常快照走“首次校验”分支；之后的快照应按正常 Track / 库存结算流程处理。

### 4.3 上一次关门时有未结算操作

若用户操作后立刻关门，上一轮没有得到稳定快照，`needs_reconciliation` 会保留为 `True`。下一次开门虽然本地库存存在，也不能一直跳过快照：

```text
等待首个正常的连续 N 帧无手快照
→ 使用该快照执行一次正式库存结算。
```

对于上一次未结算的操作，没有可用的旧 Track；若本次开门后又发生了新的手操作，则本次新建的 Track 仍会随快照一起冻结并参与结算。其余物品仍可通过严格匹配、局部匹配、遮挡、出库和入库逻辑更新库存。短帧首次校验不能用于这项补结算。


## 5. 开门期间逐帧处理与库存结算

正常 `OPEN` 期间，摄像头和 YOLO 始终按正常帧率运行；待机只是不再无意义地积累无手帧、投票生成快照或更新不存在的 Track。

```python
def should_collect_snapshot():
    # 会话刚开始需要一次初始化校验 / 补结算，或者刚刚发生过手操作时才收集无手帧。
    return (
        operation_pending
        or initial_check_state == WAITING
        or initial_check_state == RECONCILE_LOCAL
    )
```

一次正常库存结算完成后，`operation_pending = False`，且 `initial_check_state` 不再是 `WAITING` / `RECONCILE_LOCAL`；此时系统进入待机。下一次检测到手时，Track 的有手分支会立即令 `operation_pending = True`，从而重新允许手离开后的连续 N 帧生成快照。

```python
def process_open_frame(item_detections, hand_detections):
    if hand_detections 不为空:
        # 必须在 Track 的有手分支清空 no_hand_buffer 之前调用。
        finalize_initial_check_before_hand()

    # process_frame()：有手时更新 Track；无手时仅在 should_collect_snapshot() 为 True 时累计帧。
    # 只有连续 N 帧无手时才返回 snapshot，否则返回 None。
    snapshot = process_frame(item_detections, hand_detections)

    if snapshot is None:
        return

    if initial_check_state == WAITING:
        # 这是冷启动且从未有手时得到的正常 N 帧首次快照。
        只验证 snapshot 中每个 B 能否对应 inventory 中的一个【可见】A
        initial_check_state = DONE
        return

    if initial_check_state == RECONCILE_LOCAL:
        # 上一轮没有结算完成；本轮必须等待完整 N 帧快照后才补结算。
        freeze_all_tracks()
        settle_inventory(
            inventory=inventory,
            snapshot=snapshot,
            frozen_tracks=frozen_tracks,
        )
        needs_reconciliation = False
        initial_check_state = DONE
        return

    if operation_pending:
        # 稳定快照已经生成；此时才冻结本次尚未结算的 Track。
        freeze_all_tracks()

        settle_inventory(
            inventory=inventory,
            snapshot=snapshot,
            frozen_tracks=frozen_tracks,
        )

        # settle_inventory() 的最后一步会调用 clear_tracks_after_settlement()
        # 并重置 track_session_is_ambiguous 与 operation_pending。
```

`settle_inventory()` 就是《另一个版本.md》中的完整流程：

```text
严格匹配
→ 局部匹配
→ Track 唯一整理配对
→ 遮挡 / 出库 / 入库
→ 隐藏物品恢复判断
```

若手在凑满 N 帧前再次出现，`no_hand_buffer` 会被清空，但 Track 尚未冻结；这视为同一次尚未结算的复合操作，Track 可以继续更新。


## 6. 关门

关门后画面变暗，不能再依靠暗帧生成快照或补做库存判断。

```python
def on_door_close():
    if not session_active:
        return

    if operation_pending:
        # 最后一次手操作没有得到连续 N 帧无手的快照。
        # 暗帧没有可靠视觉信息，不能猜测最终入库、出库或整理。
        记录本次存在未结算操作
        needs_reconciliation = True

    # 上传的是最后一次已经完成结算后的本地 inventory。
    将当前 inventory 发送给后台()

    # 跨关门保留 inventory、has_local_inventory、next_item_id、needs_reconciliation。
    # item_by_id 只是 inventory 的内存索引，不是独立库存数据；若程序重启后恢复 inventory，
    # 必须从恢复后的 inventory 重建 item_by_id，不能序列化旧对象地址。

    # 只清理本次开门 Session；inventory 与 item_by_id 保留到下一次开门。
    track_buffer.clear()
    frozen_tracks.clear()
    clear_snapshot_buffer()
    track_session_is_ambiguous = False
    operation_pending = False
    initial_check_state = NONE
    session_active = False
```

若用户刚移动物品就立刻关门，系统没有机会得到最终稳定快照。当前版本不使用关门后的暗帧补算；后台收到的是最后一次已确认结算后的库存，同时记录“本次有未结算操作”。
