# 快照的说明（2.0）

> 快照不是某一帧的 YOLO 结果。
> 快照是连续 N 帧都没有手时，将这 N 帧 YOLO 结果投票合成的结果。

本版本的默认参数为：

```python
target_frame_count = 3  # 即 N = 3
vote_ratio = 1 / 2      # 物品必须出现在“超过一半”的帧中
```

因此，默认情况下物品必须在 3 帧中的至少 2 帧被识别到，才会进入快照。

## 1. 快照与 Track 的分工

```text
有手
→ 只处理 Track；Track 先确认库存物品是否真的被手移动。
→ 不保存快照帧。

无手，且当前需要快照
→ 当前需要快照只包括：冷启动的首次只读校验，或一次手操作后的正式结算。
→ 逐帧保存 YOLO 的非手物品结果。
→ 连续保存满 N 帧后，生成一个快照。

无手，但当前不需要快照（已有本地库存刚开门，或一次库存结算 / 首次校验完成后的待机）
→ 不向 no_hand_buffer 保存这一帧。
→ 摄像头和 YOLO 仍按正常帧率运行；只是没有必要重复投票、生成相同快照。
```

`no_hand_buffer` 只属于快照模块。Track 不能直接向它 `append()`；Track 只能调用快照模块提供的“清空缓存”或“加入一帧无手结果”接口。

普通情况下，手一旦重新出现，之前累计的无手帧全部作废，重新从第 1 帧开始保存。

唯一例外是冷启动的首次库存校验：若本地没有库存、首次 N 帧尚未凑满就出现手，外层流程会在清空缓存前一次性使用已有的 k 帧（`1 <= k < N`）生成短帧校验快照。完整规则见《开门与关门的说明.md》。


## 2. 连续 N 帧无手

```python
# 有手时由 Track 调用；只有快照模块实际修改 no_hand_buffer。
def clear_snapshot_buffer():
    no_hand_buffer.clear()


# 调用者必须已经确认当前帧无手。
def collect_no_hand_snapshot_frame(item_detections):
    # should_collect_snapshot() 定义在《开门与关门的说明.md》。
    # 待机时绝不积累无手帧；下一次手操作会把 operation_pending 设为 True，重新启用它。
    if not should_collect_snapshot():
        return None

    # 原样保存这一帧的非手 YOLO 识别结果。
    # 此时不修改库存，也不提前过滤过小框。
    no_hand_buffer.append(item_detections)

    if no_hand_buffer.size < target_frame_count:
        return None

    snapshot = generate_snapshot_from_frames(no_hand_buffer)
    clear_snapshot_buffer()
    return snapshot
```

无手期间不需要为快照建立复杂 Track，也不会因为某个物品在其中一帧漏检就重置这 N 帧。漏检由后面的投票阈值处理。


## 3. N 帧中的物品投票

N 帧收集完成后，统计每个物品在 N 帧中被 YOLO 识别到多少次。
为了知道不同帧中的 Detection 是否属于同一个投票物品，使用独立的、比“库存与快照匹配”更严格的 `snapshot_item_matches()`：

```text
1. cls_id 相同；
2. 中心点距离足够小；
3. 宽度差足够小；
4. 高度差足够小。
```

这些阈值应独立配置：要能容忍同一物品的 YOLO 小幅抖动，但不能把相邻的同类、同尺寸物品合并为一个候选。它只用于计票和平均框：不是 Track，不产生库存 `item_id`，也不影响库存状态。

不能对每个 Detection 直接取“第一个匹配候选”。例如同一帧有两个靠得很近的同类苹果时，两个 Detection 都可能命中同一个候选；后一个 Detection 被丢弃或并入前一个候选，都会破坏物品数量。

因此，每一帧都先收集全部候选边，再做一次 **Detection 与临时快照候选的一对一配对**：

```text
先最大化本帧成功配对的数量；
在配对数量相同的方案中，再选择总匹配分数最高的方案。
```

`snapshot_match_score()` 只在 `snapshot_item_matches()` 已通过时才计算；中心距离更近、宽高更接近、重叠更合理的配对分数更高。同分时按固定索引顺序打破平局，保证结果可复现。

```python
def build_snapshot_by_vote(frames, vote_ratio):
    snapshot_candidates = []

    for frame_index, frame_items in enumerate(frames):
        candidate_edges = []

        for D_index, D in enumerate(frame_items):
            for candidate_index, candidate in enumerate(snapshot_candidates):
                # 防御性限制：同一个候选在同一帧最多只能得到一票。
                if candidate.last_vote_frame == frame_index:
                    continue

                if snapshot_item_matches(candidate, D):
                    candidate_edges.append(
                        MatchEdge(
                            detection_index=D_index,
                            candidate_index=candidate_index,
                            score=snapshot_match_score(candidate, D),
                        )
                    )

        # 返回本帧的全局一对一最佳配对：
        # 先最多配对，再在同等数量下选总 score 最大的组合。
        matched_pairs = select_best_one_to_one_pairs(candidate_edges)
        matched_detection_indices = set()

        for D_index, candidate_index in matched_pairs:
            D = frame_items[D_index]
            candidate = snapshot_candidates[candidate_index]

            old_count = candidate.vote_count
            candidate.box = average_box(
                candidate.box, old_count,
                D.box, 1,
            )
            candidate.vote_count += 1
            candidate.last_vote_frame = frame_index
            matched_detection_indices.add(D_index)

        # 本帧没有与旧候选配对的 Detection，才各自创建一个新候选。
        for D_index, D in enumerate(frame_items):
            if D_index in matched_detection_indices:
                continue

            snapshot_candidates.append(
                SnapshotCandidate(
                    cls_id=D.cls_id,
                    box=copy_box(D.box),
                    vote_count=1,
                    last_vote_frame=frame_index,
                )
            )
```

这样每一个 Detection 和每一个临时快照候选在同一帧中都至多使用一次；两个相近的同类物品会保留为两个候选，而不是被“第一个匹配候选”的写法合并掉。

正常情况下，物品 A 每帧都被识别到：

```text
A.vote_count = N
```

若 YOLO 抖动或漏检，A 可能只在 N 帧中的 k 帧被识别到：

```text
A.vote_count = k
```


## 4. 票数过滤与平均框

N 帧统计结束后，只保留票数超过阈值的物品：

```python
snapshot = []

for candidate in snapshot_candidates:
    if candidate.vote_count > len(frames) * vote_ratio:
        snapshot.append(SnapshotItem(
            cls_id=candidate.cls_id,
            box=candidate.box,       # 所有已计票框的平均值
            item_id=-1,
        ))
```

默认采用 `vote_ratio = 1/2`：

```text
N = 3 时：candidate.vote_count > 3 × 1/2
即：candidate.vote_count >= 2
```

这个默认值能滤掉只出现 1 帧的偶发误检，同时能容忍 YOLO 在 3 帧中漏检 1 次。

若以后实际画面中连续 2 帧的误检很多，再考虑改成 `vote_ratio = 2/3`；按照当前“严格大于”的判定式，N = 3 时它会要求 3 帧全部检测到，默认不采用它。

因此：

```text
连续 N 帧无手
→ 保存这 N 帧 YOLO 结果
→ 统计每个物品出现的帧数
→ 出现次数超过阈值才保留
→ box 取该物品所有已计票框的平均值
→ 得到最终快照。
```

如果连续 N 帧都没有有效物品 Detection，最终得到空快照。


## 5. 生成快照后再过滤小框

先让所有 Detection 参与投票和平均，再检查最终快照物品的框是否过小。

```python
def filter_small_snapshot_boxes(snapshot):
    return [
        B for B in snapshot
        if B.box.width 不过小 and B.box.height 不过小
    ]


def generate_snapshot_from_frames(frames):
    # frames 可以是正常的 N 帧，也可以是冷启动首次校验时的 k 帧。
    snapshot = build_snapshot_by_vote(
        frames=frames,
        vote_ratio=vote_ratio,
    )
    return filter_small_snapshot_boxes(snapshot)
```

这一步就是《另一个版本.md》“对比前的预操作”中的快照小框过滤。过滤完成后，快照才进入库存结算流程。


## 6. 交给库存结算

生成后的 `SnapshotItem` 没有正式库存 `item_id`：

```text
投票快照
→ 过滤最终快照中的过小框
→ 按面积排序
→ 分配 temporary_id 与初始 item_id = -1
→ 进入《另一个版本.md》的库存结算流程。
```

快照生成阶段只负责得到可靠的当前画面，不直接修改库存；严格匹配、局部匹配、Track 的整理 / 出库结果、遮挡和入库，全部仍由《另一个版本.md》处理。

冷启动的首次短帧校验快照是唯一例外：它不进入上述普通库存结算，只验证“快照中看见的 B 能否在后台初始库存中找到对应的【可见】A”，并且不因缺少某个 A 而修改库存。
