> IoM(A, B) = 面积(A ∩ B) / min(面积(A), 面积(B))


**严格匹配**:
1. [cls_id]是否一样
2. [中心位置的距离]是否足够小    <!-- 中心位置的距离越小, 说明两个框在空间位置上越接近 -->
3. [框高的差值]是否足够小
4. [框宽的差值]是否足够小       <!-- [框高的差值、框宽的差值]这两个都小, 说明两个框的大小形状越接近 -->



**局部匹配**:
1. [cls_id]是否一样
2. [IoM(A,B)] 是否足够接近 1    <!-- 公式越接近1, 说明两个框的越接近包含关系 (可能是A包含B, 或者B包含A) -->



**先明白几个概念**
1. 这个版本只有【可见】与【遮挡】两种状态
2. 库存中可能有【可见】、【遮挡】物品
3. 虽然说快照上的物品没有状态一说, 但快照的物品本质上全都是【可见】物品
<!-- 4. 库存的【可见】物品 ≥ 快照的【可见】物品。 -->

> 框变小 —— 被遮挡的更多 (原先没被挡->现在被挡; 原先被挡->现在被遮挡的更多)
> 框变大 —— 被遮挡的更少 (原先被遮挡的更多->现在被遮挡的更少)



**快照**
> 这个版本的快照依旧是用原先的那种 [无手、稳定的n帧合成一个快照]



**track**
> 这个版本的 track 依旧是用原先的 track



**附近的量化**
> near(A, C)：
>   1. normalized_distance(A, C) 是否足够小
>   2. intersect_area(A.box, C.box) 是否足够大(或是否大于0)
其中：
    normalized_distance = center_distance(A, C) / min(A的对角线, C的对角线)
    intersect_area(A.box, C.box) 表示两个框的交集面积
注意:
    1. 我们要做的是找附近的物品, 所以其实 A 与 C 是否是同一类物品都无所谓的
    2. 而且我们使用的是快照与库存的物品进行对比, 这时候如果真的有物体挡住了或有物体移开了, 他们这样必
然原先是有重叠的面积的, 所以应该使用 intersect_area(A.box, C.box)

**注意**
我们之所以需要判断是不是在附近, 通常是因为有物品无法[严格匹配], 然后只能用IoM来[部分匹配], 这时候才会需要用到附近来判断
> 如果框变小了,我们来检查是否是有其他物品遮挡了原先的库存物品A, 这时候需要用[库存物品A的框](框较大)与[快照中物体的框]来遍历对比
> 如果框变大了,我们会检查是不是原先有物品从原先的库存物品A移走了,我们使用的是[快照物体B的框](框较大)与[库存中物体的框]来遍历对比
这样的话,感觉我们这种方法其实就能实现“附近”的判断, 但是核心关键是要正确的进行对比
(而不是盲目的用库存的物品对比库存的物品,快照的物品对比快照的物品)

# .block_ids 属性
> 有 .block_ids, 但是这个版本的 .block_ids 用法相对简单, 不会很复杂。
> 例如:
1. 若一个库存中的物品A看不见了, 并且快照中有个新的物品进来, 并且这个新的物品现在的位置能把原先库存中的这个物品A的位置几乎完全覆盖了, 那么这个物体A就变成【遮挡】, 并且记录这个物体A的 block_id 为这个新物品
2. 若当一个物品A被判断为【整理】, 我们就检查所有原先被这个物品遮挡的物品C, 如果整理后物体的位置(从快照可得) 跟被他遮挡的原先的物品不再重合, 那么这些物体C的 block_id 就去掉物品A的信息记录; 并且这个物品A整理后的位置如果挡住了其他物品B, 那么这个物品B的 block_id 就添加物品A的信息记录;
3. 若当一个物品A被判断为【出库】, 我们就检查所有原先被这个物品遮挡的物品C, 如果整理后物体的位置(从快照可得) 跟被他遮挡的原先的物品不再重合, 那么这些物体C的 block_id 就去掉物品A的信息记录
> block_ids 只记录按照当前业务流程判断为位于目标物品前方, 并且与目标物品 base_box 存在有效交集的物品
> 因此, 后续使用 block_ids 中的物品进行 apply_cover 时, 可以直接把它们当作前方遮挡物
> **整理后重新放置的物品, 以及本轮确认入库的新物品, 都视为位于发生重叠的旧物品前方**
(.block_ids 不是一个数, 而是一个集合set, 他要允许记录多个物品信息记录, 而且能自动**去重**)


# .base_box 属性
> 对库存物品 A 增加一个 .base_box 属性, 在物品 A 第一次入库时 A.base_box = A.box
> 这个 .base_box 并非是临时的(一轮的), 而是一直存在的
> 而且只在第一次入库时写入, 后续只有在[整理]时会被修改, 其他时候都不修改 
(我们这里简单(大胆)的认为: 整理之后, 不会有物体遮挡着A, A.block_ids 直接清空, 并且 A.base_box = A.box)
(可以用这个 .base_box 以及 .block_ids 来计算A是否完全被遮挡)

# apply_cover 函数
> 这个函数用来检测 A 是否被完全遮挡
> apply_cover 的作用、完整定义和判定条件见《矩形动态遮挡问题说明.md》



**先明白几个概念**
1. 库存中【可见】物品的 box 表示的是最近一次的box (上一次快照的box)
2. 库存中【遮挡】物品的 box 表示的是最近一次【可见】时的box (最近一次快照中看得见的时候的box)


**对比前的预操作**
1. 对比前, 先将快照物品中, [框的宽度过于小的]或[高度过于小的]物品进行过滤
> 因为[框的宽度过于小的]或[高度过于小的]这些物体, yolo看到的几乎是一条缝隙而已, 这些我们不应该认为他被成功识别

2. 然后, 先像将快照物品按照面积的大小进行排序 (大的先处理)
> 因为面积大的快照物品更可能对上库存中【可见】的物品, 这些物品更可能匹配的上
> (这只是一个代码实现中的小技巧, 逻辑本身没有改变; 如果排序本身的代价更重的话, 也可以不排序)

3. 给快照中的物品一个临时的 temporary_id 和 item_id
> 由于只有库存中的物品才有 item_id, 而快照中的物品没有 item_id
> 为了方便操作, 我们给排完序之后的快照中的物品一个临时的**temporary_id (从-1开始递减)**, 并且也给他们初始一个 item_id=-1
> 当快照中的物品的 item_id=-1 时表明他们还没有与库存中的物品匹配上, 否者表示已经匹配上了

4. 使用持久的 `next_item_id` 分配新物品 ID
> `next_item_id` 是跨关门保存的状态，表示下一个从未使用过的 item_id；不能每轮通过当前库存的最大 ID 重新计算。
> 每次有新物品入库时：
> ```python
> B.item_id = next_item_id
> next_item_id += 1
> ```
> 即使原来最大 ID 的物品已经出库，或 inventory 当前为空，`next_item_id` 也不能回退。

5. 建立临时映射 matched_snapshot_of_item
> matched_snapshot_of_item 只在当前一次快照结算中存在
> 它表示：当前库存物品A是否真的有一个当前快照物品B与之匹配; 若存在，则可通过该映射找到A当前对应的快照物品B
> matched_snapshot_of_item[库存 item_id] = 与该库存物品匹配的快照物品
> matched_snapshot_of_item 是一个字典 / 映射：
>   key   = 库存物品 item_id
>   value = 该库存物品本轮对应的快照物品 B
> contains_key(item_id)：
>   表示该 key 是否存在；
>   不会创建新项。
> 只有 contains_key(item_id) 为 True 时，
> 才允许读取 matched_snapshot_of_item[item_id]

6. 建立映射 item_by_id
> item_by_id[库存 item_id] = 对应库存物品对象
> item_by_id 与持久 inventory 一直同时保留, 不会在关门时清空；物品入库时向其中插入, 物品出库时从其中删除
> 当快照物品 B 入库时, 必须先把 B 转换 / 复制为持久的库存物品对象, 再放入 inventory 和 item_by_id；不能让 item_by_id 长期指向本轮快照中的 B。
> 下文写“物品 B 入库”之后，后续的 B 均表示这个已经创建好的持久库存物品对象。

### C++ 实现时的对象与容器约束

```text
1. inventory 是物品的唯一所有者；item_by_id 只是 item_id -> 持久物品对象的索引。
   快照 B 的生命周期只到本轮结算结束，绝不能把它的地址存入 item_by_id。

2. item_by_id 若保存 Item*（或 std::reference_wrapper<Item>），对应 Item 的地址必须稳定。
   例如 inventory 可保存 std::unique_ptr<Item>（vector 扩容不会移动 Item 本体），
   或使用其他稳定地址的所有权容器；不要把指向 vector<Item> 元素的裸指针
   长期放进 item_by_id 后又随意 push_back。

3. 一轮结算开始时，先从正式 `inventory` 复制出 `working_inventory`，并固定本轮
   原有物品的 `original_item_ids` 列表。结算期间的 item_by_id 指向 working_inventory
   中的物品；正式 inventory 与其持久索引在本轮中不修改。

   后续仍按本文既定顺序在 working_inventory 中执行：新入库物品插入 working_inventory
   和本轮 item_by_id；出库物品先从所有 block_ids 中移除其 ID、从本轮 item_by_id 删除，
   并在当前阶段不再需要它后再物理删除。全部步骤成功完成后，才用 working_inventory
   整体替换正式 inventory，并重建其持久索引。
```

### 本轮结算中“库存物品”的含义

```text
除非特别写明，本文后续的“库存物品”均指 working_inventory。

1. 严格匹配、局部匹配、整理、处理原本可见 / 原本遮挡的 A：
   遍历 original_item_ids，再按 item_id 到 working_inventory 中找到当前 A。
   这样本轮新入库的 B 不会被误当成“本轮原有 A”。

2. 更新 block_ids、计算 apply_cover、入库或出库时清理关联：
   遍历当前的 working_inventory。这样前面阶段刚整理或刚入库的 B，能立即参与后续的遮挡判断。

3. 正式 inventory 在本轮结算开始后保持不变；若任一步骤失败，则直接放弃
   working_inventory。该约定只保护提交，不改变本文的比较顺序或 block_ids 的前后遮挡语义。
```

## 1. 严格匹配

> 严格匹配的目标是先绑定那些“位置和大小几乎没有变化”的物品
> 严格匹配应该跳过【遮挡】的物品 (先让【可见】与看得见的物品匹配, 这样更稳)
> 我们最好要 A 与 B 一对一才好, 所以这里不应在扫描到第一个匹配时立刻修改 `A.affirm` 或`B.item_id`，而应分为两个阶段


### 1.1 收集严格匹配候选

以下候选表只在当前一次快照结算中临时存在，不写入正式库存：

strict_A_to_B[A.item_id]：A 可以匹配的 B.temporary_id 列表
strict_B_to_A[B.temporary_id]：B 可以匹配的 A.item_id 列表

```python
for A in working_inventory:
    if A.status != 【可见】:
        // 严格匹配是库存中看得见的与快照中看得见的进行的严格匹配, 因此只允许【可见】状态的物品进行匹配更合理, 也更高效
        continue

    for B in 快照物品:
        if 严格匹配(A, B):
            if A.block_ids 为空 and A.box.area*(1 + visible_area_growth_ratio_eps) < B.box.area:
                # visible_area_growth_ratio_eps 定义为非负配置值，初版可先用 0.10
                # 原本没有被遮挡的 A 不应无理由变大；
                # 此时可能是同类物品重叠，不作为严格匹配。
                continue

            strict_A_to_B[A.item_id].add(B.temporary_id)
            strict_B_to_A[B.temporary_id].add(A.item_id)
```


### 1.2 只接受双向唯一的严格匹配
> 若 A 有多个候选 B, 或 B 有多个候选 A, 则本轮不能仅凭严格匹配绑定它们

```python
for A in working_inventory:
    if strict_A_to_B[A.item_id].size != 1:
        continue

    B_id = strict_A_to_B[A.item_id][0]

    if strict_B_to_A[B_id].size != 1:
        continue

    B = 根据 B_id 找到对应快照物品

    A.affirm = True
    A.box = B.box
    B.item_id = A.item_id
    matched_snapshot_of_item[A.item_id] = B
```


**注意**
这里的严格匹配使用的阈值可以稍微严格一点 (但也不要过于严格, 以防全都匹配不上)
想法: 冰箱中并非所有物品全都改动很大的, 我们先来把那些改动不大的物品先匹配上(绑定上), 这样后续对比时就能少对比一点
(提前过滤掉一部分物品, 减少对比的次数, 相当于剪枝)
一开始会先给每一个库存物品A 都设置一个临时变量 A.affirm, 初始化为 False, 表示这个物品没有被匹配上
一开始会先给每一个快照物品B 都设置一个临时变量 B.item_id 初始化为 -1, 表示一开始是未匹配上的



## 2. 局部匹配
> 局部匹配只处理严格匹配后仍未绑定的物品
> 局部匹配也应该跳过【遮挡】的物品 (先让【可见】与看得见的物品匹配, 这样更稳)
> 局部匹配同样先收集候选, 再接受双向唯一关系


### 2.1 收集局部匹配候选

partial_A_to_B[A.item_id]：A 可以局部匹配的 B.temporary_id 列表
partial_B_to_A[B.temporary_id]：B 可以局部匹配的 A.item_id 列表

## 3. 处理没匹配的

> 直到这一步, 我们可以大胆认为:
1. 库存中剩下的没匹配上的物品 A (.affirm == False) 
    > 1.1 如果原先是【可见】的话, 要么是[被完全遮挡了]要么是[被整理到其他地方]或者[被拿走出库了]
    > 1.2 如果原先是【遮挡】的话, 要么是[依旧被完全遮挡]或者[其实已经露出了一点了,但是还没匹配上]
        > 1.2.1 如果原先是【遮挡】的话, 然后现在是[其实已经露出了一点了,但是还没匹配上]的话必然同时满足：
            > (1) 存在一个快照物品B与A满足"局部匹配" (也就是说现在快照物品B中应该有还没匹配上的, 并且B能与A进行"局部匹配")
            > (2) 在 .block_ids 稳定后(处理完“整理”、“出库”、“入库”之后), 还要计算 A 的面积是否没有被完全遮挡
            > (3) base_box 包含 B.box
2. 快照中剩下的没匹配上的物品 B (.item_id == -1) 要么是[新放进来的], 要么是[被整理到这里的], 要么是[原先是【遮挡】的,现在露出来了]


## 3.1 先处理[整理]

```python
    # B.box 就是整理后 A 的新 base_box
    A.box = B.box
    A.base_box = A.box

    # 正式确认 A 整理到 B
    A.affirm = True
    B.item_id = A.item_id
    matched_snapshot_of_item[A.item_id] = B

    # 按当前业务假设：整理后的 A 不被其他物品遮挡
    A.block_ids.clear()

    # 更新“被 A 遮挡”的其他库存物品 C
    for C in working_inventory:
        if C.item_id == A.item_id:
            continue

        if A.item_id in C.block_ids \
            and intersection_area(A.base_box, C.base_box) <= overlap_area_eps:
            C.block_ids.erase(A.item_id)

        if intersection_area(A.base_box, C.base_box) > overlap_area_eps:
            C.block_ids.insert(A.item_id)
```


## 3.2 局部匹配[库存中【遮挡】物品]与[剩余未匹配的快照物品]

> 之前的[严格匹配]与[局部匹配]中, 【遮挡】物品都跳过了匹配, 现在才来尝试匹配 (是故意这样做的)


**注意**
> 【遮挡】物品 A 与快照物品 B 匹配不是为了真的确认 A 与 B 的匹配关系, 而是为了先处理那些[连【遮挡】物品都匹配不上的物品]
> 所以我们要先来"临时"绑定【遮挡】物品 A 与快照物品 B


### 3.2.1 收集局部匹配候选

shelter_partial_A_to_B[A.item_id]：A 可以局部匹配的 B.temporary_id 列表
shelter_partial_B_to_A[B.temporary_id]：B 可以局部匹配的 A.item_id 列表

```python
for A in working_inventory:
    if A.affirm == True or A.status == 【可见】:
        continue

    for B in 快照物品:
        if B.item_id != -1:
            continue

        if not base_box_contains(A.base_box, B.box, contain_eps):
            continue

        if 局部匹配(A, B):
            shelter_partial_A_to_B[A.item_id].add(B.temporary_id)
            shelter_partial_B_to_A[B.temporary_id].add(A.item_id)
```

### 3.2.2 只接受双向唯一的局部匹配
```python
for A in working_inventory:
    if A.affirm == True or shelter_partial_A_to_B[A.item_id].size != 1:
        continue
    B_id = shelter_partial_A_to_B[A.item_id][0]

    if shelter_partial_B_to_A[B_id].size != 1:
        continue
    B = 根据 B_id 找到对应快照物品

    A.affirm = True
    B.item_id = A.item_id
    matched_snapshot_of_item[A.item_id] = B
```


## 3.3 处理[库存中未匹配的【可见】物品]

> 原本库存中【可见】, 但是现在这些物品匹配不了, 提出之前的[整理]情况后, 有以下几种情况：
1. 这个【可见】物品是[被完全遮挡了] (需要检查快照中是否有一个未匹配的物品完全覆盖了这个物品)
2. 这个【可见】物品是[被拿走出库了]

```python
for A_item_id in original_item_ids:
    if not item_by_id.contains_key(A_item_id):
        continue    # A 已在前面阶段出库
    A = item_by_id[A_item_id]

    if A.status != 【可见】 or A.affirm:
          continue
    temp_block_items=[]
    for B in 快照物品:
        if B.item_id==-1 and intersection_area(A.base_box, B.box) > overlap_area_eps:
            temp_block_items.append(B)
    # 计算A的剩余空间
    remaining = [normalize_box(A.base_box)]
    for C_item_id in A.block_ids:
        C = item_by_id[C_item_id] 
        new_cover= normalize_box(C.base_box)
        remaining, _ = apply_cover(remaining=remaining, new_cover=new_cover)
    for B_temp_block in temp_block_items:
        new_cover= normalize_box(B_temp_block.box)
        remaining, _ = apply_cover(remaining=remaining, new_cover=new_cover)

    if float(region_area(remaining)) <= area_eps:   # area_eps 要足够小
        # 到这里就直接认为这些 B 共同挡住了 A
        A.affirm = True
        A.status = 【遮挡】
        # 这些 B 要入库
        for B_temp_block in temp_block_items:
            物品 B_temp_block 入库, 修改 B_temp_block 状态为【可见】
            B_temp_block.affirm = True
            B_temp_block.item_id = next_item_id
            next_item_id += 1
            B_temp_block.base_box = B_temp_block.box
            B_temp_block.block_ids.clear()
            item_by_id[B_temp_block.item_id] = B_temp_block

            # 新物品入库, 要处理 .block_ids
            for C in working_inventory:
                if B_temp_block.item_id == C.item_id:
                    continue
                if intersection_area(B_temp_block.base_box, C.base_box) > overlap_area_eps:
                    C.block_ids.insert(B_temp_block.item_id)   # 要去重
    
    # 这里的 !A.affirm 是区分上一个循环的操作
    if !A.affirm:
        # 到着来没有确认是什么情况的话, 直接认为是"出库"了 
        removed_item_id = A.item_id
        物品 A 出库, 修改状态
        A.affirm = True
        item_by_id.erase(removed_item_id)
        # 旧物品出库, 要处理 .block_ids
        for C in working_inventory:
            if removed_item_id in C.block_ids:
                C.block_ids.erase(removed_item_id)    # 删不了也不要报错
```


## 3.4 处理[快照中未匹配的物品]

> 快照中看得见, 而且到现在都还没有匹配, 那么这种情况就默认是:
1. 这个物品是[新放进来的]

```python
for B in 快照物品 :
    if B.item_id == -1:
        物品 B 入库, 修改 B 状态为【可见】
        B.affirm = True
        B.item_id = next_item_id

        B.base_box = B.box
        B.block_ids.clear()
        item_by_id[B.item_id] = B

               continue 
            if intersection_area(B.base_box, C.base_box) > overlap_area_eps:

```


## 3.5 处理[库存中【遮挡】物品]

> 这时还是【遮挡】物品只有两种:
1. 这个【遮挡】物品之前与一个快照物品有匹配成功(临时匹配)：这个【遮挡】物品有可能露出了部分, 变成【可见】
> 必然同时满足：
    > (1) 存在一个快照物品B与A满足"局部匹配" (也就是说现在快照物品B中应该有还没匹配上的, 并且B能与A进行"局部匹配")
    > (2) 在 .block_ids 稳定后(处理完“整理”、“出库”、“入库”之后), 还要计算 A 的面积是否没有被完全遮挡
    > (3) A.base_box 包含 B.box
2. 这个【遮挡】物品没有匹配成功：这个物品依旧是【遮挡】不变

```python
for A_item_id in original_item_ids:
    if not item_by_id.contains_key(A_item_id):
        continue    # A 已在前面阶段出库
    A = item_by_id[A_item_id]

    if A.status == 【遮挡】and A.affirm == True and matched_snapshot_of_item.contains_key(A.item_id):
        B = matched_snapshot_of_item[A.item_id]
        flag = True
        if base_box_contains(A.base_box, B.box, contain_eps):
        # 这个 contain_eps 不要太小, 否者太严格 (当然也不能过于大)
            remaining = [normalize_box(A.base_box)]
            for C_item_id in A.block_ids:
                C = item_by_id[C_item_id] 
                new_cover= normalize_box(C.base_box)
                remaining, _ = apply_cover(remaining=remaining, new_cover=new_cover)

            if float(region_area(remaining)) > area_eps:    # area_eps 要尽量小一点
                A.status = 【可见】
                A.box = copy_box(B.box)
                flag = False
        
        if flag:
            # 说明 A 现在依旧是完全被遮挡的, 说明 B 并不是 A 露出后看到的, B现在大概率是新进来的物品
            matched_snapshot_of_item 删除键 A.item_id
            A 保持【遮挡】状态
            物品 B 入库, 修改 B 状态为【可见】
            B.affirm = True
            B.item_id = next_item_id
            next_item_id += 1
            B.base_box = B.box
            B.block_ids.clear()
            item_by_id[B.item_id] = B
            # 新物品入库, 要处理 .block_ids
            for C in working_inventory:
                if B.item_id == C.item_id:
                    continue
                if intersection_area(B.base_box, C.base_box) > overlap_area_eps:
                    C.block_ids.insert(B.item_id)   # 要去重
```
