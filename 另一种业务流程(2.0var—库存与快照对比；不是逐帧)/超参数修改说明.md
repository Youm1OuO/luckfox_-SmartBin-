本文件对应已经实现的 2.0 流程。所有业务阈值集中在：

```text
代码地址：tools/luckfox_pico_rkmpi_example/example/luckfox_pico_rtsp_yolov5n/include/fridge_config.h
2.0 配置起点：第 187 行（“2.0 库存 / 快照流程超参数”）
```

## 0. 当前无后台时的测试建库开关

| 常量 | 当前值 | 代码地址 | 作用 |
| --- | --- | --- | --- |
| `ALLOW_SNAPSHOT_BOOTSTRAP_WHEN_BACKEND_UNAVAILABLE` | `true` | `include/fridge_config.h` 第 223 行附近 | 第一次启动没有本地库存、后台又不可用时，用首次连续无手稳定快照建立本地测试库存。 |

## 1. 快照参数

代码使用位置：

```text
生成快照：src/snapshot.cc
调用时机：src/session.cc 的 should_collect_snapshot_() / process_frame()
```

| 常量 | 当前值 | 作用 | 调整建议 |
| --- | ---: | --- | --- |
| `SNAPSHOT_N` | `3` | 正常手后结算要连续收集的无手帧数 | 误检多可增至 4～5；响应太慢可保持 3。冷启动被手打断时，会按实际已有的 k 帧生成只读短快照，不受此处强行补足。 |
| `SNAPSHOT_S` | `0.5` | 投票条件为 `count > 实际帧数 × S` | `N=3,S=0.5` 要至少 2 票。误检多可提高；不能误以为是 `>=`。 |
| `SNAPSHOT_MIN_SCORE` | `0.5` | 进入快照投票的最低 YOLO 分数 | 漏检多可略降；误检多应优先提高。它也影响主循环送给业务层的物品。 |
| `SNAPSHOT_MIN_BOX_WIDTH` / `SNAPSHOT_MIN_BOX_HEIGHT` | `12 px` | 投票结束后过滤过小的最终框 | 图像分辨率或最小物品尺寸变化时一起调整；不要在投票前过滤。 |
| `SNAPSHOT_VOTE_CENTER_NORM` | `0.30` | 同一物品跨帧投票的归一化中心距离 | 太小会把抖动拆成多个物品，太大会把相邻同类物品合并。 |
| `SNAPSHOT_VOTE_WIDTH_RATIO` / `SNAPSHOT_VOTE_HEIGHT_RATIO` | `0.25` | 跨帧投票允许的宽、高相对差 | 与中心阈值一起标定。 |

`snapshot.cc` 对每一帧使用 Detection 与临时快照候选的全局一对一匹配，优先最大化匹配数量，再比较分数；不要改回“找到第一个候选就合并”的写法。

## 2. 库存与快照匹配 / 遮挡参数

代码使用位置：`src/session.cc` 顶部的 `strict_match()`、`partial_match()`、`apply_cover()` 和 `settle_snapshot_()`。

| 常量 | 当前值 | 作用 | 调整建议 |
| --- | ---: | --- | --- |
| `INVENTORY_STRICT_CENTER_NORM` | `0.26` | 严格匹配中心距离 | 太小会让不动的物品也落入后续流程；太大可能把相邻同类物品误绑。 |
| `INVENTORY_STRICT_WIDTH_RATIO` / `INVENTORY_STRICT_HEIGHT_RATIO` | `0.25` | 严格匹配宽、高相对差 | 与中心阈值一起调；严格匹配不使用 IoU。 |
| `INVENTORY_PARTIAL_IOM` | `0.84` | 局部匹配的 IoM 下限 | 降低可容忍更多遮挡/框变化，但更容易把相邻同类物品绑定。 |
| `VISIBLE_AREA_GROWTH_RATIO_EPS` | `0.10` | 原来没有 blocker 的可见物品允许变大的比例 | 过大可能把新放入的同类物品当成旧物品；过小可能把正常检测抖动拒掉。 |
| `BASE_BOX_CONTAIN_EPS` | `5 px` | 遮挡物品局部匹配时 `base_box` 包含关系的边界容差 | 坐标映射误差更大时提高；不要大到允许框明显跑出原位置。 |
| `BLOCK_OVERLAP_AREA_EPS` | `4 px²` | 写入 / 删除 `block_ids` 所需的最小有效交集面积 | 用于忽略仅边缘接触。 |
| `COVER_REMAINING_AREA_EPS` | `4 px²` | `apply_cover()` 后认为“已完全遮挡”的剩余面积上限 | 太大可能误判完全遮挡；太小会被浮点碎片阻挡。 |
| `TRACKED_BLOCKER_OCCLUSION_COVER_RATIO` | `0.60` | 旧物品在快照中消失、且本轮 Track 已确认前景物品 MOVED 时，前景框覆盖旧 `base_box` 的容差下限 | 只用于吸收 YOLO 框边缘误差，不影响普通静态缺失或 OUT。遮挡漏判可小幅降低；误把半遮挡当全遮挡则提高。 |

这里的 `block_ids` 是集合，且遮挡计算会逐块做矩形差集。不要改成“只记录一个 blocker”或只比较单个覆盖率。

## 3. Track 参数（整理 / 出库的必要证据）

代码使用位置：`src/session.cc` 的 `update_track_by_visible_item_()`、`update_track_by_hand_or_mark_invalid_()`、`get_track_settlement_result()`。

| 常量 | 当前值 | 作用 | 调整建议 |
| --- | ---: | --- | --- |
| `TRACK_ASSOCIATE_CENTER_NORM` | `1.00` | 有手期间 Detection 与既有 Track 的关联范围 | 太大易串到相邻同类物品；太小会让可见 Track 频繁转入遮挡分支。 |
| `TRACK_ASSOCIATE_WIDTH_RATIO` / `TRACK_ASSOCIATE_HEIGHT_RATIO` | `0.70` | Track 关联时的宽高容差 | 这是逐帧 Track 关联，不等于库存严格匹配。 |
| `TRACK_START_REAPPEAR_CENTER_NORM` | `0.55` | 判断物品是否仍留在原位 | 太宽会误判“仍在原位”，太窄会漏掉实际未移动物品。 |
| `TRACK_HAND_NEAR_NORM` / `TRACK_HAND_OVERLAP` | `1.25` / `0.12` | 候选建立和可见 Track 的接触证据 | 误建候选多时收紧；漏掉接触时放宽。 |
| `TRACK_FULL_OCCLUSION_OVERLAP` | `0.58` | 手完全遮住旧物品时建立候选的覆盖要求 | 它计算的是“物品被手覆盖的比例”。 |
| `TRACK_CARRY_OVERLAP` | `0.20` | 物品不见时，手仍可携带代理框的最低覆盖要求 | 只影响遮挡携带分支。 |
| `TRACK_HAND_MOVE_EPS` / `TRACK_OBJECT_MOVE_EPS` | `12 px` / `10 px` | 有效移动的最小像素位移 | 1280×720 下的起始值。分辨率改动时按比例调整。 |
| `TRACK_MOVE_DIRECTION_COS_MIN` | `0.65` | 手和物品位移的最小方向一致性 | 越接近 1 越严格。 |
| `TRACK_MOVE_MAGNITUDE_RATIO_MIN` / `MAX` | `0.25` / `3.50` | 物品位移 / 手位移的允许比例 | 太宽容易把无关抖动认成携带；太窄会拒绝真实操作。 |
| `TRACK_STILL_AT_START_FRAME_LIMIT` | `3` | 手移动但 A 连续留在原位几帧后判候选无效 | YOLO 抖动明显时可略增。 |
| `TRACK_LOST_FRAME_LIMIT` | `4` | 无足够携带证据时保留遮挡候选的帧数 | 太大可能积累旧候选；太小会漏掉短暂漏检。 |
| `TRACK_SETTLEMENT_CENTER_EPS` | `38 px` | Track 终点与最终快照 B 的中心距离 | 是像素单位，分辨率变化时按比例调。 |
| `TRACK_SETTLEMENT_WIDTH_EPS` / `HEIGHT_EPS` | `28 px` | Track 终点与最终快照 B 的宽、高绝对差 | 与上项一起标定。 |

重要约束：`OUT` 不能通过调低静态匹配阈值得到。代码只在冻结的 `hold_and_move=True` Track 没有唯一终点 B 时确认出库；若 Track 终点不唯一或同轮有多个结果，本轮不提交。

## 4. 手检测门槛

代码地址：`include/fridge_config.h` 第 41～46 行，以及第 223～229 行；主循环使用位置：`src/main.cc` 的 YOLO 检测分流。

| 常量 | 当前值 | 作用 |
| --- | ---: | --- |
| `YOLO_HAND_SCORE_THRESH` | `0.30` | YOLO 后处理保留手的最低分数。 |
| `HAND_CONTEXT_SCORE_THRESH` | 等于手阈值 | 达到它就视为“有手”：清空快照缓存、开始 / 继续手后流程。 |
| `OSD_STRONG_HAND_SCORE_THRESH` 等 | 仅显示用途 | 不参与库存与快照逻辑，不要用它替代 `HAND_CONTEXT_SCORE_THRESH`。 |

如果手漏检，优先检查模型类别和 `YOLO_HAND_SCORE_THRESH`；不要先放宽 Track 的移动条件。

## 5. 门状态机参数

代码使用位置：`src/main.cc` 第 146～170 行的原始亮度辅助函数，以及第 360 行附近的状态机。

| 常量 | 当前值 | 作用 | 调整约束 |
| --- | ---: | --- |
| `DOOR_OPENING_CANDIDATE_BRIGHTNESS` | `58` | CLOSED → OPENING 的平均亮度候选 | 必须高于稳定关门亮度。 |
| `DOOR_OPEN_LIGHT_THRESHOLD` | `68` | OPENING → OPEN 的确认亮度 | 必须高于 opening candidate。 |
| `DOOR_OPEN_CONFIRM_FRAME_COUNT` | `5` | 连续亮帧确认数 | 越大越稳但开门响应越慢。 |
| `DOOR_CLOSING_GUARD_THRESHOLD` | `42` | CLOSING 的绝对暗度条件 | 必须小于 opening candidate。 |
| `DOOR_CLOSING_DROP_RATIO` | `0.62` | 相对 open 亮度基准的下降比例 | 必须小于 1。 |
| `DOOR_DARK_PIXEL_THRESHOLD` / `DOOR_CLOSING_DARK_PIXEL_RATIO_THRESHOLD` | `38` / `0.72` | 多数像素变暗的条件 | 用于排除局部阴影、手遮挡与轻微曝光变化。 |
| `DOOR_CLOSE_CONFIRM_FRAME_COUNT` | `5` | 连续高置信暗帧确认数 | 越大越不易误关门，但关门确认更慢。 |
| `OPEN_REFERENCE_UPDATE_THRESHOLD` | `72` | 哪些 OPEN 亮帧能更新亮度基准 | 应不低于 `DOOR_OPEN_LIGHT_THRESHOLD`。 |
| `OPEN_DARK_PIXEL_RATIO_LIMIT` | `0.35` | 允许更新基准的最大暗像素占比 | 偏暗帧不能把基准拉低。 |
| `OPEN_REFERENCE_WINDOW_SIZE` | `20` | 亮度基准中位数的窗口长度 | 大一些更稳，小一些更快适应稳定光照变化。 |

当前默认关系满足：

```text
DOOR_CLOSING_GUARD_THRESHOLD < DOOR_OPENING_CANDIDATE_BRIGHTNESS < DOOR_OPEN_LIGHT_THRESHOLD
OPEN_REFERENCE_UPDATE_THRESHOLD >= DOOR_OPEN_LIGHT_THRESHOLD
DOOR_CLOSING_DROP_RATIO < 1
```

## 6. 推荐标定顺序

1. 先固定 YOLO 模型、摄像头分辨率和安装位置。
2. 用无操作视频标定快照投票与严格匹配，确认相邻同类物品不会被合并。
3. 用拿取、放回、整理视频标定 Track 的接触、移动和终点参数。
4. 用“新物体完整挡住旧物体”“遮挡物移开后露出”视频标定遮挡参数。
5. 最后采集正常开门最暗、正常关门最亮、局部遮挡、自动曝光变化等画面，标定门状态机。

每次只调整一组参数，并记录测试视频、误判类型和改动前后的结果。不要为了让某一个样例通过，同时大幅放宽快照、库存匹配和 Track 三组阈值。
