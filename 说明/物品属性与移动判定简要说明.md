# 当前代码中的物品属性与“整理”判定

对应代码：`luckfox_pico_rtsp_yolov5n/include` 与 `src`。以下都是已存在的字段。

## 四种“物品记录”

| 结构 | 字段 | 用途 |
| --- | --- | --- |
| `Detection` | `box`、`score`、`cls_id` | YOLO 单帧检测结果。 |
| `Track` | `track_id`、`cls_id`、`box`、`score`、`state`、`frames_since_update`、`hit_count`、`last_frame_id`、`start_frame` | ByteTrack 的临时轨迹；用于记录物品在每帧中的移动。 |
| `VotingItem` | `cls_id`、`box`、`best_score`、`count` | 稳定快照中的物品；`count` 是它在 4 帧投票窗口内出现的帧数。它本身没有 `item_id` 或 `track_id`。 |
| `InventoryItem` | 见下表 | 本地库存中的长期物品记录，真正用它保持身份。 |

## 每个库存物品 `InventoryItem` 的全部属性

| 字段 | 做什么 |
| --- | --- |
| `item_id` | 库存稳定身份；苹果移位后仍保留这个值。 |
| `track_id` | 最近关联的 ByteTrack 临时 ID；不是长期身份。 |
| `cls_id` | YOLO 类别，例如苹果。 |
| `box` | 主位置框，即流程文档中的 `anchor_box`。 |
| `visible_box` | 当前实际检测到的框；遮挡导致框变小，只更新它。 |
| `score` | 最近一次 YOLO 置信度。 |
| `status` | `VISIBLE`（可见）、`OCCLUDED`（遮挡）、`OUT`（出库）。 |
| `created_frame` / `updated_frame` | 创建与最近更新的帧号。 |
| `created_time_ms` / `out_time_ms` | 创建与出库时间；出库超过 10 分钟会清理。 |

## 快照以外，用来把 A 连到 B 的证据

| 结构 | 关键字段 | 用途 |
| --- | --- | --- |
| `TrackEvidence` | `track_id`、`associated_item_id`、`start_box`、`end_box`、起止帧、`occluded_by_hand` | 将某条物品轨迹关联到库存 `item_id`，记录它从哪里移动到哪里。 |
| `HeldProxyEvidence` | `item_id`、原物品/手的 `track_id`、`last_visible_box`、`proxy_boxes`、起止帧、`confidence` | 物品被手挡住而断轨时，连续记录手框，作为该物品的临时代理路径。 |
| `PendingRelocation` | `item_id_A`、旧框、新框、候选 B、`reid_score`、`evidence_score` | 证据不足的移动候选，等待下一份稳定快照确认。 |

## 当前代码实际如何判定“左边苹果移到右边”

1. 旧快照的左边苹果 A 会通过其主位置框 `box` 匹配到库存 `item_id`。
2. 每帧 `TrackEvidence` 记录 A 的起点和终点；手覆盖 A 后 A 消失，则建立 `HeldProxyEvidence`，持续保存手框路径。
3. 新快照出现右边苹果 B 后，系统先检查同类、面积接近、宽高比接近、检测分数接近；这叫当前代码的 `reid_score`。
4. 若 A 的轨迹终点或手代理路径终点靠近 B，证据分达到阈值，且 B 是唯一最优候选，就触发 `MOVED`：保留 A 的 `item_id`，把 A 的 `box` 与 `visible_box` 更新为 B 的框。
5. 若证据不够，先存入 `PendingRelocation`；仍不够时，才退回普通的“取出 + 放入”逻辑。

注意：当前 `reid_score` **还没有**使用颜色直方图、截图或深度 ReID 特征；它只使用类别、框面积、宽高比和置信度。因此“轨迹/手代理证据”在当前实现中特别重要。
