# 端侧上传逻辑详细说明

## 核心原则

**只传变化的物品，不传所有物品。**

每次快照差异判断后，只上报发生变化的单个物品信息。

---

## 上传时机

### 1. 入库（ITEM_IN）

**触发条件**：一个物品被认定为新物品，并且设置为【可见】状态时

**对应场景**：
- 用户放入一个新物品
- 物品从出库状态恢复为可见（放回冰箱）

**上报内容**：
```json
{
  "device_id": "luckfox-001",
  "event_type": "ITEM_IN",
  "timestamp": 1750083600000,
  "data": [
    {
      "local_track_id": 2,
      "category": "苹果",
      "confidence": 0.92,
      "bbox": [590, 309, 760, 478],
      "crop_image": "/9j/4AAQSkZJRgABAQ..."
    }
  ]
}
```

**特点**：
- 带截图（crop_image）：后端用于云端复核、图片保存、去重
- bbox 是物品当前位置 [x1, y1, x2, y2]
- category 是中文细粒度（如"苹果"）

---

### 2. 出库（ITEM_OUT）

**触发条件**：一个物品被判定为【拿出】时

**对应场景**：
- 用户从冰箱中拿走一个物品

**上报内容**：
```json
{
  "device_id": "luckfox-001",
  "event_type": "ITEM_OUT",
  "timestamp": 1750087200000,
  "data": [
    {
      "local_track_id": 1,
      "category": "苹果",
      "confidence": 0.95,
      "bbox": [586, 262, 754, 431],
      "crop_image": ""
    }
  ]
}
```

**特点**：
- 不带截图（crop_image 为空）
- bbox 是物品消失前的位置
- category 是中文细粒度

---

### 3. 整理（ITEM_MOVED）

**触发条件**：一个物品被判定为【整理】时

**对应场景**：
- 用户在冰箱内移动物品位置

**上报内容**：
```json
{
  "device_id": "luckfox-001",
  "event_type": "ITEM_MOVED",
  "timestamp": 1750089000000,
  "data": [
    {
      "local_track_id": 2,
      "category": "牛奶",
      "confidence": 0.88,
      "bbox": [200, 100, 350, 350],
      "crop_image": ""
    }
  ]
}
```

**特点**：
- 不带截图
- bbox 是物品的新位置
- category 是中文细粒度

---

## 不上传的情况

以下情况**不会触发上传**：

1. 物品从【遮挡】恢复为【可见】（只是状态变化，不是新物品）
2. 物品位置被动更新（因为其他物品遮挡变化导致 bbox 变化）
3. stable_frames 计数更新
4. 快照差异判断中的例行清理

---

## 与其他机制的关系

| 机制 | 是否触发上传 | 说明 |
|------|------------|------|
| 新物品入库 | ✅ ITEM_IN | 上传新物品信息 |
| 物品拿出 | ✅ ITEM_OUT | 上传拿出物品信息 |
| 物品整理 | ✅ ITEM_MOVED | 上传整理物品信息 |
| 遮挡变化 | ❌ 不上传 | 只是内部状态变化 |
| stable_frames | ❌ 不上传 | 只是内部计数 |
| 关门库存快照 | ✅ DOOR_CLOSE | 上传完整库存清单 |

---

## 总结

当前实现完全符合要求：
1. **只传变化的物品**，不传所有物品
2. **入库时带截图**，出库和整理不带
3. **实时上传**，每次快照差异判断后立即上报
