# C 被手遮挡、拿起、放下的细化规则

这里的 C 是已有库存物品；`C.box` 始终指进入 HAND_* 前保存的可靠完整框。
B 是当前帧中与 C 同类、尚未被任何旧库存、已有 D 或其他 HAND_* C 唯一认领的检测框。

只要某个 C 仍处于 HAND_*，同类贴手 B 必须先作为 C 的候选处理，不能立刻登记成 `HAND_VISIBLE_D`；若多个 C 都同样可能对应 B，则保持未决，不强行认领。

## 1. HAND_PARTIAL + hold_and_move=False

1. 先检查 C 原位置：若能匹配回 C，`not_hold_evidence_count += 1`，并清零 `hold_evidence_count`；连续达到阈值后释放 C。
2. 若原位置没有 C、也没有已确认物品 D 覆盖 C，并且 B 能匹配 `C.box + C.move_values` 得到的预计框，则 B 暂认给 C：`hold_evidence_count += 1`，记录 B 和轨迹。
3. 连续两次第 2 种证据后，设 `hold_and_move=True`。
4. 原位置与预计位置都无法可靠判断时是模糊帧；两个计数都不改变，不能因看不见 C 而释放或判出库。

## 2. HAND_PARTIAL + hold_and_move=True

此时已经确认 C 被手带着移动，不再用原位置决定“是否拿起”。每个有效手帧只更新 C 的移动量、预计框和已认领 B 的轨迹。

若 B 持续跟随手，继续记录轨迹。若 C 曾暂时看不见、之后突然出现同类 B，首次出现的 B 只能记为 `reappear_candidate_box`，不能立即认作 C 或新 D；下一帧还要能匹配到同一个 B。

当手继续移动、B 的位移明显小于手位移，且 B 与手逐渐脱离或 B 的框的大小更接近完整 C.box 时，`drop_evidence_count += 1`。连续达到阈值后，确认 C 已放下：`placed_box=B.box`、`state=PLACED`。框面积逐渐变大只是辅助证据，不能单独确认放下。

## 3. HAND_FULL + hold_and_move=False

C 完全看不见时，只需检查原位置：

1. 原位置看见 C，或有已确认库存物品 / D 覆盖 C：`not_hold_evidence_count += 1`；C 仍在原处或被遮挡。
2. 当前手框仍覆盖 C 原位置：模糊帧，两个计数都不改变。
3. 手已明显离开 C 原位置，原位置既没有 C、也没有已确认遮挡物：`hold_evidence_count += 1`。
4. 连续达到正向证据阈值后，设 `hold_and_move=True`；单帧看不见 C 不能直接确认拿起。

## 4. HAND_FULL + hold_and_move=True

此时 C 已确认被手带走，只记录手轨迹和 C 的完整预计轨迹。直到某帧出现同类、未被其他对象认领的 B，才建立 `reappear_candidate_box`。

B 必须在 C 从被遮挡开始后的候选轨迹附近，并在下一帧继续自匹配。若手继续移动而 B 基本停留原地，同时 B 与手分离或逐渐露出完整框，则累计 `drop_evidence_count`；连续确认后将 B 作为 C 的 `placed_box`，等待无手稳定快照确认整理。

## 5. 手离开后，仍为 HAND_PARTIAL / HAND_FULL + hold_and_move=False

不要立即 OUT，先使用连续无手稳定快照按以下顺序收尾：

1. C 原位置能匹配回 C：C 没有被拿走，恢复/保持可见。
2. 原位置没有 C，但 C 的完整候选轨迹上有唯一、稳定、未认领的 B：将 B 认作 C 的新位置，确认 MOVED。
3. C 原位置被已确认库存物品 / 新 D 覆盖：C 为 OCCLUDED，不是 OUT。
4. 前三者都不成立，且稳定无手快照中原位置、整条候选轨迹都找不到 C：才确认 OUT。

所有“首次出现的 B”都至少需要后续一帧自匹配或稳定快照支持；不能仅凭一帧同类检测框改变库存身份。
