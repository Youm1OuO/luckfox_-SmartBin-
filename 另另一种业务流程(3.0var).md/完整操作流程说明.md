# 2.0var：库存与快照对比的完整操作流程

本文把《问题.md》和 3.0var 版本中已经确定的思路，整理成一套完整的中文操作流程。这里的“快照”指某一帧 YOLO 输出的结果；库存更新仍然是“当前快照与库存的比较”，而手部移动、物品轨迹等信息则使用连续快照逐帧维护。

## 一、基本原则

系统同时维护两份库存：正式库存和工作库存。
正式库存是上一段操作已经确认的结果, 只有在本次手部操作结束、所有未决物品完成最终判断后才修改。
手进入后, 先把正式库存复制为工作库存；手还在画面中时，所有暂时确认的遮挡、移动、疑似入库和疑似出库都只写入工作库存。
这样一次手部操作连续整理多个物品时，后续帧能够使用前面已经得到的临时结果，但中途误判不会立即破坏正式库存。

库存物品具有唯一的 item_id。
当前检测框没有自己的库存身份，不能因为某个检测框暂时和某件物品相似就直接生成新的正式库存物品。
新物品必须经过后续帧稳定观察后，才能分配 item_id 并正式入库。

每个库存物品的状态分为“可见”“遮挡”“被手部分遮挡”和“被手完全遮挡”。
“遮挡”表示物品仍在原位置，只是被其他物品挡住；
“被手部分遮挡”和“被手完全遮挡”表示当前手部正在影响这个物品，但此时还不能据此认定它被拿起或移动。


## 二、开始一段连续手部操作

当连续帧中第一次识别到手时，系统开始一段新的手部操作。
如果当前没有工作库存，就先复制正式库存。随后保存第一帧的手框，并建立手的轨迹。

手刚进入画面时，默认只认为手在造成遮挡，不能在第一帧就认为手已经拿走了物品。
此时先检查手框附近是否出现物品检测框。
手附近的检测框可能是库存中原有的物品，也可能是手从画面外带进来的新物品，因此第一帧只能把它们记录为“疑似物品”，不能马上判定为入库。

如果库存中的物品被手部分遮挡，就把它改为“被手部分遮挡”。把这一帧被手挡住后仍然识别到的局部框同时记录为 `first_hand_block_box` 和 `last_hand_block_box`，并保留物品原来的 `box`。
`first_hand_block_box` 是刚被手挡住时的第一个局部框，只在进入该状态时记录一次，后续保持不变；`last_hand_block_box` 是最近一帧实际识别到的手遮挡局部框，每次成功匹配当前帧物品后都要更新。物品恢复“可见”或结束本次手部处理时，两者都清空。

如果库存中的物品被手完全遮挡，就把它改为“被手完全遮挡”，同样保留它被遮挡前的原位置，不因为当前看不到就修改 box。
上一帧手框 `old_hand` 是所有物品共用的帧级数据，不属于某个物品。
每一帧只根据当前手框与 `old_hand` 计算一次手部位移，然后把这次位移分别追加到当时已被手影响的每个物品自己的移动值列表中。
需要估计某个物品的新位置时，把它自己的位移列表相加得到净位移向量；如果要统计手实际经过的总路程，则把每个向量的长度相加。不能让多个物品共用一个累计列表。


## 三、每一帧的总体顺序

每得到一张新的快照，先判断当前是否检测到手。
如果上一帧也有手，就用公共的 `old_hand` 与当前手框计算本帧位移，并把同一个位移分别追加到所有已经处于“被手部分遮挡”或“被手完全遮挡”的物品的移动值列表中，然后把当前手框加入 hand_track。
当前帧才刚进入手部遮挡状态的物品从下一帧开始记录位移。
需要估计某个物品的新位置时，再把该物品列表中的位移逐项相加；
物品结束手部影响状态或手离开后，清空它自己的列表。

如果手没有发生足够明显的移动，我们直接不进行后续的出来, 直接进入下一帧。

如果手发生了明显移动，优先处理之前已经处于“被手部分遮挡”或“被手完全遮挡”的库存物品。
其他没有被手影响的物品不参与复杂的移动判断，避免把手臂遮挡、检测漏检或普通物品抖动误认为整理。

同一帧中，一个检测框只能被一个物品认领。
处理时先处理被手部分遮挡的物品，再处理与库存可见物品的局部匹配，再处理被手完全遮挡的物品，最后才处理无法解释的检测框。
一个检测框一旦被成功认领，后续物品不能再次使用它。
如果一个检测框有多个同样合理的来源，或者一个物品对应多个同样合理的检测框，则暂时保持未决，不强行选择。
(我们的移动值、物品的估计狂、手的框的轨迹这些全都有保存的, 而且是物品被手遮挡后各自保存不会出错, 所以这种设计方法允许暂时保持未决，不强行选择, 可以后续再尝试选择)


## 四、处理被手部分遮挡的物品

设库存物品 C 在手移动前处于“被手部分遮挡”。先检查 C 被手影响前的旧位置，也就是本段手操作期间保持不变的 `C.box`。这里不能使用 `last_hand_block_box` 代替旧位置，因为后者表示手遮挡后的最近局部框。旧位置的判断必须区分三种情况：原来的 C 仍在那里、原来挡住 C 的物品被重新露出、或者出现了一个库存中没有的物品。

### 4.1 旧位置仍然是 C

如果旧位置检测到的框仍然能够与 C 匹配，说明 C 很可能只是被手短暂遮挡，实际上没有被拿起。为了避免单帧 YOLO 抖动导致状态来回切换，第一次发现旧位置仍是 C 时只设置“暂时怀疑没有被手带走”，不要立刻清除 hold_and_move；如果下一帧仍然确认旧位置是 C，再把 C 恢复为“可见”，清除手部影响状态，更新 C 的 box 和其他普通跟踪信息。

### 4.2 旧位置露出一个已知库存物品

如果旧位置不再匹配 C，但出现了一个已经存在于库存中的物品 D，并且此前 D 确实位于 C 后方、被 C 遮挡，那么说明 C 可能已经离开旧位置，D 只是重新露出。此时不能仅凭 D 露出就立即确认 C 出库，还要继续根据手的移动量寻找 C 的新位置。

### 4.3 旧位置出现库存中没有的物品

如果旧位置不再匹配 C，并且那里出现了一个当前库存中没有的检测框 D，同时 D 还与手附近出现的疑似新物品相符，则更可能是新物品被放到了 C 原来的位置。此时 C 可能仍在原处，只是被新物品挡住；不能把 C 直接判为出库，也不能把 D 立即确认成入库。

### 4.4 旧位置没有任何可靠检测

如果旧位置既没有重新看到 C，也没有看到明确的新物品，只能说明 C 当前没有被看见。它可能被手拿走，也可能仍在原处但被手臂、手掌、其他物品或 YOLO 漏检遮住。因此这一帧只能保留“疑似被手带着移动”的状态，不能立即发出库事件。

### 4.5 根据移动量寻找 C 的新位置

在 4.2 或 4.4 的情况下，首先使用 C 的 `last_hand_block_box` 加上本帧手移动值，计算这一帧的局部估计位置；`last_hand_block_box` 就是最近一帧实际看到的手遮挡局部框。如果中间发生漏检、逐帧衔接失败，再使用保持不变的 `first_hand_block_box` 加上该物品的总移动值尝试重新找回。这里不能直接拿未被手遮挡时的完整框代替局部框。

然后在手框附近寻找检测物品 B，并用允许少量抖动和偏移的严格匹配检查 B 是否仍然是 C。若匹配成功，说明 C 很可能被手握住并移动到了 B 所在的位置，更新 C 的当前框、轨迹和移动状态，并把 B 标记为已经认领。若匹配失败，不能立即把 C 判为出库；继续保留 C 的疑似移动状态，等待后续帧验证，因为移动量累计误差、手臂遮挡、YOLO 漏检以及 C 尚未露出都可能造成暂时匹配失败。

## 五、处理手附近但尚未解释的检测框

如果手附近的 B 没有匹配到任何被手部分遮挡的物品，再拿它与工作库存中当前可见的物品 A 做局部匹配。局部匹配只说明 B 与 A 可能是同一物品的不同可见部分或不同遮挡程度，不能单凭局部匹配就判定发生了入库或整理；匹配成功后继续跟踪 A/B 的后续位置。

如果仍然匹配不上，再检查被手完全遮挡的库存物品。若 B 的类别与某个被手完全遮挡物品一致，且当前的空间关系合理，则认为原来完全看不见的物品现在露出了一部分，把 B 归还给该库存物品，并继续观察它是否随手移动。

如果 B 仍然无法与任何库存物品对应，才把它记录为“疑似新物品”。疑似新物品只保存类别、首次位置和最近位置，不立即写入正式库存。它必须在后续若干帧中持续存在并能稳定匹配，手离开后仍然可见，才确认是新入库物品。若它再次被手遮挡，继续保留疑似记录；若它很快消失，只删除未确认的疑似记录，不能因此反向生成出库判断。

手进入第一帧就贴近手出现的检测框与手移动过程中后来出现的检测框要区分记录。第一批疑似物品可能只是手带来的旧物品，也可能是原库存物品被重新检测到；后续批次则可能是手放下的新物品。两者都必须通过连续观察确认，不能只按出现时机直接判定。

## 六、处理被手完全遮挡的物品

对于被手完全遮挡的库存物品 C，因为看不到物品本身的框，不能根据“手移动了而 C 仍然看不见”就认定 C 被拿走。手臂没有被 YOLO 完整框出时，C 可能只是一直处于手臂阴影或遮挡区域。

因此，完全遮挡的 C 只记录旧位置、手的累计移动轨迹和可能的遮挡关系。若手移动后 C 在旧位置重新出现，说明它只是被短暂遮挡；若 C 在手附近或估计轨迹附近重新出现并能匹配，说明它可能被手带着移动；若两处都看不到，则继续保持未决，直到手离开并且相关区域真正恢复可观察。

## 七、遮挡关系和物品状态更新

每帧完成物品认领后，再处理剩余库存物品的遮挡关系。先处理已经确认被手带着移动或已确认新放置的物品，再根据它们与其他物品的矩形交集更新 block_ids 和遮挡状态。整理后重新放置的物品以及本轮确认入库的新物品，视为位于发生重叠的旧物品前方。

如果一个库存物品不再被手直接影响，但被其他物品遮挡，则状态为“遮挡”，保留原位置和库存身份；如果重新露出，则恢复为“可见”。只有在有足够证据表明它离开旧位置、并且后续在新位置或轨迹上重新找到它时，才把它记录为“已整理/已移动”。

## 八、整理的确认

整理必须满足“库存物品被手带到另一个位置并放下”这一条件。对于部分可见的物品，如果它露出的框在手移动过程中与手同步移动，并且在手停下或继续移动时出现明显的“掉队”，再结合新框与旧框的包含关系和局部匹配，才确认它被放下。若露出部分大小和形状明显改变，或重新回到旧位置，则优先认为只是遮挡。

对于完全遮挡的物品，只有在手移动过程中后来在手附近或估计轨迹附近重新出现，并且能与原物品唯一匹配，才确认整理。仅仅因为它一直没有被看到，不足以确认整理，更不足以确认出库。

一旦某物品在工作库存中确认完成整理，就更新它的工作位置和轨迹，并让后续帧使用这个新位置进行比较。正式库存仍然等到整段手部操作结束后统一提交。

## 九、入库的确认

新物品只能通过“手带入、在手附近出现、之后稳定存在”这一链路确认。手刚进来时附近出现的检测框先放入疑似新物品记录；手移动过程中在旧位置出现、但无法与任何库存物品对应的检测框，也放入同一类记录。

如果疑似物品在手离开后仍然存在，连续若干帧都能被同一条轨迹匹配，并且无法与已有库存物品对应，则确认它是新入库物品，分配新的 item_id，加入工作库存。只有在最终提交工作库存时，它才成为正式库存的一部分。

单摄像头存在无法解决的情况：如果新拿进来的物品与旧物品类别、大小和位置都完全相同，并且从摄像头角度完全重合，那么无法判断是新物品放入还是原物品一直存在。遇到这种情况按“没有发生可确认的入库”处理，不强行增加库存数量。

## 十、出库的确认

出库必须满足：物品曾经受到手部影响，手移动后物品在旧位置消失，随后在估计移动轨迹和手附近都没有重新出现，并且手离开后这些区域连续若干帧清晰可见。

手还在画面中时，任何“看不见 C”的结果都只能记为疑似出库，不能直接删除工作库存。尤其当手臂可能挡住 C、旧位置仍不可观察、或轨迹中存在其他遮挡时，C 必须保留为未决。

手离开后进行最终检查：如果 C 在原位置重新出现，撤销出库怀疑；如果 C 在轨迹附近稳定出现，确认整理；只有原位置和整条可能移动路径都清晰可见却始终没有 C，才把 C 标记为待出库，并在正式提交时发出 OUT 事件。没有明确出库证据的缺失物品继续保留在正式库存，不直接删除。

## 十一、手离开和本次操作结束

当连续快照中不再检测到手时，先不要立刻清空所有临时状态，而是进入本次手部操作的收尾阶段。此时使用手离开前保存的 hand_track、各物品的 track、旧位置以及最后几帧快照，对所有疑似移动、疑似入库和疑似出库物品做最终确认。

收尾结束后，确认没有移动的物品恢复为正常可见或遮挡状态；确认整理的物品保留新的位置；确认入库的疑似物品获得新的 item_id；确认出库的物品从工作库存移除；仍然无法观察清楚的物品保持未决并继续留在工作库存。

只有通过这一步最终检查，才把工作库存整体提交为正式库存，并统一产生 IN、OUT、MOVED 等正式事件。提交完成后清空本次手部操作的疑似新物品、待出库记录、手轨迹、物品移动值和临时状态。若操作异常中断，则丢弃工作库存，正式库存保持不变。

## 十二、整个流程的核心判断顺序

整个系统始终遵循以下优先级：先确认旧物品是否仍在旧位置，再判断旧位置是否露出已知库存物品或新物品；然后用手的移动量和物品轨迹寻找被带走的旧物品；再处理手附近检测框与可见库存、完全遮挡库存的匹配；最后才把无法解释的检测框当作疑似新物品。任何单帧的消失、出现或遮挡，都不能直接等价为出库、入库或整理，必须结合手部轨迹、旧位置、可观察性和手离开后的最终结果共同确认。
