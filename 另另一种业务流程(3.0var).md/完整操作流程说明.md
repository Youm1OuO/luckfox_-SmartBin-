# 2.0var：库存与快照对比的完整操作流程

本文把《问题.md》和 3.0var 版本中已经确定的思路，整理成一套完整的中文操作流程。这里的“快照”指某一帧 YOLO 输出的结果；库存更新仍然是“当前快照与库存的比较”，而手部移动、物品轨迹等信息则使用连续快照逐帧维护。

## 一、基本原则

系统同时维护两份库存：正式库存和工作库存。
正式库存是上一段操作已经确认的结果, 只有在本次手部操作结束、所有未决物品完成最终判断后才修改。
手进入后, 先把正式库存复制为工作库存；手还在画面中时，所有暂时确认的遮挡、移动、疑似入库和疑似出库都只写入工作库存。
这样一次手部操作连续整理多个物品时，后续帧能够使用前面已经得到的临时结果，但中途误判不会立即破坏正式库存。

库存物品具有唯一的 item_id。
当前检测框没有自己的库存身份，不能因为某个检测框暂时和某件物品相似就直接生成新的正式库存物品。
新物品必须经过后续帧稳定观察后，才能分配 item_id 并正式入库。

每个库存物品的状态分为“可见”“遮挡”“被手部分遮挡”和“被手完全遮挡”。
“遮挡”表示物品仍在原位置，只是被其他物品挡住；
“被手部分遮挡”和“被手完全遮挡”表示当前手部正在影响这个物品，但此时还不能据此认定它被拿起或移动。


## 二、开始一段连续手部操作

当连续帧中第一次识别到手时，系统开始一段新的手部操作。
如果当前没有工作库存，就先复制正式库存。随后保存第一帧的手框，并建立手的轨迹。

手刚进入画面时，默认只认为手在造成遮挡，不能在第一帧就认为手已经拿走了物品。
此时先检查手框附近是否出现物品检测框。
手附近的检测框可能是库存中原有的物品，也可能是手从画面外带进来的新物品，因此第一帧只能把它们记录为“疑似物品”，不能马上判定为入库。

如果库存中的物品被手部分遮挡，就把它改为“被手部分遮挡”。把这一帧被手挡住后仍然识别到的局部框同时记录为 `first_hand_block_box` 和 `last_hand_block_box`，并保留物品原来的 `box`。
`first_hand_block_box` 是刚被手挡住时的第一个局部框，只在进入该状态时记录一次，后续保持不变；`last_hand_block_box` 是最近一帧实际识别到的手遮挡局部框，每次成功匹配当前帧物品后都要更新。物品恢复“可见”或结束本次手部处理时，两者都清空。

如果库存中的物品被手完全遮挡，就把它改为“被手完全遮挡”，同样保留它被遮挡前的原位置，不因为当前看不到就修改 box。
上一帧手框 `old_hand` 是所有物品共用的帧级数据，不属于某个物品。
每一帧只根据当前手框与 `old_hand` 计算一次手部位移，然后把这次位移分别追加到当时已被手影响的每个物品自己的移动值列表中。
需要估计某个物品的新位置时，把它自己的位移列表相加得到净位移向量；如果要统计手实际经过的总路程，则把每个向量的长度相加。不能让多个物品共用一个累计列表。

完整的手框轨迹只保存一份公共 `hand_track`，不在每个物品中重复保存。某个物品开始进入“被手部分遮挡”或“被手完全遮挡”时，只记录当前手框在公共轨迹中的下标 `hand_track_start_index`。以后需要这个物品对应的手轨迹时，从公共列表的这个下标开始读取即可。因此，不同物品从不同时间开始被手遮挡也不会混淆，同时每个物品只额外占用一个整数。


## 三、每一帧的总体顺序

每得到一张新的快照，先判断当前是否检测到手。
如果上一帧也有手，先把当前手框追加到公共 `hand_track`，再用公共的 `old_hand` 与当前手框计算本帧位移，并把同一个位移分别追加到所有已经处于“被手部分遮挡”或“被手完全遮挡”的物品的移动值列表中。
当前帧才刚进入手部遮挡状态的物品从下一帧开始记录位移。
需要估计某个物品的新位置时，再把该物品列表中的位移逐项相加；
物品结束手部影响状态或手离开后，清空它自己的列表。

如果手没有发生足够明显的移动，对于 `hold_and_move=False` 的物品不进行估计轨迹匹配，也不增加正向或反向证据。因为“手停着，物品也停着”既可能是手正握着物品，也可能只是手挡在它前面，这一帧没有区分力，应当作模糊帧跳过。对于已经 `hold_and_move=True` 的物品，不再重新判断是否被握住；仍然继续维护它的 `track`，但单帧匹配不能单独确认放下。

如果手发生了明显移动，优先处理之前已经处于“被手部分遮挡”或“被手完全遮挡”的库存物品。对其中 `hold_and_move=False` 的物品，执行旧位置与估计位置的两类证据判断；对 `hold_and_move=True` 的物品，跳过这类证据判断，只更新 `track` 并尝试确认放下。
其他没有被手影响的物品不参与复杂的移动判断，避免把手臂遮挡、检测漏检或普通物品抖动误认为整理。

同一帧中，一个检测框只能被一个物品认领。
处理时先处理被手部分遮挡的物品，再处理与库存可见物品的局部匹配，再处理被手完全遮挡的物品，最后才处理无法解释的检测框。
一个检测框一旦被成功认领，后续物品不能再次使用它。
如果一个检测框有多个同样合理的来源，或者一个物品对应多个同样合理的检测框，则暂时保持未决，不强行选择。
(移动值和物品估计框由每个被手影响的物品分别保存；手框轨迹只公共保存一份，每个物品通过自己的 `hand_track_start_index` 取得相应片段。因此可以暂时保持未决，在后续帧继续判断，而不会混淆不同物品开始被遮挡的时间。)

**注意**
> 在本帧刚刚被改成【被手部分遮挡】与【被手完全遮挡】的物体, 他们的 shelter_or_hold=True, hold_and_move=False
> 他们只是被认为是被手遮挡而已, 目前还没有确认是否被手握住并移动。HAND_* 状态下的 `hold_and_move=False` 始终表示“待确认”，不是“已确认没有移动”。
> 每个待确认物品保存 `hold_evidence_count` 和 `not_hold_evidence_count`。连续两次有效证据支持随手移动，才把 `hold_and_move` 设为 `True`；连续两次有效证据支持仍在旧位置，才释放该候选并恢复为“可见”。相反方向的有效证据会清零另一个计数；无法得出结论的模糊帧不增加、也不清零任何计数。
> 连续确认“没有移动”后，该 `item_id` 暂时进入 `released_hand_candidate_ids`。在手仍然遮挡该物品时，不要每帧反复把它建立为 HAND_* 候选；手真正移开后解除这个抑制，因此以后手再回来拿它时仍能重新判断。


## 四、处理被手部分遮挡的物品

设库存物品 C 在手移动前处于“被手部分遮挡”,。
先查看 `C.hold_and_move` 再分支。`hold_and_move=False` 时，C 仍是待确认物品，才需要检查旧位置和估计位置并累计两类证据；`hold_and_move=True` 时，C 已经完成“跟手移动”的确认，不再重复做是否被握住的判断，只维护 `track` 并寻找放下证据。

### 4.1 `hold_and_move=False`：仍处于待确认

先检查 C 被手影响前的旧位置，也就是本段手操作期间保持不变的 `C.box`。这里不能使用 `last_hand_block_box` 代替旧位置，因为后者表示手遮挡后的最近局部框。旧位置的判断必须区分三种情况：原来的 C 仍在那里、原来挡住 C 的物品被重新露出、或者出现了一个库存中没有的物品。

#### 4.1.1 旧位置仍然是 C

如果旧位置检测到的框仍然能够唯一与 C 匹配，说明 C 很可能只是被手短暂遮挡，实际上没有被拿起。只有在手本帧明确移动时，才把这当作一次有效反向证据，令 `not_hold_evidence_count` 加一并清零 `hold_evidence_count`。连续两次有效判断都确认旧位置是 C，才把 C 恢复为“可见”，清除手部影响状态，更新 C 的 box 和其他普通跟踪信息。手没有明确移动时不增加计数。

#### 4.1.2 旧位置露出一个已知库存物品

如果旧位置不再匹配 C，但出现了一个已经存在于库存中的物品 D，并且此前 D 确实位于 C 后方、被 C 遮挡，那么说明 C 可能已经离开旧位置，D 只是重新露出。此时不能仅凭 D 露出就立即确认 C 出库，还要继续根据手的移动量寻找 C 的新位置。

#### 4.1.3 旧位置出现库存中没有的物品

如果旧位置不再匹配 C，并且那里出现了一个当前库存中没有的检测框 D，同时 D 还与手附近出现的疑似新物品相符，则更可能是新物品被放到了 C 原来的位置。此时 C 可能仍在原处，只是被新物品挡住；不能把 C 直接判为出库，也不能把 D 立即确认成入库。

#### 4.1.4 旧位置没有任何可靠检测

如果旧位置既没有重新看到 C，也没有看到明确的新物品，只能说明 C 当前没有被看见。它可能被手拿走，也可能仍在原处但被手臂、手掌、其他物品或 YOLO 漏检遮住。因此这一帧只能保留“疑似被手带着移动”的状态，不能立即发出库事件。

#### 4.1.5 根据移动量寻找 C 的新位置

在 4.1.2 或 4.1.4 的情况下，且仅当 `hold_and_move=False` 时，首先使用 C 的 `last_hand_block_box` 加上本帧手移动值，计算这一帧的局部估计位置；`last_hand_block_box` 就是最近一帧实际看到的手遮挡局部框。如果中间发生漏检、逐帧衔接失败，再使用保持不变的 `first_hand_block_box` 加上该物品的总移动值尝试重新找回。这里不能直接拿未被手遮挡时的完整框代替局部框。

然后在手框附近寻找检测物品 B，并先排除能严格匹配其他库存物品的 B，再用允许少量抖动和偏移的严格匹配检查 B 是否仍然是 C。若 B 匹配成功，同时 C 的旧位置已看不到 C 且没有未知物品占位，就累加一次 `hold_evidence_count` 并清零反向计数。连续两次有效判断都满足这组条件后，才设置 `hold_and_move=True`。在正式确认放下以前，`C.box` 继续保留本段 HAND_* 前的旧位置；B 只用来更新 `last_hand_block_box` 和候选轨迹。

若 B 匹配失败，或旧位置被未知物品占用，这是模糊帧，不能立即把 C 判为出库，也不能直接恢复为“可见”。两个证据计数都暂停，保留 C 的待确认状态与候选轨迹，等待后续有效帧。移动量累计误差、手臂遮挡、YOLO 漏检以及 C 尚未露出都可能造成这种情况。

### 4.2 `hold_and_move=True`：只跟踪并确认放下

一旦 C 的 `hold_and_move` 已经为 `True`，就不再检查旧位置来累计“没有移动”的证据，也不再修改两种证据计数。后续每帧只继续更新 C 的 `track`，并用轨迹估计框寻找检测物品 B。B 必须先排除能严格匹配其他库存物品的情况；即使 B 与 C 的 track 匹配，也只能说明 B 很可能是 C。

只有在手继续移动而 C 的框明显掉队，或者已经出现 C 与手分离的证据时，才确认 C 被放下并完成整理，随后用终点框更新 C 的工作库存位置。单独的 track 匹配不能确认放下。

## 五、处理手附近但尚未解释的检测框

如果手附近的 B 没有匹配到任何被手部分遮挡的物品，再拿它与工作库存中当前可见的物品 A 做局部匹配。局部匹配只说明 B 与 A 可能是同一物品的不同可见部分或不同遮挡程度，不能单凭局部匹配就判定发生了入库或整理；匹配成功后继续跟踪 A/B 的后续位置。

如果仍然匹配不上，再检查被手完全遮挡的库存物品。若 B 的类别与某个被手完全遮挡物品一致，且当前的空间关系合理，则把 B 归还给该库存物品。若该物品 `hold_and_move=False`，B 只作为待确认阶段的候选正向证据；若已经 `hold_and_move=True`，则跳过握持判断，只把 B 用于 track 匹配，并继续寻找掉队或与手分离的放下证据。

如果 B 仍然无法与任何库存物品对应，才把它记录为“疑似新物品”。疑似新物品只保存类别、首次位置和最近位置，不立即写入正式库存。它必须在后续若干帧中持续存在并能稳定匹配，手离开后仍然可见，才确认是新入库物品。若它再次被手遮挡，继续保留疑似记录；若它很快消失，只删除未确认的疑似记录，不能因此反向生成出库判断。

手进入第一帧就贴近手出现的检测框与手移动过程中后来出现的检测框要区分记录。第一批疑似物品可能只是手带来的旧物品，也可能是原库存物品被重新检测到；后续批次则可能是手放下的新物品。两者都必须通过连续观察确认，不能只按出现时机直接判定。

## 六、处理被手完全遮挡的物品

对于被手完全遮挡的库存物品 C，因为看不到物品本身的框，不能根据“手移动了而 C 仍然看不见”就认定 C 被拿走。手臂没有被 YOLO 完整框出时，C 可能只是一直处于手臂阴影或遮挡区域。

先查看 `C.hold_and_move`：

对于 `hold_and_move=False` 的 C，只有手本帧明确移动时才进行判断。旧位置唯一看到 C，是一次“没有跟手移动”的有效证据；根据 C 的估计轨迹找到一个与 C 唯一匹配、且不能严格匹配其他库存物品的 B，是一次“跟着手移动”的有效证据。两种证据分别累计，连续两次支持同一方向才采取对应动作；相反方向的有效证据会清零另一边计数。手没有明确移动、B 匹配不唯一、旧位置被未知物品占用或当前没有找到 B 时，都是模糊帧，两个计数都不增加也不清零。

对于 `hold_and_move=True` 的 C，已经确认它跟着手移动，不再重复检查旧位置，也不再修改上述两个计数。后续只继续维护 C 的 `track`，并将轨迹估计框与快照中的 B 匹配；B 必须先排除其他库存物品的严格匹配。只有结合 C 掉队或已经与手分离的证据，才确认 C 被放下、整理成功；单独的 track 匹配不能证明已经放下。

## 七、遮挡关系和物品状态更新

每帧完成物品认领后，再处理剩余库存物品的遮挡关系。手还在时，只有 `hold_and_move=True` 且已经出现掉队或分离证据的物品，才算“确认被手带到新位置”；在此之前它仍是 HAND_* 状态，只更新 track，不把它当作已放下物品。确认放下或确认入库后，再根据它们与其他物品的矩形交集更新 block_ids 和遮挡状态。整理后重新放置的物品以及本轮确认入库的新物品，视为位于发生重叠的旧物品前方。

如果一个库存物品不再被手直接影响，但被其他物品遮挡，则状态为“遮挡”，保留原位置和库存身份；如果重新露出，则恢复为“可见”。`hold_and_move=False` 的物品不能仅因消失就记录为“已整理/已移动”；`hold_and_move=True` 的物品也必须等到掉队或分离证据出现后，才把轨迹终点写入工作库存。

## 八、整理的确认

整理判断必须先看 `hold_and_move`。`hold_and_move=False` 的物品还没有确认跟手移动，不能在手还在时直接标记为整理；只能继续累计正、反向证据。只有 `hold_and_move=True` 后，才进入“跟踪并寻找放下证据”的整理分支。

对于已经 `hold_and_move=True` 的部分可见物品，如果它露出的框在手移动过程中与手同步移动，并且在手继续移动时出现明显的“掉队”，再结合新框与旧框的包含关系和局部匹配，才确认它被放下。若露出部分大小和形状明显改变，或重新回到旧位置，则优先认为只是遮挡。单独与 `track` 匹配不能确认放下。

对于已经 `hold_and_move=True` 的完全遮挡物品，只有在手附近或估计轨迹附近重新出现一个 B，B 先排除能严格匹配其他库存物品的情况，再与 C 的 `track` 估计框匹配，并且同时有掉队或与手分离的证据，才确认整理。仅仅因为它一直没有被看到，或单独因为 B 与 track 匹配，都不足以确认整理，更不足以确认出库。

一旦某物品在工作库存中确认完成整理，就更新它的工作位置并结束这次 HAND_* 临时状态，让后续帧使用这个新位置进行比较。正式库存仍然等到整段手部操作结束后统一提交。

## 九、入库的确认

新物品只能通过“手带入、在手附近出现、之后稳定存在”这一链路确认。手刚进来时附近出现的检测框先放入疑似新物品记录；手移动过程中在旧位置出现、但无法与任何库存物品对应的检测框，也放入同一类记录。

如果疑似物品在手离开后仍然存在，连续若干帧都能被同一条轨迹匹配，并且无法与已有库存物品对应，则确认它是新入库物品，分配新的 item_id，加入工作库存。只有在最终提交工作库存时，它才成为正式库存的一部分。

单摄像头存在无法解决的情况：如果新拿进来的物品与旧物品类别、大小和位置都完全相同，并且从摄像头角度完全重合，那么无法判断是新物品放入还是原物品一直存在。遇到这种情况按“没有发生可确认的入库”处理，不强行增加库存数量。

## 十、出库的确认

出库只能在手离开后的收尾阶段确认。手还在画面中时，任何“看不见 C”的结果都只能记为疑似出库，不能直接删除工作库存；只要还没有找到足够证据，C 就保留为未决。

手离开后进行最终检查，并按 `hold_and_move` 解释结果。对于 `hold_and_move=False` 的 C，不能把 False 当成“没有移动”：在原位置(A.box)看到 A，就确认没有移动；在候选 `track` 的其他位置看到 A，就补确认整理；在旧位置和整条候选轨迹上都没有重新找到 A，就补确认出库。对于 `hold_and_move=True` 的 C，不再重新进行两次握持证据判断；手离开本身提供了分离条件，若候选 `track` 的其他位置找到未被其他库存物品认领的 A，就确认整理，若旧位置重新找到 A，则按终局结果恢复没有移动，若两处都找不到 A，则确认出库。没有明确出库证据的缺失物品继续保留在正式库存，不直接删除。

## 十一、手离开和本次操作结束

当连续快照中不再检测到手时，先不要立刻清空所有临时状态，而是进入本次手部操作的收尾阶段。此时根据每个物品的 `hand_track_start_index` 读取公共 `hand_track` 中属于它的轨迹片段，再结合各物品的 track、旧位置以及最后几帧快照，对所有疑似移动、疑似入库和疑似出库物品做最终确认。收尾列表不能只包含 `hold_and_move=True` 的物品；所有仍在 HAND_* 中的 `False` 物品也必须进入收尾，因为它们是待确认而不是已否定。True 物品不再做握持证据判断，但仍要完成放下、没有移动或出库的终局判断。

收尾结束后，确认没有移动的物品恢复为正常可见或遮挡状态；确认整理的物品保留新的位置；确认入库的疑似物品获得新的 item_id；确认出库的物品从工作库存移除。没有明确出库证据的物品保持未决并继续留在工作库存。

只有通过这一步最终检查，才把工作库存整体提交为正式库存，并统一产生 IN、OUT、MOVED 等正式事件。提交完成后清空本次手部操作的疑似新物品、待出库记录、手轨迹、物品移动值和临时状态。若操作异常中断，则丢弃工作库存，正式库存保持不变。

## 十二、整个流程的核心判断顺序

整个系统始终遵循以下优先级：先按 `hold_and_move` 分支；False 的物品先用有效移动帧判断“仍在旧位置”或“跟着手移动”，True 的物品跳过握持判断、只维护 track 并寻找掉队或分离证据；随后再判断旧位置是否露出已知库存物品或新物品，再处理手附近检测框与可见库存、完全遮挡库存的匹配，最后才把无法解释的检测框当作疑似新物品。任何单帧的消失、出现或遮挡，都不能直接等价为出库、入库或整理，必须结合对应分支、物品轨迹、旧位置和手离开后的最终结果共同确认。
