# 同类旧物品未决时的新物品 D 仲裁

## 1. 核心问题

旧物品 C 没有成功匹配到新位置 B，**不等于** B 是新物品 D。
快速移动、漏检、框跳动以及同类物品靠近，都可能让 C→B 的匹配暂时失败。
因此不能因为“B 未被认领”就直接增加库存数量。

## 2. 帧内时序与同类 B 仲裁

`track_buffer` 中已经存在，不等于该 C 已成熟。
每个新建的 `CONTACT_*` / `HAND_*` C 都要在运行时保存“B 认领保护期剩余帧数”或进入帧（不写入 `InventoryItem`）；
只有自进入该状态后**完整经过两张后续有效帧**的 C，才是成熟 C，才可参与 B 的排他认领。

```text
成熟 C：已完整经过两张后续有效帧，且当前没有自己的可信检测框
保护期 C：刚因手路过/遮挡而建立，或两帧保护期尚未结束
```

处理未认领的同类 B 时：

- 保护期内的新建 C 仍必须用自己的原位置、`last_hand_block_box`、估计框或真实轨迹去尝试匹配 B，并记录“暂定 B”、连续匹配次数、`hold/not_hold` 等本地证据。
- 但保护期内的暂定 B 不是排他归属：新建 C 不能把 B 写成“只属于自己”的已认领框，不能阻止成熟 C 或 D 链路继续检查 B，也不能仅凭它确认自己已经移动。
- 只有已结束两帧保护期的成熟 C，才可把连续且唯一的暂定 B 升级为正式候选归属。
- 候选 C 还必须与 B 同类、没有自己的检测框，并且 B 能接上 C 自己的真实轨迹、估计轨迹或最后可靠框。
- 恰好一个成熟 C 合理：B 暂认给这个 C，继续整理确认。
- 多个成熟 C 合理：B 保持歧义；不生成 D，也不立即 OUT。
- 没有成熟 C 合理，但存在仍在保护期且与 B 相关的同类新建 C，或存在其他同类旧物品尚未解决：B 进入未决池，本帧既不归 C，也不建立 D。
- 没有任何同类旧物品未解决，且 B 具有手操作证据并连续出现：才开始疑似 D 链路。

保护期的时间线为：

```text
t0：C 刚进入 CONTACT/HAND，可记录暂定 B，但不能排他认领
t1：第一张后续有效帧，继续本地匹配和累计证据，仍不能排他认领
t2：第二张后续有效帧，仍只记录暂定 B；本帧结束后保护期结束
t3：C 成熟，才可把连续且唯一的暂定 B 升级为正式归属
```

若 C 在保护期内回到自己的原位置，就累计 `not_hold` 并清除自己的暂定 B；不必为了它强行等待完整两帧。若 C 持续缺失，且 B 连续接上 C 的路径，t3 起才允许 C 参与竞争。若此时仍有多个 C 合理解释 B，继续保持歧义。

## 3. 稳定快照结算

处理顺序为：

```text
已结束保护期的旧 C / HAND / CONTACT 认领
    -> 静态旧库存认领
    -> 保护期结束后的同类未决 B 与剩余旧 C 做一对一匹配
    -> 最后处理疑似新物品 D
```

稳定快照中的同类框必须一对一分配：一个 C 最多认一个 B，一个 B 最多属于一个 C。若仍有同类旧 C 没有得到独立的“仍在原位 / 已移动 / 明确 OUT”结论，就不能只因出现 B 而正式 IN。类别数量只作为保守约束，不能单独推断身份；例如“取出一个橙子又放入一个橙子”仍需各自的 OUT/IN 证据。

疑似 D 在稳定无手快照确认前始终是临时候选；无法区分时宁可保持未决，也不让库存数量膨胀。

不要只靠放宽轨迹阈值解决问题；应记录 C、B 的候选列表及被拒绝原因，区分“没有候选”“候选冲突”和“轨迹跳出范围”。
