# 同类旧物品未决时的新物品 D 仲裁

## 1. 核心问题

旧物品 C 没有成功匹配到新位置 B，**不等于** B 是新物品 D。
快速移动、漏检、框跳动以及同类物品靠近，都可能让 C→B 的匹配暂时失败。
因此不能因为“B 未被认领”就直接增加库存数量。

## 2. 同类 B 的处理规则

- 未认领的 B 与手相贴，且仍有同类旧物品 C 处于 `HAND_*`、`CONTACT_*` 或待确认缺失状态时，先记为“同类未决 B”，不能登记 D。
- 若只有一个旧 C 能根据原位置、真实轨迹和类别/尺寸解释 B，就把 B 暂认给 C，继续走整理确认流程。
- 若多个旧 C 都可能解释 B，保持歧义；不生成 D，也不立即 OUT，等待后续有效帧或稳定无手快照。
- 只有所有同类旧物品都已独立确认存在，且仍多出一个持续出现、具有手操作证据的 B，才允许建立疑似 D。

## 3. 稳定快照结算

处理顺序为：

```text
旧 C / HAND / CONTACT 认领
    -> 静态旧库存认领
    -> 同类未决 B 的全局匹配
    -> 最后处理疑似新物品 D
```

同一类别的旧物品数量没有减少而检测数量也没有增加时，优先解释为 `MOVED`，不能同时产生 `IN`。
疑似 D 在稳定无手快照确认前始终是临时候选；无法区分时宁可保持未决，也不让库存数量膨胀。

不要只靠放宽轨迹阈值解决问题；应记录 C、B 的候选列表及被拒绝原因，区分“没有候选”“候选冲突”和“轨迹跳出范围”。
