3.0var 超参数位置、作用与调节说明
====================================

一、参数代码位置
----------------

业务参数统一位于：

tools/luckfox_pico_rkmpi_example/example/luckfox_pico_rtsp_yolov5n/include/fridge_config.h

3.0 的会话状态机实现位于：

tools/luckfox_pico_rkmpi_example/example/luckfox_pico_rtsp_yolov5n/src/session.cc

修改参数后必须重新交叉编译。建议一次只改一项，并保存“参数版本 + 视频 +
事件日志”；多个阈值一起放宽，出现误匹配时会无法判断是哪一项造成的。

当前版本（3.0-r8）的固定规则（不是超参数）：同一张有手帧里，若旧物品已经拥有
自己的唯一最近严格检测框，该 item_id 会先占用该框；旁边同类、贴手且尚未被占用
的框才有机会进入疑似 D 链路。若某个 HAND_* 旧 C 没有自己的检测框，而同类贴手
B 又能唯一落在 C 的候选轨迹附近，B 会先作为 C 的 `reappear_candidate` 暂存，不能
立刻建立 D。多个 C 都合理时保持未决；单摄像头无法区分时不会凭类别相同强行增加数量。


二、无手稳定快照
------------------

SNAPSHOT_N（当前 3）
    连续多少张无手帧合成一份稳定快照。
    调大：抗 YOLO 漏检和框抖动更强，手离开后的确认更慢。
    调小：响应更快，但单帧误检/漏检更容易影响提交。

SNAPSHOT_S（当前 0.5）
    物品在 N 帧中出现比例必须严格大于 N*S 才进入快照。
    调大：更保守，误检更难进入快照，但部分露出物品可能被过滤。
    调小：更容易保留暂时可见物品，也更容易让噪声进入快照。

SNAPSHOT_MIN_SCORE、SNAPSHOT_MIN_BOX_WIDTH、SNAPSHOT_MIN_BOX_HEIGHT
    快照投票前的最低置信度和最小框尺寸。
    调大：去除小框噪声更有效，但远处、小物品或部分遮挡物品更容易丢失。
    调小：召回率更高，但错误检测也更多。

SNAPSHOT_VOTE_CENTER_NORM、SNAPSHOT_VOTE_WIDTH_RATIO、
SNAPSHOT_VOTE_HEIGHT_RATIO
    同一稳定快照内部，跨帧 YOLO 框是否属于同一候选的容差。
    调大：容忍抖动，但相邻同类物品可能被错误合并。
    调小：物品之间更容易区分，但同一物品可能因抖动被拆成多票。


三、库存身份匹配
------------------

INVENTORY_STRICT_CENTER_NORM、INVENTORY_STRICT_WIDTH_RATIO、
INVENTORY_STRICT_HEIGHT_RATIO
    严格匹配：稳定位置上的同一物品判断。
    调大：框抖动时更容易保持同一 item_id，但同类相邻物品误认风险上升。
    调小：身份更保守，但轻微移动也可能匹配失败。

INVENTORY_PARTIAL_IOM
    正常局部匹配阈值。用于物品部分露出、但仍在原位置时。
    调大：只有高度重叠才认同一物品，安全但容易漏掉遮挡后的局部框。
    调小：局部框更容易继承旧 item_id，但同类邻居更可能误配。

FLOW3_HAND_PARTIAL_MIN_OBSERVED_COVER、
FLOW3_HAND_PARTIAL_MAX_AREA_RATIO、FLOW3_HAND_PARTIAL_CENTER_NORM
    这三项只用于“手正在影响物品”时，把 YOLO 的局部框优先认领给已有库存
    物品，避免移动旧物品时被错误建成新的 D。它们不参与无手稳定快照匹配。
    MIN_OBSERVED_COVER 调大：局部框必须更多地落在旧框内，较安全，但遮挡较深
    时容易把旧物品漏成 D；调小：更能容忍局部框偏移，但相邻同类物品误认风险升高。
    MAX_AREA_RATIO 调大：允许局部观测框比旧框略大，容忍 YOLO 抖动，但真正的新
    物品更可能被旧物品吸收；调小：更保守，但框变大时可能误建 D。
    CENTER_NORM 调大：允许局部框中心偏离更远，减少遮挡下的重复 IN；过大则会
    增加同类邻居被错误认领的风险。

FLOW3_TRACK_CENTER_NORM、FLOW3_TRACK_PARTIAL_IOM、
FLOW3_TRACK_WIDTH_RATIO、FLOW3_TRACK_HEIGHT_RATIO
    HAND_* 期间的轨迹匹配容差。它比普通严格匹配宽，用于“旧框 + 该物品自己的
    累计移动值”所得到的预计位置。
    调大/调小的影响与严格匹配相同，但这里过大尤其危险：会把相邻同类物品当成被手
    拿着移动的那个物品。

FLOW3_REAPPEAR_CANDIDATE_CENTER_NORM、
FLOW3_REAPPEAR_CANDIDATE_WIDTH_RATIO、FLOW3_REAPPEAR_CANDIDATE_HEIGHT_RATIO
    只用于 C 曾暂时看不见后，判断一个同类 B 是否足够接近 C 的完整候选路径，从而
    暂记为 `reappear_candidate`。它比普通 FLOW3_TRACK_* 略宽，但候选还必须连续
    自匹配，且最终仍要通过无手稳定快照，所以它不会单帧产生 MOVED 或 IN。
    调大：更能抵抗手框/YOLO 在相邻有效帧间的大跳动，减少“移动 C 被误建成 D”；
    过大：较远的同类新物品也更可能被保守地暂认给 C，导致真实 IN 延后或保持未决。
    调小：同类身份更严格，但快速手移动或运动模糊时更容易重新落入 D 链路。

FLOW3_OLD_POSITION_OVERLAP_AREA
    判断某个检测是否占据旧位置的最小交集面积。
    调大：只有明显占位才影响旧位置判断，较抗边缘抖动；过大可能漏掉真实局部露出。
    调小：对小面积占位敏感，但更容易被框边缘误差干扰。


四、手框与有效帧
----------------

HAND_MICRO_MOVE_SKIP_EPS（当前 6 像素）
    没有任何未决 HAND_* / CONTACT_* 轨迹时，连续两帧手框四条边的差异都小于该值，
    当前帧才会跳过。存在活动轨迹时，即使手框不动也继续检查物品检测框，避免漏掉
    手指推动。该跳过只减少业务层计算；如果上游已经先完成 YOLO 推理，不会减少推理本身。
    调大：普通静止手帧计算更少，但可能吞掉小幅手框变化。
    调小：更灵敏，但普通手框抖动会带来更多业务层处理。

FLOW3_CONTACT_PATH_CENTER_NORM（当前 1.10）
    CONTACT_* 中，当前物品框相对 A 的原框或 observed_track 某一点的最大归一化中心
    距离。仍需同时满足类别和宽高比例条件。
    调大：能容忍快速推拉或 YOLO 框跳动，但相邻同类物品串身份风险上升。
    调小：身份更安全，但快速移动时容易暂时找不到 B。

FLOW3_CONTACT_WIDTH_RATIO、FLOW3_CONTACT_HEIGHT_RATIO（当前均 0.35）
    CONTACT_* 的 B 与 A 完整框/历史真实框的相对宽高差容差。
    调大：容忍视角和检测框尺寸变化，但同类邻居更容易被吸收。
    调小：形状约束更严格，但框抖动或轻微尺度变化可能使候选保持未决。

FLOW3_CONTACT_OBJECT_MOVE_EPS（当前 12 像素）
    CONTACT_CANDIDATE 中，物品相对上一真实观测框的最小中心移动量；超过它才累积
    hold 证据。它同时用于低覆盖率候选判断“是否仍在原位置”。
    调大：更能过滤 YOLO 抖动和手指微动，但小幅整理可能无法确认。
    调小：小幅推拉更容易确认，但误移动和原位判断抖动风险上升。

CONTACT_* 的固定规则（不是单独超参数）：接触状态保存在 OperationTrack.contact_state，
不写入 InventoryItem。CONTACT_* 只保存物品真实 observed_track/observed_move_values；
手部 hand_track 和 hand_move_values 仅作辅助，不用手腕位移计算物品终点。首次有效 B
需要与手相贴，连续两次真实移动证据才进入 CONTACT_MOVING；没有可靠 B 时两个证据计数
都暂停。手离开后先查原位置，再查 observed_track；两者都没有时先保持未决，稳定无手
帧持续缺失且没有遮挡解释后才允许 OUT。若接触候选后来达到 e2/e1 转入 HAND_*，
会把接触阶段最后一次真实 B 保存为 HAND_* 的估计锚点，但仍保留 original_box 作为
最终原位置比较基准，避免“已推开但仍与旧框局部重叠”被释放为未移动。

FLOW3_HAND_ATTACH_DISTANCE
    手与新物品 D 的边缘最大距离；用于“相贴”而不是“遮挡”。除有手阶段的
    HAND_VISIBLE_D 外，它也用于 POST_HAND_REVEAL_D：手离开后，完整 B 必须
    与本次公共 hand_track 中至少一段手框相贴/接近，才可作为“全程被手遮住的
    新物品”候选。
    调大：更容易发现手带入的新物品，也更容易把手旁边的旧物品误当 D。
    调小：D 判断更保守，但新物品和手之间有检测间隙时可能漏掉。

FLOW3_HAND_NEAR_MAX_INTERSECTION_AREA
    hand_is_near 允许的手/物品最大交集面积。相贴时理论上应几乎无交集，YOLO
    抖动会造成少量交集，所以保留这个容差。
    调大：更容易把实际被手压住的物品当成“相贴 D”。
    调小：更符合“相贴”定义，但手框抖动时可能漏掉真实 D。

FLOW3_HAND_PARTIAL_COVER_RATIO（e2，当前 0.30）
    已有库存物品进入 HAND_* 的最低覆盖率。对进入 HAND_* 前的可靠完整框 A.box
    计算 r = intersection_area(hand.box, A.box) / area(A.box)：r < e2 时不进入
    HAND_*；e2 <= r < e1 时进入 HAND_PARTIAL。
    调大：只有手实质遮住更多物品面积才建立候选，手从旁边经过更不容易误触发；
    但手刚压住物品、覆盖尚浅时可能漏掉候选。
    调小：更早开始跟踪手影响的物品，但手框抖动或手臂边缘擦过时更可能产生候选。

FLOW3_HAND_FULL_COVER_RATIO（e1，当前 0.88）
    手覆盖已有完整物品多少比例后，才从 HAND_PARTIAL 升为 HAND_FULL。它必须大于
    e2 且接近 1；r >= e1 为 HAND_FULL，中间区间始终是 HAND_PARTIAL。当前是否还能
    检测到物品不参与这一分类，局部 YOLO 框也不能作为分母。
    调大：更接近视觉上的“完全遮挡”，避免把普通交叠误视为 HAND_FULL；但 YOLO
    手框偏小或边缘不准时，真实完全遮挡可能长期停在 HAND_PARTIAL。
    调小：更早建立 HAND_FULL，但会将较深的部分遮挡误当作完全遮挡。

FLOW3_HAND_DETECTION_OVERLAP_AREA（当前 300 像素²）
    只用于“新物品 D 是否贴手/与手相交”及其放下判断，不能用于已有库存物品的
    HAND_PARTIAL/HAND_FULL 分类。POST_HAND_REVEAL_D 检查 B 与历史 hand_track
    的每一段关系时也会使用它。D 初次出现时没有可靠的被遮挡前完整框，因而不能
    套用 e1/e2 覆盖率规则。
    调大：D 必须与手有更大交集才被认为贴手，误建 D 更少，但可能漏掉手框与物品框
    之间只有少量重叠的真实新物品。
    调小：D 更容易获得贴手证据，也更容易把手旁的旧框误当成 D。

FLOW3_D_REAPPEAR_MIN_PARTIAL_COVER（当前 0.35）
    仅用于 D 的“局部框 → 手离开后完整框”路径重现。若最终完整检测框 B 覆盖
    D 路径中某个预测局部框的比例达到该值，可作为重现候选；C 不使用此规则。
    调大：要求 B 与预测局部位置重叠更多，身份更安全，但手持偏移或 YOLO 框抖动时
    可能漏掉真实 D。
    调小：更容易接回局部→完整的 D，但同类物品靠近路径时更可能产生误关联。

FLOW3_D_REAPPEAR_MAX_CENTER_SHIFT_NORM（当前 0.45）
    当 B 没有足够覆盖预测局部框时，允许的最大归一化中心偏移；分母使用 B 和局部
    框中较大的对角线。它同样只用于 D 的局部→完整重现。
    调大：容许手中物品相对手框发生更大偏移，召回率更高，但同类邻居误关联风险更高。
    调小：路径重现更严格，安全但可能遗漏“放下后完整框偏移较大”的 D。

TRACK_HAND_MOVE_EPS
    手明确移动的距离阈值；主要用于判断物品是否可能掉队放下。
    调大：过滤慢速手抖，慢速整理可能难确认。
    调小：慢速动作更容易确认，但手抖也可能累积成移动证据。


五、hold_and_move 与放下
-------------------------

FLOW3_HOLD_EVIDENCE_REQUIRED（当前 2）
    连续多少次有效“物品出现在自己的预计轨迹上、旧位置干净”的证据后，才把
    hold_and_move 设为 True。
    调大：更谨慎，减少误判拿起；确认整理/出库更慢，短动作可能不够证据。
    调小：响应更快，但一次误匹配就可能变成移动候选。CONTACT_CANDIDATE 也使用
    此门槛；只有达到后才把 contact_state 设为 CONTACT_MOVING。

FLOW3_NOT_HOLD_EVIDENCE_REQUIRED（当前 2）
    连续多少次有效“物品仍在旧位置”的证据后，释放 HAND_* 候选。
    调大：更能容忍一帧错误旧位置匹配，但候选持续更久。
    调小：很快释放，可能错过随后真正拿起或推拉的动作。CONTACT_CANDIDATE 只有在
    A 真实回到原位置时才增加该计数；漏检或歧义帧不会增加。

FLOW3_DROP_FALL_BEHIND_RATIO
    手继续移动而物品框移动明显较少时，“掉队”的比例。它只是放下证据的必要条件；
    还必须同时满足 B 已与手脱离或 B 的宽高更接近完整 C.box，并连续达到
    FLOW3_DROP_EVIDENCE_REQUIRED 次才会进入 PLACED。
    调大：更容易累积放下证据，可能把手持但慢速移动的物品提前放下。
    调小：更严格，放下确认更慢，更多依赖无手稳定快照。

FLOW3_REAPPEAR_CANDIDATE_CONFIRM_FRAMES（当前 2）
    `reappear_candidate` 首次出现后，需要连续多少次能匹配到同一个 B，才可把 B
    作为旧 C 的已确认重新出现位置。若 B 是在无手第一帧才首次可见，也同样使用
    这个门槛；稳定快照仍是正式提交的最后一步。
    调大：对一帧误检、同类串身份更稳，但快速操作后确认整理更慢。
    调小：更快恢复 C 的身份，但单帧 YOLO 跳动更容易造成错误整理。

FLOW3_DROP_EVIDENCE_REQUIRED（当前 2）
    连续多少帧出现“手继续走、B 基本停住、且 B 脱手/更接近完整框”的组合证据后，
    才确认放下并进入 PLACED。
    调大：避免单帧手框跳动触发整理，代价是放下确认更慢。
    调小：实时性更高，但单帧误差可能提前确认放下。

FLOW3_DROP_FULL_BOX_IMPROVEMENT（当前 0.08）
    B 相对完整 C.box 的宽高差至少改善多少，才把“框逐渐变完整”视为辅助放下证据。
    调大：只有明显从局部框变完整时才计入，较安全但可能漏掉轻微改善。
    调小：更容易把框大小变化计入放下，适合局部框变化小的模型，但更容易受抖动影响。

FLOW3_COMMIT_MOVE_CENTER_DISTANCE
    最终提交时，旧 base_box 与新 base_box 的中心距离达到此值才发 MOVED。
    调大：小幅整理不会发事件；调小：YOLO 框抖动也可能被报告为整理。


六、D、新入库、遮挡
--------------------

NEW_ITEM_CONFIRM_FRAMES（当前 2）
    suspect D 连续有效自匹配次数达到该值后，才提升为工作库存物品。
    调大：更难误入库，但手快速放下物品时确认会变慢。
    调小：实时性更高，但一帧误检更容易成为候选 D。

    说明：D 在第二次有效观察达到该值后进入工作库存；正式 IN 仍要再等连续
    SNAPSHOT_N 张无手稳定帧完成结算。若感觉“手已离开但一直不提交”，先看画面
    左上角是否仍是 HAND / rawH>0；只要仍检测到手，稳定快照会被重置。

    疑似 D 的发现入口有三个：贴手出现的 HAND_VISIBLE_D、无法认领且替代 C 原位置
    的 C_POSITION_REPLACEMENT_D、以及手离开后首次完整出现的 POST_HAND_REVEAL_D。
    前两者从有手帧开始计数；第三者以首张无手完整 B 记为第 1 次，下一张有效无手帧
    必须自匹配才可提升。三者都不能绕过稳定快照直接正式 IN。

FLOW3_C_REPLACEMENT_MIN_COVER_RATIO（当前 0.30）
    有手阶段，若已有库存 C 已进入 HAND_*、本帧又没有自己的检测框，而一个未被
    库存认领的 D 覆盖 C 的原始完整框达到该比例，则将 D 以
    C_POSITION_REPLACEMENT_D 预登记；即使 D 已经不贴手也一样。
    调大：只有 D 明显盖住 C 才会记录，误把路过框当 D 的风险更低，但部分遮挡的
    “放下 D 覆盖 C”可能漏掉。
    调小：更容易保护 C 不被误判 OUT，并更早记录 D；但框边缘轻微交叠也更可能生成
    无法确认的 D 候选。

FLOW3_POST_HAND_REVEAL_WINDOW_FRAMES（当前 2）
    手离开后，允许从“库存无法认领、且贴近本次 hand_track”的完整 B 创建
    POST_HAND_REVEAL_D 的最早无手帧数。它必须留出至少一次后续无手自匹配，才可能
    在当前稳定快照中正式 IN；当前 SNAPSHOT_N=3、NEW_ITEM_CONFIRM_FRAMES=2，因此
    设为 2。
    调大：手离开稍晚才被 YOLO 看到的真实新物品更不容易漏掉；但会扩大“旧物重现或
    误检被误建 D”的时间范围，而且过大时本轮稳定快照没有足够帧完成二次确认。
    调小：入库来源更紧贴手离开时刻，安全性更高；但首帧漏检时更容易漏掉全程被手
    遮挡的真实 D。

FLOW3_D_PARTIAL_COVER_RATIO
    已确认的新 D 放下后，对一个旧 HAND_* 物品达到多少覆盖比例时，可作为
    “C 先保留、不能判 OUT”的遮挡证据。
    调大：更严格，部分遮挡下 C 更可能保持未决。
    调小：更容易把 C 判为遮挡，可能隐藏真实取出。

BLOCK_OVERLAP_AREA_EPS、COVER_REMAINING_AREA_EPS
    矩形差集遮挡计算的面积误差。代码使用 apply-cover 思路计算多个框的并集覆盖，
    不直接把交集面积相加。
    调大：更容忍 YOLO 框边缘缝隙，容易把接近完整覆盖当成完整覆盖。
    调小：几何判断严格，但边缘抖动可能导致遮挡关系无法确认。


七、调参顺序
--------------

1. 先调 SNAPSHOT_*：确保没有手时同一物品的稳定框不会乱跳。
2. 再调 INVENTORY_STRICT_* 与 INVENTORY_PARTIAL_IOM：确保静态库存不产生
   新 item_id，也不合并相邻同类物品。
3. 调手框参数与 HAND_MICRO_MOVE_SKIP_EPS：先让“手经过但没拿”不产生移动。
4. 最后调 FLOW3_TRACK_*、FLOW3_CONTACT_*、两类 evidence 阈值、放下与遮挡参数。
   若“移动旧 C 却误报 IN”，先检查/小幅调大 FLOW3_REAPPEAR_CANDIDATE_*；若
   “真正相邻同类 IN 长期保持未决”，再小幅调小它们，并保留回放验证。

每次验证至少回放以下操作：

- A 移动后放回；
- A 移动到 B 前方，B 遮挡；
- 再移开 A，B 露出；
- 取出 A；
- 放入新 D；
- 同类物品无法唯一判断时，库存数量不得增加，状态应保持未决。
- 手腕基本不动、手指推动物品时，旧 item_id 不得变成新的 D；应先出现
  CONTACT_CANDIDATE，连续真实框移动后才变为 CONTACT_MOVING。

重要原则：稳定快照中“没有绑定 item_id 的框”不会自动入库。只有具有 D 的
“有手阶段已发现（贴手或替代 C 原位置）→ 连续自匹配 → 稳定存在”，或
“手离开后首次显现且贴近本次 hand_track → 连续无手自匹配 → 稳定存在”证据链，
才允许产生正式 IN 事件。

同类相邻验证应分两种情况：

- 旧物品和新物品各自都有独立检测框时，应保留旧 item_id，并让新框完成 D→IN；
- 两者已经完全重叠，只剩一个同类检测框时，单摄像头没有足够证据区分数量，系统
  应保持未决，不应伪造新的 item_id。
