# 低覆盖率推、拉物品的处理思路

手没有握住物品、只是用手指推动或拉动物品时，手与物品的覆盖率可能低于 `e2`。
这类情况不能直接当作普通可见物品，也不能直接登记为新物品 D。

## 1. 两类状态分开记录

遮挡状态：

```python
r >= e1       -> HAND_FULL
e2 <= r < e1  -> HAND_PARTIAL
r < e2        -> 普通可见
```

当 `r < e2` 但手与物品相贴时，增加独立的手部影响状态：

```python
NONE -> CONTACT_CANDIDATE -> CONTACT_MOVING
```

不需要扩大手框；接触条件使用手框与物品的距离及少量交集判断。

## 2. 低覆盖率候选的确认

`CONTACT_CANDIDATE` 只表示“可能被推、拉”，暂时不确认移动。

后续检测到 B 时，B 必须满足：

- 与 A 同类，宽高与 A 的完整框接近；
- 没有被其他库存物品认领；
- 与 A 的上一观测框或已有轨迹连续；
- 实际移动量超过检测抖动阈值；
- 初次确认时 B 应与手相贴。

只有唯一的 A 能解释 B 时才累计证据；多个同类物品都可能解释时保持未决，不生成 D。

连续两次得到有效 B 后，确认 `CONTACT_MOVING`（即推、拉已确认），之后沿 B 的轨迹继续处理。确认后每帧不再强制要求 B 始终与手相贴。

## 3. 两个证据计数

```text
找到唯一且确实移动的 B：
    hold_evidence_count += 1
    not_hold_evidence_count = 0

A 在原位置重新出现：
    not_hold_evidence_count += 1
    hold_evidence_count = 0

当前帧没有可靠 B：
    两个计数都暂停
```

连续确认 A 仍在原位置后释放候选；不能因为单帧漏检就判断未移动，也不能立即判定出库。

## 4. 手框不动时的跳帧

手框严格匹配且没有活动的 `CONTACT_CANDIDATE/CONTACT_MOVING` 时，可以跳过重复帧。

只要存在低覆盖率候选，就不能因为手腕或手框没有明显移动而整帧跳过；物品可能被手指移动。手框严格匹配应允许少量检测抖动。

## 5. 每帧处理顺序

```text
1. 更新已有物品的 HAND_* 与 CONTACT_* 候选
2. 用轨迹和连续证据确认旧物品是否移动
3. 处理手离开后的候选和稳定快照
4. 最后才把无法被任何旧物品解释的检测登记为新物品 D
```

低覆盖率接触候选在移动确认前保持旧物品身份，避免“只是推动旧物品却误登记新 D”。
