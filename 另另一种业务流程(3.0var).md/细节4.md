# 新物品 D 全程被手遮挡、手离开后才首次完整出现

## 问题

现有的 D 流程要求：D 至少在一帧【有手】画面中以局部框出现，先被预登记为疑似 D；之后即使被手完全遮挡，也能在手离开后通过整条候选路径，把完整检测框 B 重新认回 D。

但还有另一种正常入库情况：手拿着 D 进入画面时，D 始终被手完全遮挡（或所有能看到 D 的帧都被忽略），直到手离开后，YOLO 才第一次得到 D 的完整框 B。此时不存在可预登记的局部 D，因此不能再要求“B 必须能接上先前的 D 证据链”；否则真实入库会被错误忽略。

这不是把所有“库存无法匹配的检测”都自动入库。这里只补充一条独立的、**手离开后首次显现**的新物品证据链。

## D 的三个发现入口、两种确认链路

“在哪里第一次发现疑似 D”和“之后怎样确认它能正式 IN”是两件事。

围绕同一次手操作，以下三种情况都应当创建或更新疑似 D；创建疑似 D 只是在工作状态中保留线索，**不等于立即 IN**：

1. `HAND_VISIBLE_D`：有手帧中看见一个贴手、且无法由已有库存认领的 D；
2. `C_POSITION_REPLACEMENT_D`：有手操作期间，已有库存 C 在自己的原位置看不见，而 C 的原位置出现一个无法由任何已有库存物品认领的 D。此时 D 即使已经离开手框、不再贴手，也必须预登记；它是“D 放在 C 上面、C 被 D 遮挡”的重要线索；
3. `POST_HAND_REVEAL_D`：D 一直被手完全遮挡，手离开后才第一次出现完整框 B。本来源没有有手帧 D 框，必须在无手阶段创建。

前两种都有一个已观察到的 D 框，因此共用“有手期间已见过 D”的确认链路；第三种使用本文件新增的“手离开后首次显现”确认链路。

### 1. 有手期间已见过 D：贴手 D 或 C 原位置替代 D

沿用 `细节3.md`：

1. D 在有手操作期间被发现：它要么贴手出现，要么出现在看不见 C 的 `C.box` 原位置；无论哪一种，D 都不能合理认领给已有库存；
2. 将 D 预登记为疑似新物品，维护局部框、手轨迹、自己的移动量和候选 `track`；
3. 手离开后，完整 B 在 D 的整条候选路径上唯一地重新出现；
4. B 在后续稳定无手快照中继续存在；
5. D 进入工作库存，稳定结算时正式 IN。

### 2. D 一直被手完全遮挡，手离开后首次看见完整 B

这是本文件新增的链路：

1. 本次确实发生过有效的手操作，并且手刚离开；只有本次操作结束后的最早几个无手有效帧可以启动该链路；
2. 在这些无手帧中出现完整检测 B；
3. B 先经过已有库存物品 C、已预登记 D、以及其他待确认对象的正常认领流程，均不能被它们合理认领；
4. B 与本次操作保存的**公共手框轨迹中的至少一段**相交、相贴或足够接近。不能只比较最后一帧手框：手可能已在较早的位置放下 D，随后才移开；
5. B 不是与其他候选发生身份冲突的检测框；同一检测框只能属于一个对象。若某个 C/D 与 B 同样合理，先保持未决，不创建新的 D；
6. 满足上述条件后，为 B 创建“手离开后首次显现”的疑似 D。此时 B 已是完整框，可保存为该疑似 D 的 `first_seen_box`、`last_seen_box` 和暂定 `placed_box`；它不需要伪造一个先前的局部框；
7. 下一帧（或稳定快照所需的后续有效无手帧）仍能匹配到同一个 B，才确认它确实稳定存在：将该 D 提升到工作库存；
8. 当包含 B 的无手稳定快照提交时，才正式发送 IN 并写入正式库存。

若第 7 步之前 B 消失、不能自匹配、被已有 C/D 认领，或超出“手刚离开”的确认窗口，则直接丢弃这个疑似 D，不产生 IN 或 OUT。

## 关键顺序

无论在哪个阶段，旧物品都必须优先于新物品来源认领检测框；但有手和无手阶段的新增入口不同。

### 有手阶段

1. 先让已有库存 C 按当前可见/遮挡状态、完整 `C.box` 和自身轨迹认领检测；
2. 再更新已经存在的疑似 D；
3. 对仍未被认领的检测：贴手的检测可作为 `HAND_VISIBLE_D` 预登记；若 C 在原位置不能被认回、而该剩余检测 D 出现在 `C.box` 原位置，则以 `C_POSITION_REPLACEMENT_D` 预登记。后者不要求 D 此刻仍贴手；

### 无手阶段

1. 先让已有库存 C 用完整 `C.box`、自己的移动量和整条候选路径寻找检测；
2. 再让已经在有手帧预登记过的 D，按 `细节3.md` 的局部→完整路径规则寻找检测；
3. 只有仍未被任何旧 C 或已有 D 认领的完整检测 B，才有资格进入本文件第 2 条“手离开后首次显现”的 D 证据链；
4. 最后再更新稳定快照和正式库存。

这样可以避免把“原来被遮挡、现在重新露出的 C”错误当成新物品。尤其是 C 曾被新放下的 D 覆盖时，C 的重新露出必须优先恢复为原来的 C，而不是生成另一个 D。

## 这条链路与手轨迹的关系

对于全程被手遮挡的 D，系统没有 D 的初始局部框，也就不能得到“D 自己的精确估计路径”。因此这里使用的是公共 `hand_track` 作为**来源证据**，而不是用它给 B 计算精确身份位置。

判断的是“B 是否出现在手本次实际经过/停留过的位置附近”，而不是“手是否曾经大致从画面里路过”。实际实现应使用整条手框轨迹逐段检查 B 的框与手框的交集、边缘距离或覆盖关系；若 B 距所有轨迹段都很远，则不启动此链路。

`hand_track` 只能说明 B 有可能由这只手带入，不能单独保证身份。因此仍必须同时满足：B 未被旧库存认领、处于手刚离开的确认窗口、并在后续无手帧稳定出现。

## 与已有库存物品 C 的区别

C 原本已有可靠的完整 `C.box` 和 `item_id`，即使它从 HAND_PARTIAL 变为 HAND_FULL、暂时完全看不见，也应继续保留 C 的 HAND 状态、移动量和候选路径；不能因连续看不见就把 C 当作新物品或直接恢复为可见。

本文件的第 2 条链路只适用于“本次操作前库存中不存在、也没有任何有手帧局部记录”的 D。它永远不会产生 OUT；确认失败只会清理疑似 D。

## 所需状态与可调项

建议给疑似 D 增加一个来源标记，例如：

- `HAND_VISIBLE_D`：有手帧中看过局部 D，使用 `细节3.md` 的路径重现链路；
- `C_POSITION_REPLACEMENT_D`：有手操作中，无法认领的 D 出现在 C 的原位置并遮挡/替代 C；同样使用 `细节3.md` 的路径重现链路；
- `POST_HAND_REVEAL_D`：D 全程被手遮挡，首次完整框 B 在手离开后出现，使用本文件链路。

`POST_HAND_REVEAL_D` 至少需要保存：`source`、完整 `first_seen_box`、`last_seen_box`、`placed_box`、无手自匹配次数、创建时的手轨迹范围/操作编号，以及确认窗口计数。

后续实现需要新增或明确以下超参数：

- 手离开后允许创建 `POST_HAND_REVEAL_D` 的帧数窗口；窗口更大更不容易漏判为 IN，但误入库风险也更高；
- B 与任一手轨迹段相交/相贴/接近的阈值；阈值更大更宽松，但更容易把手附近的旧物误判为新物；
- 无手自匹配确认次数（通常至少两次有效观察，或由稳定快照的多数规则共同保证）；次数更高更稳，但入库会更慢；
- “已有 C/D 优先认领 B”时的严格匹配、局部匹配和歧义判定阈值。

## 结论

“手来过该位置，手离开后出现一个库存无法认领且稳定存在的 B”在本业务中应当成为有效的入库来源；但它必须绑定到**刚结束的这次手操作的整条轨迹**，并在旧 C、已有 D 全部优先认领失败后才使用。这样既能处理 D 全程被手遮挡的真实入库，也不会把任意无手画面中的陌生检测框直接当成 IN。
