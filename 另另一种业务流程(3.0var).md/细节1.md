1. 每一帧我们识别到手后, 就先用大家共用的上一帧手框 `old_hand` 与当前手框计算得到本帧[移动值]。`old_hand` 是帧级公共变量，不属于任何一个物品；再把这个本帧移动值分别追加到当前已经被手影响的每个物品自己的移动值列表中。以后要得到某个物品的净移动值时，就把它自己的列表按向量加总即可；如果要算实际走过的路程，则把每次移动值的长度加总。

    > 完整的手框轨迹也只公共保存一份 `hand_track`，每一帧只追加一次当前手框，不给每个物品重复复制。某个物品刚进入【被手部分遮挡】或【被手完全遮挡】时，只记录自己的 `hand_track_start_index`。以后需要查看这个物品受手影响期间的手轨迹时，就从公共 `hand_track` 的这个下标开始读取。这样即使不同物品从不同帧开始被手遮挡，也能取得各自正确的轨迹片段。

2. 对每个处于【被手部分遮挡】或【被手完全遮挡】的物品 C，先查看 `C.hold_and_move`，再选择处理分支：
    > 如果 `C.hold_and_move=True`，说明已经用连续两次有效证据确认 C 跟着手移动。本帧不再重复检查“是否真的被握住”，也不再修改 `hold_evidence_count` 和 `not_hold_evidence_count`；后续只更新 C 的候选 `track`，并尝试用轨迹估计框匹配快照中的 B。B 必须先排除能严格匹配其他库存物品的情况；即使 B 与 track 匹配，也还要结合 C 掉队或与手分离的证据，才能确认 C 已经放下并完成整理。
    > 如果 `C.hold_and_move=False`，说明 C 仍处于待确认状态，不表示已经确认 C 没有移动。下面 2.1～2.5 的旧位置、移动证据和计数处理只适用于这个分支。
    > 2.1 只有手本帧明确移动时，旧位置仍然唯一匹配到 C 才算一次“C 只是被手短暂遮挡、没有移动”的有效证据。此时令 `C.not_hold_evidence_count += 1`，同时把 `C.hold_evidence_count` 清零；手没有明确移动时不增加任何计数。
        > 2.1.1 如果 `C.not_hold_evidence_count < 2`，还不立即恢复为【可见】，也不更新作为旧位置的 `C.box`，继续等待下一个有效判断。
        > 2.1.2 如果连续两次有效判断都在旧位置看到 C，才把 C 恢复为【可见】，用当前检测框更新 `C.box`，并清空手部遮挡、证据计数、候选 track 等临时状态。
    > 2.2 如果旧位置出现了一个已知库存物品 D，并且 D 原本就在 C 后方、之前被 C 遮挡 → 说明 C 可能已经离开旧位置，D 被重新露出；但还要在估计位置找到 C，不能只凭 D 出现就确认。
    > 2.3 如果旧位置出现了一个不属于库存的 D，并且 D 是手附近出现的疑似物品 → 说明这是新物品放入，我们认为 C 可能仍在原处。
    > 2.4 如果旧位置没有任何检测 → 只能说明 C 当前看不见。C 可能被拿走，也可能仍被手臂或其他物品挡着；这个“没看到”不能单独累加正向证据。

    > 2.2 或 2.4 的情况出现时，且手本帧明确移动，说明 C 可能被拿走，再通过[移动值]计算【被手部分遮挡】的 C 这一帧的估计位置。**这里使用 C.last_hand_block_box（最近一帧实际看到的手遮挡局部框）与[移动值]计算估计框，而不是使用未被手遮挡时的完整框。C.first_hand_block_box 只记录刚被手挡住时的第一个局部框，后续保持不变。**然后用估计位置与手相贴的这些物品 B 看能不能[严格匹配](阈值可以松一点, 允许略微抖动或偏移)。手本帧没有明确移动时，不进行这次估计匹配，也不增加任何证据计数。
        > 如果 B 先排除能严格匹配其他库存物品的情况，并且再能[严格匹配](阈值可以松一点, 允许略微抖动或偏移) C，同时 C 的旧位置看不到 C、也没有未知物品占位，就令 `C.hold_evidence_count += 1`，同时把 `C.not_hold_evidence_count` 清零。只有连续两次有效判断都支持这个结果，才设置 `C.hold_and_move=True`。HAND_* 期间的 `C.box` 仍保留旧位置，当前 B 只更新 `C.last_hand_block_box` 和候选 track；等确认放下后才用终点更新 `C.box`。
        > 如果不能[严格匹配](阈值可以松一点, 允许略微抖动或偏移)，或者旧位置被一个未知物品占用，这一帧就属于模糊帧。可能是移动值累计有误、手臂遮挡了 C、检测框暂时漏检，或者 C 还没有移动到能够被看见的位置。此时两个证据计数都不增加也不清零，保留 C 的待确认状态，等待后续有效帧。**对的, 这样也能有效避免被手臂挡住的那种误判情况。**

3. 如果【被手部分遮挡】的物品都匹配不上这些与手相贴的物品B的话, 再来看看能不能与库存中【可见】的物品A符合[局部匹配], 如果是的话就说明这个物品B是之前的物品A

4. 如果还是无法匹配的话，再查看【被手完全遮挡】的物品的 `cls_id` 是否与 B 一致。

    > 对 `hold_and_move=False` 的完全遮挡物品，B 只能作为“可能跟手移动”的正向证据；仍要先确认旧位置没有 C、没有未知物品占位，并累计到连续两次有效证据后，才设为 `True`。
    > 对 `hold_and_move=True` 的完全遮挡物品，不再回头做两种证据计数。B 必须先排除能严格匹配其他库存物品的情况，再与 C 的当前 `track` 估计框严格匹配；同时还要有手继续移动而物品掉队，或物品已经和手分离的证据，才能确认 C 放下、整理成功。

5. 如果还是无法匹配的话, 可能是手原先拿着一个新物品D进来, 但是新物品D一直被手完全挡住, 然后现在终于露出来了(有可能是手放下了,也有可能是视角变得可见了), 反正这个物品B就认为是这个新物品D

    > 5.1 这里的“认为是新物品D”只是暂时给这个检测结果记为“疑似新物品”，不能在这一帧就立即确认入库。需要继续观察它后面的运动：如果它在手离开后仍然稳定存在，并且能够连续匹配到同一个物品，那么再确认它是新入库物品；如果它之后又被手遮挡，则继续跟踪这个疑似物品；如果它很快消失，也不能因此反过来认定它是出库，只能删除这次没有被确认的疑似记录。

6. 同一帧中，一个检测框只能被一个物品认领，不能让多个库存物品同时匹配到同一个 B。

    > 处理顺序应当保持为：先处理“被手部分遮挡”的库存物品 C，再处理与库存中可见物品 A 的局部匹配，再处理“被手完全遮挡”的库存物品，最后才把仍然无法解释的 B 作为疑似新物品。前面的匹配一旦成功，就把这个 B 标记为已经使用，后面的物品不能再次使用它。
    > 如果同一个 B 同时有多个可能的来源，或者同一个来源同时对应多个 B，就不要强行选择其中一个。这个检测结果应暂时保持未决，等待后续帧提供更多信息，否则一次错误匹配可能会连锁影响多个物品。

7. 每一帧处理完所有检测结果后，再统一整理本帧的物品状态。

    > 对于已经确认只是短暂遮挡的 C，把它恢复为“可见”，并用当前检测框更新位置。
    > `hold_and_move=True` 只表示“已经确认 C 跟着手移动”，还不等于已经完成整理。在确认放下以前，C 仍保持手部影响状态，只继续维护 `track`；只有出现掉队或与手分离等放下证据后，才把它记录为“已整理”或“已移动”，并更新工作库存中的位置。
    > `hold_and_move=False` 的 C 仍是待确认物品，不能因为暂时看不见就当作已移动或已出库。
    > 对于暂时看不见、但仍可能被手臂或其他物体遮挡的 C，保留它在工作库存中，不要立即删除，也不要立即发出库事件。
    > 对于本帧新出现、但还没有经过连续帧确认的物品，只保留为疑似新物品，不立即正式加入库存。

8. 手继续移动时，后续帧必须按 `hold_and_move` 分开处理，不能只依赖“这一帧有没有看到 C”。

    > 对 `hold_and_move=False` 的 C，只有手本帧明确移动时才检查旧位置和估计位置：旧位置唯一看到 C 是反向有效证据；估计位置找到唯一的、未被其他库存物品认领的 B 是正向有效证据；其他情况都是模糊帧。手没有明确移动时，两个计数都不变。
    > 对 `hold_and_move=True` 的 C，不再检查旧位置来累加“没有移动”证据，也不再修改两种计数。每帧只继续更新 `track`、寻找与 track 相符且未被其他库存物品认领的 B，并等待“掉队”或“与手分离”的放下证据。单独找到一个与 track 匹配的 B，只能说明它很可能是 C，不能立刻确认整理。
    > 无论 `hold_and_move` 是 True 还是 False，手还在时都不能只因 C 暂时没被看到就判定出库。

9. 手离开后，才对本次手部操作中仍然没有完成最终处理的物品做收尾确认。

    > 对 `hold_and_move=False` 的 C，不能直接按“没有移动”处理，而是严格按最终三步判断：在原位置(A.box)看到 A，就确认没有移动；在候选 `track` 的其他位置看到 A，就补确认整理；在旧位置(A.box)和整条候选轨迹上都没有重新找到 A，就补确认出库。
    > 对 `hold_and_move=True` 的 C，不再重新进行“两次证据”判断。手离开本身提供了“与手分离”的终局证据：若在候选 `track` 的其他位置找到未被其他库存物品认领的 A，就确认整理；若旧位置重新找到 A，则以该终局结果恢复为没有移动；若旧位置和候选轨迹都找不到 A，则确认出库。
    > 上述旧位置检查是手离开后的最终位置确认，不是把 `hold_and_move=True` 又重新改回待确认状态。

10. 本次操作中的“实时更新”和“正式确认”要分开理解。

    > 手还在画面中时，可以在工作库存中暂时记录已经较有把握的整理、入库和遮挡状态，这样同一次手部操作先后处理多个物品时，后面的判断可以使用前面已经得到的临时结果。
    > 但是，正式库存中的物品只有在手离开并完成上述未决检查后才最终提交。这样即使中间某一帧判断错误，也不会立刻把正式库存改坏；未决的物品继续保留，已经确认的结果则在最后统一提交。
