    增加一个物体在库存中的状态, 从原来的【可见】、【遮挡】这两个状态, 变为【可见】、【部分遮挡】、【完全遮挡】
    【可见】是默认状态, 完全不遮挡
    【部分遮挡】是当物体被部分遮挡时, 状态会变为这个
    【完全遮挡】是当物体完全被遮挡时, 状态会变为这个
    (部分遮挡换句话也是部分可见, 因此快照与库存对比时, 必须要对【可见】与【部分遮挡】都要进行检测)


# anchor_box 与 current_box
    原先是库存表的每个物品都有 anchor_box 与 proxy_box 两个框 (原先应该是有的)
    反正现在不管之前怎么样, 我们现在都要决定库存表的每个物品都有 anchor_box 与 current_box 两个框
    而快照只需要有 Yolov5n() 输出的 box 就行 (快照不用区分 anchor_box 与 current_box)

他们的含义：
> anchor_box: 表示的是一开始的框, 完整的框
> current_box: 表示的是当前的框
> box: 表示的是Yolov5n() 输出的框

正常来说(根据我的推理):
> 【可见】的物品：anchor_box ≈ current_box
> 【部分遮挡】的物品：anchor_box ≥ current_box
> 【完全遮挡】的物品：anchor_box 非空, current_box 空\



我们应该要注意到一个很重要的事情: 
    即便是【部分遮挡】还是【完全遮挡】, 都不是凭空出现的, 他们最初最初必然也是【可见】, 然后经过某些事件后才变成了【部分遮挡】或【完全遮挡】
    也就是说：即便是【部分遮挡】、【完全遮挡】, 他们的 anchor_box 必然也是存在的, 而且 anchor_box 表示的是他们最开始【可见】时的框, 即完整的框
而且：
    我们的这个库存表是从 0 开始的, 只要我们每一步都是正常的话, 那么这个库存表就符合马尔可夫性

# 快照与库存对比的规则：
> 通过遍历库存表去对比, 这样回去会更好 (我当前的想法是这样)


我们可以这样理解：
>【可见】是第一批
>【部分遮挡】是第二批
>【完全遮挡】是第三批


当我们有了一个快照后我们就可以开始对比 (库存表是一直有, 一直维护的)：
1. 遍历库存表中【可见】的物品, 与快照的物品进行**严格匹配**
    > 将匹配成功的物品打上标记
2. 遍历库存表中【部分遮挡】的物品, 与快照的物品进行**严格匹配**
    > 将匹配成功的物品打上标记
3. 遍历库存表中【部分遮挡】的物品, 与快照的物品进行**严格匹配**
    > 将匹配成功的物品打上标记
4. 在遍历完上述的库存物品后, 查看库物品中是否还存在未匹配成功的物品
    > 4.1 如果所有库存物品都匹配成功, 则查看快照中是否还有 item_id = -1 的物品 (即快照中是否有未匹配到的)
        > 4.1.1 如果快照有未匹配到的, **则表明:库存中的物品都对得上, 而快照中有物品对不上, 很大概率是新增物品。**那么就将这些物品增加到库存中, 他们的item_id 就依次递增, 并且都设置为【可见】, 他们的 anchor_box = current_box = box
        > 4.1.2 如果快照没有未匹配到的, **则表明:库存中的物品都对得上, 快照中的物品也都对得上的, 很大概率是没事发生。**什么都不该
    > 4.2 如果有库存物品未匹配到的, 则查看快照中是否还有 item_id = -1 的物品 (即快照中是否有未匹配到的)
        > 4.2.1 如果快照有未匹配到的, **则表明:库存中有物品对不上的, 而快照中也有物品对不上, 很大概率是。**
        > 4.2.1 先查看这些未匹配的物品, 且状态是【可见】的, 看看他们是否存在 track (根据 item_id 即可找到他们对于的 track)
            > 4.2.1.1 如果有 track, 看看这个track的路径位置(或者最后的位置), 在快照中

**将匹配成功的物品打上标记**
# -----------------------
> 注意的是：库存的物品要标记, 快照的物品也要标记

> 对于快照的物品的标记, 我想到的一个方法是：
    > 在进行对比之前, 先创建一个字典, 这个字典的key是库存中所有物品的 item_id, value 初始化为 False
    > 每当一个物品匹配成功, 就将这个物品的 item_id 对应的 value 设置为 True

> 对于快照的物品的标记, 我想到的一个方法是：
    > 在快照生成时先给快照中的每一个物品都设置 tiem_id = -1
    > 这样在库存与快照匹配成功时, 将快照中的这个物品的 tiem_id 取值为库存中的 tiem_id
    > 这样只要看到  tiem_id 不是 -1 的话就说明这个物品是匹配成功的, 如果这个物品依旧是 tiem_id = -1 的话, 说明这个物品没有匹配成功

(这只是我一时的想法, 未必就是最好的, 如果有更好的想法可以改进的)
