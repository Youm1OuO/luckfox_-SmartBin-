# 单框与遮挡关系的完整快照对比规则

> 这份规则保留原来“先匹配、再处理少了的和多出来的”主流程。
>
> Track 只用于把【出库 + 新入库】升级为【整理】；没有 Track、Track 错误或不唯一时，仍按普通快照规则结算。

> 库存不保存 `anchor_box + current_box` 两套框。
>
> 每个物品只保存最近一次确认看见它的 `last_box`；框变小、变大、消失，都是本轮与 `last_box` 的关系。


# 1. 库存、快照与状态

库存物品 A：

```text
item_id；
cls_id；
last_box；            // 最近一次确认看见的框；允许大 / 小
status：VISIBLE / OCCLUDED；
blocker_id：可空；    // 上一次确认挡住 A 的库存 item_id
new_item_pending：bool； // 新入库后的首次框尚未确认；默认 false
```

快照物品 B：

```text
cls_id；
box；
score；
```

> 快照物品 B **没有状态，也没有 item_id**。

```text
A、D：库存物品；
B、C、E：本轮快照物品。

A：当前要判断的库存物品；
B：尝试绑定给 A 的快照物品；
C：本轮实际挡住 A 的快照物品；
D：A.blocker_id 指向的旧库存物品；
E：本轮与 D 对应的快照物品（若 D 本轮仍可见）。
```

```text
VISIBLE：
    物品当前还能看见；last_box 非空。
    last_box = 本轮确认看见它的框；可以是完整大框，也可以是小框。

OCCLUDED：
    当前看不见；last_box 保留。
    last_box = 最后一次确认看见它的框；只是后续对比的参考，不是当前框。
    blocker_id 必须有值。
```

> `new_item_pending` 不是第三种状态。
>
> 新 B 直接入库时无法知道它是不是小框，因此先设为 `true`；
> 后续第一次 `NORMAL`、已确认的 `SHRINK` 或一次专用 `GROW` 后清为 `false`。

> 【出库】不是永久库存状态。
>
> 本轮只写 `planned_out[A.item_id] = true`；等所有遮挡关系结算完，再从**活跃库存**删除 A。若后台需要历史，只记录出库事件，未来快照不再匹配这个 A。

> 【部分遮挡】不作为永久状态。
>
> 一旦小框 B 确认属于 A，就直接写入 `last_box`，A 仍是 `VISIBLE`；下一轮小框会直接与小框匹配。


# 2. 三种框关系

**IoM：框之间的基础对比方法**

> `NORMAL / SHRINK / GROW` 都先要求：`A.cls_id == B.cls_id`。

```text
IoM(库存物品 A, 快照物品 B)
    = area(A.last_box ∩ B.box) / min(area(A.last_box), area(B.box))；

SHRINK / GROW：
    除原来的“大 / 小、中心偏移、长宽比”条件外，
    还要求 IoM(A, B) >= τ_contain；

NORMAL：
    仍使用原来的严格匹配；
    额外要求 IoM(A, B) >= τ_normal。
```

> `IoM` 接近 1，只说明小框几乎被大框包含；仍只是【候选】。
>
> 特别是 `GROW` 还必须保留原来的面积增幅上限；不能因为大框包含小框就直接认作同一个物品。
>
> 下列阈值都只写入配置，后续用真实视频标定：
> `τ_normal / τ_contain / τ_center_normal / τ_center_contain / τ_shape_normal / τ_shape_contain / ρ_normal_min / ρ_normal_max / ρ_shrink / ρ_grow_min / ρ_grow_max / τ_block / τ_full / τ_leave`。

```text
center_shift(A, B)
    = center_distance(A.last_box, B.box)
      / max(diagonal(A.last_box), diagonal(B.box))；

area_ratio(A, B)
    = area(B.box) / area(A.last_box)；

shape_delta(A, B)
    = abs(log((B.box.width / B.box.height)
              / (A.last_box.width / A.last_box.height)))；
```

> `center_shift` 的分母取较大框：小框 / 大框是正常遮挡现象，不能因小框作分母而把正常偏移放大。

```text
NORMAL(库存物品 A, 快照物品 B)：
    IoM(A, B) >= τ_normal。
    center_shift(A, B) <= τ_center_normal。
    ρ_normal_min <= area_ratio(A, B) <= ρ_normal_max。
    shape_delta(A, B) <= τ_shape_normal。

SHRINK(库存物品 A, 快照物品 B)：
    B.box 比 A.last_box 明显更小，且基本被 A.last_box 包含；
    IoM(A, B) >= τ_contain；
    area_ratio(A, B) <= ρ_shrink；
    center_shift(A, B) <= τ_center_contain；
    shape_delta(A, B) <= τ_shape_contain。

GROW(库存物品 A, 快照物品 B)：
    B.box 比 A.last_box 明显更大，且基本包含 A.last_box；
    IoM(A, B) >= τ_contain；
    ρ_grow_min <= area_ratio(A, B) <= ρ_grow_max；
    center_shift(A, B) <= τ_center_contain；
    shape_delta(A, B) <= τ_shape_contain。
```

> `SHRINK / GROW` 都只是候选；不能只因“包含”就绑定身份。
>
> 一个 B 对多个 A 成立，或一个 A 对多个 B 成立：本轮不认。(只认一对一)


# 3. blocker_id：处理小框 → 大框的依据

```text
确认框变小：(被部分遮挡)
    库存物品 A 与快照物品 B 满足 SHRINK(A, B)；
    同时快照物品 C 盖住 A.last_box 中 B.box 没盖住的区域；
    → A.blocker_id = C.inventory_id。

确认完全遮挡：(被完全遮挡)
    库存物品 A 没有匹配到任何快照物品 B；
    同时快照物品 C 基本盖住 A.last_box；
    → A.status = OCCLUDED；A.blocker_id = C.inventory_id。

确认框变大 / 重新露出：(也可能是完全露出, 也有可能是部分露出, 反正就是比原来的大)
    库存物品 A 与快照物品 B 满足 GROW(A, B)；
    或 A 原先是 OCCLUDED，且满足 NORMAL(A, B)；
    且 BLOCKER_LEFT(A, B) 成立；
    → A.last_box = B.box；清空 A.blocker_id。
```

```text
C.inventory_id：
    C 已绑定旧库存    → binding[C]；
    C 是 maybe_in    → planned_new_id[C]；

BLOCKER_LEFT(库存物品 A, 快照物品 B)：
    D = planned[A.blocker_id]；    // D 是库存物品 (库存中, D 原先挡住了 A) 

    if planned_out[D.item_id]：
        return true；              // D 本轮已确认出库；提交时才删除

    else if 快照物品 E 已绑定到 D，且 role[E] == MOVED：
        return area(E.box ∩ B.box) / area(B.box) <= τ_leave；
        // D 已确认移动到别处，并且不再挡住当前 B

    else：
        return false；
        // D 可能仍在原处，只是自己变小 / 被遮挡，不能确认 A 变大
```

> `BLOCKER_LEFT(A, B)` 的作用：
>
> **判断原来挡住库存物品 A 的库存物品 D，是否已经确认不再挡住当前快照物品 B。**
>
> D 没有正常框并不等于 D 已离开；D 也可能只是被遮挡。因此只有 D 本轮已确认出库，或 D 已 MOVED 到不覆盖 B 的位置时，才返回 `true`。


# 4. 对比前

```text
已经得到 N 帧连续无手的稳定 Snapshot；
operation_pending == true；

planned = InventoryDB 的副本；
initial_status[item_id] = 本轮开始前的状态；
planned_out[item_id] = false；    // 仅本轮使用；提交时删除对应活跃库存项
binding[snapshot_id] = -1；
matched[item_id] = false；
role[snapshot_id] = NONE；
reserve[snapshot_id] = false；
maybe_in[snapshot_id] = false；
unresolved[item_id / snapshot_id] = false；
out_used_by_grow[item_id] = false；
failed_grow_pair = 空集合；
retry_snapshot_only = 空集合；
```

```text
role：
    DIRECT    原位置仍可见；
    MOVED     Track 唯一证明整理；
    REVEALED  原本 OCCLUDED 的物品重新可见；
    NEW_ITEM  本轮按新物品入库；不回查历史出库物品。
```

> 没有 `operation_pending` 时：只允许 `NORMAL` 刷新 `last_box`；
> 若该物品 `new_item_pending == true`，这次 `NORMAL` 同时将它清为 `false`。
> 不能改遮挡、出库或新入库结果。


# 5. 快照与库存对比

## 1. 先匹配正常不变的物品 (严格匹配)

```text
normal_options[库存物品 A] = 空列表；
normal_options[快照物品 B] = 空列表；

for 每个 initial_status == VISIBLE 的库存物品 A：
    for 每个未绑定的快照物品 B：
        if NORMAL(A, B)：
            同时加入 normal_options[A] 与 normal_options[B]；

for 每个 NORMAL(A, B) 候选：
    if normal_options[A] 只有 B
       且 normal_options[B] 只有 A：
        库存物品 A ↔ 快照物品 B；
        planned[A].last_box = B.box；
        planned[A].new_item_pending = false；
        role[B] = DIRECT；

    else：
        unresolved[A / B] = true；
        // 同类物品无法唯一分配；不能按遍历顺序硬选一边
```

> 这一步结束后：
>
> - 未匹配的 VISIBLE 库存物品 A = “少了的旧物品”；
> - 未绑定的快照物品 B = “多出来的快照物品”。

(注意：
    这个版本只有【可见】与【遮挡】两种状态
    库存中可能有【可见】、【遮挡】物品
    **虽然说快照上的物品没有状态一说, 但快照的物品本质上全都是【可见】物品**
而且这里没有固定大小关系：
    库存的【可见】物品可以 > 快照的【可见】物品（遮挡 / 出库）；
    也可以 < 快照的【可见】物品（新物品拿进来）；
所以：
    上面这个for循环相当于是用库存的【可见】物品去对比快照的【可见】物品做严格匹配
    这个严格匹配过后:
>   (1) 匹配成功的自然就连接起来, 即是：不变的, 保持原样的
>   (2) 库存中剩下的【可见】物品就是快照中没有的, 即是：消失了的、少了的、不见了的 **后面再判断【遮挡】或【出库】**
>   (3) 快照中剩下的物品（相当于是【可见】状态的）就是库存中没有的, 即是：新增的、多的、新出现的 **后面再判断【露出】、【小框】或【新入库】**


也就是说这个 for 循环做的事情就更之前的区分"多了的"、"少了的"、"不变的"
)


## 2. 先收集 Track 的【整理】候选，不立即绑定

```text
track_options[库存物品 A] = 空列表；
track_options[快照物品 B] = 空列表；

for 每个“少了的库存物品” A：    // 即上述严格匹配过后, 现在库存中剩下的没匹配上的【可见】库存物品A

    if A 有可靠冻结 Track：

        if Track.release_box 非空且可靠：
            // 已确认 A 被放在 release_box 这个位置
            if “多出来的快照物品 B”唯一严格匹配 release_box：
                同时加入 track_options[A] 与 track_options[B]；    // 【强整理候选】

        else if Track.path 中存在可靠代理框：
            // release_box 为空，不等于 A 没被放下；可能只是没有捕捉成功
            // 只要 B 命中这条 Track 中的任意一个路径点即可；不要求命中最后一个点
            if “多出来的快照物品 B”严格匹配 Track.path 中某个代理框
               且 B 只对应这一条 Track
               且 B.box 已明显离开 A.last_box：
                同时加入 track_options[A] 与 track_options[B]；    // 【弱整理候选】

    else：
        什么都不做；    // 后面仍按遮挡 / 出库 / 新入库的普通快照规则处理

for 每个 Track 候选 A ↔ B：
    if track_options[A] 只有 B
       且 track_options[B] 只有 A：
        track_candidate[A] = B；
    // 不唯一的 Track 不确认 MOVED；后面按普通快照规则处理
```
track_candidate[库存物品 A] = 快照物品 B, 的意思是：
    怀疑是库存物品 A 整理到快照物品 B 处; 但未先这么快就直接确认, 先标记一下, 后续合适时机再确认



> Track 候选不能覆盖后面由快照本身确认的绑定。
>
> `release_box` 是最强证据，但**不是判断整理的必要条件**。
>
> 同一条 Track 中，B 命中多个相邻路径点仍算一个候选；但 B 同时命中多个库存物品的 Track，或 A 同时对应多个 B，都不唯一。
>
> 不唯一或与快照规则冲突时，直接丢弃该弱候选。


## 3. 先从“多出来的 B”中收集露出、框变大的候选

> 本节只收集，不绑定、不 `reserve`。
>
> 先把所有【框变大 / 重新露出】可能性保存下来；第 4 节还要和【框变小】候选一起做一对一判断。

1. 原先是【可见】的库存物品 A：
   > A 原先被部分遮挡；若 `GROW(A, B)`，则 B 可能是 A 露出更多后的框。

2. 原先是【遮挡】的库存物品 A：
   > 若 `NORMAL(A, B)` 或 `GROW(A, B)`，则 B 可能是 A 重新露出的框。

> 除 `new_item_pending` 的首次框变大外，上面两种都要求 `A.blocker_id` 非空。
> `A.blocker_id` 指向原遮挡的**库存物品 D**；D 若本轮仍可见，对应的才是**快照物品 E**。
> 这里**只收集候选，不立即绑定**。第 4 节会先做双向唯一判断；第 6 节再判断 `BLOCKER_LEFT(A, B)`。

```text
grow_options[A / B]：
    所有“B 可能是 A 露出后的框”关系；
    此时只收集，A 或 B 可以暂时对应多个候选。

reserve[快照物品 B] = true：
    第 4 节已确认 A ↔ B 是唯一框候选；
    在候选得出结果前，不能再绑定为【整理】或【新入库】。

out_used_by_grow[库存 item_id] = false：
    本轮是否已经用“该物品出库”来确认另一个物品露出。
```

**注意: 这里虽然是对快照中多出来的物品B进行处理, 但实际上只是一个预处理**
> 这里只是先将那些"可能是原先被旧物体遮挡, 现在旧物体移走了导致其露出了"的物品B做一个标记, 初步怀疑他们是这种可能
> 当到后面我们发现了原先遮挡他们的那个物体确实移动走了, 这才能坐实这种可能
> (也就是说：多出来的物品B还有一种可能是新物体拿进来的, 但这里并不是处理这种情况的时候, 这要留到后面再处理)

```text
for 每个仍“多出来的快照物品 B”：
    for 每个仍未绑定的库存物品 A：

        if initial_status[A] == OCCLUDED
           && A.blocker_id 非空
           && (NORMAL(A, B) 或 GROW(A, B))：
            在 grow_options[A] 与 grow_options[B] 中加入
            {A, B, REVEALED, need_blocker_left = true}；

        if initial_status[A] == VISIBLE
           && A 是“少了的库存物品”
           && GROW(A, B)
           && (A.blocker_id 非空 或 A.new_item_pending == true)：

            在 grow_options[A] 与 grow_options[B] 中加入
            {A, B, DIRECT,
             need_blocker_left = (A.blocker_id 非空)}；
            // new_item_pending 的 A 没有已知 blocker；
            // 仅允许它在首次框变大时走这一条专用 GROW
```



### Track 暂不确认，等第 4 节所有框候选收集完

> Track 不能只避开 `GROW`；也要避开后面的 `SHRINK`。
>
> 因此这里先保留 Track，等第 4 节确认 B 没有任何框候选后再绑定为 `MOVED`。

**为什么要这样？**
因为：
1. 整理 Track(A, B)
     → 不是 A.last_box 与 B.box 严格匹配；
     → 而是 B 严格匹配 Track.release_box / Track.path 的预测位置；
     → 它是“位置预测严格匹配”，不是物理身份的绝对证明。

2. 因为 Track.path 可能漂移 / 接错 / 估计位置不准
例如：
> 若 B 实际是 A2 在遮挡物移开后重新露出;
> 但由于 Track.path 本身受“漂移 / 接错 / 估计位置不准” 等问题影响导致结果并非完全准确, 导致错误的把 B 绑定给整理 A1,
> 这就会错误保留 A1.item_id, 并让 A2 丢失本该属于它的 B。

尤其是 Track.path 的弱候选的时候，不应轻易抢走一个可能是【露出】的 B


```text
这里不绑定 Track；
第 4 节先确认 B 是否属于 GROW / SHRINK 候选。
```

> 被框候选占用的 Track，会在第 6 节的 GROW 成败确定后再处理。


## 4. 收集小框候选，再统一确认候选 / 整理 / 新物品

> 第 3、4 节都遍历“多出来的 B”。
>
> 此时 B 未被 `reserve`，只表示它尚未完成框候选判断；不代表它一定不是 GROW。

1. 原先是【可见】的库存物品 A：
   > 若 `SHRINK(A, B)`，则 B 可能是 A 遮挡更多后的框。

2. 原先是【遮挡】的库存物品 A：
   > 若 `SHRINK(A, B)`，则 B 可能是 A 从完全遮挡重新露出的一小部分。

```text
shrink_options[库存物品 A] = 空列表；
shrink_options[快照物品 B] = 空列表；

for 每个仍“多出来的快照物品 B”：
    for 每个仍未绑定的库存物品 A：
        if SHRINK(A, B)：
            同时加入 shrink_options[A] 与 shrink_options[B]；

box_options[A / B]
    = grow_options[A / B] + shrink_options[A / B]；

for 每个 box_options 中的候选 A ↔ B：
    if box_options[A] 只有 B
       且 box_options[B] 只有 A：

        if 候选来自 grow_options：
            grow_candidate[A] = {B, role, need_blocker_left}；
        else：
            shrink_candidate[A] = B；

        reserve[B] = true；

    else：
        unresolved[A / B] = true；
        // 同一个框关系不唯一，不让 Track / 新入库替它猜身份
```

### 再确认没有框候选冲突的【整理】与【新物品】

> Track 是辅助证据，必须等所有框候选收集完才确认。
>
> 这样 Track 不会抢走可能属于【露出】或【小框】的 B。

```text
for 每个 track_candidate[A] = B：
    if A、B 都未绑定
       且 unresolved[A] == false
       且 unresolved[B] == false
       且 box_options[A] 为空
       且 box_options[B] 为空：

        库存物品 A ↔ 快照物品 B；
        planned[A].last_box = B.box；
        planned[A].status = VISIBLE；
        planned[A].blocker_id = 空；
        planned[A].new_item_pending = false；
        role[B] = MOVED；

for 每个仍未绑定的快照物品 B：
    if box_options[B] 为空
       且 unresolved[B] == false：

        maybe_in[B] = true；
        planned_new_id[B] = 预分配的新 item_id；
```

> `maybe_in[B]` 只是“疑似新放入”。它也可能先作为遮挡物 C，最终再一起新建入库。


## 5. 用遮挡物 C 确认框变小或完全遮挡

**快照物品 C 可以作为遮挡物，当且仅当：**

```text
1. C 已绑定到某个库存物品，且 `role[C] == MOVED / REVEALED`；
2. C 是 `maybe_in`，即将新建为库存物品；
3. 库存物品 A 原本是 OCCLUDED，且 C 已 DIRECT 绑定到 `A.blocker_id` 指向的库存物品 D。
4. A 是 `new_item_pending`，且 C 已 DIRECT 绑定旧库存物品。
```

> C **不要求**与 A 的 `cls_id` 相同。
>
> 不使用“中心距离近”或“普通交集大”判断 C；C 是否真是遮挡物，只看它是否覆盖了 A 缺失的区域。

> 第 3 条只用于“完全遮挡的 A 露出一小部分，但原遮挡物仍在”。
>
> 原本 VISIBLE 的 A，不能把一个原地未动的 DIRECT 物品当作新的遮挡物；
> 但 `new_item_pending` 是例外：新物品可能从一开始就被原地旧物品挡住。

```text
COVER(目标区域 R, 快照物品 C)
    = area(R ∩ C.box) / area(R)；

确认小框：
    COVER(A.last_box \ B.box, C) >= τ_block；

确认完全遮挡：
    COVER(A.last_box, C) >= τ_full；
```

```text
for 每个 shrink_candidate[库存物品 A] = 快照物品 B：

    if 存在快照物品 C != B，且：
        C 符合上面的遮挡物条件；
        COVER(A.last_box \ B.box, C) >= τ_block；

        库存物品 A ↔ 快照物品 B；
        planned[A].last_box = B.box；
        planned[A].status = VISIBLE；
        planned[A].blocker_id = C.inventory_id；
        planned[A].new_item_pending = false；
        role[B] = (initial_status[A] == OCCLUDED) ? REVEALED : DIRECT；
        reserve[B] = false；

    else：
        unresolved[A] = true；
```

```text
for 每个仍“少了的 VISIBLE”库存物品 A 且 A 没有 shrink_candidate、没有 grow_candidate：

    if unresolved[A]：
        什么都不做；
        // 已存在不唯一的 NORMAL / SHRINK / GROW 候选；最终不提交

    else if 存在快照物品 C，且：
        C 符合遮挡物条件；
        COVER(A.last_box, C) >= τ_full；

        planned[A].status = OCCLUDED；
        planned[A].blocker_id = C.inventory_id；
        planned[A].new_item_pending = false；

    else：
        planned_out[A.item_id] = true；    // 本轮先保留 A；提交时再从活跃库存删除
        planned[A].blocker_id = 空；
```

> 这里不再使用“同类 B 在附近”的兜底。
>
> 除唯一 Track 已确认的 `MOVED` 外，若 B 不能与 A 形成唯一的 `NORMAL / SHRINK / GROW` 关系，它就不能证明仍是 A；普通流程按【A 出库 + B 新入库】结算。候选不唯一时，前面已经写入 `unresolved`。

> 初始就是 `OCCLUDED` 的 A，若本轮仍没有框，保持原样；不能因为持续看不见而直接出库。


## 6. 最后确认保留的“框变大 / 露出”候选

> 这一步放在【完全遮挡 / 出库计划】之后，
> 因为现在才能知道原遮挡物 D 是本轮已确认出库、已 MOVED，还是仍然无法确认。
>
> 只有 `new_item_pending` 的首次框变大不需要 `BLOCKER_LEFT`；它没有旧 blocker 可查。

```text
for 每个 grow_candidate[库存物品 A]
        = {快照物品 B, candidate_role, need_blocker_left}：

    if A 已绑定：
        cancel grow_candidate[A, B]；
        reserve[B] = false；
        failed_grow_pair[A, B] = true；
        retry_snapshot_only[A, B] = true；
        // A 已有别的绑定；B 回到普通快照规则

    else if need_blocker_left == false
            或 BLOCKER_LEFT(A, B)：

        if need_blocker_left：
            D = planned[A.blocker_id]；
            if planned_out[D.item_id]：
                out_used_by_grow[D.item_id] = true；

        库存物品 A ↔ 快照物品 B；
        planned[A].last_box = B.box；
        planned[A].status = VISIBLE；
        planned[A].blocker_id = 空；
        planned[A].new_item_pending = false；
        planned_out[A.item_id] = false；
        role[B] = candidate_role；
        reserve[B] = false；
        discard track_candidate[* → B]；
        // 已确认【露出】或新物品的首次框变大；Track 不再抢 B

    else：
        cancel grow_candidate[A, B]；
        reserve[B] = false；
        failed_grow_pair[A, B] = true；
        retry_snapshot_only[A, B] = true；
        // GROW 没确认，不等于 Track 一定错误；先释放 B，稍后再试 Track
```


## 7. 正式确认刚才被延后的【整理】

```text
for 每个 track_candidate[库存物品 A] = 快照物品 B：

    if A 仍未绑定
       且 B 仍未绑定
       且 unresolved[A] == false
       且 unresolved[B] == false
       且 reserve[B] == false
       且 out_used_by_grow[A.item_id] == false：

        库存物品 A ↔ 快照物品 B；
        planned[A].last_box = B.box；
        planned[A].status = VISIBLE；
        planned[A].blocker_id = 空；
        planned[A].new_item_pending = false；
        planned_out[A.item_id] = false；
        role[B] = MOVED；

    else if out_used_by_grow[A.item_id] == true：
        discard track_candidate[A → B]；
        // A 已被当作原遮挡物出库来确认露出；本轮不再用 Track 把它复活
```

> `GROW` 已确认时，B 已绑定，不会进入这里；只有 `GROW` 失败后释放的 B，才有机会使用原来的 Track 候选。


## 8. GROW 失败后，回到普通快照规则

```text
所有 GROW 候选处理完后：
    收集所有 retry_snapshot_only 中仍未绑定的 A、B；
    一次性重跑；不能按单个 A ↔ B 立即重跑。
    // 否则前一个失败 pair 的结果会影响后一个 pair，产生遍历顺序依赖

for 每个仍未绑定的 B：
    重跑第 4 节【小框 / 新入库】判断；
    但排除所有 failed_grow_pair[*, B]；
    // 不再把失败 GROW 当成旧物品匹配；仍可尝试其他 A 的 SHRINK

for 每个仍未绑定的重试 A：
    if initial_status[A] == VISIBLE：
        重跑【完全遮挡 / 出库】判断； // 可使用刚确认的 MOVED / NEW_ITEM 遮挡物
    else：
        保持 OCCLUDED；
```

> 若这次普通快照判断仍没有唯一结果，才写入 `unresolved`；不是因为 Track 与 GROW 曾经同时出现，就整次不提交。


## 9. 最后把真正多出来的 B 新建入库

```text
for 每个未绑定的快照物品 B：

    if B 是 maybe_in：
        item_id = planned_new_id[B]；
        在 planned 中新建 item_id：
            cls_id = B.cls_id；
            last_box = B.box；
            status = VISIBLE；
            blocker_id = 空；
            new_item_pending = true；
        binding[B] = item_id；
        role[B] = NEW_ITEM；

    else：
        unresolved[B] = true；
```

> 到这里仍是 `maybe_in` 的 B，就按当前 B.box 新建入库；不再判断它是不是“完整框”。
>
> 历史上已出库的物品即使再次出现，也走 `NEW_ITEM`；不恢复旧 `item_id`。


# 6. 最后检查与提交

```text
if 存在 unresolved[A] / unresolved[B]：
    不提交；

else if 每个本轮快照物品 B 都绑定唯一 item_id：
    if 每个 item_id 最多绑定一个 B
       且不存在仍保留的库存物品 X，使得 X.blocker_id 非空
                                      且 planned_out[X.blocker_id] == true：

        for 每个活跃库存物品 A，且 planned_out[A.item_id] == true：
            可选：记录 A 的出库事件；
            从 planned 的活跃库存删除 A；

        一次性提交 planned；

    else：
        不提交；

else：
    不提交；
```

> `GROW` 仍有信息边界：
>
> “原小物品重新露出”和“原小物品被拿走 + 新大同类物品放入”，只靠 `cls_id + box` 有时完全一样。
>
> 若 `BLOCKER_LEFT(A, B)` 不能确认，就**不能把 B 绑定回旧 A**；随后回到普通规则。
> 普通规则能唯一结算时，按【旧 A 出库 + B 新入库】处理；仍不唯一时才保持 `unresolved`。
