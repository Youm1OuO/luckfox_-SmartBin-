> IoM(A, B) = 面积(A ∩ B) / min(面积(A), 面积(B))


**严格匹配**:
1. [cls_id]是否一样
2. [中心位置的距离]是否足够小    <!-- 中心位置的距离越小, 说明两个框在空间位置上越接近 -->
3. [框高的差值]是否足够小
4. [框宽的差值]是否足够小       <!-- [框高的差值、框宽的差值]这两个都小, 说明两个框的大小形状越接近 -->



**局部匹配**:
1. [cls_id]是否一样
2. [IoM(A,B)] 是否足够接近 1    <!-- 公式越接近1, 说明两个框的越接近包含关系 (可能是A包含B, 或者B包含A) -->



**先明白几个概念**
1. 这个版本只有【可见】与【遮挡】两种状态
2. 库存中可能有【可见】、【遮挡】物品
3. 虽然说快照上的物品没有状态一说, 但快照的物品本质上全都是【可见】物品
4. 库存的【可见】物品 ≥ 快照的【可见】物品

> 框变小 —— 被遮挡的更多 (原先没被挡->现在被挡; 原先被挡->现在被遮挡的更多)
> 框变大 —— 被遮挡的更少 (原先被遮挡的更多->现在被遮挡的更少)



**附近的量化**
> near(A, C)：
>   1. normalized_distance(A, C) 是否足够小
>   2. intersect_area(A.box, C.box) 是否足够大(或是否大于0)
其中：
    normalized_distance = center_distance(A, C) / min(A的对角线, C的对角线)
    intersect_area(A.box, C.box) 表示两个框的交集面积
注意:
    1. 我们要做的是找附近的物品, 所以其实 A 与 C 是否是同一类物品都无所谓的
    2. 而且我们使用的是快照与库存的物品进行对比, 这时候如果真的有物体挡住了或有物体移开了, 他们这样必
然原先是有重叠的面积的, 所以应该使用 intersect_area(A.box, C.box)

**注意**
我们之所以需要判断是不是在附近, 通常是因为有物品无法[严格匹配], 然后只能用IoM来[部分匹配], 这时候才会需要用到附近来判断
> 如果框变小了,我们来检查是否是有其他物品遮挡了原先的库存物品A, 这时候需要用[库存物品A的框](框较大)与[快照中物体的框]来遍历对比
> 如果框变大了,我们会检查是不是原先有物品从原先的库存物品A移走了,我们使用的是[快照物体B的框](框较大)与[库存中物体的框]来遍历对比
这样的话,感觉我们这种方法其实就能实现“附近”的判断, 但是核心关键是要正确的进行对比
(而不是盲目的用库存的物品对比库存的物品,快照的物品对比快照的物品)

# 库存与快照的对比逻辑

**说明一下**
> 当前这一版是纯净的使用[严格匹配]+[局部匹配]+对比的逻辑而已


> 有 .block_id, 但是这个版本的 .block_id 用法相对简单, 不会很复杂。
> 例如:
1. 若一个库存中的物品A看不见了, 并且快照中有个新的物品进来, 并且这个新的物品现在的位置能把原先库存中的这个物品A的位置几乎完全覆盖了, 那么这个物体A就变成【遮挡】, 并且记录这个物体A的 block_id 为这个新物品
2. 若当一个物品A被判断为【整理】, 我们就检查所有原先被这个物品遮挡的物品C, 如果整理后物体的位置(从快照可得) 跟被他遮挡的原先的物品不再重合, 那么这些物体C的 block_id 就去掉物品A的信息记录; 并且这个物品A整理后的位置如果挡住了 其他物品B, 那么这个物品B的 block_id 就添加物品A的信息记录;
3. 若当一个物品A被判断为【出库】, 我们就检查所有原先被这个物品遮挡的物品C, 如果整理后物体的位置(从快照可得) 跟被他遮挡的原先的物品不再重合, 那么这些物体C的 block_id 就去掉物品A的信息记录
(.block_id 不是一个数, 而是一个列表, 他要允许记录多个物品信息记录)


> 要给物体一个是否被收握住移动的标识 .hold_and_move, 初始化为 False
> 要同时满足这2个条件才会令 .hold_and_move=True：
1. 手进来时与物品A距离很近(疑似握住物品) 
    **代码角度**：
    1.1 看到见手的框的同时也能看得见物品A的框的话 (手和物体A的框都从yolo中看), 要求[物体A的框要与手的框相邻] (两个框的边相贴, 允许边缘有微微重合的情况);
    1.2 若看到见手的框的但看不见物品A的框的话 (手的框从yolo中看, 物体A的框从库存中看), 要求[手的框完全覆盖物体A的框] (手的框包含了物体A的框)
2. 后几帧手移动的时候, 物体A也跟着移动
    **代码角度**：
    2.1 看到见手的框的同时也能看得见物品A的框的话 (手和物体A的框都从yolo中看), 要求[手和物体A的框都移动] (严格点的话, 他们移动的方向与幅度也要一致);
    2.2 若看到见手的框的但看不见物品A的框的话 (手的框从yolo中看, 物体A的框从库存中看), 要求[手的框移动后,在原位置依旧看不见原来A的框] (手的框包含了物体A的框)

> 当库存中一个物体A少了, 同时快照中一个物体B多了, 并且库存物体A与快照物体B cls_id一样，而且他们的框的大小几乎一样,
> 如果通过track能证明他们两个是整理的话, 就直接整理
> 如果track无法证明他们两个是整理的话, 这时候库存物体A的.hold_and_move=True的话我们也当作他们是整理



**先明白几个概念**
1. 库存中【可见】物品的 box 表示的是最近一次的box (上一次快照的box)
2. 库存中【遮挡】物品的 box 表示的是最近一次【可见】时的box (最近一次快照中看得见的时候的box)


**对比前的预操作**
1. 对比前, 先将快照物品中, [框的宽度过于小的]或[高度过于小的]物品进行过滤
> 因为[框的宽度过于小的]或[高度过于小的]这些物体, yolo看到的几乎是一条缝隙而已, 这些我们不应该认为他被成功识别

2. 然后, 先像将快照物品按照面积的大小进行排序 (大的先处理)
> 因为面积大的快照物品更可能对上库存中【可见】的物品, 这些物品更可能匹配的上
> (这只是一个代码实现中的小技巧, 逻辑本身没有改变; 如果排序本身的代价更重的话, 也可以不排序)

3. 给快照中的物品一个临时的 temporary_id
> 由于只有库存中的物品才有 item_id, 而快照中的物品没有 item_id
> 为了方便操作, 我们给排完序之后的快照中的物品一个临时的 temporary_id (从1开始递增), 并且也给他们初始一个 item_id=-1
> 当快照中的物品的 item_id=-1 时表明他们还没有与库存中的物品匹配上, 否者表示已经匹配上了

4. 找出库存物品中 item_id 对最大值, 赋值给 count
> 因为如果有新物品进来, 我们要给他一个 item_id
> count = 库存物品中 item_id 对最大值


## 1. 先严格匹配

for B in 快照物品 :

            if A.block_id is None and A.box.area < B.area:

                // 这时候有可能是同类物品前后重叠放在一起了
                continue
            A.affirm = True
            B.item_id = A.item_id

**注意**
