# 细节16：先保留原位置候选，再用自适应位移完成静态恢复与移动判定

## 0. 本文件的用途和边界

本文件是下一次修改 3.0 业务代码的实施指导。此次修改围绕
《讨论用/测试后的结果与发现的问题.md》最新记录的实测卡死问题，以及
《讨论用/分析.md》中提出的“不同大小物品不应共用固定像素移动阈值”的问题。

本文件要求处理两件有关联、但必须分阶段完成的事情：

1. 修复无手收尾的流程入口。一个已经找到的旧物体原位置候选，不能因为
   中心偏移超过 CONTACT 的小位移门槛，就在身份匹配阶段被直接丢弃。
2. 将“最终是否发生正式移动”的判断逐步改为基于物体完整原框的归一化、
   自适应位移判断，而不是所有物体共用同一个固定像素值。

本次不是重写整个 HAND、CONTACT、D、遮挡、IN、OUT 或 MOVED 状态机。
更不是通过简单调大、调小一个阈值去掩盖这一条日志。要以最小范围修复
错误入口，并保持已有正确的所有权、连续帧和无手提交约束。

**原先代码已经具备并验证过很多有效功能，本身是很好的。此次修改绝不能把
原先已经正确的正常 MOVED、IN、OUT、C-D alias、HAND_VISIBLE_D、遮挡、揭示、
工作库存隔离、无手条件提交和同类物体仲裁改差。**

特别禁止为了通过本例而全局放宽严格匹配、让普通 NORMAL 物体也使用局部匹配，
或把所有 `12px~28px` 的位移一律强行判成 MOVED。

## 1. 本次实测问题的准确原因

### 1.1 现场关键物体和数据

本次真实移动的是 item#8 苹果。item#7 橙子没有被用户主动整理，但在手遮挡、
手离开后，它的 YOLO 框由近似：

```text
原完整框： (638,460) ~ (785,634)
恢复框：   (594,460) ~ (787,645)
```

变为新的稳定框。两个框的中心约为：

```text
原完整框中心： (711.5, 547.0)
恢复框中心：   (690.5, 552.5)
中心距离：      约 21.7px
```

这个变化主要来自恢复框向左扩张，右边界几乎没有变化。它可能是手遮挡后 YOLO
完整框恢复时的几何变化，也可能是附近物体受到轻微碰撞后的真实小位移；仅凭一帧
不能可靠区分。

### 1.2 当前实际阈值

```text
FLOW3_CONTACT_OBJECT_MOVE_EPS = 12px
FLOW3_COMMIT_MOVE_CENTER_DISTANCE = 28px
```

其中：

- `12px` 是 CONTACT 路径中，物体相对上一真实观察框是否发生有效推拉的
  小位移门槛，也曾被用于 CONTACT 的原位判断。
- `28px` 是最终提交 MOVED 事件时的固定中心距离门槛。

item#7 的约 `21.7px` 位移正好处于两者之间。

### 1.3 当前错误流程

在 `src/session.cc` 的无手观察逻辑中，旧 C 会先按 original_box 查找候选框。
随后，当前代码对存在 `hand_estimate_anchor_box` 的 track 调用
`contact_detection_is_at_original()`。该函数要求中心距离不超过 `12px`；若超过，
调用方将刚刚找到的候选设置为 `found = -1`。

错误流程是：

```text
找到 item#7 的原位置严格/局部候选
    -> 因中心距离 21.7px > 12px，被 CONTACT 原位检查否定
    -> found 被清成 -1
    -> 后面的静态灰区结算函数收不到这个候选
    -> 日志反复出现 no-hand-no-path-candidate
    -> item#7 一直 needs_no_hand_settlement=1
    -> 整轮无手收尾一直 defer-commit
```

代码中已经存在“12px 与 28px 之间的静态灰区，两帧稳定后恢复静态”的逻辑，
但它位于候选框已经被保留之后。此次问题中，候选在更早的入口被清空，因此该逻辑
没有执行。日志中没有 `STATIC-SETTLE` 记录，就是这个事实的直接证据。

因此本例不是单纯的“物体数量太多”，也不是“一帧 YOLO 偶然错检”。恢复框在多张
无手帧中连续出现，问题是业务流程把稳定候选错误地拒绝在灰区处理之前。

## 2. 这次必须遵守的总原则

### 2.1 身份匹配、位移判定、最终事件必须分开

一个检测框需要依次经过三层判断：

```text
检测框
    -> 这个框唯一属于哪个旧物体？
    -> 这个旧物体相对原位置是静止、待确认还是移动？
    -> 是否已经拥有足够连续证据，允许更新工作库存并产生正式事件？
```

绝不能把第二层的“中心位移超过 12px”反过来用于否定第一层的身份归属。

### 2.2 原位置所有权优先级不变

同一检测框的归属优先级仍然是：

```text
旧物体自己的严格原位置证据
    > 旧物体自己的局部连续证据
    > 另一旧物体的 estimated_box、track、tentative B 或 reappear 路径猜测
```

必须先建立当前帧的直接原位置所有权计划，之后才允许 HAND、CONTACT 或 D 使用
估计路径匹配。一个已经唯一属于旧 C 的框，不能被另一旧 C 作为移动正向证据，也
不能被 suspect D 升级或抢走。

### 2.3 NORMAL 的安全边界不得放宽

普通状态是指：既不处于 HAND、CONTACT，也不处于本次手操作遗留的无手恢复阶段。

对这种普通 NORMAL 旧物体：

```text
只允许 original/base_box 的严格匹配。
严格匹配失败即为本帧未匹配。
不得退化成局部匹配、路径匹配、自动 MOVED、自动 IN 或自动 OUT。
```

这是防止相邻同类物体串身份的关键旧规则，不能因为本次修复而被放宽。

## 3. 流程入口的具体修改方案

### 3.1 不要简单删除 12px 判断

不能只把当前 `contact_detection_is_at_original()` 调用删掉。这样会使 CONTACT 物体
在小幅真实推拉时过早被当作静止，破坏 CONTACT 的移动证据链。

正确做法是把它从“候选框过滤器”改成“状态决策条件”：

```text
错误：
    找到候选 -> 超过 12px -> 删除候选

正确：
    找到候选 -> 记录归属和匹配强度 -> 按当前状态解释这个候选
```

`contact_detection_is_at_original()` 应只回答：

```text
当前 CONTACT 路径中，这个真实观察能否立刻作为“仍在原位”的反向证据？
```

它不能再回答：

```text
这个检测框是否属于该旧物体？
```

### 3.2 增加明确的直接匹配结果

建议新增纯数据结构或等价 helper 返回值，用于保存一个旧物体的直接原位置候选：

```text
DirectOriginalMatch
    detection_index
    strength
    source
```

其中 `strength` 至少区分：

```text
STRICT
LOCAL_CONTINUOUS
LOCAL_WEAK
NONE
```

定义如下：

1. `STRICT`
   - 类别相同。
   - 中心、宽、高满足现有严格匹配。
   - 是最强的原位置证据。

2. `LOCAL_CONTINUOUS`
   - 严格匹配失败。
   - 当前局部框与该物体自己的 `last_hand_block_box` 连续局部匹配。
   - 只适用于 HAND_PARTIAL、CONTACT 或 HAND 恢复路径。

3. `LOCAL_WEAK`
   - 没有可靠的上一局部框连续性。
   - 仅能证明当前框与旧完整框有足够包含关系或高 IoM。
   - 只能保护所有权或保持未决，不能单帧释放为静止、确认 MOVED 或确认 D。

4. `NONE`
   - 没有可用的直接原位置解释。

该 helper 必须无副作用：不能修改 `claimed`、工作库存、证据计数、runtime 状态或
事件列表。它只产生本帧计划，随后由统一仲裁写入。

### 3.3 按状态使用严格和局部匹配

下一次实现必须严格遵守下表：

| 当前状态 | 匹配顺序 | 候选用途 |
|---|---|---|
| 普通 NORMAL | 只允许 STRICT | 严格失败就未匹配，不能局部退化 |
| CONTACT_* | STRICT 后 LOCAL_CONTINUOUS，最后才可 LOCAL_WEAK | 候选先保留，再判断原位、移动或待确认 |
| HAND_PARTIAL_* | STRICT 后 LOCAL_CONTINUOUS，最后才可 LOCAL_WEAK | 局部连续框可维护自身路径，但不能直接确认 MOVED |
| HAND_FULL_* | 先检查自己的 STRICT 原位置；失败后才允许局部或 reappear/path 候选 | 无框不是移动或出库证据 |
| HAND 恢复中的 NORMAL | 按本次操作的 HAND 恢复规则：STRICT 后本人的局部连续候选 | 必须进入无手恢复结算，不得套用普通 NORMAL 的立即终态语义 |

“HAND 恢复中的 NORMAL”不能只靠 `state == NORMAL` 判断。当前代码已使用
`needs_no_hand_settlement`、`has_hand_estimate_anchor_box`、operation-start old C 等
信息表达这一阶段。下一次修改时应集中封装成一个清晰的 predicate，或明确的
recovery 标记，避免在多个位置散落相同条件。

### 3.4 直接所有权计划必须先于动态路径

每张手帧和无手收尾帧，处理顺序应为：

```text
1. 构建旧 C 的直接原位置候选与所有权计划。
2. 解决严格优先、局部连续次之、局部弱最末的唯一归属。
3. 标记无法唯一裁决的原位置歧义框。
4. 只有未被旧 C 直接占用、也不是原位置歧义的检测框，
   才允许进入 estimated_box、track、tentative B、reappear 和 D 的动态路径。
```

规则：

- 一个框唯一属于 B 时，A 不得把它作为 A 的 hold、drop、reappear、last_seen 或
  MOVED 证据。
- 原位置歧义框不能按 map 遍历顺序硬分给任意物体。
- 原位置歧义框也不能被 suspect D 用于 self_match、promote 或 placed 证据。
- 普通 C-D alias、HAND_VISIBLE_D 和细节15既有所有权防线必须保留。

### 3.5 现有入口的最小修复目标

在无手观察中，发现 original candidate 后：

```text
不得再因为“有 hand_estimate_anchor_box 且中心位移大于 CONTACT 12px”
直接把 found 清成 -1。
```

应改成：

1. 保留候选框及其 `DirectOriginalMatch::strength`。
2. 若当前确实是 CONTACT 路径，使用 CONTACT 的短时移动规则决定它是否是
   “立即静止证据”、移动路径观察或模糊观察。
3. 若当前是 HAND 恢复中的旧 C，允许该候选进入静态灰区结算。
4. 只有在所有权不唯一、候选已严格属于另一旧 C、或局部候选不连续且不安全时，
   才保持未决。

绝不能让修复后的候选绕过 claim grace、同类唯一仲裁、reappear 自匹配和无手
连续帧确认。

## 4. 静态灰区结算规则

### 4.1 内部必须保留“待确认”

外部最终事件可以只有“没有移动”或“MOVED”，但内部不能只有二选一。单帧图像确实
存在无法可靠区分的情况，因此必须保留：

```text
STATIC          可以恢复为没有移动
PENDING         暂不产生事件，继续观察
FORMAL_MOVE     有资格进入正式移动流程
```

`PENDING` 不是第三种库存事件，只是暂时不乱下结论。

### 4.2 HAND 恢复静态灰区的释放条件

对于 operation-start 旧 C，若它经历过 HAND，但当前已经进入无手收尾，且出现
属于自己的直接候选：

```text
候选唯一属于当前旧 C
    + 候选为 STRICT 或可靠的 LOCAL_CONTINUOUS
    + 与原完整框在尺度和 IoM 上仍可解释为同一物体
    + 尚未具备真实跟手移动 / 放下证据
    + 不存在 C-D alias、claim 或路径歧义
    + 连续至少 FLOW3_NO_HAND_D_CONFIRM_FRAMES 张无手帧稳定匹配自己
    -> 释放为 STATIC_CONFIRMED
```

释放后：

- `item.box` 可以更新为当前稳定检测框；
- 不发 MOVED；
- 不把当前框作为前景遮挡物；
- 不把检测框形状恢复产生的微小变化写成正式 `base_box` 位置迁移；
- 清除本次仅因误判移动而保留的临时候选、placed、drop 或 alias 残留；
- 不得影响其他真正移动、入库或出库物体的收尾。

### 4.3 真实轻微移动的邻居物体

用户真实操作 A 时，邻居 B 可能被碰到、滚动或轻微位移。B 未必是被手直接抓住，
但若系统已经有本次手操作上下文，B 最终位置稳定且唯一可确认，则应允许更新 B。

默认建议：

```text
B 处于本次手操作影响范围
    + B 的直接身份唯一且连续稳定
    + B 的归一化最终位移达到正式移动门槛
    + 没有同类所有权冲突或 D 冲突
    -> B 也记录为 MOVED，并更新 base_box
```

若 B 只落在灰区，或主要表现为框单侧扩张、IoM 很高、没有稳定真实移动证据，则保持
PENDING，最终按静态恢复处理，不得误发 MOVED。

这里的“允许邻居 B 发生轻微位移”不是要求把每一次微小变化都记录成正式移动，而是
要求流程不能因为 B 没有被手直接抓住，就把这种变化一律当成异常、丢失或身份变化：

- 如果变化主要是遮挡解除后的框变宽、框变高、中心轻微跳动或普通 YOLO 抖动，属于
  正常检测误差。应通过严格匹配、局部连续匹配、IoM、连续帧和无手收尾吸收，不能仅凭
  这种抖动发出 MOVED。
- 如果 B 确实因碰撞、滚动或挤压改变了位置，且新位置在连续有效无手帧中稳定、身份唯一，
  并达到正式的归一化移动阈值，则这是允许的真实邻居移动，应记录 MOVED 并更新
  `base_box`。
- 如果真实位移很小、仍处于灰区，或者身份/遮挡关系有歧义，则暂不发事件而保持
  `PENDING`；待证据足够时再确认，不能为了“允许碰撞”而强行判 MOVED。

没有本次手操作上下文的普通 NORMAL 物体仍只适用严格匹配，不能因为远处框轻微变化
自动产生 MOVED。

### 4.4 稳定灰区候选不得永久卡住

灰区的作用是避免单帧误判，不是让候选无限期停留。对于一个灰区候选，只要同时满足：

```text
候选连续出现在有效无手帧中
    + 每帧都能唯一归属于同一个旧物体
    + 框的位置/尺度变化只在允许的抖动容差内
    + 没有 C-D alias、同类 claim 或其他身份歧义
    + 未达到正式 MOVED 的可靠证据
    + 连续帧数达到 FLOW3_NO_HAND_D_CONFIRM_FRAMES（当前为 2）
    -> 结束 PENDING，释放为 STATIC_CONFIRMED
```

“连续稳定”允许 YOLO 的小幅中心抖动和边界抖动，不要求每一帧的四个坐标完全相同。
只有连续的**无手有效帧**才能累计这项计数；手仍在画面中时，即使框暂时看起来不变，
也不能提前把物体认定为静止。若候选消失、换成其他候选、变得不唯一或出现新的移动
证据，计数应按现有规则暂停或清零并继续 `PENDING`。

因此，典型的“连续几帧框差不多，只是正常抖动”的情况应最终正常收尾为静态，而不是
永久 `defer-commit`；但“连续几帧一样却无法确认身份”的情况仍必须保留歧义保护。

## 5. 归一化、自适应最终位移判定

### 5.1 为什么不能继续只用固定像素

同样的 `20px` 对不同大小物体含义不同：

- 对小物体，可能已经移动了自身宽度的很大比例。
- 对大物体，可能只是检测框边缘恢复或 YOLO 抖动。

因此最终 MOVED 的位移判断不能长期只依赖所有物体共用的 `28px`。

### 5.2 使用可靠完整原框，不使用遮挡后的局部框

移动尺度必须以 `original_box` 或可靠 `base_box` 为准。不得按当前局部框面积、
被手遮挡后缩小的框，或临时 reappear 框作为归一化分母；否则遮挡本身会改变阈值，
导致同一物体在不同帧得到不一致结论。

建议的第一版公式：

```text
reference_scale = clamp(
    diagonal(original_complete_box),
    FLOW3_MOTION_REFERENCE_DIAGONAL_MIN_PX,
    FLOW3_MOTION_REFERENCE_DIAGONAL_MAX_PX
)

normalized_motion =
    center_distance(original_complete_box, current_complete_box) /
    reference_scale
```

使用完整原框对角线而不是面积的原因：

- 对角线同时反映宽和高，直观且与当前代码的几何工具一致；
- 面积会因局部遮挡、框变宽或框变小而波动得更明显；
- `clamp` 可避免极小或极大框把比例放大、缩小得过头。

若后续数据表明长条形物品很多，再单独评估按 x/y 分别归一化的公式；在没有回放数据前，
不要一次引入更复杂的方向权重。

### 5.3 新参数建议

下一次迁移最终移动判断时，建议在 `fridge_config.h` 增加明确的新参数：

```text
FLOW3_MOTION_REFERENCE_DIAGONAL_MIN_PX
FLOW3_MOTION_REFERENCE_DIAGONAL_MAX_PX
FLOW3_STATIC_CENTER_SHIFT_NORM
FLOW3_FORMAL_MOVE_CENTER_SHIFT_NORM
```

语义：

- `FLOW3_STATIC_CENTER_SHIFT_NORM`：低于该值时，可作为低位移静态候选。
- `FLOW3_FORMAL_MOVE_CENTER_SHIFT_NORM`：达到该值时，才有资格作为正式位置变化。
- 两个阈值之间是静态灰区，必须依赖连续帧和状态证据，不能强制二选一。

要求：

```text
FLOW3_STATIC_CENTER_SHIFT_NORM
    < FLOW3_FORMAL_MOVE_CENTER_SHIFT_NORM
```

`FLOW3_CONTACT_OBJECT_MOVE_EPS` 暂时保留为 CONTACT 路径中“相对上一真实观察框”
的短时推拉证据门槛。它不能继续承担无手恢复原位置候选的全局否定职责。

`FLOW3_COMMIT_MOVE_CENTER_DISTANCE` 不要贸然改成 `20px`。最终应由新的归一化 helper
替换它在正式 MOVED 判定中的职责；兼容期内必须明确每个调用点到底使用旧规则还是
新规则，不能混用含义相同但单位不同的阈值。

### 5.4 阈值值如何确定

不要凭一条日志直接定最终比例。实施时先增加只记录、不改变业务的诊断日志，至少输出：

```text
item_id
原完整框对角线
中心位移像素
归一化位移
IoM
宽高比例变化
直接匹配强度
唯一 owner / 歧义原因
最终状态：STATIC / PENDING / FORMAL_MOVE
```

然后收集两类样本：

1. 物体实际上没有移动，但手遮挡后框恢复、变大、变小或轻微跳动的样本。
2. 物体确实发生整理、邻居滚动、碰撞位移的小物体和大物体样本。

设定方法：

```text
静止样本中最大的正常归一化位移
    -> 静态阈值应略高于它

真实移动样本中最小的可信归一化位移
    -> 正式移动阈值应略低于它
```

若两类样本重叠，不能靠继续压缩阈值解决，必须依赖 PENDING、多帧稳定、手部上下文、
局部连续性、drop/分离证据和同类所有权仲裁。

实现时应把“检测框抖动容忍”和“真实碰撞位移可记录”作为两个不同判断：前者是
静态恢复的容差，后者才可能进入正式 MOVED。两者都不能破坏已有的严格匹配、原位置
所有权、无手提交和同类物体仲裁规则。

## 7. 必须新增或保留的回放测试

### 7.1 本次现场问题的最小回放

构造：

- 初始库存包含 item#7 橙子和 item#8 苹果。
- 手进入并影响两者。
- item#8 移动到明确的新位置。
- item#7 在恢复时使用与现场接近的框：原中心与恢复中心差约 `21.7px`，且恢复框
  连续稳定。

断言：

```text
只有 item#8 产生 MOVED。
item#7 最终 VISIBLE，不产生 MOVED、OUT、IN、OCCLUDED 或 REVEALED。
无手收尾可以提交，不能永久 defer-commit。
```

### 7.2 灰区一帧抖动

构造：

- HAND 恢复旧 C 只出现一张灰区框，下一张框消失、换框或成为歧义。

断言：

```text
不得单帧释放为静止。
不得单帧确认 MOVED。
必须保持 PENDING，等待现有安全收尾规则。
```

### 7.3 CONTACT 的真实小幅推拉

构造：

- CONTACT 物体相对上一真实观察框发生超过 CONTACT 小位移门槛的连续移动。

断言：

```text
修复不能让它因为仍与原框局部重叠，就被错误释放为静止。
它应继续走现有 CONTACT_MOVING、连续证据和放下判断链路。
```

### 7.4 普通 NORMAL 物体不得获得局部匹配

构造：

- 两个相邻同类普通旧物体；其中一个只与另一物体局部重叠。

断言：

```text
NORMAL 物体严格匹配失败时，不能因本次修改使用 LOCAL_CONTINUOUS 或 LOCAL_WEAK。
不得错误串身份、自动 MOVED、自动 IN 或自动 OUT。
```

### 7.5 大小不同物品的归一化验证

构造：

- 小物体和大物体分别移动相同像素距离。
- 两者分别存在“真实移动”和“仅框形状恢复”两种变体。

断言：

```text
相同像素位移在不同物体尺寸下可得到不同的归一化结论。
没有真实移动的恢复框不应误发 MOVED。
稳定、唯一、达到正式归一化阈值的真实移动应更新 base_box 并发 MOVED。
```

### 7.6 被碰撞或滚动的邻居 B

构造：

- A 被手移动。
- B 没有被直接抓住，但在本次手操作影响范围内被碰到后，稳定地移动到新位置。

断言：

```text
当 B 达到正式归一化位移、连续无手稳定、身份唯一时，可确认 B 的 MOVED。
若 B 只处于灰区或框形状不稳定，则不得误发 MOVED。
```

### 7.7 原有回放必须继续通过

至少持续运行并保持通过：

- 正常 MOVED、IN、OUT。
- 遮挡、揭示、多个 blocker 的矩形覆盖并集。
- C-D alias 的 shared、distinct、stale-missing 无手收尾。
- HAND_VISIBLE_D 让渡给静态旧 C。
- 相邻同类物体、原位置替代 D、POST_HAND_REVEAL_D。
- 细节15和现有 r16 静态灰区相关回放。
- 输入检测数组顺序变化、map 遍历顺序变化时，结果仍一致。

## 8. 实施顺序和版本要求

建议分两次小而可验证的实施，不做一次大改：

### 第一步：入口修复版本

1. 修复候选被 `12px` 错误清除的问题。
2. 引入或整理 DirectOriginalMatch / 匹配强度和所有权计划。
3. 让当前 item#7 灰区候选能进入已有两帧静态恢复逻辑。
4. 增加现场最小回放、CONTACT 小幅推拉回放、NORMAL 不得局部退化回放。
5. 初期保留正式 `28px` MOVED 行为，不同时修改全部阈值。
6. 通过全部既有回放后，版本号从当前 `3.0-r17` 增加到下一版本号。

### 第二步：归一化最终 MOVED 版本

1. 先加入只记录诊断指标的日志和回放数据。
2. 添加独立的归一化最终位移 helper 与超参数。
3. 只迁移正式 MOVED / base_box 更新判定，不破坏 CONTACT 的短时路径语义。
4. 用大小不同、真实移动、框恢复、邻居滚动的回放校准阈值。
5. 同步更新《超参数位置与调节说明.txt》和《版本说明.md》。
6. 通过全部回放后再增加版本号。

## 9. 明确禁止的修改方式

不得：

1. 把 `FLOW3_COMMIT_MOVE_CENTER_DISTANCE` 直接改为 `20px`，就认为问题已解决。
2. 把 `12px~28px` 的全部灰区一律判定为 MOVED 或一律判定为静止。
3. 全局放宽 NORMAL 物体的严格匹配，使其可以无条件局部匹配。
4. 用当前被遮挡的局部框面积作为最终移动归一化分母。
5. 删除 CONTACT 的短时移动保护，而不提供等价的状态决策。
6. 因为修 item#7 而绕过同类唯一所有权、claim grace、D 隔离、reappear 两帧确认
   或无手条件提交。
7. 用检测数组顺序、item_id 顺序或 map 遍历顺序解决歧义。
8. 为本次修改顺手重写无关模块、重构整个文件、改变云端上报、OSD 或模型阈值。
