# 细节21：统一历史与当前覆盖语义，完成“已遮挡物随 blocker 离开而露出”

## 0. 文档用途

本文件是下一次修改 3.0 状态机前的实施指导。它只处理最新实机回放中已经
确认的一处遮挡因果缺口：

```text
上一事务：苹果 A 已确认移动到橙子 B 前方，B 已正式 OCCLUDED；
下一事务：A 已确认 MOVED 到远处，B 当前也有合法直接 detection；
结果：A 正确 MOVED、没有假 D/IN、B 的 blocker 关系已清空，
      但 B 仍保持 OCCLUDED，未产生 REVEALED。
```

本次修正不是推翻《细节20.md》的身份仲裁或 blocker 因果模型，而是补齐其中
“跨操作比较覆盖前态与后态时必须使用同一种正式覆盖语义”的要求。

此前《细节18.md》《细节19.md》《细节20.md》中关于正式库存、工作库存、
`base_box`、`block_ids`、C-D alias、D guard、MOVED/IN/OUT 门槛、事件顺序和
事务边界的约束继续全部有效。

## 1. 最高优先级：当前已经有效的功能很好，绝对不能改坏

**当前代码已经解决了许多重要问题。下一轮只能做职责清晰、可验证、可回退的
最小逻辑修正，绝对不能为了让橙子露出而把这些已经有效的功能改坏。**

最新实机日志本身已经证明下列行为在本轮是正确的，必须作为不可回归基线：

- 苹果 A `item#2` 从原位置正确结算为 `MOVED` 到真实终点；
- 没有多出苹果 `IN`，库存总数仍为 4；
- 低分跨类别重复框没有再把 A 错静态结算，也没有让右侧真实 A 终点变成假 D；
- 正式 `block_ids` 已识别到 A 离开，橙子 B 的 blocker 数从 1 变为 0；
- `REVEALED` 没有仅因 B 自己出现 detection 就被草率产生；
- HAND、CONTACT、同类 C-D alias、D quarantine、普通两帧 OUT、低置信度假 IN
  防线、小位移容忍和已成功的完全遮挡路径仍然有效；
- `inventory_`、`working_inventory_`、`operation_start_inventory_` 的事务隔离和
  `replace_all()` 提交边界仍然正确；
- YOLO 业务输入、OSD、截图和日志不能因为身份/遮挡仲裁而删除或改写 detection。

以下做法明确禁止：

- 不能把所有 `OCCLUDED` 物品重新纳入普通 HAND/C 轨迹；
- 不能因为已遮挡物有一张 detection 就直接写 `VISIBLE` 或直接生成 `REVEALED`；
- 不能删除历史 `block_ids`、把 `old.status == OCCLUDED` 直接等价成“前态一定完整覆盖”；
- 不能全局放宽或收紧 `strict_match_box()`、`partial_match_box()`、`track_match_box()`；
- 不能降低 MOVED、D 或 OUT 的确认帧数，也不能全局过滤低分框或提高 YOLO/NMS 阈值；
- 不能让未确认 D、HAND 临时框、路径推测框成为正式 blocker；
- 不能按 item_id、detection 数组顺序或 timeout 强行解决同类身份歧义；
- 不能把本轮逻辑塞进一个新的大条件链或把所有代码挤在同一个文件中。

## 2. 最新日志的事实与正确诊断

### 2.1 实机已经正确完成的部分

本次现场结果不是上一轮错误的原样复发。日志表明：

```text
初始正式关系：
    item#2 apple 覆盖 item#4 orange
    item#4.status == OCCLUDED
    item#4.block_ids 包含 item#2

本次操作结算：
    MOVED(item#2)
    item#2: (530,285)~(741,487) -> (892,247)~(1060,414)
    没有 IN(new apple D)
    inventory-after == 4
    item#4.block_ids 变为空
```

因此，A 的身份、D 防线和历史 blocker 移除已经生效。当前错误是一个保守的
false negative：应露出的 B 没露出，而不是重新发生“假入库 + 无原因露出”的
高风险 false positive。

### 2.2 B 的 detection 并不是这次的主要缺口

frame 282 的有手日志已经出现：

```text
candidate=0 cls=2 action=yield-to-direct-old-owner-plan owner=4
```

这说明橙子框能严格属于旧 `item#4`。在无手结算中，`item#4` 也是唯一的橙子
旧库存候选；现有 `settle_no_hand_frame_()` 的双向唯一绑定会把这类框作为当前
observation 使用。

`CANDIDATE-CONTEXT` 中的：

```text
candidate=3 cls=2 direct-old=[] viable-unresolved-old=[]
```

只表示该阶段只统计存在活动运行时轨迹的旧 C。已经正式 `OCCLUDED` 的 B 不建立
普通 HAND/C 轨迹，因此它不会出现在这组运行时诊断里；这不是把 B 变成新 D 的
授权，也不应据此重写普通 owner/D 逻辑。

### 2.3 真正的断点：覆盖前态与后态使用了不对称语义

当前 `refresh_confirmed_blockers_()` 的核心关系可抽象为：

```text
coverage_before_full
    = fully_covered_by(operation-start target, operation-start historical blockers)
      // 只有严格完整覆盖

coverage_after_full
    = strict_full_covered
      OR current-confirmed edge-residual-full
      // 当前确认前景允许已有的边缘残余覆盖语义

coverage_changed_by_confirmed_front
    = (coverage_before_full != coverage_after_full)
      AND blocker 有确认的 added/removed/moved
```

而正式 `OCCLUDED` 的建立路径已经允许：

```text
strict full coverage
OR
confirmed-front 的边缘残余仍在容差内的 full coverage
```

这会产生一个跨操作语义不一致：

```text
上一事务：A 对 B 的正式遮挡依靠 edge-residual-full 成立；
下一事务开始：before 只用 strict，错误得到 false；
本事务结束：A 已 MOVED 离开，after 也为 false；
结果：false -> false，系统认为“覆盖没有变化”，
      即使 B 已被合法观察，也不允许 REVEALED。
```

这正好解释现场最终的矛盾状态：

```text
item#4.status == OCCLUDED
item#4.block_ids.empty()
```

不是系统仍认为 A 在遮挡 B；而是系统知道关系已移除，却因 `before` 被错误算为
非完整覆盖，丢失了“覆盖从完整变为不完整”的因果差分。

打印日志中的整数框是 `box` 的可见表示；正式判断使用 `base_box` 和浮点几何。
因此不能只依赖日志四舍五入后的边缘肉眼判断本例一定是严格覆盖。下一轮必须用
回放和 plan trace 把 `strict`、`edge-residual`、`full` 三者分别打印和断言。

## 3. 本轮要恢复的正式不变量

### 3.1 同一项正式遮挡，前后比较必须采用同一覆盖分类器

对同一个目标 B：

```text
上一事务能够以某种正式覆盖语义把 B 写成 OCCLUDED，
下一事务就必须以兼容的正式覆盖语义计算 before。
```

否则 blocker 实际离开时，会出现“关系已删除、状态无法转移”的悬空状态。

正确的 Reveal 条件仍然是：

```text
operation_start[B].status == OCCLUDED
AND B 有本帧合法 direct observation
AND coverage_before_full == true
AND coverage_after_full == false
AND 至少一个历史 blocker 有确认 MOVED/OUT 或其他确认位置变化
```

满足后才允许：

```text
MOVED(A) -> REVEALED(B)
OUT(A)   -> REVEALED(B)
```

### 3.2 历史 edge residual 的资格必须很窄

“历史 blocker 可以用 edge residual 参与 before”不等于任何历史交叠都可当成
完整遮挡。只有同时满足下列条件时才可把 historical edge residual 视为
`coverage_before_full`：

1. B 在操作开始时已正式是 `OCCLUDED`；
2. B 的 `historical_block_ids` 非空；
3. 参与计算的框全部来自 `operation_start_inventory_` 中的历史 blocker 的可靠
   `base_box`，不是本帧手框、预估框、低分临时框或未确认 D；
4. 历史 blocker 与 B 有正面积前景关系；
5. 严格覆盖不成立时，只有既有
   `FLOW3_CONFIRMED_OCCLUSION_EDGE_RESIDUAL_PX` 的残余几何判定为真，才可视为
   historical full；
6. 该结果只用于比较本次事务的 before/after，不能单独新建 `OCCLUDED`，不能让
   一个原本 `VISIBLE` 的物品因为旧关系变成遮挡。

特别禁止：

```text
if (old.status == OCCLUDED) coverage_before_full = true;
```

这会把“上一轮 blocker 已离开但 B 当时没有被看见”的遗留状态也伪造为完整覆盖，
并可能在之后的无关操作中制造假 REVEALED。必须仍以历史 `block_ids` 和可靠框的
实际几何为依据。

### 3.3 当前 after 的资格保持更严格

当前事务的 `coverage_after_full` 仍只能由：

```text
历史仍有效的 blocker 的可靠框
union
本轮已确认且当前直接出现的 MOVED/IN 前景物的可靠框
```

计算。边缘残余只在前景已经满足现有 confirmed MOVED/confirmed IN 门槛时可用。
未确认 D、quarantined D、低分跨类别重复框、HAND 框、`expected_box`、路径中间点
都不能进入 after 覆盖，更不能成为新的 blocker。

## 4. 推荐实现模型

### 4.1 抽出明确的覆盖评估结果

不要在 `refresh_confirmed_blockers_()` 中分别手写两套布尔表达式。建议在遮挡职责
区域增加一个只读、frame-local 的小结构或 helper 返回值，例如：

```text
CoverageEvaluation
    strict_full
    edge_residual_full
    full
    cover_box_count
```

示意接口：

```text
evaluate_full_coverage(target_box, cover_boxes, allow_edge_residual)
```

其中：

```text
strict_full         = fully_covered_by(target_box, cover_boxes)
edge_residual_full  = !strict_full
                      && allow_edge_residual
                      && edge_residual_within_target_border(...)
full                = strict_full || edge_residual_full
```

它只是几何分类结果，不写 `InventoryItem`，不发布事件，也不分配 detection owner。

### 4.2 before 的正确输入和开关

在 `refresh_confirmed_blockers_()` 中：

```text
historical_target_box
    = operation-start B.base_box（无 base_box 时才退回 box）

historical_cover_boxes
    = operation-start 的 historical_block_ids 中仍有可靠框的 blocker base_box

allow_historical_edge_residual
    = operation-start B.status == OCCLUDED
      && historical_block_ids 非空
      && historical_cover_boxes 非空
```

然后：

```text
before_coverage = evaluate_full_coverage(
    historical_target_box,
    historical_cover_boxes,
    allow_historical_edge_residual)

plan.coverage_before_full = before_coverage.full
```

这里 historical edge residual 的依据是“该关系已经被上一事务正式提交”，不是
当前帧视觉猜测。因此它不会放宽新遮挡的创建条件。

### 4.3 after 的正确输入和开关

保持现有责任边界：

```text
after_target_box = 本轮 final_items[B] 的可靠 base_box
after_cover_boxes = effective_blocker_ids 的可靠框
allow_current_edge_residual = 至少有参与当前覆盖的 confirmed MOVED/IN front

after_coverage = evaluate_full_coverage(
    after_target_box,
    after_cover_boxes,
    allow_current_edge_residual)

plan.coverage_after_full = after_coverage.full
```

历史 blocker 只是漏检但尚未确认 OUT 时，仍按已有逻辑保留关系；本轮不能因为
当前 detection 丢失就从 `effective_blocker_ids` 静默删除它。

### 4.4 按方向计算因果条件，而不是只依赖通用差异

现有 `coverage_changed_by_confirmed_front` 可以保留为诊断摘要，但正式许可应明确
表达方向：

```text
confirmed_front_changed
    = added_blocker_ids / removed_blocker_ids / moved_blocker_ids 至少一个非空

allow_occluded_transition
    = !before.full
      && after.full
      && confirmed_front_changed
      && B 没有合法 direct observation

allow_revealed_transition
    = before.full
      && !after.full
      && confirmed_front_changed
      && B 有合法 direct observation
```

这样现场操作会成为：

```text
before: A 的历史正式覆盖（strict 或已提交 edge residual） = true
after:  A 已确认 MOVED 到远处，覆盖 B = false
B:      当前唯一合法橙子 detection = true

=> MOVED(A) -> REVEALED(B)
```

### 4.5 observation 和身份流程本轮不要重写

本例中，不应为了让 B 露出而给所有 `OCCLUDED` 物品创建普通 HAND 轨迹。
这会破坏当前“被遮挡旧物不会被一帧框直接变可见”的保护，也会扰乱同类 D/alias。

应保留现有分层：

```text
无手双向唯一绑定
    -> 当前 B 是否有合法 observation

BlockerTransitionPlan
    -> 该 observation 是否在本轮具有使正式状态变更的因果条件
```

若追加日志证明某个实际例子中 B 没有进入 `observed_ids`，那应作为独立的
observation-owner 缺口另开最小修复与回放；不能把两种问题混在本轮里。当前日志
和代码路径首先应修复的是 coverage before/after 的语义不一致。

## 6. 日志与诊断要求

下一次实机排查不应再只看到“状态没变”。在 `BlockerTransitionPlan` 完成后增加一条
只读 trace，至少记录：

```text
target id
historical blocker ids
effective blocker ids
observed / observation_conflict
before.strict_full
before.edge_residual_full
before.full
after.strict_full
after.edge_residual_full
after.full
added / removed / moved blocker ids
allow_occluded_transition
allow_revealed_transition
reason
```

建议类别名为 `OCCLUSION-PLAN`。例如本例理想日志应能读成：

```text
target=4 observed=1
before=(strict=0 edge=1 full=1)
after=(strict=0 edge=0 full=0)
moved=[2] removed=[2]
allow-revealed=1 reason=confirmed-blocker-moved-away
```

若实际 `observed=0`，再单独检查 observation binding；若 `before.full=0` 而上一轮
曾正式产生 `OCCLUDED`，即可直接验证本文件锁定的覆盖语义缺口。

日志只能诊断，不能成为以数组顺序、时长或 item_id 选择身份的依据。

## 7. 必须新增或保留的回放

所有测试必须继续使用当前的主机 `session3_replay`，并断言库存数量、item id、状态、
`base_box`、`block_ids`、事件次数、事件顺序和提交状态。

### 7.1 核心回放：历史 edge residual 的 blocker 移走后 reveal

构造一个能触发既有边缘残余容差的正式遮挡：

```text
第一事务：
    A 已按既有 MOVED 门槛确认到 B 前方；
    strict cover 留下不超过 FLOW3_CONFIRMED_OCCLUSION_EDGE_RESIDUAL_PX 的边缘残余；
    B 在无直接 observation 时正式 OCCLUDED，block_ids={A}。

第二事务：
    A 已按既有 MOVED 门槛确认移到 B 外；
    B 当前有一张同类别、严格、唯一的直接框；
```

断言：

```text
MOVED(A) 存在；
REVEALED(B) 存在；
MOVED(A) 的事件索引小于 REVEALED(B)；
B.status == VISIBLE；
B.block_ids.empty()；
库存数量不增加；
没有 IN(new D)。
```

该测试必须在修复前失败、修复后通过，不能只手工把 B.status 改为 OCCLUDED 而绕过
第一事务的正式 edge-residual 建立路径。

### 7.2 现场形状回放：三苹果加一个已遮挡橙子

在上面的几何单元回放之外，再增加接近实机拓扑的回放：

```text
item#1 apple: 静态可见
item#2 apple: 历史 blocker，随后移动到远处
item#3 apple: 静态可见且靠近 B 的局部前景区域
item#4 orange: 已正式 OCCLUDED，block_ids={item#2}
```

最终无手帧应同时出现三个苹果和一个橙子。断言 `item#2` 仍保持自身 MOVED 身份，
`item#4` 露出，不生成新苹果 D/IN。这个测试防止复杂现场密度重新触发同类 owner
或 D guard 的倒退。

### 7.3 必须保留的反向保护

以下场景必须继续通过，尤其不能因“before 允许 historical edge residual”而退化：

1. B 有直接框，但任何历史 blocker 都没有确认 MOVED/OUT：B 继续 `OCCLUDED`，无
   `REVEALED`；
2. A 已移走，但 B 没有合法直接 observation：无 `REVEALED`，继续既有
   occlusion-loss/OUT 证据链；
3. 只有历史 `block_ids` 或普通部分相交，B 原来是 `VISIBLE`：不能新建
   `OCCLUDED`；
4. A 仍完整覆盖 B：即使检测器给出一个 B 小框，也保持 `OCCLUDED`；
5. 多 blocker 中只有一个移动，但覆盖并集仍完整：B 继续 `OCCLUDED`；
6. 历史 blocker 只是当前帧漏检、尚未达到 OUT：不能清关系、不能 reveal；
7. 低分跨类别苹果/橙子近同框 + 真实 A 终点：仍为 `MOVED(A) -> REVEALED(B)`，
   没有假 D/IN；
8. 真实新 D 两帧以上稳定入库、普通 OUT、HAND、CONTACT、C-D alias、小位移和已
   有严格完全遮挡回放全部继续通过。

### 7.4 事件顺序

必须继续保证：

```text
MOVED(A) -> REVEALED(B)
OUT(A)   -> REVEALED(B)
MOVED(A) -> OCCLUDED(C)
IN(D)    -> OCCLUDED(C)
```

事件仍应在同一个正式事务中集中生成，但前景事件必须先于 visibility 事件。不得
因为 map 遍历或 item_id 使 B 的 `REVEALED` 出现在 A 的 `MOVED` 之前。

## 8. 超参数约束

本轮正确修正应复用已有的：

```text
FLOW3_CONFIRMED_OCCLUSION_EDGE_RESIDUAL_PX
```

它不是一个新的分数阈值，本轮不应新增 YOLO、NMS、D、MOVED 或 OUT 超参数，也不应
调整现有残余像素值来“碰巧通过”现场案例。

因此，若实现严格按本文件完成，通常不需要修改
`超参数位置与调节说明.md`。若后来确实新增参数，则必须：

1. 只放入 `include/fridge_config.h` 的对应业务配置区；
2. 在《超参数位置与调节说明.md》中写明默认值、作用范围、不是全局检测过滤、
   可观察日志和调节风险；
3. 为边界值新增可重复回放；
4. 不得复用 OSD 阈值或 YOLO 置信度阈值充当 blocker 因果规则。

## 9. 实施顺序

1. 先新增 7.1 的 edge-residual 跨操作回放，并确认旧实现确实无法发出
   `REVEALED`；
2. 增加 `OCCLUSION-PLAN` 诊断，验证失败时是
   `before.strict=0 edge=0 full=0`、`after.full=0`，而 A/B identity 已正确；
3. 抽出共享 `CoverageEvaluation`，先在不改变事件逻辑的情况下让 before 使用
   合法 historical edge residual；
4. 把 `allow_occluded_transition` 和 `allow_revealed_transition` 改为明确方向条件；
5. 运行 7.2、7.3、7.4 的全部回放；
6. 运行完整 `-Werror` 回放、ASAN/UBSAN 与 `git diff --check`；
7. 部署到板端后，复测本次“移动遮挡橙子的苹果”操作，并检查
   `OCCLUSION-PLAN` 是否输出预期前态/后态。

任一步出现既有成功回放退化，都应停在上一个通过点定位，不能通过删历史关系、
放宽 D、降低确认帧数或调高全局分数阈值压过去。

## 10. 完成条件

本轮只有同时满足以下条件才算完成：

- A 的真实移动仍为 `MOVED(A)`，没有假 D/IN；
- B 在 A 确认离开且 B 被合法观察时，产生且只产生一次 `REVEALED(B)`；
- B 自己出现 detection、但 blocker 没有确认变化时，绝不 reveal；
- 前态和后态对同一正式遮挡使用兼容的 strict/edge-residual 覆盖语义；
- 历史 blocker 漏检、部分前景、未确认 D、HAND 框和路径推测仍不能伪造遮挡或揭示；
- `MOVED/OUT/IN` 始终先于相关 `OCCLUDED/REVEALED` 事件；
- 跨类别重复身份修复、D guard、C-D alias、HAND/CONTACT、普通 OUT/MOVED 和
  已有遮挡回放均无回归；
- 完整 replay、`-Wall -Wextra -Werror`、ASAN/UBSAN 和 `git diff --check` 全部通过。

## 11. 核心原则

```text
同一种正式遮挡资格，跨操作比较时必须使用同一种覆盖语义；
历史 edge residual 只能作为已提交遮挡关系的 before 证据，不能凭空创建遮挡；
目标 detection 只是 observation，是否 REVEALED 仍由 blocker 的确认变化决定；
先确认身份和 blocker 最终位置，再计算覆盖差分，最后提交 visibility 事件；
当前已经有效的功能很好，下一轮只修覆盖前后语义不一致，绝不能把原有防线改坏。
```
