# 细节31：无手期补登记（后手矫正）——一次操作后对 IN / OUT 做严格准入的兜底

## 0. 文件性质与最高约束

本文是下一次修改 3.0 业务代码的实施指导说明。目标是新增一个**无手期的后手矫正
（补登记）机制**：一次操作（开门→有手→无手）结束时，对"有手期因证据不足而没能
建立结论"的 IN / OUT 做一次严格准入的兜底补登记。典型受益场景：透明蛋盒整盒放入
（YOLO 只看到手和一堆鸡蛋、看不到盒子）、整盒取走。但机制本身是通用的，所有物品受益。

**最高优先级：绝不能把已经有效的功能改坏或改差。** 下列能力必须原样保持：

- 单手/双手 入库、出库、整理、静态回原位、连续多物品；
- CONTACT、严格遮挡、因果遮挡（细节29 的归属歧义免疫）、遮挡解除、REVEALED；
- 正常 D/IN、C-D alias、原子提交边界（`replace_all()`）；
- 细节27 类别无关 shadow / 全局一对一归属；细节28 统一实体图；
- 细节30 §3.1 的 reappear 移动证据；reclassify 纠正与纠正后同类去重。

**本次绝对禁止：**

- 改动任何**有手期**逻辑（本机制只在无手结算的最后、事件生成阶段起作用）；
- 降低有手期建立 IN/OUT/遮挡的既有门槛，或放宽匹配/NMS/帧数/面积/距离阈值；
- 在"本轮操作从未有手进入过"的纯静止画面里补 IN 或补 OUT（挡住纯背景误检）；
- 把"被遮挡"误当"消失"来补 OUT，或把"某物品的重复/误分类框"误当新物品补 IN；
- 让补登记绕过或改写原子提交边界、或让单个物品抢先提交清空其他未决 runtime。

若改动或复用任何超参数，必须同步更新 `超参数位置与调节说明.md`（原值/新值/用途/风险）。
本次预期新增 2~3 个明确命名的超参数（见 §5），默认值保守。

## 1. 背景与现状（已核实代码）

> ⚠️ **本节描述的是"改动之前的老行为 / 待打破的现状"，不是本次要遵守的规矩。**
> 本次新增的补登记机制（见 §2）正是用来打破下面这条老限制的——把有手期没能入库/出库的
> 物品，在无手期补回来。

**改动前的老行为（缺口所在）**：3.0 现状下，无手结算**只结算有手期已经建立的结论，
自身从不产生新的 IN**。证据在 `src/session_settlement.cc:1692` 注释与 1738~1744：
未绑定的无手框一律 `result=no-auto-in`。当初这样设计是为了防误入库，但它太保守——
凡是有手期没能建立 D 链的新物品，无手期一律不补，于是产生下面的鸡蛋盒缺口。
**本次就是要在保持防误入库的前提下，给无手期加上"补 IN / 补 OUT"的能力。**

鸡蛋盒问题（见《测试后的结果与发现的问题.md》）正撞在这里：手抓透明盒边缘放入，
6 个鸡蛋里只有贴到手框的 2 个在有手期建立了 D suspect（`hand_visible_d`，
`session_hand.cc:2410`），其余 4 个在无手期被 `reject=outside-hand-track`
（`session_no_hand.cc:195`），最终只 IN 了 2 个。整盒取走同理会漏 OUT。

**根因不是 bug，是设计边界**：系统只承认"被手碰过"的新物品；隔着盒子放入时多数
鸡蛋没碰到手。补登记就是为这条边界提供**第二条独立证据来源**：画面静止后，
"稳定、同类、同位置、同大小、高分、且无法归属任何已有物品/D 的框"本身就是可靠证据。

**为什么"无手宽松"是安全的（设计直觉）**：有手期严，是因为手在动、物在移、遮挡在变，
动态过程易误判。无手期画面静止，"连续多帧同位置同类同大小高分"反而是**强证据**。
所以补登记不是"降低警惕"，而是"利用静止稳定性拿到有手期拿不到的另一种可靠证据"。

## 2. 机制设计

### 2.1 触发时机与位置

只在 `SessionManager::settle_no_hand_operation_`（`session_settlement.cc`）里、
**当前所有既有结算完成、`has_unresolved_state==false`、事件即将生成之前**，插入一个
新步骤 `apply_no_hand_correction_()`。它对两类残余做补登记：

- **补 IN**：本帧无手快照里存在、连续 N 帧稳定、却 `observation_owner[si] < 0`
  （未绑定给任何 item，即现在打印 `no-auto-in` 的那些框）；
- **补 OUT**：`operation_start_inventory_` 里存在、但连续 N 帧无手快照中确实缺失、
  且**没有任何遮挡解释**的 item。

**关键：它绝不改有手期。** 有手期照常运行、照常建立它能建立的 IN/OUT/遮挡；补登记
只处理"有手期没能定论"的残余，是纯增量兜底。

### 2.2 "本轮操作确有手进入过"这个前提天然成立

补登记只在一个 active operation 的无手结算里执行。而 operation 只会由
`begin_working_operation_` 创建，后者只在检测到手时被调用（`session.cc:484~485`）。
因此"纯静止、从未有手进入过的画面"根本不会进入带 active operation 的无手结算 →
**补登记天然不会在纯背景场景触发**。这条红线由现有生命周期免费保证，无需额外判断。

### 2.3 补 IN 的准入条件（必须全部满足）

一个未绑定的无手框 B 要补 IN，必须同时满足：

1. **稳定连续**：连续 ≥ `FLOW3_NOHAND_CORRECT_FRAMES`（=3）帧，在几乎同一位置出现
   同 cls_id、框大小接近的框（用既有 `track_match_box` / 中心归一化 + 宽高比阈值判断，
   不新造几何判据）。单帧或双帧幻影不够。
3 帧比 2 帧更能排除 YOLO 偶发双帧幻影（用户已确认接受 3 帧的延迟）。
2. **高分**：`score >= YOLO_OBJECT_SCORE_THRESH`（复用既有物品阈值，不额外放宽）。
3. **无法归属任何已有物品/D**：不 `strict_match`/`track_match` 任何 `working_inventory_`
   项，不属于任何活动 runtime / suspect（即它确实是"多出来的"，不是某个已有项的观察）。
4. **不与任何已登记框高度重叠**（排除"同一物体的重复/误分类框"）：与任何已被绑定的
   观察框、以及任何其它补 IN 候选框，IoM < `RECLS_DEDUP_IOM_THRESH`（复用细节31 去重阈值
   的同一把尺）。**这条专门挡住"稳定误分类"**——例如一个苹果被稳定识别成 apple+onion，
   那个 onion 框满足条件 1/2 却会因为与 apple 框高度重叠而在此被拒。
5. **互不重叠的多个候选可同时补**：整盒 6 个鸡蛋是 6 个互不重叠的独立框，各自独立满足
   1~4，就各自补一个 IN；这不是"一个物体多个框"。

补 IN 落地：为每个通过的 B 分配新 item_id、以其当前框为 base_box、`status=VISIBLE`，
生成 `EventKind::IN` 事件（与现有 IN 事件同源，带截图上云路径不变）。

### 2.4 补 OUT 的准入条件（必须全部满足）

一个 `operation_start_inventory_` 里的 item C 要补 OUT，必须同时满足：

1. **连续缺失**：连续 ≥ `FLOW3_NOHAND_CORRECT_FRAMES`（=3）帧，无手快照中都没有能
   匹配 C 的框（同类、位置/大小可匹配）。
2. **无遮挡解释**：C 当前不是 `OCCLUDED`，且本事务的 `transition_plans` 没有给它任何
   遮挡/HOLD 计划，也不在 `pending_occlusion_*` 证据链里。**被遮挡的物品绝不能补 OUT。**
3. **不在既有 OUT 流程内**：不在 `pending_out_ids_` / `confirmed_moved_ids_`（避免与
   既有出库/整理结论重复或冲突）。
4. **本轮确有手活动**：由 §2.2 天然保证。

补 OUT 落地：从 `final_items` 移除该 C，生成 `EventKind::OUT` 事件（与现有 OUT 同源）。

### 2.5 与既有机制的先后顺序（避免打架）

补登记是**最后一道**，必须在以下都跑完之后才执行，且只处理它们的"残余"：

- 既有 IN（`pending_in_ids_`）、MOVED（`confirmed_moved_ids_`）、OUT（`pending_out_ids_`）；
- 遮挡/露出 lifecycle plan（`transition_plans`）与 `HOLD_FOR_PENDING_OCCLUSION`；
- reclassify 纠正 + 纠正后同类去重（发生在更上游的 main.cc，进入业务层的已是干净框）。

即：**凡是被上述任何机制解释掉的框/物品，补登记都不再碰。** 它只对"谁都没解释"的
残余下手。这保证它是纯增量，不会覆盖或改写任何既有结论。

### 2.6 "连续 N 帧"的状态怎么记

补 IN/OUT 都需要跨无手帧的连续计数。不要新造一套复杂结构，复用现有做法：

- 在 SessionManager 里加两个轻量 map（仅本 operation 生命周期内有效，
  `begin_working_operation_` / 提交后 `reset_operation_runtime_` 处清空）：
  - `nohand_correct_in_streak_`：key 为候选框的稳定标识（用"上一帧候选框 + 类别"做
    连续匹配，匹配上则 ++，匹配不上则重置为 1，逻辑与既有 `update_reappear_candidate`
    同型），value 为连续帧数与最近框。
  - `nohand_correct_out_streak_`：key 为 item_id，value 为连续缺失帧数。
- 只有连续计数达到 `FLOW3_NOHAND_CORRECT_FRAMES` 才在**当帧**执行补登记；未达到则
  和现在一样 `defer-commit`（仅多等 1~2 帧，符合用户预期）。
- 计数每类证据每帧只推进一次（对齐现有 `update_pending_occlusion_evidence_` 的
  单调推进原则），防止一帧被算成多帧。

### 2.7 全局开关

`FLOW3_NOHAND_CORRECTION_ENABLED`（默认 true）。置 false 立即回到当前行为
（无手不补 IN/OUT），用于演示前对照排查、或万一现场异常时快速回退。

## 3. 为什么这不会把原功能改坏（逐条对照最高约束）

- **有手期零改动**：新逻辑只在无手结算末尾、事件生成前插入一个函数，有手期代码不动。
- **纯增量**：只处理"既有机制全都没解释"的残余；被 IN/OUT/MOVED/遮挡解释过的一律不碰。
- **防误入库不被削弱**：补 IN 要求 §2.3 全部 5 条（稳定+高分+无法归属+不重叠+独立），
  比"看得见 2 帧"严得多；尤其第 4 条用去重同一把尺挡住"稳定误分类框"。
- **防误出库不被削弱**：补 OUT 明确排除遮挡（§2.4 第 2 条），被遮挡物品绝不 OUT。
- **纯背景不触发**：§2.2 由 operation 生命周期天然保证。
- **原子提交不变**：补登记只是往同一批 `final_items` / events 里增删，仍走原有
  `replace_all()` 一次性提交，不新增提交点、不让任何物品抢先提交。

**残余风险（如实列出，验证时重点盯）：**

- 若某次真的有"稳定 3 帧、高分、不与任何框重叠、又非任何已有物品"的误检（例如一个
  从未训练、反复误报成某类的背景物），补 IN 会误登记。缓解：3 帧 + 高分 + §2.2 限定
  在有手操作窗口内，已大幅压低概率；演示前可用 `FLOW3_NOHAND_CORRECTION_ENABLED` 兜底。
- 若一个物品被手拿在空中、YOLO 连续多帧漏检其原位，补 OUT 可能早判。缓解：补 OUT 要求
  "无任何遮挡/HOLD 计划且不在既有 OUT 流程"，且 3 帧连续缺失；正常整理/遮挡都会先被既有
  机制接管，轮不到补 OUT。

## 4. 实施落点小结（供改代码时对照）

- **新增开关/阈值**：`include/fridge_config.h`（见 §5）。
- **新增函数**：`session_settlement.cc` 内 `apply_no_hand_correction_()`，在
  `settle_no_hand_operation_` 里、`has_unresolved_state` 判定通过之后、生成 events 的
  循环之前调用。补 IN 追加到 events + `final_items`；补 OUT 从 `final_items` 移除并追加
  OUT event。
- **新增连续计数状态**：`include/session.h` 的 SessionManager 私有成员两个 map，
  在 `begin_working_operation_` 与提交后 `reset_operation_runtime_` 处清空（对齐现有
  `pending_occlusion_*` 的清理点）。
- **不动**：所有 `session_hand.cc`（有手期）、reclassify、去重、遮挡 proof、全局归属。

## 5. 超参数（集中在 fridge_config.h，演示前可自行调）

```cpp
// 无手期后手矫正（补登记）总开关。置 false 立即回到"无手不补 IN/OUT"的当前行为。
constexpr bool  FLOW3_NOHAND_CORRECTION_ENABLED = true;
// 补 IN / 补 OUT 都要求的连续稳定帧数。3 比 2 更能排除 YOLO 双帧幻影；
```

若实现中确需再引入常量，必须回填本文件并登记到 `超参数位置与调节说明.md`。

## 6. 验证方式（改完必须做，缺一不可）

1. **新增针对性主机回放**（放 `tests/`，参照 `session3_replay_no_hand.cc` 结构）：
   - 整盒放入：初始空库存，有手帧手只碰到部分同类框，无手后 6 个互不重叠同类框稳定
     ≥3 帧 → 断言补出 6 个 IN，库存=6，无重复。
   - 整盒取走：初始 6 个同类在库，有手后无手快照持续为空 → 断言补出 6 个 OUT，库存=0。
   - **反向守护 A（稳定误分类不误 IN）**：一个位置上稳定同时出现 apple 框与 onion 框
     （高 IoM）→ 断言只保留/登记 1 个，另一个被 §2.3 第 4 条拒，不产生多余 IN。
   - **反向守护 B（遮挡不误 OUT）**：一个 item 被确认前景物遮挡（细节29 场景）→ 断言
     它进入 OCCLUDED 而**不是**被补 OUT。
   - **反向守护 C（纯静止不触发）**：构造一个未激活 operation 的静止序列，画面里有框
     → 断言不产生任何补 IN/OUT（由 §2.2 保证）。
2. **回归全套现有主机回放**：`session3_replay_basic / hand_contact / no_hand / ownership`
   全过；逐行比对：开启补登记前后，**不涉及补登记的场景其 events/commit 必须完全一致**
   （证明纯增量、对既有场景零影响）。
3. **ASAN/UBSAN 回放**通过。
4. 板端实测：整盒鸡蛋放入 → 6 个 IN；从中取走 2 个 → 2 个 OUT；整盒取走 → 全部 OUT。
   并复跑单手/双手 入/出/整理/遮挡，确认既有行为无退化。同时验证
   `FLOW3_NOHAND_CORRECTION_ENABLED=false` 能干净回退。

只有全部通过才算闭环。任何一项失败都回到根因，不允许为凑过断言而放宽 §0 禁止的任何条件。

## 7. 一句话交接

在无手结算的**最后、生成事件之前**加一个 `apply_no_hand_correction_()`：对"既有 IN/OUT/
MOVED/遮挡全都没解释"的残余，用"连续 3 帧稳定 + 高分 + 无法归属 + 不与已登记框重叠"补 IN，
用"连续 3 帧缺失 + 无任何遮挡解释 + 不在既有 OUT 流程"补 OUT。有手期一行不改，纯增量，
纯静止场景天然不触发，被遮挡物绝不 OUT，稳定误分类框被去重同尺挡住。开关默认开，可一键回退。
