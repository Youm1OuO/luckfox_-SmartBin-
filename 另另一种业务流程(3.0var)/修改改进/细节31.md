## 0.5 架构定位（v2 核心，整份文档的灵魂）

**有手期与无手期是两个独立的"工作部门"，不是一条流水线的上下游。**

- **有手期 = 主力操作部门。** 入库、出库、整理、遮挡，能处理的都在这里以完整证据处理。
  正常情况下有手期一一匹配、把该做的都做完，无手期无事可做。这部分逻辑本次**一行不改**。
- **无手期补登记 = 独立质检部门（兜底）。** 它只在手离开、画面静止后，拿**无手静态快照**
  与**当前工作库存**做一次对比，修正两者的不一致：
  - 快照里有、库存里没有（配不上任何库存物品）的框 → **补 IN**；
  - 库存里有、快照里连续缺失（配不上任何快照框）、且状态仍是【可见】的物品 → **补 OUT**；
  - "整理没被判对"会自然表现为"旧位置 OUT + 新位置 IN"，兜底同时补齐。

**两条铁律（v2 与首版的根本区别）：**

1. **无手质检不查询、不依赖任何有手期轨迹信息。** 具体就是：补登记路径**绝不调用**
   `detection_can_belong_to_active_track` / `estimated_box` / `track[]` / reappear 路径
   这一类"这个框像不像某条有手期轨迹"的判断。首版正是栽在这里——有手期只建了 4 条
   鸡蛋轨迹，第 5、6 个鸡蛋的框因为"位置沾到某条轨迹的移动路径"被判成"已有轨迹的抖动"
   而 `reject=active-track`，于是无手期跟着有手期一起漏。v2 把这层耦合从补登记路径里
   彻底摘掉。

2. **判据只用无手快照自身 + 库存，用"双向严格匹配消解"（见 §2.3）。** 不再"逐个未绑定框
   问它属于谁"，而是把快照框与库存物品双向匹配：能配上的成对消掉，快照剩下的余数补 IN、
   库存剩下的余数补 OUT。

**信任 YOLO 的前提（用户明确）：** 站在"YOLO 输出基本可信"的立场——允许偶发一两帧抖动，
但不会持续错。因此"同一物体被分裂成两个框"这类**YOLO 侧的错误由 YOLO 侧负责**，业务层
不为它设计复杂防御；偶发分裂靠"连续 N 帧稳定"这一条自然滤除。同位置双框（egg/orange、
apple/onion）用户已在 reclassify + 去重里手动处理，此处不再重复考虑。

## 1. 背景与现状（已核实代码）

> ⚠️ **本节描述的是"改动之前的老行为 / 待打破的现状"，不是本次要遵守的规矩。**
> 本次新增的补登记机制（见 §2）正是用来打破下面这条老限制的——把有手期没能入库/出库的
> 物品，在无手期补回来。

**改动前的老行为（缺口所在）**：3.0 现状下，无手结算**只结算有手期已经建立的结论，
自身从不产生新的 IN**。证据在 `src/session_settlement.cc:1692` 注释与 1738~1744：
未绑定的无手框一律 `result=no-auto-in`。当初这样设计是为了防误入库，但它太保守——
凡是有手期没能建立 D 链的新物品，无手期一律不补，于是产生下面的鸡蛋盒缺口。
**本次就是要在保持防误入库的前提下，给无手期加上"补 IN / 补 OUT"的能力。**

鸡蛋盒问题（见《测试后的结果与发现的问题.md》）正撞在这里：手抓透明盒边缘放入，
6 个鸡蛋里只有贴到手框的 2 个在有手期建立了 D suspect（`hand_visible_d`，
`session_hand.cc:2410`），其余 4 个在无手期被 `reject=outside-hand-track`
（`session_no_hand.cc:195`），最终只 IN 了 2 个。整盒取走同理会漏 OUT。

**根因不是 bug，是设计边界**：系统只承认"被手碰过"的新物品；隔着盒子放入时多数
鸡蛋没碰到手。补登记就是为这条边界提供**第二条独立证据来源**：画面静止后，
"稳定、高分、在手活动区域内、且与工作库存双向匹配都配不上的框"本身就是可靠的新物品证据。

**为什么"无手宽松"是安全的（设计直觉）**：有手期严，是因为手在动、物在移、遮挡在变，
动态过程易误判。无手期画面静止，"连续多帧同位置同类同大小高分"反而是**强证据**。
所以补登记不是"降低警惕"，而是"利用静止稳定性拿到有手期拿不到的另一种可靠证据"。

## 2. 机制设计

### 2.1 触发时机与位置

只在 `SessionManager::settle_no_hand_frame_`（`session_settlement.cc`）里、
**当前所有既有结算完成、`has_unresolved_state==false`、事件即将生成之前**，插入一个
新步骤 `apply_no_hand_correction_()`。它对 §2.3 双向匹配后的两类"余数"做补登记：

- **补 IN**：无手快照里的框，两轮匹配都配不上任何库存物品（快照余数），且连续 N 帧稳定；
- **补 OUT**：工作库存里的物品，两轮匹配都没被任何快照框配上（库存余数），且状态为【可见】。

**关键：它绝不改有手期。** 有手期照常运行、照常建立它能建立的 IN/OUT/遮挡；补登记
只处理"有手期没能定论"的余数，是纯增量兜底。

### 2.2 "本轮操作确有手进入过"这个前提天然成立

补登记只在一个 active operation 的无手结算里执行。而 operation 只会由
`begin_working_operation_` 创建，后者只在检测到手时被调用（`session.cc:484~485`）。
因此"纯静止、从未有手进入过的画面"根本不会进入带 active operation 的无手结算 →
**补登记天然不会在纯背景场景触发**。这条红线由现有生命周期免费保证，无需额外判断。

### 2.2.5 "快照"用什么？——当前帧的 YOLO 结果，不做 N 帧投票合成（性能关键）

本机制里的"无手快照"**就是当前这一帧的 YOLO 物品框**，直接拿来和工作库存比，
**不模仿 2.0 那种"攒 N 帧投票融合成一个平均快照"**。原因：

- 3.0 是逐帧架构，**每帧本来就在跑 YOLO + 结算**，当前帧的框随手就有，无需额外攒帧；
- 稳定性由 §2.3.2 / §2.4 的**"连续 N 帧确认"**（时间维度）保证，等价于投票的"去抖"目的，
  但**省掉了"融合 3 帧的框"那步额外计算**——所以逐帧比更快，不是更慢；
- 补 IN 时用**当前帧那个最新框**当 `base_box`（比合成的平均框更贴近真实最新位置）。

计算量：每个无手帧只做 1 次"快照框 × 库存物品"的几何比较（约 M×N，物品个位/十几个 →
几十上百次浮点比较，微秒级），远小于一次 YOLO 推理，也比有手期既有的费用流/多轮结算轻。
"连续 N 帧"只是维护一个计数器，不存历史帧、不投票。

### 2.3 补登记的核心判据（v2：无手快照 ↔ 工作库存的双向严格匹配消解）

**思路（对齐 §0.5，用户明确）**：无手质检不"数个数"，而是把**无手静态快照**与**工作库存**
做一次**双向匹配消解**——能配上对的成对消掉（确认物品还在），配不上的"余数"就是变化：
快照剩下的框 → 补 IN，库存剩下的物品 → 补 OUT。整个过程**只用快照 + 库存，绝不查询任何
有手期轨迹**（不调 `detection_can_belong_to_active_track` / `estimated_box` / `track[]`）。

**两条身份铁律（务必遵守）：**
- **快照框是匿名的，没有 item_id；item_id 只属于库存物品。** 因此匹配全程**只用几何**
  （cls_id + 中心距 + 宽高差 / IoM），**绝不用 item_id 去配**。item_id 只在两处出现：
  补 IN 结尾给新物品**分配一个新 id**（`working_next_item_id++`）；补 OUT 时**用老物品自己
  的 id** 发事件。中间的匹配/消解全程不碰 item_id。
- **匹配用工作库存物品的 `base_box`**（有手阶段结算后可信的完整位置；用户已同意），
  不用可能是中间态的 `box`。

匹配定义见《另另一个版本.md》，直接复用既有函数：
- **严格匹配**（`strict_match`）= 同 cls_id + 中心距离够近 + 框宽差够小 + 框高差够小。
- **局部匹配**（`partial_match_box`）= 同 cls_id + IoM 足够接近 1（一个框基本包含另一个，
  处理"露一部分/被压住"）。

**匹配顺序（关键，务必遵守）——先全局做完严格，再对剩余做局部；每轮都只接受"双向唯一"：**

第 1 轮 · **全局严格匹配，只接受双向唯一配对。** 把**所有**快照框与**所有**库存物品
（用 base_box）两两求严格匹配候选。**只有当"某库存项 A 唯一严格匹配某快照框 B、且 B 也
唯一严格匹配 A"时才绑定**；若 A 有多个候选框、或某框够得上多个库存项（同类挤在一起时
常见），则**该项/该框本轮保持未决，绝不按位置或顺序硬配**。所有双向唯一的先全部配掉。
> 不能"逐框先试严格再试局部"——否则某个框可能用局部匹配抢先占掉了另一个框本该严格
> 配对的库存项。严格匹配是全局第一优先级，必须整轮做完。

第 2 轮 · **对第 1 轮的剩余做局部匹配，同样只接受双向唯一。** 只在"严格没配上的快照框"
和"严格没配上的库存项"之间做局部匹配，再配掉一批（仍要求双向唯一）。这一轮吸收
"框大小略变、被部分压住"的情况，避免误判成"消失 + 新增"。

第 3 步 · **处理两边的余数：**
- **快照里仍未配对的框 → 补 IN 候选**（快照有、库存没有 → 新入库的）；
- **库存里仍未配对的物品 → 补 OUT 候选**（库存有、快照没有 → 被拿走的）。

**补 IN / 补 OUT 候选还要各自通过 §2.3.2 / §2.4 的安全准入**（手活动区域、连续 N 帧、
遮挡否决等），通过后才真正补登记。整理没被有手期判对，会自然表现为"旧位置库存余数→OUT
+ 新位置快照余数→IN"，兜底同时补齐。

**与首版的关键区别：** 判据从"逐框问它属于哪条有手期轨迹"彻底换成"快照↔库存双向匹配"。
第 5、6 个鸡蛋即使位置靠近有手期某条轨迹的移动路径，只要它在快照里配不上任何现有库存项，
就是快照余数 → 补 IN。这就是 §0.5 铁律 1 的落地。

#### 2.3.2 补 IN 候选的安全准入（在"快照余数框"之上再过滤）

一个"快照余数框"要真正补 IN，还需满足（都只用快照自身信息，信任 YOLO）：

- **高分**：`score >= YOLO_OBJECT_SCORE_THRESH`（复用既有物品阈值）；
- **落在本轮手活动区域内**（见 §2.3.1）：与手活动区域 IoM ≥
  `FLOW3_NOHAND_CORRECT_REGION_IOM`。手没去过的地方冒出来的框不补（挡住远处背景）；
- **连续 ≥ `FLOW3_NOHAND_CORRECT_FRAMES`（=3）帧稳定**：连续多帧都作为"快照余数"稳定
  出现在几乎同一位置（用既有 `track_match_box` 判连续）。偶发一两帧的 YOLO 抖动/分裂
  自然被这条滤掉——信任 YOLO，不为持续性以外的错误做额外防御。

通过后：为该框分配新 item_id、以其框为 `base_box`、`status=VISIBLE`、发 `EventKind::IN`
（与现有 IN 事件同源，带截图上云路径不变）。

#### 2.3.1 "手活动区域"的定义

- 本轮 operation 从 `begin_working_operation_` 开始，累积**每一帧出现过的所有手框**
  （不是只取最后一帧、也不是只取一只手）。
- 每个手框在纳入时**按自身宽/高向外扩一圈**：每边扩 `FLOW3_NOHAND_CORRECT_HAND_MARGIN_RATIO`
  （=0.20，即宽高各放大约 40%）。用比例而非固定像素，手离相机远近都稳（与既有
  `OSD_STRONG_HAND_MIN_AREA_RATIO` 等按比例的风格一致）。
- 判定"B 是否落在手活动区域内"= B 与"任一扩圈手框"的 IoM ≥ `FLOW3_NOHAND_CORRECT_REGION_IOM`
  （满足任意一个即算命中，因为鸡蛋只需落在手掠过的某一处）。
- 实现上不必真的合并成一个复杂多边形，逐个扩圈手框做 IoM 取最大即可。

### 2.4 补 OUT 候选的安全准入（在"库存余数物品"之上再过滤）

一个 `operation_start_inventory_` 里的 item C 成为"库存余数"（§2.3 两轮匹配都没被任何
快照框配上）后，要真正补 OUT，还必须同时满足：

1. **消失位置在本轮手活动区域内（与补 IN 同一把尺）**：C 的 `base_box` 与"手活动区域"
   （§2.3.1）的 IoM ≥ `FLOW3_NOHAND_CORRECT_REGION_IOM`。手去动过那个位置，东西才可能
   被拿走；手从没去过的地方东西突然不见，更可能是遮挡或漏检，不该轻易判 OUT。
2. **连续缺失**：连续 ≥ `FLOW3_NOHAND_CORRECT_FRAMES`（=3）帧，C 都是"库存余数"
   （两轮匹配都配不上）。偶发一帧漏检不算。
3. **遮挡判定：绝大多数"读现成状态"，只对"悬而未决的 HOLD"额外看一眼老位置**。
   分三种情况处理 C（按现成状态分派，快路径为主）：
   - **`status == OCCLUDED`（已确认遮挡）→ 不补 OUT。** 直接读现成状态，不重算。
     一个【遮挡】物品快照看不见很正常，它还在库里。
   - **普通 `status == VISIBLE`、且不处于遮挡待确认 → 可补 OUT。** 逻辑闭环（用户洞察）：
     一个本该看得见的【可见】物品，快照里却连续看不见 → 就是被拿走了。
   - **悬而未决的 `HOLD_FOR_PENDING_OCCLUSION`（有手期怀疑被遮挡但没确认，`status` 仍为
     VISIBLE）→ 必须额外看一眼"老位置在快照里空不空"再决定**：
     - 因为这个 HOLD 到无手期不会再有新信息确认，会一直挂着；一刀切"不动"会让真被拿走
       的永远卡住，一刀切"OUT"会误删真被挡住的。所以只对这种物品破例做一次轻量几何：
     - 看 C 的 `base_box` 在当前快照里**是否被任一"未匹配上库存的框"覆盖**
       （用既有 `iom()` / 交集判断）：**被覆盖 → 真被挡住 → 不 OUT**；
       **老位置空了（无框覆盖）→ 确实不见了 → 可补 OUT**。
     - 这只在 HOLD 物品上做，数量极少（通常 0 个），性能可忽略；普通物品仍走上面的
       "读状态"快路径，不做任何额外几何。
   > 依据：有手阶段已把遮挡结论写进工作库存状态（实测打印基本正确），读它是安全的；
   > 唯独 HOLD 这个中间态 `status` 不可靠（仍是 VISIBLE），才需看一眼几何来区分
   > "真被挡住"与"其实被拿走"。这不是"把遮挡判断重做一套"，而是只为一个悬而未决的
   > 中间态补一次最小判断。
4. **不在既有 OUT 流程内**：不在 `pending_out_ids_` / `confirmed_moved_ids_`（避免与
   既有出库/整理结论重复或冲突）。
5. **本轮确有手活动**：由 §2.2 天然保证。

补 OUT 落地：从 `final_items` 移除该 C，生成 `EventKind::OUT` 事件（与现有 OUT 同源）。

### 2.5 与既有机制的先后顺序（避免打架）

补登记是**最后一道**，必须在以下都跑完之后才执行，且只处理它们的"残余"：

- 既有 IN（`pending_in_ids_`）、MOVED（`confirmed_moved_ids_`）、OUT（`pending_out_ids_`）；
- 遮挡/露出 lifecycle plan（`transition_plans`）与 `HOLD_FOR_PENDING_OCCLUSION`；
- reclassify 纠正 + 纠正后同类去重（发生在更上游的 main.cc，进入业务层的已是干净框）。

即：**凡是被上述任何机制解释掉的框/物品，补登记都不再碰。** 它只对"谁都没解释"的
残余下手。这保证它是纯增量，不会覆盖或改写任何既有结论。

### 2.6 "连续 N 帧"的状态怎么记

补 IN/OUT 都需要跨无手帧的连续计数。不要新造一套复杂结构，复用现有做法：

- 在 SessionManager 里加轻量状态（仅本 operation 生命周期内有效，
  `begin_working_operation_` 起累积、提交后 `reset_operation_runtime_` 处清空）：
  - `hand_activity_boxes_`：`std::vector<BBox>`，累积本轮每帧出现过的手框（已扩圈或
    在判定时扩圈皆可；建议存原始框、判定时统一扩，避免重复放大）。每有手帧就把当帧
    手框追加进来。
  - `nohand_correct_in_streak_`：**快照余数框**的连续稳定记录。每个元素记 {类别, 最近框,
    连续帧数}。每张无手帧先做 §2.3 的两轮匹配得到"快照余数框"，再把这些余数框按
    "上一帧余数框 + 类别"连续匹配：匹配上则 ++、更新框；匹配不上则作为新余数从 1 开始。
    **这一步只看快照 + 库存，不查任何有手期轨迹。**
  - `nohand_correct_out_streak_`：key 为 item_id，value 为"连续作为库存余数（配不上）"的帧数。
- 补登记在达标帧执行：连续帧数已达 `FLOW3_NOHAND_CORRECT_FRAMES` 的余数框才补 IN、
  余数物品才补 OUT。只要还有余数在攒证据（连续帧数未达标）就 `defer-commit` 再等一帧
  （仅多等 1~2 帧，符合用户预期）。
- 计数每类证据每帧只推进一次（对齐现有 `update_pending_occlusion_evidence_` 的
  单调推进原则），防止一帧被算成多帧。

### 2.7 全局开关

`FLOW3_NOHAND_CORRECTION_ENABLED`（默认 true）。置 false 立即回到当前行为
（无手不补 IN/OUT），用于演示前对照排查、或万一现场异常时快速回退。

### 2.8 与既有测试 `test_unbound_no_hand_box_never_auto_in` 的关系

现有回放 `tests/session3_replay_no_hand.cc` 里的
`test_unbound_no_hand_box_never_auto_in`：手只碰左侧旧苹果，远处一个稳定橙子，
断言橙子**绝不自动 IN**。

**好消息：v2 的"手活动区域"钥匙让这条测试原样通过，无需改写。** 那个橙子在画面远处，

自然不补。它想守护的红线（"手没去过的地方不补"）正是 v2 的核心判据，二者一致。

## 3. 为什么这不会把原功能改坏（逐条对照最高约束）

- **有手期零改动**：新逻辑只在无手结算末尾、事件生成前插入一个函数，有手期代码不动。
- **纯增量**：只处理"既有机制全都没解释"的残余；被 IN/OUT/MOVED/遮挡解释过的一律不碰。
- **无手期与有手期解耦（v2 核心）**：补登记路径**不调用** `detection_can_belong_to_active_track`
  等有手期轨迹判断，只用无手快照 + 库存做双向严格匹配消解。有手期没配上的，无手期不再跟着漏。
- **防误入库靠"手活动区域"这把精确钥匙**：补 IN 候选（快照余数框）还要过"落在本轮手
  实际动过区域内 + 高分 + 连续 3 帧稳定"。手没去过的地方冒出来的框不补（挡远处背景）。
  背景假框由 YOLO 侧负责，业务层不重复防御。
- **防误出库不被削弱（大多读现成状态，HOLD 才看一眼几何）**：补 OUT 按 §2.4 第 3 条三分派——
  `OCCLUDED` 绝不 OUT（读现成状态）；普通 `VISIBLE` 才可 OUT；唯独"遮挡待确认 HOLD"
  （status 仍 VISIBLE、会一直挂着）额外看"老位置在快照里是否被框覆盖"，被覆盖不 OUT。
  普通物品**不重算遮挡**（不查 transition_plans/pending_occlusion 那整套中间链），只有极少的
  HOLD 物品做一次轻量覆盖检查——既快又能区分"真被挡住"与"其实被拿走"，不误删被遮挡物。
  且消失位置须在手活动区域内。
- **纯背景不触发**：§2.2 由 operation 生命周期天然保证（纯静止画面无 active operation）。
- **原子提交不变**：补登记只是往同一批 `final_items` / events 里增删，仍走原有
  `replace_all()` 一次性提交，不新增提交点、不让任何物品抢先提交。

**残余风险（如实列出，验证时重点盯）：**

- 若 YOLO **持续**（≥3 帧）把某个位置误报成一个独立的高分同类框、又恰好在手区域内，
  会误补 1 个。但按"信任 YOLO、偶发抖动不持续"的前提，这属于 YOLO 侧问题；连续 3 帧
  稳定已滤除偶发分裂；现场可用 `FLOW3_NOHAND_CORRECTION_ENABLED` 兜底。
- 若一个物品被手拿在空中、YOLO 连续多帧漏检其原位，补 OUT 可能早判。缓解：补 OUT 要求
  物品状态是【可见】（被遮挡的读现成状态即挡住）、3 帧连续配不上、且消失位置在手活动
  区域内、不在既有 OUT 流程；正常整理/遮挡都会先被既有机制接管，轮不到补 OUT。

## 5. 超参数（集中在 fridge_config.h，演示前可自行调）

```cpp
// 无手期后手矫正（补登记）总开关。置 false 立即回到"无手不补 IN/OUT"的当前行为。
constexpr bool  FLOW3_NOHAND_CORRECTION_ENABLED = true;
// 补 IN / 补 OUT 都要求的连续稳定(或连续缺失)帧数。3 比 2 更能排除 YOLO 双帧幻影；
// 代价是比正常慢 1~2 帧。演示前可试 2 或 3。
constexpr int   FLOW3_NOHAND_CORRECT_FRAMES = 3;
// "手活动区域"外扩比例：每个手框按自身宽/高各边外扩此比例(0.20=宽高各放大约 40%)。
// 用比例而非固定像素，手离相机远近都稳。放大可覆盖盒子边缘的物品，过大则纳入过多背景。
constexpr float FLOW3_NOHAND_CORRECT_HAND_MARGIN_RATIO = 0.20f;
// 候选框与"手活动区域"的重叠判据(IoM)。>= 此值算"大部分落在手动过的地方"。
// 用 IoM 而非"框中心落入"，对"物品一半探出手区"更稳。补 IN 和补 OUT 用同一把尺。
constexpr float FLOW3_NOHAND_CORRECT_REGION_IOM = 0.50f;
```

- **严格匹配**用既有 `strict_match` / `strict_match_box`（阈值

- `YOLO_OBJECT_SCORE_THRESH`（补 IN 高分门槛）、`track_match_box`（判连续）、`iom()`（手区域）。

即匹配判据全部复用既有函数与阈值，**不新增匹配相关常量**；本次只新增上面 4 个

## 7. 一句话交接

**无手期 = 独立质检部门（v2）。** 在无手结算的最后、生成事件之前加一个补登记步骤，
只拿**无手静态快照 vs 工作库存**做**双向严格匹配消解**，**绝不查询有手期轨迹**
（不调 `detection_can_belong_to_active_track` 那套）。**快照框匿名、无 item_id——匹配全程
纯几何、不用 item_id**（item_id 只在补 IN 结尾分配、补 OUT 用老 id 发事件）。匹配顺序：
先对所有快照框与库存（用 `base_box`）做**全局严格匹配**（既有 `strict_match`），剩余的再做
**局部匹配**（既有 `partial_match_box`），**每轮只接受双向唯一配对，有歧义就留着不硬配**；
两轮都配不上的：快照余数 → 补 IN，库存余数 → 补 OUT。这样"整盒挤着放、有手期只数到 4 个"，
剩下 2 个在快照里配不上任何库存项，就补齐到 6 个。补 IN 余数再叠"高分 + 手活动区域内 +
连续 3 帧稳定"；补 OUT 余数再叠"连续 3 帧配不上 + 消失位置在手区域内 + **遮挡三分派**"：
`OCCLUDED` 不 OUT、普通 `VISIBLE` 可 OUT、`HOLD_FOR_PENDING_OCCLUSION` 则额外看"老位置在
快照里有没有被框压着"（压着不 OUT、空了才 OUT，专治 HOLD 永远卡住）——绝大多数读现成状态，
只有极少 HOLD 才做一次轻量几何。有手期一行不改，纯增量，纯静止不触发，信任 YOLO（偶发分裂
靠 3 帧稳定滤除）。**本次是把已有那版无手纠正就地改对、复用骨架、删掉旧分支，不新增平行结构。**
开关 `FLOW3_NOHAND_CORRECTION_ENABLED` 默认开、可一键回退。既有测试全部原样通过，只新增用例。
