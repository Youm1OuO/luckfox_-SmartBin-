# 单摄像头下同类合并框的可见实例结算

> 本文是对细节 8 的补充。若两者冲突，以细节 9 为准。
>
> 覆盖范围必须严格限定：细节 9 只改变“手已离开后，同一 cls_id 的旧物品
> 数量大于可见检测框数量”这一最终结算规则。它不推翻细节 8 对有手阶段、
> 同类新 D、防重复入库、两个独立框时的 C 到 B 身份匹配的要求。

## 1. 新确认的业务前提

系统只有单摄像头和单帧目标检测框，没有第二视角、重量、深度或 RFID 等额外
信息。因此，两个外观相近且 cls_id 相同的物品真正重叠时，画面可能只留下一个
检测框。

在这种情况下，单摄像头无法可靠回答下面的问题：

    这个框代表一个物品，
    还是两个同类物品恰好重叠后的合并可见结果？

继续要求程序保留每一个不可观察的物理个体身份，会导致无法结束的未决操作。
这正是当前“两个相邻苹果/橙子，拿走一个后永远不 OUT”的根本原因。

本版本采用明确的业务决定：

    在最终无手结算中，同一 cls_id 的一个可靠可见检测框，
    按一个可见物品处理。

换言之，库存的这一部分以单摄像头实际可见的实例数量为准，而不是试图猜测
检测框背后是否还存在肉眼和摄像头都无法区分的第二个同类物品。

这是一条有意识的业务语义，不是通过放宽或收紧几何阈值得出的偶然结果。

## 2. 细节 8 中需要被覆盖的局部规则

细节 8 的目标是防止同一个旧 C 被保留、同时又被当作新 D 入库。这个目标仍然
完全保留。

但细节 8 的下列结论不再适用于本节定义的最终无手数量不足场景：

    两个同类旧 C 都可能解释同一个最终 B
    -> 永远保持 UNRESOLVED
    -> 不允许任何 C OUT

此前的回放用例 test_same_class_merged_box_keeps_active_a_unresolved 正是在验证上述
旧策略。它必须改为新的可见实例结算用例，不能继续把“永久未决”当作正确结果。

新的优先级是：

    有手阶段：
        继续按细节 8 保守地保护同类 C、B、D，不能抢身份，不能提前建 D。

    手刚离开后的首张无手帧：
        继续先收集直接原位证据、移动证据、D 证据；不能单帧提交 OUT。

    连续直接无手帧的最终结算：
        若同类旧物品数大于可靠可见框数，则采用“一框一物品”的数量规则；
        不再因为一个框也落在另一个 C 的候选路径附近而无限阻止 OUT。

因此，细节 8 的“同类歧义时不强认 MOVED、不误建 D”仍然有效；变化仅在于，
最终无手画面确实只看见较少同类实例时，系统不再假定那些不可见实例一定还在。

## 3. 适用范围与不可接受的简化

### 3.1 适用条件

可见实例结算只能同时满足下列条件时启用：

1. 当前会话正在处理一次已经开始的手操作。
2. 当前帧没有手框，且进入正常的直接无手收尾。
3. 比较对象来自本次操作开始时已存在的旧库存，且 cls_id 相同。
4. 对该 cls_id，当前可靠可见框数量小于尚需按可见状态结算的旧物品数量。
5. 数量不足状态连续保持至少 FLOW3_NO_HAND_OUT_MISSING_FRAMES 张直接无手帧。
6. 当前不是已经由确认前景物品完整遮挡的旧 C；已确认遮挡仍使用 OCCLUDED_CONFIRMED，不能被本规则错误 OUT。

当前 FLOW3_NO_HAND_OUT_MISSING_FRAMES 为 2。它继续作为本规则的时间确认条件：
第一张无手帧只记录数量不足，第二张连续无手帧才允许提交 OUT。

### 3.2 不适用条件

下列情况不得使用“一框一物品”直接改变数量：

- 有手框仍存在。手还在时，重叠、局部框、手遮挡和新 D 都必须按现有保护逻辑处理。
- 不同 cls_id 的物品。不同类别仍按各自身份、遮挡和 D 规则处理。
- 同类可见框数量不少于旧物品数量。数量没有减少时，不能仅靠数量推断 OUT。
- 同类数量恰好不变、但可能发生了“取出一个又放入一个”的替换。该场景仍需
  现有 C 到 B 与 D 证据链，不能把数量相等误当作身份正确。
- 单帧 YOLO 短暂漏检。第一张直接无手帧不能产生 OUT；如果下一张重新看见足够框，
  必须清除本次数量不足候选。
- 已有独立、完整证据链的疑似新物品 D。不能为了凑旧 C 数量而吞掉已经确认的 D。

### 3.3 明确接受的边界

若两个同类物品真实都还在，但它们在手离开后的稳定画面中持续只得到一个检测框，
系统会按一个物品处理，并使库存数量减少一个。

同样地，若一个物品被移动到同类物品后面，最终持续只看见一个同类框，系统也会
按一个物品处理。以后两个物品再次分开并重新看见两个框时，多出的那个框会按正常
同类 D 规则重新进入库存。

这是单摄像头可观察库存定义下有意识接受的取舍。系统不能从一个框中恢复不可见的
第二个物品，也不能同时做到“一个框算一个”和“永远保留可能隐藏的第二个”。

## 4. 必须保持的非回归约束

本次修改的目的仅是修复相邻同类物品的出库卡死。以下能力已经在当前版本表现良好，
实现时必须保持：

1. 两个同类物品在无手阶段仍有两个独立完整框：

       两个旧 C 都应保留；
       被移动的 C 应走 MOVED；
       静止的 C 应保持原身份；
       不得额外 IN，不得错误 OUT。

2. 旧同类 B 静止在原位，旁边真实放入一个新的同类 D，且最后能看到两个框：

       B 必须保留；
       D 必须继续走现有的 suspect D -> 连续确认 -> IN 链路；
       不得因本次出库修复而把 D 吸收为旧 B。

3. 旧 C 被移动、手离开后在路径附近有唯一完整框：

       继续走现有的 reappear candidate -> 连续无手确认 -> MOVED；
       不得因可见数量规则把移动误报为 OUT。

4. 一个旧 C 没有独立结论、同时出现同类完整 B：

       若该 cls_id 的可见数量没有减少，仍保持细节 8 的保守身份仲裁；
       不得借本规则错误创建 D 或强认 MOVED。

5. 旧 C 被确认由前景物品完整遮挡：

       必须保持 OCCLUDED，而不是因为没有独立框就 OUT。

6. 现有的防重复入库防线：

       任何旧 C 未解决时，不能把同一实体额外创建为 D；
       一个检测框在同一帧最多只能保留给一个旧 C 或一个已确认的 D。

## 5. 最终无手结算的正确算法

### 5.1 先做一对一保留，不做“一个框属于所有 C”

对每个 cls_id，最终无手帧必须先建立一次全局、一对一的保留关系：

    一个可见检测框最多保留一个旧 C；
    一个旧 C 最多保留一个可见检测框；
    同一个框绝不能既证明 B 还在，又同时阻止 A 的缺失 OUT。

保留顺序应为：

1. 先保留每个旧 C 自己唯一、直接、稳定的原位置检测框。
2. 对仍未保留的旧 C，继续使用现有的唯一移动路径、reappear candidate、
   已确认放下位置等证据。
3. 对仍未分配的同类框和旧 C，使用明确的、可复现的一对一成本分配；
   不能由 map 遍历顺序碰巧决定。
4. 若成本完全相同、画面无法区分，使用稳定的内部决胜规则，例如：

       优先保留上一张直接无手帧已保留的 item_id；
       再比较与各自最后可靠框/原位置的成本；
       仍完全相同才按 item_id 从小到大固定选择。

这里的 item_id 决胜只用于让日志、库存和下一帧一致；对用户而言，同类不可区分
物品中“哪一个编号留下”没有业务差异。

### 5.2 邻居原位框必须成为排除证据

这是本次实机问题的直接修复点。

当前代码在 A 的候选路径附近看到一个框，同时该框严格属于静止邻居 B 时，会把它
记为 A 的 no_hand_candidate_ambiguous，随后阻止 A 的 OUT。

新规则必须改为：

    若该框已通过第 5.1 节被独立、一对一地保留给 B，
    它对 A 的含义是“不是 A 的框”，而不是“也许是 A 的框”。

因此：

    B 使用该框保持在库；
    A 不能认领该框为 MOVED；
    A 也不能因为这个框永久保持歧义；
    A 应作为未分配旧 C，进入正常的连续无手缺失计数。

这正好对应真实例子：

    操作前：橙子 #23 + 橙子 #24
    手离开后：只剩 #24 的一个稳定完整框

    第 1 张无手帧：
        该框保留给 #24；
        #23 的缺失计数为 1，不提交。

    第 2 张连续无手帧：
        仍保留 #24；
        #23 的缺失计数达到 2；
        #23 OUT，库存只剩一个橙子。

### 5.3 同类可见数量不足时的数量结论

对某个 cls_id，设：

    old_visible_count：
        本次操作开始时、应按可见状态维护的旧物品数。

    retained_old_count：
        当前直接无手帧中，经第 5.1 节一对一保留给旧 C 的框数。

    confirmed_occluded_count：
        已有确认遮挡结论的旧 C 数，不纳入可见数量缺失。

只有在下面条件成立时才形成可见数量不足：

    retained_old_count < old_visible_count - confirmed_occluded_count

数量差额为：

    visible_count_deficit =
        old_visible_count - confirmed_occluded_count - retained_old_count

在连续无手帧中，必须选择恰好 visible_count_deficit 个未保留旧 C 作为 OUT 候选。
选择顺序应优先让已有稳定原位框、已确认 MOVED 框、已确认遮挡 C 留下；剩余 C
按第 5.1 节的稳定决胜规则保留一个，其他成为数量不足 OUT 候选。

这些 OUT 候选不应再被“同类邻居框严格属于另一旧 C”这一事实阻塞。该邻居框已经
在一对一关系中被消费，不能再次作为候选歧义。

### 5.4 D 的优先级和数量保护

本规则不能把所有同类检测框机械塞给旧 C，否则会破坏已经正确的入库流程。

必须保持以下顺序：

1. 已有完整、独立证据链并已确认的 D，仍属于 D，不能被旧 C 抢走。
2. 旧 C 的原位或唯一移动框先按第 5.1 节一对一保留。
3. 剩余且数量超过旧 C 可解释范围的同类框，才按现有规则考虑 suspect D。
4. 当同类可见框数量少于旧 C 数量时，未认领框不能被误建为新的同类 D；
   它们应优先用于保留已有旧 C 或已确认 D。

特别注意“旧 A 被取出，同时放入一个同类 D，最终同类框数量不变”的场景：

    数量规则不能单独判断谁 OUT、谁 IN；
    必须继续使用现有 C 到 B、D 来源和连续确认链路；
    如果证据不足，保持未决比伪造 OUT + IN 更安全。

### 5.5 连续性和撤销

数量不足不能只看一次，也不能在两帧之间随意更换“留下的 item_id”。

实现应保存一次按 cls_id 的无手可见实例结算上下文，至少包括：

    cls_id
    当前帧各检测框保留给哪个 item_id
    未保留、正在累计 OUT 的 item_id
    连续数量不足帧数
    决胜原因：原位 / 移动路径 / 上一帧延续 / 最小成本 / item_id 决胜

行为要求：

- 首张数量不足无手帧：只建立或更新该上下文，OUT 候选计数为 1。
- 后续帧仍满足相同的数量不足关系：沿用可行的上一帧保留关系，再把同一 OUT
  候选计数加一。
- 若同类可见框数量恢复、候选框明显不连续、或手再次出现：清除本次未提交的
  数量不足上下文和相关缺失计数；不能在后来随机帧继续凑次数。
- 达到当前 OUT 的连续帧门槛后：将选中的旧 C 标为 OUT_CONFIRMED，允许本次操作
  提交；日志必须写明这是可见实例数量结算，而不是“完全找不到同类检测”。

## 6. 建议修改的代码位置

以下是实现导向，字段和函数名可按代码风格调整；不能只改一处 if 条件后就结束。

### 6.1 OperationTrack 或操作级结算上下文

需要保存“本帧被其他同类旧 C 独占的框”与“本 item 因可见数量不足而缺失”的
不同语义。

建议增加操作级、按 cls_id 的结算记录，而不要把一个框同时写进多个 C 的
reappear candidate。必要时可增加类似下面的枚举或等价日志原因：

    DIRECT_STATIC
    UNIQUE_MOVED
    RESERVED_BY_OTHER_SAME_CLASS_C
    VISIBLE_COUNT_DEFICIT
    CONFIRMED_D

其中 RESERVED_BY_OTHER_SAME_CLASS_C 对 A 的含义必须是“排除该框，继续检查 A 的
缺失”，不能再等同于 no_hand_candidate_ambiguous。

### 6.2 observe_no_hand_frame_ 的候选处理

目前“检测框严格属于另一旧物品”会把当前 A 标记为歧义。该处理需要拆分：

    框没有经过全局一对一保留：
        仍可保留为真实身份歧义，维持细节 8 的保护。

    框已经稳定、独立地保留给邻居 B：
        从 A 的候选集合排除；
        不把 A 标为 no_hand_candidate_ambiguous；
        让 A 在后续 has_unresolved_no_hand_state_ 中获得真实的缺失处理机会。

同时，所有同类框必须先经过按 cls_id 的一对一保留/分配，再进入逐 track 的
MOVED、OUT、D 判断。不能继续让每个 track 分别扫描同一个框并各自留下歧义。

### 6.3 has_ambiguous_no_hand_reappear_candidate 与无手提交

该辅助判断不能只因“候选框严格属于另一旧 C 且落在 A 路径附近”就返回 true。
它必须知道该框是否已经被稳定分配给另一 C。

若是，则：

    对 A 返回“没有可用候选框”；
    允许 A 进入缺失计数；
    由可见实例结算上下文确保不会把同一个框同时算给 A。

has_unresolved_no_hand_state_ 也必须区分：

    身份仍真的不清楚、数量没有减少
        -> 保持 UNRESOLVED。

    同类框数已经持续不足，且 A 被确定为本次数量差额 OUT 候选
        -> 继续累计或确认 A 的 OUT；
        -> 不得因邻居 B 的框反复阻止提交。

### 6.4 register_post_hand_reveal_suspects_ 与 D 防线

细节 8 的 D 防线不得删除。应在一对一保留关系之后决定：

- 已保留给旧 C 的框不能创建 D。
- 已确认 D 的框不能被旧 C 抢回。
- 同类可见框数量不足旧 C 数量时，未认领框不能被误建为新的同类 D。
- 同类框数量多于可由旧 C 和已确认 D 解释的数量时，额外框才可能继续 D 链路。

这样可以同时保证：

    两个相邻橙子拿走一个：一个旧橙子 OUT，不会出现伪 D。

    一个旧苹果仍在、旁边真放入一个新苹果：旧苹果保留，新苹果仍能 IN。

### 6.5 不建议修改的内容

本次不应通过下列方式“解决”问题：

- 不要降低 FLOW3_NO_HAND_OUT_MISSING_FRAMES。当前为 2，已经足以解释
  “第二个橙子拿走后两个同时 OUT”的现象，问题不在等待帧数。
- 不要盲目缩小 FLOW3_TRACK_CENTER_NORM、FLOW3_REAPPEAR_CANDIDATE_* 或
  INVENTORY_STRICT_*。这样可能让这一个摆放距离碰巧通过，却重新损坏快速移动、
  同类整理和新 D 防重复入库。
- 不要删除所有同类歧义保护。手还在时、数量没有减少时、同类换入换出时，现有
  保守策略仍然必要。
- 不要以 map 遍历顺序决定留下谁、OUT 谁。必须有稳定且可记录的决胜规则。

## 7. 必须新增或改写的回归测试

所有测试都应先在宿主机完整回放套件中运行，再交叉编译到板端。新增测试必须同时
断言事件、最终库存数量、保留的 item_id 和不存在的错误 IN/MOVED/OUT。

### 7.1 实机复现：两个相邻橙子，取出其中一个

使用与实机日志接近的原始框：

    #23: (238,252)~(430,443)
    #24: (409,245)~(610,443)

两个框横向有少量重叠，类别都为 orange。手操作影响 #23，手离开后连续两张无手帧
只提供 #24 的完整框。

期望：

    首张无手帧：不提交，#23 只有一张缺失证据。
    第二张无手帧：只产生 #23 OUT。
    #24 保留在库存，库存橙子数量从 2 变为 1。
    不产生 #23 MOVED，不产生同类 D IN，不保持 operation_pending。

这条测试必须在当前代码上失败，修改后通过，才说明确实修复了本次真实问题。

### 7.2 两个同类真正合并为一个最终框

初始有两个同类旧 C。手离开后连续无手帧始终只有一个同类完整框，且该框可同时
接近两个旧 C。

期望：

    按一框一物品结算；
    稳定保留一个 item_id；
    另一个旧 C 在连续无手确认后 OUT；
    不再保持永久 UNRESOLVED。

这是对细节 8 第 7.4 节和现有
test_same_class_merged_box_keeps_active_a_unresolved 的有意替换。

### 7.3 同类整理但最后仍有两个独立框

初始有两个同类旧物品 A、B。移动 A 到 B 旁边，但手离开后每一帧仍能稳定得到
A、B 两个独立框。

期望：

    A MOVED，B 保留；
    库存数量保持 2；
    没有 OUT，没有 D IN。

现有 test_active_a_moves_next_to_static_same_class_b 必须继续通过，不能被改成
数量结算。

### 7.4 同类旧 B 加入新同类 D

初始有一个静止旧苹果 B。手操作后，B 的原位框和真正新苹果 D 的完整框都连续存在。

期望：

    B 保留；
    D 按既有来源和连续确认规则 IN；
    不得把 D 吸收成 B；
    不得因为“同类框靠近”产生额外 OUT。

现有 test_adjacent_same_class_new_item_gets_its_own_d_chain 必须继续通过。

### 7.5 同类数量不变的换入换出

初始有旧橙子 A、B。手操作后只看到两个橙子框，但其中可能是“保留 B + 新 D”，
也可能是“移动 A + 保留 B”。

期望：

    可见数量规则不得单独产生 OUT 或 IN；
    继续依赖现有身份和 D 来源证据；
    证据不足时保持未决。

这防止“一框一物品”被错误扩展成“同类数量相等就随意换身份”。

### 7.6 短暂漏检与重新出现

两个相邻同类旧物品都在。手离开后的第一张无手帧只检测到一个框，下一张恢复两个框。

期望：

    不产生 OUT；
    清除可见数量不足候选；
    两个旧 item_id 都保留。

### 7.7 遮挡、远距离取出和原有完整套件

继续运行并保持通过：

- 已确认前景遮挡时 C 保持 OCCLUDED，前景离开后正确 REVEALED。
- 同类物品分开放置、取出其中一个时，原有两帧无手 OUT 仍正确。
- 快速移动后 C 重新出现时仍正确 MOVED。
- 保护期内同类 B 不误建 D。
- 多个成熟 C 在有手阶段竞争同一个 B 时仍不按遍历顺序抢身份。
- 新 D 只在自己的连续证据链完整后 IN。
- 细节 8 的“旧 C 未结案时不能同时保留旧 C 又 IN 同一实体”防线持续有效。

## 8. 诊断日志要求

已有的 FLOW3_DEBUG_TRACE_LOG 必须扩展，而不是只保留最终 EVENT。默认仍应为 false，
开启后需要新增可检索的日志标签，例如：

    [3.0-TRACE][VISIBLE-COUNT]

每次进入无手同类数量结算时，至少记录：

    operation_id
    frame_id
    cls_id
    old_visible_count
    confirmed_occluded_count
    当前同类检测框总数和每个框的 index、BBox、score
    每个框最终保留给哪个旧 C、已确认 D 或未分配
    每个旧 C 的分配来源：原位 / 移动 / 上一帧延续 / 最小成本 / item_id 决胜
    visible_count_deficit
    本帧开始、取消或继续累计的 OUT item_id
    no_hand_missing_count 的旧值和新值
    最终结果：DEFER / CONFIRM_OUT / CLEAR_DEFICIT

当一个框严格属于 B、但同时落在 A 的旧候选路径附近时，日志必须明确写出：

    detection=<index> reserved_for_item=<B>
    excluded_from_item=<A>
    reason=independent-same-class-survivor

不能再只打印“同类歧义”而不说明该歧义是否已经被一对一保留关系消除。

提交摘要还应说明：

    item#A OUT 的原因是 visible-count-deficit，
    而不是 no-detection-at-all 或 new-D replacement。

这样实机复测时可以直接核对“一个框被保留给谁、另一个为何允许 OUT”。

## 10. 验收标准

本次修改只有同时满足全部条件才算完成：

1. 两个贴近的同类物品取出一个后，在手完全离开、两张直接无手帧内只报一个 OUT，
   不再等待把第二个也取走。
2. 最终库存中恰好留下一个同类物品；不会额外 IN，也不会两个一起 OUT。
3. 两个同类物品仍有两个独立框时，整理操作继续得到 MOVED，库存数量不变。
4. 真正放入的同类 D 仍能正常 IN，且不会被本次逻辑吸收。
5. 数量相同的同类换入换出不被数量规则臆断，仍遵守现有身份防线。
6. 一帧短暂漏检不会 OUT；手再次出现或检测数量恢复会正确清除未提交候选。
7. 遮挡、D 防线、旧 C 不提前失活、快速移动认回等所有既有回放测试继续通过。
8. 新增日志能完整解释每一次可见数量 OUT 的框分配、决胜原因和连续帧证据。

若某项验收失败，不能通过单独调大或调小几何阈值掩盖问题；应先检查一对一保留、
数量差额计算、D 优先级和候选撤销的实现是否违反本说明。
