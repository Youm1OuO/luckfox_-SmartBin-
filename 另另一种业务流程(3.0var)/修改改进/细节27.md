# 细节27：通用物品证据链、全局归属与联合结算

## 0. 本文性质、范围与最高约束

本文是下一次修改 3.0 业务代码的实施指导，**不是本次已经完成的代码修改**。

本次要解决的不是“手是否完全挡住物品”这个单一问题，而是多物品操作中每个物品是否拥有自己的、可复核的证据链。尤其包括：

1. 两个同类苹果同时整理时，低分重复苹果框被当作新 D，形成伪 `C-D alias`，两个真实移动终点无法结算；
2. 双手同时取出三个或更多物品时，有些物品可能只被部分遮挡、只短暂可见，甚至在后续完全不再被检测到；
3. 多个物品同时放入时，某些新物品也可能只部分可见、多个同类物品可能临时重叠或只剩一个检测框；
4. 以上场景都不能因为一个物品先结案而提前清空其他物品的 operation runtime。

本文件的算法原则对所有食品类别统一有效。类别标签只是归属证据的一部分：同类竞争、跨类别重复、类别暂时抖动和局部框都进入同一个“候选检测图”处理，不再为同类和异类各维护一套互相矛盾的结算规则。

**首要约束：当前已经可实现的功能必须保持有效，尤其不能破坏单手功能。**

必须保留并完整回归：

- 单手入库、出库、整理；
- 一只手连续操作多个物品；
- 两只手独立、反向移动不同物品；
- 现有 `hand_id`、每物品 `carrier_hand_id` 和手框歧义时不写错误 `move_values` 的保护；
- 当前 `CONTACT_*` 的真实物品观测路径；
- 已有的严格遮挡、因果遮挡、遮挡解除、`REVEALED` 和细节24的 causal-occlusion proof；
- 所有类别的一框一物品、静态邻居保护、正常 `C-D alias`、隔离 D、正常 D/IN 链路；
- 无手连续确认、工作库存事务和一次性原子提交；
- 手框短暂漏检、合并、拆分、输出顺序变化时仍拒绝错误手位移。

特别禁止为了让压力测试看起来成功而做以下事情：

- 不按手框数量推断物品数量；
- 不按检测数组下标、画面左右位置、物品 ID 或最近手强行绑定；
- 不因手框合并或歧义而放宽 `HAND_TRACK_MATCH_*`，或把另一只手的 delta 写入该物品；
- 不把“物品被手部分遮挡”或“物品消失”直接等价为 `OUT`；
- 不把“当前看到一个移动框”直接等价为 `MOVED`；
- 不因为两个新物品暂时只检测到一个框而产生两个 `IN`；
- 不删除或全局 NMS 掉低分检测框来掩盖状态机问题；
- 不让一个已确认物品先局部提交并清空尚未结案同伴的运行时状态；
- 不修改遮挡阈值来掩盖同类归属或手关联问题。

代码不必全部写在一个文件中，应按检测归属、手/物品证据、无手匹配、联合结算和测试职责拆分。

本说明优先复用现有参数和已有确认窗口。若实现中确实新增或修改任何阈值、帧数、比例、距离或计数上限，必须同步更新：

`另另一种业务流程(3.0var)/超参数位置与调节说明.md`

说明位置、原值/新值、用途、适用场景和调节风险。若未改超参数，也必须在实现说明中明确写出“本次未改超参数”。

## 1. 先明确：部分可见不等于证据弱

物品是否被手完全遮挡，不应作为出库或入库的必要条件。

对于一个旧库存物品 C，证据强度应大致按以下顺序理解：

```text
物品自己的连续、唯一可见路径
    > 物品自己的可靠手接触/遮挡上下文 + 物品路径
    > 严格的手组离场 witness + 连续无手缺失
    > 只有“画面里曾出现过手”
```

因此，物品在手边露出一部分并不一定更难。若该部分框能连续归属给同一个 C，且相对原位置确实移动，它反而是很有价值的直接证据。困难来自以下情况：

- 同类物品之间无法唯一归属；
- 同一物品同时出现高分完整框和低分局部/重复框；
- YOLO 对同一物品的框大小、位置跳动，导致当前帧无法延续自身路径；
- 两只手同时接触同一物品区域，不能安全使用其中任意一只手的位移；
- 物品完全不可见后，没有它自己的离开事实，只剩“手离开后没有检测到”。

后续实现必须把“物品自己的可见事实”和“手的辅助事实”分别保存，不能用全局 `any_hand_moved`、手数量、类别数量或同批其他物品的结果替代某个物品的证据。

### 1.1 统一对象和证据模型

代码中的角色仍然保持现有含义：

```text
C = operation 开始时已经在库存中的旧物品
D = operation 中新出现、尚未正式 IN 的候选物品
B = 当前帧食品检测框
H = 内部 hand_id 对应的手轨迹
```

每一条候选关系都必须带有来源和生命周期，而不是只保存一个布尔值。至少区分：

```text
DIRECT_OBJECT       物品自己的直接检测/连续路径
HAND_CONTEXT        手接触、覆盖或 carrier 关联上下文
EXIT_WITNESS        物品级或严格手组的离场见证
COUNT_AUXILIARY     可见数量缺额，仅作辅助
OCCLUSION_PROOF     既有正式遮挡/因果 proof
IDENTITY_CONFLICT   同一 B 被多个实体竞争或 alias
```

`COUNT_AUXILIARY` 和 `HAND_CONTEXT` 永远不能单独升级为 `MOVED/OUT/IN`；`DIRECT_OBJECT`、严格 `EXIT_WITNESS` 和现有 `OCCLUSION_PROOF` 也必须经过各自已有的连续确认门。证据必须能撤销或过期：重新出现、原位恢复、归属冲突、手轨迹失效时，撤销受影响的临时证据，不得把旧证据跨 operation 使用。

## 2. 已确认问题 A：两个同类苹果同时整理

### 2.1 当前日志的真实根因

该压力测试中的低分框不是跨类别误分类，而是**同类别重复检测**：两个原库存物品和额外低分框均为 `cls=0` 的苹果。

```text
frame 399:
高分苹果框：score=0.765
低分苹果框：score=0.261
低分框几乎完全落在高分框内
```

现有“跨类别重复框”保护只针对类别不同的检测，因此它不应被误认为已经覆盖本问题。

当前低分同类框进入了新 D / quarantine 生命周期，并建立 `C-D alias`。之后无手帧中，两个真实苹果终点被局部逐框地视为共享候选；系统没有把所有旧 C 与所有检测框放在同一个一对一图中求解，因此一直保持未决。

该场景的可行关系实际类似：

```text
苹果 #6 -> 终点框 0 或终点框 1
苹果 #7 -> 终点框 0

全局一对一关系应推出：
苹果 #6 -> 终点框 1
苹果 #7 -> 终点框 0
```

局部看到“终点框 0 可属于两个苹果”并不等于全局无解；只有完整匹配图真的存在多组同样合理的解时，才应保持身份未决。

### 2.2 通用重复观测 shadow，不按类别分叉

在创建 `HAND_VISIBLE_D`、quarantine D 或 `C-D alias` **之前**，增加一个类别无关的“重复观测 shadow”判断。类别关系（相同、不同或暂时变化）只影响匹配分数和诊断，不决定是否必须走另一套算法。

候选检测 X 只有在以下事实全部成立时才能暂时成为 shadow：

1. X 与同帧另一个检测 Y 具有近乎同一的空间实体关系：包含/IoM、中心、尺度和局部形状都相容；
2. Y 已被某个旧 C、已确认 D 或严格全局归属计划唯一直接拥有；
3. X 没有自己此前连续、独立、空间分离的历史，也没有独立的 CONTACT/HAND 路径；
4. X 与 Y 的类别差异没有得到独立的时序或空间证据支持；若类别相同，也不能因此自动认为是真实第二件物品；
5. 将 X 视为重复观测不会破坏任何已成立的正式遮挡 proof 或其他强 owner；
6. 当前不存在两个实体各自拥有互不重叠的直接框、且 X 明确属于第二实体的证据。

shadow 的行为统一为：

```text
X -> 只记录诊断和待复核关系
X -> 不创建正式 D
X -> 不建立排他的 C-D alias
X -> 不抢占已确认 owner 的 detection
X -> 不参与本帧的实体数量增加/减少结算
```

这不是删除 X，也不是修改 YOLO/NMS。若 X 后续与 Y 分离、连续独立出现、拥有自己的手/物品路径，或 Y 的 owner 已独立结案而 X 仍存在，则释放 shadow，重新进入原有 C/D 归属和 IN 链路。

不能只用分数低、类别相同或单帧 IoM 高来建立 shadow。必须保存 `owner、geometry、score、frame、independent-history` 等来源，并在后续帧复核。若新增或修改专用重复判定参数，必须同步更新超参数说明；优先复用现有几何和连续确认门。

### 2.3 所有类别的旧 C/D 必须进行全局一对一归属

在有手后期和无手阶段，对所有 operation-start 旧 C、临时/已确认 D 与当前食品检测框构建统一的候选图，而不是让每个检测框独立调用“唯一 owner”后立刻把多候选视为永久歧义。

候选边只能来自现有、可解释的物品级证据。类别相同是强兼容条件；类别不同默认不能直接继承物品身份，只有现有跨类别重复/类别抖动规则提供证据时才允许进入候选图：

- 严格直接旧位置 owner；
- 已连续确认的 `reappear_candidate`；
- 同一个实体的真实 `observed_track` / CONTACT 路径；
- 自己可靠 `carrier_hand_id` 的预计路径；
- 已确认的 `placed_box`；
- 旧 C/D 自己的普通轨迹路径；
- 经统一 shadow/类别兼容判断保留下来的候选边。

候选边应包含证据来源、强度、时间连续性和冲突标记，不能只保存一个“能匹配/不能匹配”的结果。

处理顺序必须是：

```text
先锁定严格直接 owner 与已确认 endpoint
    ↓
在剩余 C 与剩余检测之间求全局一对一匹配
    ↓
只接受在全部可行匹配中都成立、或证据严格更强的归属
    ↓
在后续直接无手帧中保持同一归属并完成现有连续确认
    ↓
按已有 MOVED 规则确认，而不是因一次匹配立即确认
```

若候选图存在真正对称的多种完整解，例如两个外观相同或类别暂时不同的物品在手后互换且没有任何物品路径能区分，则不得按 item ID、左右位置、检测顺序或类别数量强行指定身份。此时应保留未决，或另行设计集合级事件；本次不能伪造逐 item 身份。

匹配计划必须在同一帧内一对一，也要在连续无手帧之间保持身份稳定。一个检测框只能被一个实体正式占用；一个实体不能借用另一个实体的 detection、hand delta 或终点证据。全局匹配只解决“归属”，不替代 `MOVED/OUT/IN` 的确认门。

## 3. 已确认问题 B：双手同时取出多个物品

### 3.1 当前日志的真实根因

三个物品同时取出的日志中，两个橙子能通过同一类别的 `VISIBLE-COUNT` 缺额进入 `OUT_CONFIRMED`，但唯一苹果没有可用于身份确认的数量辅助。这不是橙子和苹果的特殊规则，而是任何类别数量辅助都只能覆盖“集合缺额”，不能替代单个物品的归属证据。

苹果自身的事实是：

```text
开始时被手接触/部分遮挡
    ↓
手关联变为 ambiguous，系统正确地暂停错误 delta
    ↓
后续没有苹果自己的移动后检测框
    ↓
无手后也没有苹果框
    ↓
missing-without-sufficient-out-evidence
```

所以当前 `defer-commit` 是正确保护：两个橙子可暂存 OUT，但苹果还没有合法结案路径，不能只提交两个 OUT 并清空整轮 runtime。

同一手带走的另一个橙子已经 OUT，**不能自动成为苹果 OUT 的证据**。手数量、同手物品数量、已出库同伴数量都不能替代苹果自己的证据。

`VISIBLE-COUNT` 对任何类别都只做辅助：它可以在一对一归属无法观察个体时确认某个类别/兼容组的数量缺额，但不能决定缺少的是哪个 item，也不能跨类别传播 `OUT`。若数量缺额与直接物品路径、遮挡 proof 或 D/alias 冲突，应优先保持未决并记录冲突。

### 3.2 路径一：部分可见物品的直接离开证据

不要求物品被手完整遮挡。对于旧 C，若它在有手阶段部分可见，应优先利用自己的可见路径建立现有 `direct_exit_evidence`，或复用现有 `reappear_candidate` / `observed_track` 字段，而不是另造一套不一致的轨迹。

一条部分可见路径只有同时满足下列条件时，才可成为 OUT 缺失链的入口：

1. C 已在本轮按既有规则进入 `HAND_*` 或从合法 `CONTACT_*` 转入 HAND；
2. 当前框已在全局一对一归属中唯一属于该 C，不能与另一个 C、D 或 shadow 共享；
3. 框即使是局部框，也必须与 C 自己的上一条观察/候选连续自匹配，不能是单帧远处同类噪声；
4. 该框相对 C 的 operation-start `original_box` 满足既有 `boxes_differ_as_move()`；
5. 框在对应手边出现，或属于 C 已有的连续 CONTACT/HAND 真实观察路径；
6. 不存在 `C-D alias`、任何实体 owner 歧义、遮挡解释、claim grace 或被更强 owner 预约；
7. 证据只记录为“允许开始原有无手缺失计数”，不是单帧 OUT。

之后仍必须沿原有：

```text
连续无手缺失 >= FLOW3_NO_HAND_OUT_MISSING_FRAMES
    + 没有重新出现
    + 没有正式遮挡/alias
=> mark_pending_out_()
```

手只擦过物品、物品仍在原位、部分框无法连续匹配、或出现实体/类别竞争时，必须清除/拒绝该证据，不能因为“看起来像被拿走”而 OUT。

若现有可靠 `carrier_hand_id`、`hold_and_move` 或 CONTACT 路径已经能够完成正常确认，必须继续走原有路径；本节只是为 hand delta 中断、局部框或部分遮挡补充受限证据，不能替换、降低或重置原有单手/正常多手门槛。

### 3.3 路径二：完全不可见时的严格手组离场 witness

某些真实取出场景中，物品在被拿起后完全看不到，因而无法建立第 3.2 节的直接物品离开框。对此可以增加一个比普通 hand delta 更弱、但仍严格的物品级 `hand_group_exit_witness`。

它不是 `move_values`，不能把合并/歧义手框的位移补写回去，也不能直接生成 `MOVED`。它只是在全部条件满足时，允许该旧 C 进入已有的无手缺失确认链。

建议为每个旧 C 维护概念上类似的数据：

```text
possible_carrier_hand_ids        // 仅记录实际触碰/覆盖过该 C 的候选 hand_id 集合
carrier_capture_context          // 首次可靠手-物接触或覆盖事实
hand_group_exit_witness          // 是否已得到严格离场见证
hand_group_exit_frame
```

建立 witness 至少必须满足：

1. C 在本轮确实有自己的手-物接触/覆盖上下文，而不是画面中只出现过一只手；
2. C 在手关联歧义前至少曾唯一绑定过一个 `carrier_hand_id`，或候选 hand_id 集合只由“物体仍可见时真实接触该物体”的手加入；不得把远处任意手加入集合；
3. hand_id 在候选期间自身连续可追踪；若候选 hand 也暂失、身份不明或被任意重绑，则不能建立 witness；
4. 当物品变得不可见后，所有仍可能携带它的候选手都已从 C 的原区域向合法离场区域移动并离开；不能只看到其中一只手动了；
5. 之后必须有直接无手帧，C 不在原位也不在任何可唯一归属的位置；
6. 不存在当前/潜在 blocker、实体竞争、D/alias、静态恢复或其他可解释该 C 的检测；
7. 通过 witness 后仍必须等待现有连续无手缺失门槛；任何重新出现、手返回原区域或新的竞争检测都应立即撤销 witness。

“离场区域”应是明确、可测试的相机画面边界/手离开观察区概念，不能简单等同于 `move_length(delta) > eps`。若现有项目没有可靠的离场区域语义，应先实现并验证该概念；不能仅为了让当前日志成功而把任意方向的大 hand delta 当作出库。

若当前实机帧无法满足上述条件，正确结果仍是保持未决。视觉中没有足够信息时，代码不能同时保证“必定判出库”和“绝不把连续漏检误判出库”。此时可通过提高 held-object 检测质量、实例分割、深度/多视角或明确的离场区域补强输入，但不能用猜测替代证据。

## 4. 多物品同时入库及混合操作的统一规则

多个新物品同时放入与多物品取出方向相反，但原则相同：每个新 D 必须拥有自己的可见和放置证据。若同一 operation 同时包含旧 C 的整理/出库和新 D 的入库，仍使用同一候选图和同一原子结算门，不能按类别或事件类型分成互相抢框的流程。

### 4.1 部分可见的新物品只可成为 provisional D

新物品在手边只露出局部时可以登记为 provisional D，但以下事实都不足以立即 `IN`：

- 画面中有两只手；
- 一只手看起来拿着两个物品；
- 当前有一个局部检测框；
- 某一类别或兼容组的总数量似乎增加；
- 另一个 D 已经确认 IN。

每个 D 必须满足：

```text
不是旧 C 的直接/全局终点
    + 不是任何类别的重复 shadow
    + 有自己的连续观测路径
    + 无手后得到独立、稳定、唯一的放置框
    + 达到既有 D 的连续无手确认门槛
=> IN
```

一个检测框最多属于一个 C 或一个 D。两个真实新物品（无论同类还是异类）暂时完全重叠、只产生一个框时，系统最多只能确认一个实例；第二个必须等到独立可见后再确认。不得由手数量、D 数量预期或计数差补造第二个 `IN`。

### 4.2 真实新物品不能被 shadow 规则误杀

重复 shadow 仅是当前帧的非阻塞临时状态。出现以下任一事实时，候选必须恢复正常 D 仲裁：

- 它与高分框在空间上明确分离；
- 它在连续无手帧中拥有自己的独立框；
- 它能与所有旧 C 和其他 D 建立一对一的独立匹配；
- 原先高分框所属的旧 C 已独立结案，而候选仍持续存在。

## 5. 联合结算顺序必须保留

本轮 operation 的正确顺序应为：

```text
1. 识别所有类别的重复 shadow，避免伪 D/alias 干扰
2. 对所有旧 C、已有 D 与当前检测建立全局一对一归属计划
3. 更新每个物品自己的部分可见路径、直接终点或直接离开证据
4. 更新严格手组离场 witness；它只作为 OUT 缺失链入口
5. 处理无手连续确认、遮挡/alias/blocker 生命周期
6. 对每个 operation-start C 和 D 计算：
   MOVED / OUT / IN / OCCLUDED / STATIC / UNRESOLVED
7. 仅当全部相关对象都不是 UNRESOLVED 时，原子提交库存和全部事件
```

以下状态均不是结案，不能让提交门放行：

```text
只在本帧部分可见，但没有连续自身路径
shadow 候选尚未分离或被安全回收
MOVED/OUT/IN 尚未达到原有确认窗口
手组离场 witness 缺任一必要条件
候选图仍有多组同样合理的匹配
未解决 C-D alias
普通 missing，但没有物品级 direct exit 或严格 hand-group witness
```

当前原子 `defer-commit` 的原则必须保留。它不是导致卡住的根因；错误在于有些旧 C 没有合法恢复/离开路径。不能通过删除提交门或先提交一半事件来“解决”。

## 6. 推荐的代码职责划分

- `include/session.h`：仅增加本事务有效的 shadow 状态引用、全局匹配结果、候选 carrier hand 集合和 hand-group witness 所需字段；必须定义清理时机；
- `session_ownership.cc` / `session_internal.h`：实现类别无关的 shadow 纯判断、所有 C/D 与检测的全局一对一匹配计划、类别兼容边和匹配唯一性判断；
- `session_hand.cc`：维护 `hand_id` 连续性、物品实际接触上下文、部分可见直接路径、候选 carrier hand 集合和 witness 的建立/撤销；不在这里直接提交事件；
- `session_no_hand.cc`：维护无手连续自匹配、普通 missing、alias、D 连续确认；只在合法 direct exit 或 hand-group witness 存在时让旧 C 进入现有 OUT 计数，并让所有类别共用同一证据门；
- `session_settlement.cc`：在完整全局归属计划后确认 MOVED，应用联合未决门，并且只做一次原子提交；
- `tests/`：新增确定性 replay 和负向测试，不能仅查看 trace 文本。

禁止在 `session_hand.cc`、`session_no_hand.cc` 和 `session_settlement.cc` 各自复制不同版本的“部分可见即可移动/离开”的条件。必须有权威的纯判断函数或统一结算入口，避免状态矛盾。

## 7. 必做测试

### 7.1 当前问题的正向回放

| 场景 | 必须结果 |
| --- | --- |
| 两个同类苹果同时整理，低分同类重复框近乎被高分框包含 | 不创建阻塞性伪 D/alias；在连续无手帧后得到两个 `MOVED`；不永久 `defer-commit`。 |
| 两个同类苹果中 A 移到 B 原位置附近，B 移到新位置 | 全局图能得到唯一分配时输出两个 `MOVED`；不按左右位置或检测下标决定身份。 |
| 两个不同类别物品同时整理、交换或互相靠近 | 类别兼容边与物品路径共同归属；输出正确的 `MOVED`，不因类别差异制造伪 D/OUT。 |
| 双手同时取出三个物品，其中一个仅部分可见但有连续自身移动路径 | 每个物品各自经证据和连续无手确认后得到三个 `OUT`。 |
| 双手同时取出三个物品，其中一个最终完全不可见但具备严格 hand-group exit witness | witness + 既有无手缺失门成立后得到该物品的 `OUT`；不借用另一物品的 OUT。 |
| 多物品同时入库，两个新物品均在手边部分可见且最终分开稳定出现 | 不论类别是否相同，每个 D 独立确认，产生对应数量的 `IN`。 |
| 同一 operation 混合旧 C 整理/出库与新 D 入库 | 使用同一全局候选图和一次原子提交，不让 C 与 D 互相抢框或半提交。 |

### 7.2 必做负向测试

| 场景 | 不允许发生的错误 |
| --- | --- |
| 低分重复框与任意类别的强 owner 几乎同框，但后续消失 | 不创建 D，不建立 alias，不产生 IN。 |
| 两个真实物品短暂重叠后分离，无论类别是否相同 | shadow 不得永久压掉第二个真实 D/IN。 |
| 多个旧 C 的完整匹配真正对称、无路径区分 | 不得按 item ID、左右位置、类别数量、手数量或检测下标强行生成逐 item 事件。 |
| 手遮住物品后移开，物品仍在原位 | 不得因 hand-group witness 或 `hand_delta_interrupted` 产生 OUT。 |
| 手擦过物品、物品没有移动 | 不得建立 direct exit evidence 或 OUT。 |
| 手框合并/拆分期间，只有一只候选手离场 | 不得把该物品当作已离场。 |
| 物品完全不可见且没有严格 witness | 允许继续未决，但不得造 OUT。 |
| 两个新物品暂时只检测到一个框 | 不得产生两个 IN。 |
| 同时入库/出库混合，旧 C 与新 D 部分重叠或类别暂时变化 | 不得破坏现有 alias、遮挡和一框一物品规则。 |

### 7.3 完整回归

除上述测试外，必须完整回归：

- 单手 MOVED、OUT、IN；
- 手框轻微抖动、短暂漏检、输出顺序变化；
- 一只手连续/同时影响多个物品；
- 两只手独立、交叉、合并后再分开；
- 所有类别的一框一物品、静态邻居、正常 C-D alias、真实 D/IN；
- CONTACT_CANDIDATE、CONTACT_MOVING、手擦过后回原位；
- 严格遮挡、因果遮挡、多 blocker、遮挡解除和 REVEALED；
- 普通 OUT、visible-count 辅助结算、无手静态恢复；
- 当前已经通过的双物品同时整理、同时取出和同时放入场景。

## 8. 建议增加的诊断日志

日志仅用于验证，不是业务状态本身。建议至少记录：

```text
ENTITY-SHADOW candidate=... owner=... relation=same/different/unstable-class action=hold-shadow / release-to-d
GLOBAL-ASSIGN group=... item=... detection=... edge-strength=... result=forced / ambiguous
PARTIAL-PATH item=... detection=... action=record-direct-exit / reject reason=...
HAND-GROUP-EXIT item=... candidate-hands=[...] action=record / reject reason=...
COUNT-AUX group=... action=assist / reject reason=...
SETTLE item=... state=UNRESOLVED reason=...
SETTLE barrier=pass / defer unresolved=[...]
```

每条日志应包含 operation id、frame id、item id 或 suspect key、class、detection index、相关 hand_id 和拒绝原因，便于确认系统使用的是物品自己的证据，而不是手数量或偶然的遍历顺序。

## 9. 其他推荐改进（不降低现有确认门槛）

以下改进不是把某个压力测试直接判成功的捷径，而是让同一套证据框架在不同类别、不同遮挡程度和不同检测质量下更稳定。实现时应先做回放验证，再逐项接入；任何新阈值都要同步写入超参数说明。

### 9.1 增加检测归一化层，但保留原始输出

在业务状态机和 YOLO 原始输出之间增加一层“候选检测归一化”：

- 原始检测不得删除，保留 `score/cls/box/frame/index` 供回放和诊断；
- 只在候选图中标记完整框、局部框、重复 shadow、类别不稳定和低质量框的角色；
- 同一实体的多个框先做几何/时间聚类，再选择业务 owner，不能让重复框各自创建 D；
- 局部框可以作为路径证据，但必须降低证据强度并要求连续自匹配；
- 不把全局输入过滤、全局 NMS 或单一 score 阈值当作身份解决方案。

这样同类重复、跨类别重复、类别抖动和部分框都能走同一层处理，单手和正常高分检测路径不需要改写。

### 9.2 统一证据账本与撤销规则

每个 C/D 维护一个本 operation 有效的证据账本，记录 `source、owner、first_frame、last_frame、strength、conflict、retract_reason`。证据只允许三种变化：

```text
未建立 -> 按条件建立 -> 被反向事实撤销或在提交时清除
```

不能把一个物品的证据复制给同批其他物品，也不能让“当前帧恢复唯一”抹去此前发生过的 hand 中断历史。每一帧输出最终 evidence snapshot，避免 `session_hand`、`session_no_hand` 和 `session_settlement` 各自维护不同结论。

### 9.3 使用可标定的 interaction/exit 区域

`hand_group_exit_witness` 不能只依赖位移长度。应在相机坐标中明确：

- 物品操作区/原库存区；
- 手可以合法离开的边界或观察区；
- 不应被解释为出库的暂时遮挡区；
- 门框、边缘和画面裁切造成的检测失效区。

区域只用于加强离场证据，不得改变既有 `MOVED/OUT/IN` 几何确认阈值。若设备安装变化，区域需要重新标定，并在配置说明中记录风险。

### 9.4 给未决 operation 一个可观测的生命周期

保留原子提交，不要用超时自动提交错误事件；但也不要让设备只显示无原因的永久 `defer-commit`。建议增加：

- 每个 operation 的 `unresolved_ids` 和首要阻塞原因；
- 证据等待阶段与“证据永久不足”阶段的可区分状态；
- 在安全的 operation 边界（例如明确取消/重新开始）清理临时证据，而不是在中途强制提交；
- 诊断日志和上报中的待处理状态。

这只改善可观测性和恢复流程，不改变库存事件语义，也不允许未结案 C/D 被丢弃。

### 9.5 优先改善输入质量，再调整业务逻辑

应收集部分遮挡、多个物品同手、同类重叠、类别暂时变化和手离场的真实片段，检查：

- 模型是否会把一个物品输出成完整框和局部框两次；
- 被手拿住的物品类别/框是否系统性掉分；
- 物品完全消失前是否至少有一帧可用路径；
- 手框合并、漏检和边缘裁切是否过于频繁。

必要时可改进训练数据、实例分割、手持物品样本、帧率或多视角/深度输入，但这些属于输入能力增强，不能用来放宽状态机安全门槛。

### 9.6 建立可重复的全类别 replay 验收

每个实机问题都应保存“原始检测 + 手框 + 期望事件 + 允许未决原因”的 replay。测试必须断言库存、item_id、事件、runtime 和 evidence snapshot，而不是只搜索日志字符串。新增算法前先通过旧回放，新增算法后再通过正向和反向回放，才能确认没有把原来可行的单手/遮挡功能改差。

### 9.7 分阶段实施，避免一次改动破坏已有路径

下一次实际修改建议按以下顺序推进，每阶段都先编译和跑旧回归，再进入下一阶段：

1. 先只增加 evidence/assignment 的诊断和 replay 断言，不改变正式事件；确认日志能逐物品说明阻塞原因。
2. 接入类别无关的重复 shadow 和候选归一化；先验证不会吞掉真实 D、单手 B 或既有遮挡框。
3. 接入全局一对一匹配计划；保留现有局部路径作为 fallback，只有全局计划明确更强时才替代局部歧义。
4. 接入部分可见 direct-object 路径，再单独接入 hand-group exit witness；两者都只能进入已有确认链，不能直接提交。
5. 最后收紧联合结算 barrier，确保所有 C/D 正式结案后才原子提交，并加入“未决但可诊断”的安全状态。

任何阶段若旧单手、CONTACT、遮挡、D/IN 或已通过的双物品回放退化，应先撤销该阶段的行为变化并定位证据边界，不能用更宽阈值掩盖回归。

## 10. 完成标准

下一次实现只有同时满足以下条件，才算完成：

1. 部分可见物品可以利用自己的连续、唯一物品路径参与 MOVED/OUT/IN，不要求完全手遮挡；
2. 完全不可见物品只有在严格 hand-group exit witness 与既有连续无手缺失都成立时才可 OUT；
3. 任意类别关系下的重复低分框不会创建伪 D/alias，但真实新物品分离后仍能正常 IN；
4. 所有多物品整理使用全局一对一归属，能够处理“一个物品移到另一个旧位置附近”的可解场景；
5. 真正无可区分身份的任意类别场景保持未决，不强行伪造 item identity；
6. 多物品入库时一框不能生成多件 IN；
7. 手框歧义仍不写错误 `move_values`，也不按手数量推断物品数量；
8. 没有任何 `needs_settle=1 / resolution=NONE` 的旧 C 被提前提交或被清空 runtime；
9. 单手、已有多手、遮挡、alias、各类别归属、入库、出库和静态恢复回归全部通过；
10. 未修改超参数；若修改，`超参数位置与调节说明.md` 已同步更新。

本次正确方向不是降低判断门槛，而是：在多物品、部分可见和手框身份不可靠的情况下，继续拒绝错误手位移，同时用全局归属和每个物品自己的可复核证据，让能够被证明的操作正确结案；无法被证明的场景宁可暂时未决，也不产生错误库存事件。
