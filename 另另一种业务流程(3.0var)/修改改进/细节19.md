# 细节19：基于实机日志的同类归属、遮挡和 OUT 时序实施指导

## 0. 文档目的和适用范围

本文件是下一次修改 3.0 状态机前的实施指导。它主要针对最近实机日志已经暴露的
两个独立问题，同时把用户观察到的原有功能轻微回归列为不可破坏的基线保护：

```text
问题 A：苹果移动到橙子前方后，橙子先被判定 OUT，随后苹果才确认 MOVED。
问题 B：同类苹果在无手帧持续重复时，状态机一直 defer-commit，永远不收敛。
基线保护 C：低置信度单帧不能假 IN；轻微碰撞/YOLO 小位移不能被误判为 MOVED/OUT。
```

问题 A、问题 B 和基线保护 C 相关，但不是同一个根因，不能用一次全局放宽匹配或
一次强制提交同时处理。实施时必须先用最小回放复现每个问题，再分别在既有状态机
边界中增加窄出口；问题 A/B 的修复不能被当作基线保护 C 的替代品。

本文件补充并优先解释《细节18.md》。如果两份文件的旧案例描述与本次实机日志
冲突，以本文件的“已确认事实”和“禁止项”为准；但《细节18.md》中关于工作库存、
正式库存、`base_box`、`block_ids` 和事务边界的基本约束继续有效。

## 1. 最高优先级：已有功能必须保护

**当前代码已经实现了很多正确且很重要的功能，后续修改只能做最小增量，绝对不能
把原来已经好的能力改坏。**

特别要保护下面这些已经存在的业务边界和防线：

- 正式 `inventory_` 与操作期间 `working_inventory_` 的隔离；手操作期间不能写正式库存；
- 只有无手结算成功后才使用既有提交路径原子更新正式库存；
- `NORMAL`、`HAND_PARTIAL_BLOCKED`、`HAND_FULL_BLOCKED`、`CONTACT_*` 的既有状态语义；
- 旧 C 的严格原位所有权、局部连续恢复、灰区静态恢复、reappear 候选和正常 MOVED 确认；
- D 的连续无手确认、C-D alias、quarantine、以及“无 D 证据绝不自动 IN”的防线；
- 真实新 D 在所有旧 C 已独立结算后，仍可按照原有帧数和流程正常 IN；
- 原有两帧无手 OUT 规则，不能为了遮挡降低确认帧数；
- 正常的小位移容忍、YOLO 抖动防御、低置信度假入库防御，以及已有 HAND/CONTACT 回放；
- `IN`、`OUT`、`MOVED`、`OCCLUDED`、`REVEALED` 只能在正式结算提交时产生；
- 现有 `fully_covered_by()` 的矩形差集并集语义，不能退化成“交集面积简单相加”。

下列方案都不是允许的修复方式：

- 不能用 timeout、固定帧数、`item_id` 顺序、检测数组顺序或“卡住太久就选一个”来结束同类歧义；
- 不能降低 `FLOW3_NO_HAND_D_CONFIRM_FRAMES`、`FLOW3_NO_HAND_OUT_MISSING_FRAMES` 或正常 MOVED 门槛；
- 不能把临时 suspect D / pending D 当成正式 blocker；
- 不能把遮挡结论反过来作为“这个框一定属于旧 A”的身份证据；
- 不能全局放宽 `track_match_box()`、`reappear_candidate_path_matches()`、普通局部匹配或 YOLO/NMS 阈值；
- 不能为了实机框的边缘误差而直接增大全局 `COVER_REMAINING_AREA_EPS`；
- 不能把本轮临时手框、局部框或未确认 D 框写进持久 `base_box` / `block_ids`。

## 2. 已由日志确认的事实

### 2.1 问题 A：移动苹果遮挡橙子，却产生 MOVED + OUT

用户的业务预期是：苹果 D 移到橙子 F 前方并完整遮挡它时，最终事件应是：

```text
MOVED(苹果 D)
OCCLUDED(橙子 F)
```

而不是：

```text
MOVED(苹果 D)
OUT(橙子 F)
```

`op=13` 的日志已经记录了确定时序：

```text
frame 332：橙子 item#5 第一次 direct-missing，计数 0 -> 1；
frame 333：橙子 item#5 第二次 direct-missing，达到现有阈值并 OUT_CONFIRMED；
frame 334：苹果 item#2 才完成 MOVED_CONFIRMED；
frame 334：最终提交 MOVED(item#2) + OUT(item#5)。
```

这说明当前错误不是“苹果从未被识别为移动”，而是**橙子的普通 OUT 链比苹果的
身份确认早一帧完成**。在 frame 333，苹果尚未满足现有 MOVED 门槛，因此不能进入
正式 `confirmed_front_ids`；橙子便按完全正常的两帧缺失规则先进入
`pending_out_ids_`。当 frame 334 苹果终于确认 MOVED 时，橙子已处于待删除状态，
后续遮挡重算无法安全挽回这次 OUT。

这不是应当删除 OUT 防线的证据。普通“物品真的被取走”的场景仍必须在两帧直接
缺失后 OUT。需要补的是一个仅在“已经存在强移动证据且目标位置确实覆盖旧 C”时
才生效的短暂事务保护。

### 2.2 问题 A 的第二个独立缺口：严格几何可能仍不认为完全覆盖

`op=13` 中移动苹果的最终框与橙子的可靠框存在大约一个窄边缘残余。当前
`fully_covered_by()` 的语义是严格正确的：它对所有 cover 做矩形差集，只有剩余
总面积不大于 `COVER_REMAINING_AREA_EPS` 才判为完整覆盖。

因此，即使先后顺序修好，若实机 YOLO 框在橙子边缘留下约数个像素宽的整条条带，
严格并集仍可能返回 false。这是检测框几何残余问题，不是身份问题。

但是，这不能成为全局放宽几何的理由。内部缝隙、两个框之间的空洞、漏检造成的
大块残余，都必须继续判定为“没有完全遮挡”。

### 2.3 问题 B：重复无手帧使同类归属永久未决

`op=11` 的 frame 281、282 中，多个苹果检测框都记录为：

```text
viable-unresolved-old=[4,5]
decision=multiple-unresolved-old-c
```

随后：

```text
item#4 -> no-hand-shared-candidate
item#5 -> no-hand-path-ambiguous
SETTLE -> defer-commit
```

用户已明确说明 frame 282 后十几帧仍是基本相同的状态。因此这里不是“日志只截到
一半，后面可能会自然恢复”，而是状态机在稳定输入下没有新的信息能够改变自身状态：

```text
候选路径仍同时匹配 item#4 与 item#5
-> no_hand_candidate_ambiguous 一直为 true
-> 普通 OUT 计数不能增长
-> 也没有旧物被确认 MOVED / IN / OUT
-> operation_pending 一直存在
-> 永久 defer-commit
```

从日志还可确认一件容易误判的事：这不是“所有静态苹果都没有认领成功”。
`item#6` 已由严格原位框独立恢复；但 `item#4` 自身仍被记录为共享候选歧义，
`item#5` 在排除 `item#6` 的独立框后仍为路径歧义。也就是说，问题是剩余旧 C 与
剩余同类 detection 的候选关系没有收敛，而不是“只剩一个无人认领框时 A 无故拒绝
认领”。

### 2.4 问题 B 的直接代码原因：宽路径和强证据被同等对待

现有 `reappear_candidate_path_matches()` 是故意较宽的“可继续观察路径”判断。它会看：

- 已有 reappear candidate；
- 历史 track 上的多个参考位置；
- 正常轨迹匹配；
- 较宽的中心距离和尺寸比例条件。

这对防止同类新 D 被误入库是必要的。但当前 owner 仲裁把“路径可行”近似当作一个
布尔值：同一 detection 只要又能匹配到第二个旧 C，就变成多 C 歧义。它没有区分：

```text
强证据：严格原位恢复、原位 recovery、已连续稳定的 reappear、已观察到的移动终点；
弱证据：仅靠宽松历史路径恰好可达该 detection。
```

于是强的静态恢复候选会被弱的宽路径否决；弱路径本来只应继续阻止 D 误入库，却
错误地升级为“也能永久阻止旧 C 的稳定归属”的同等否决权。

### 2.5 当前 `block_ids` 生命周期应当保留，而不是重新设计

`block_ids` 表示的是“已经确认位于目标 C 前方、且仍与 C 的可靠 `base_box` 相交”的
关系集合，不等于 `OCCLUDED` 状态。

正确关系为：

```text
block_ids 非空
    不代表 C 一定完全遮挡；它也可能只是部分前景关系。

所有有效 blocker 的 base_box 覆盖并集完整覆盖 C.base_box
    才代表 C.status = OCCLUDED。
```

每轮无手结算都应基于“历史已确认关系 + 本轮已确认前景”重算有效关系，而不是因为
本轮没有新的 MOVED / IN 就清空历史关系。前景物正式 OUT、正式移动到不再相交处，
或不再存在时，才从关系中移除。

本条是已有正确方向，后续实现问题 A/B 时必须继续保护它，不能为了简化本轮改动
而恢复“只保留本轮 blocker”的旧行为。

### 2.6 尚未由这两段日志证明的事项

用户另提到过“低置信度假入库”和“轻微碰撞后小位移出错”。这些都是重要回归风险，
但当前给出的 `op=13`、`op=11` 片段不能单独证明它们的直接根因。

因此下次修改时：

- 必须运行已有相关 replay；
- 若实机再次复现，应保留从手阶段到正式提交的完整 trace；
- 在没有独立失败回放前，不能以“顺便修它”为由改 D 规则、微位移规则或匹配阈值。

### 2.7 这次遮挡成功率约 50% 的含义

用户补充说明：移动物品到目标前方时，有些操作能够正确得到 `OCCLUDED`，有些
操作才会错误得到 `OUT`。这说明现有的遮挡主流程、工作库存方向、`base_box` 计算
和部分 blocker 关系并非完全错误；失败集中在身份确认与结算先后、检测框边缘残余
以及特定同类歧义分支。

因此后续实现必须遵循：

- 保留已经成功的遮挡路径和事件事务边界，只修复可复现的失败分支；
- 不因为成功率不稳定就重写整个遮挡状态机或改成“有交集即遮挡”；
- 每次修改都要同时回放成功案例和失败案例，确认成功案例没有退化；
- 不能把“约 50% 成功”理解成应该把所有阈值放宽一倍。成功案例本身是保护基线。

### 2.8 原有功能轻微回归：应保护并单独验证

### 2.8.1 低置信度单帧假入库

用户观察到有时会出现一个实际不存在的低置信度物品，随后下一次又很快 OUT。当前
两段遮挡日志不能证明具体是哪一个函数造成了它，但业务上必须固定以下不变量：

```text
一张偶发低置信度 detection
    只能成为观察/候选证据；
    不能单独创建可提交的正式 D；
    不能单独进入 pending_in_ids_；
    不能单独产生 IN；
    不能成为 blocker。
```

后续身份候选图的改动必须继续使用已有 D 连续无手确认、quarantine、C-D alias 和
“无 D 证据不自动 IN”防线。若回归测试确实发现单帧被提升，修复位置应是**提交门控
或 runtime 生命周期**，而不是降低/提高一个全局 YOLO 分数阈值，也不能用遮挡结论
替它证明身份。

至少要增加一个回归回放：在稳定库存中插入一张低分、下一帧消失的同类假框，断言
库存数量、`pending_in_ids_`、正式 `IN` 事件和 `block_ids` 均不增加；同时验证真实
两帧以上稳定的新 D 仍可按原有规则 IN。

### 2.8.2 轻微碰撞或 YOLO 小位移

用户观察到移动一个物品时，旁边物品可能被轻微挤动或检测框抖动，当前结果有时会
出错。无独立完整 trace 前不能断言这是某一个阈值的根因，但原有业务要求必须保留：

- 小范围位置变化优先沿既有静态/局部/近原位路径保留原 `item_id`；
- 小位移不能单独触发 `MOVED`；
- 小位移不能被当成直接缺失，从而触发 `OUT`；
- 轻微变化不能让一个稳定旧 C 失去自己的原位 owner，去和真正移动 A 抢终点框；
- 只有现有 `boxes_differ_as_move()`、真实手移动证据和连续无手确认共同满足时，才
  能确认 MOVED；
- 若是局部遮挡造成的小框，只能在既有遮挡上下文、双方唯一和不刷新不可靠
  `base_box` 的条件下使用受限静态局部认领。

至少要增加小位移回放：对旁边旧物连续提供 1-2 次轻微平移/尺寸抖动，同时让另一物
真实移动，断言旁边旧物保留原身份、不产生 OUT/MOVED，真实移动物仍能按原门槛确认。
这个回放必须和“真正明显移动”的对照一起运行，避免把移动门槛放得过松。

## 3. 总体解决顺序：身份先于遮挡，遮挡先于事件

所有新逻辑必须遵守以下单向依赖：

```text
同类 detection 的身份候选关系
-> 旧 A 是否可按既有证据确认 MOVED / 新 D 是否可确认 IN
-> 已确认 A/D 才能成为正式前景 blocker
-> 重算 C.block_ids 与完整覆盖状态
-> 正常无手 OUT 证据、事务提交、正式事件
```

禁止反向依赖：

```text
“A 看起来遮住 C”
-> “所以 A 一定是旧 A”
-> “所以 C 一定 OCCLUDED”
```

这会形成循环证据，并把“旧 A 出库 + 同类新 D 入库”错误写成 `MOVED`。

## 4. 第一层修复：同类候选证据分级与双向预约

### 4.1 目标

目标不是取消宽路径，也不是让歧义自动消失。目标是给现有候选关系加上正确的
证据强弱和预约边界：

```text
强的、双方唯一的旧 C <-> detection 关系
    可以先被预约，继续走既有无手连续确认。

仅宽路径可达的弱关系
    仍可阻止 D 被草率提升，但不能否决已经更强且双方唯一的旧 C 预约。

最高等级仍并列的关系
    必须保持未决，不能强选。
```

### 4.2 先建立完整候选上下文

对每个尚未被既有高优先级 owner 正式预约的同类 detection d，建立一个只存在于
当前操作/当前帧的候选上下文，至少记录：

```text
direct_old_owners
    已由既有严格原位、正常移动终点或更高优先级规则双向唯一预约的旧 C。

old_c_evidence[d][C]
    每个仍未解决旧 C 对 d 的最高证据等级及其来源。

matching_suspect_d_ids
    几何上也能命中 d 的 suspect D / pending D runtime。

reservation
    本帧已经由更强、双方唯一关系保留的 owner；没有则为空。
```

“完整”意味着：不能因为一个旧 C 已拥有别的 detection，就停止检查另一个仍未解决
旧 A 是否也可合理到达 d；也不能因为已经有临时 D runtime，就从旧 C 的候选中直接
删掉 d。

但完整候选图不等于把所有同类旧物品都塞进去。C 必须仍为操作开始时的旧物、仍处于
本轮未解决状态，且确实能通过已有严格匹配、恢复、手移动、CONTACT 或 reappear
路径规则到达 d。

### 4.3 证据等级只用于本轮仲裁，不修改全局几何阈值

推荐按下列语义分层。具体枚举名可按现有代码风格定义，但等级含义必须固定：

| 等级 | 可接受证据 | 作用 |
| --- | --- | --- |
| S4 | 已有双方唯一的严格原位/正常移动终点 owner | 保留现有最高优先级，不被新逻辑推翻 |
| S3 | 原位 recovery 或已达到既有连续门槛的 reappear candidate | 可压过仅宽路径的旧 C 主张 |
| S2 | 有真实手移动/CONTACT 动态证据，且当前 detection 与其可靠候选连续匹配 | 可继续既有 MOVED 证据链 |
| S1 | 普通 `track_match_box()`、`last_seen`、`last_hand_block` 的直接路径 | 只能在双方唯一时预约 |
| S0 | 仅 `reappear_candidate_path_matches()` 的宽路径可达 | 继续阻止 D 草率 IN，但不能否决更高等级预约 |

注意：等级不是新的确认门槛。确认 `MOVED`、确认 D、确认 OUT 的既有帧数和状态机
仍完全保留。等级只回答“同一 detection 面对多个旧 C 时，谁有资格先暂存它”。

### 4.4 双向唯一预约规则

不能依赖 map 遍历顺序或 detection 数组顺序。处理应分两个阶段：

1. 先为每个 `d` 找到最高证据等级的旧 C 集合；低于最高等级的候选不参与该 d 的
   owner 竞争，但仍保留在 D 防线的候选上下文中。
2. 再为每个旧 C 找到它在未被更高优先级占用的 detection 中的最高等级集合。
3. 只有当 `d` 的最高等级旧 C 恰好只有一个 A，且 A 的最高等级 detection 也恰好
   只有 d 时，才建立当前帧的临时预约 `A <-> d`。
4. 预约后，d 不再被其他旧 C 当作“我自己的无手歧义候选”；其他旧 C 只能把它视为
   已被更强独立 owner 保留的框。
5. 如果最高等级并列、A 有两个等强 d、或 d 有两个等强 A，保持真实歧义；不产生
   MOVED、IN、OUT 或 blocker。

这里还必须区分“候选被别人预约”和“确认看见了该旧 C”：

```text
弱 owner 的路径被强 owner 排除
    != 弱 owner 已被直接观察
    != 弱 owner 可以立即累计 OUT
```

如果一个正在移动的旧 A 只有这一条被强 owner 预约的宽路径，而没有自己的稳定终点、
直接框或足够的移动失败证据，仍应保持现有未决保护；不能因为它不再参与 d 的 owner
竞争，就把它当作已经缺失并提前 OUT。只有在既有规则已经明确证明 A 没有可行路径、
且满足原有 OUT 条件时，才允许推进 OUT。

对 `op=11` 的预期效果是：原位 recovery / 连续静态恢复的苹果应先保留自己的框；
另一个仅由宽路径碰到该框的旧苹果，不应永久否决这个恢复。已被强预约的静态框从
剩余候选中移除后，移动苹果才能按照自己的现有 reappear/无手连续链路获得真正的
终点框或保持真实未决。

这不是“弱路径失效”。弱路径继续参与以下判断：若某个 detection 没有被强预约，
且它仍可能属于未决旧 C，就不允许将其提升为独立 D。这样保留原有防假入库能力。

### 4.5 suspect D / C-D alias 的不变量

以下不变量必须在 HAND 和 NO_HAND 阶段都成立：

```text
若 d 仍可合理属于未解决旧 A，
则 d 要么已预约给 A，
要么 A 必须出现在关联 suspect D 的冲突集合中。

绝不能出现：D 没有关联 A，但 D 又以“我占用了 d”为由阻止 A 认领 d。
```

因此：

- 在创建或更新 suspect D 前，先收集完整 `old_c_evidence[d]`；
- 临时 D 只能是 runtime 解释，不能取得正式排他 owner 权；
- D 的独立确认必须排除所有仍合理的未决旧 C，而不是只排除先前恰好写进集合的子集；
- 如果 d 在后续帧才显露出与旧 A 的路径关系，必须补上冲突边或撤回 D 的排他判断；
- 真正同级的多旧 C 歧义保持 alias / defer，不能用本节的证据等级强行压掉；
- 当 A 被预约后，仍复用原有 reappear、自匹配和无手连续确认，再调用既有 MOVED
  确认路径；不能一帧预约后立即产生 MOVED。

## 5. 第二层修复：移动确认窗口中的窄 OUT 延迟保护

### 5.1 目标和边界

此保护只解决 `op=13` 这种“被遮挡 C 的 OUT 比前景 A 的 MOVED 早一帧”的时序缺口。
它不是临时遮挡状态，不是新的 blocker，也不是延长所有 OUT 的 timeout。

仅当全部条件成立时，目标旧 C 才能暂停一次普通 direct-missing OUT 证据：

1. C 是 `operation_start_inventory_` 中的旧物；
2. C 当前没有被直接观察到；
3. C 还没有被当前 `fully_occluded_item_ids` 正式解释；
4. 存在另一个操作开始时的旧 A，A 不是 suspect D、不是 `pending_out_ids_` 项；
5. A 有真实的既有移动证据，例如 `hold_and_move`、`has_meaningful_hand_move()`、
   有效 CONTACT_MOVING，或正在连续确认的 reappear/移动候选；仅 `expected_box`、
   宽路径或一张低置信度框不够；
6. A 在本帧有自己的直接无手候选或连续 reappear 候选，候选框必须与 C 的可靠
   `base_box` 有实质交集，面积大于既有 `BLOCK_OVERLAP_AREA_EPS`；
7. 该候选必须来自旧 A 的路径，不得是未确认 D 的框，也不得是仅凭“可能遮挡”
   反推出来的框。

这些条件让保护只覆盖“移动 A 已接近确认且确实落在 C 前方”的短窗口，不会让普通
取出、漏检或真实新 D 长时间保留错误库存。

### 5.2 保护期间的行为

在 `has_unresolved_no_hand_state_()` 对 C 执行普通 `no_hand_missing_count` 增长之前，
先询问是否满足第 5.1 节的保护条件。

若满足：

```text
C.no_hand_missing_count 不增加；
C 保持 needs-settlement；
本轮结果保持 unresolved / defer-commit；
不写 C.block_ids；
不改 C.status 为 OCCLUDED；
不生成任何事件；
不把 A 当作已确认 blocker；
不使用 suspect D。
```

若 C 已在前一帧因普通 direct-missing 进入 `pending_out_ids_`，而当前帧首次满足
保护条件，则仅可撤回这类“普通旧轨迹 OUT”：

```text
pending_out_ids_ 移除 C；
C.resolution: OUT_CONFIRMED -> NONE；
C.needs_no_hand_settlement = true；
C.no_hand_missing_count 恢复为阈值 - 1；
```

这样，如果 A 的候选在下一帧失败，C 会立即继续原有 OUT 证据链，而不是被永久冻结。
不要用这个机制撤回独立的 visible-count deficit OUT，除非另有单独的业务证明和回放。

### 5.3 保护结束后的两条正常路径

```text
路径 1：A 后续完成正常 MOVED_CONFIRMED
    -> A 才进入 confirmed_moved_ids_
    -> A 的最终 base_box 才可成为 C 的正式 blocker
    -> 统一重算 C.block_ids 和遮挡
    -> 若覆盖完整，C = OCCLUDED，C 的普通缺失证据清零

路径 2：A 的移动/reappear 候选失败、消失或被正常排除
    -> 保护自动失效
    -> C 不产生 REVEALED 或 OCCLUDED
    -> C 从之前恢复的缺失计数继续原有 OUT 链
```

不能通过累计保护帧数后强制把 C 设为 OCCLUDED，也不能因为一直保护就让 C 永远
留在正式库存。

## 6. 第三层修复：已确认 blocker 下的窄边缘残余容差

### 6.1 目的

保留严格 `fully_covered_by()` 完全不变。只有它严格失败、且当前实机几何残余符合
“YOLO 框只在外边缘留下很窄的条带”时，才在结算层追加一个受限判定。

建议新增一个专用参数，例如：

```cpp
FLOW3_CONFIRMED_OCCLUSION_EDGE_RESIDUAL_PX
```

参数必须放在 `fridge_config.h` 的遮挡参数附近，并同步写入
`超参数位置与调节说明.md`。它不能复用、也不能修改全局 `COVER_REMAINING_AREA_EPS`。

### 6.2 严格判定优先

伪代码语义：

```text
strict = fully_covered_by(target, covers)
if strict:
    return true

if not all_limited_conditions:
    return false

remaining = 用与严格差集相同的 cover 并集求出的残余矩形集合
for each piece in remaining:
    piece 必须完全落在 target 的左/右/上/下四条窄边缘带之一
    否则 return false

return true
```

对于边缘带，不能只检查“残余矩形碰到边缘”。每一块残余必须整体落在某一条带内：

```text
left band:   piece.x2 <= target.x1 + edge_px
right band:  piece.x1 >= target.x2 - edge_px
top band:    piece.y2 <= target.y1 + edge_px
bottom band: piece.y1 >= target.y2 - edge_px
```

任一残余块深入目标内部超过边缘带厚度，就必须失败。这样可排除：

- 内部细缝；
- 两个 blocker 之间的中间空洞；
- 从边缘贯穿到内部的大条带；
- 漏检造成的大块未覆盖区域。

### 6.3 启用条件

该容差只能在以下全部条件下调用：

1. target C 是操作开始时的旧物；
2. C 当前没有直接 observation；直接看到 C 时必须为 VISIBLE；
3. 参与覆盖的至少一个 blocker 是本轮已确认且当前直接出现的 `IN` 或 `MOVED`；
4. cover 使用的都是最终可靠 `base_box`；
5. cover 中不能含 suspect D、quarantined D、未确认 pending D、临时手框或仅历史推测框；
6. 历史 blocker 单独形成的严格失败覆盖不能使用此容差；
7. 本 helper 只影响“是否完整遮挡”的几何结论，不改变任何身份、MOVED、IN、OUT
   或 D 确认规则。

## 7. blocker 生命周期和遮挡状态的固定语义

身份已确认且最终位置已准备好后，统一在 `final_items` 上重算，而不是在 HAND 阶段
逐个临时写入库存：

```text
effective_blockers(C)
  = 仍有效的 historical C.block_ids
  union 本轮已确认且直接观察到的 IN/MOVED 前景物
  minus 正式 OUT、已移到不相交处、已不在 final_items 的 blocker
```

重算规则：

- C 直接被观察到：`C.status = VISIBLE`；仍与 C 相交的已确认 blocker 关系可以保留，
  但不能因此把 C 继续标记为 `OCCLUDED`；
- C 未被观察到且严格/窄边缘规则说明完整覆盖：保留 `item_id`、`base_box`，写入
  `effective_blockers`，设为 `OCCLUDED`，并清零普通缺失证据；
- 覆盖并集不完整：不能因为“没看到”就把 C 改成 VISIBLE 或产生 REVEALED；仍有效的
  部分 blocker 关系可以保留，但 C 按既有 OUT 证据链处理；
- blocker A 正式 OUT 或正式移动后：统一以 A 的最终位置重算所有 C，不能做局部的
  “先删旧位置、再加新位置”式临时提交；
- `REVEALED` 只在前一正式库存状态为 `OCCLUDED`、C 后续被直接观察并正式提交时产生。

## 8. 推荐实施边界

### 8.1 `session_ownership.cc` / `session_no_hand.cc`

这里实现第 4 节的候选证据分级、候选上下文和双向预约。

要求：

- 尽量复用现有 strict owner、原位 recovery、reappear、轨迹、CONTACT 和 alias helper；
- 新 helper 只返回候选证据、预约和诊断结果，不直接写正式库存或发布事件；
- `unique_c_reappear_owner_for_detection()` 不能再把所有宽路径命中无差别视为同级；
- 已被更强预约给其他旧 C 的 detection，不再反过来使弱 owner 永久 `ambiguous`；
- 被强 owner 排除的弱 owner 不能因此直接变成“已缺失”或跳过既有 OUT/MOVED 未决保护；
- 弱路径仍要保留在 D guard / alias 完整关系中，防止真实旧物被写成假 IN；
- 对真正同级的两个旧 C，返回真实歧义，保持 `defer-commit`。

### 8.2 `session_no_hand.cc` / `session_settlement.cc`

这里实现第 5 节的普通 OUT 延迟保护与必要的 staged OUT 撤回。

要求：

- 保护判断只读取当前事务状态和已有真实路径证据；
- 不新增正式 `InventoryItem` 状态；
- 不在保护窗口写 `block_ids`、`OCCLUDED`、IN、OUT、MOVED 或 REVEALED；
- 必须清楚区分普通轨迹 OUT 与 visible-count OUT；第一步只保护日志已证实的普通
  direct-missing OUT；
- A 后续失败时恢复原有 OUT 进度，不能永久 defer。

### 8.3 `session_settlement.cc` / 几何 helper

这里实现第 6 节的边缘残余容差和第 7 节的 blocker 重算。

要求：

- `fully_covered_by()` 的实现和全局语义保持不变；
- 新容差应是私有、纯几何 helper，输入为 target、已确认 cover 和 edge_px；
- 调用点负责限制“本轮 confirmed front + 未直接看到的旧 C”；
- 关系重算、事件生成、`replace_all()` 继续沿现有结算事务顺序；
- 不要为了这一点改 `inventory.h` 或公共持久化结构，优先增加私有 helper / 本轮容器。

## 9. 必须新增或保留的回放

每项实现前先加失败回放，至少断言：`item_id`、`status`、`base_box`、`block_ids`、
事件种类、事件次数、是否提交。每次改动后都跑完整已有 replay。

### 9.1 同类重复帧收敛回放

构造与 `op=11` 等价的最小场景：

1. 一个旧静态苹果拥有较强的原位 recovery / 连续恢复证据；
2. 一个旧移动苹果拥有自己的真实移动或 reappear 链；
3. 另一个旧苹果可仅通过宽路径碰到静态苹果的框；
4. 连续十张以上无手帧重复同一组 detection。

断言：

- 强的静态恢复先被预约，弱宽路径不能将它永久改回多 C 歧义；
- 移动苹果若有独立连续证据，保留原 item_id 并按现有门槛 MOVED；
- 不产生假 IN、假 OUT 或临时 D 的正式 blocker；
- 不会连续十帧 `defer-commit`；
- 若两个旧 C 的最高证据确实相同，则仍保持未决，不能因本修复强选；
- 真实新 D 对照仍按既有确认规则 IN。

### 9.2 移动遮挡的 OUT 时序回放

构造：旧苹果 A 向旧橙子 C 的位置移动。C 在 A 完成 MOVED 前已经连续两帧没有直接框，
但 A 有真实移动证据、稳定候选并与 C 的 `base_box` 大面积重叠。

断言：

- C 不得先产生 OUT；
- A 在原有 MOVED 门槛达到后才确认；
- A 确认后，C 的 `block_ids` 含 A，C 为 OCCLUDED；
- 事件仅有一次 MOVED(A) 和一次 OCCLUDED(C)，没有 OUT(C)；
- A 的候选失败对照中，C 恢复并完成原有两帧 OUT，不留下保护状态或 blocker；
- suspect D 不能触发该保护。

### 9.3 边缘残余几何回放

至少覆盖：

- 严格完整覆盖：继续通过；
- 一个确认 MOVED blocker 仅留小外边缘条带：窄容差通过；
- 内部细缝：必须失败；
- 两个 blocker 中间空洞：必须失败；
- 残余从边缘深入超过 `edge_px`：必须失败；
- 只有历史 blocker 的严格失败：不得使用窄容差；
- target 直接可见：必须为 VISIBLE，不能以容差维持 OCCLUDED；
- suspect/pending D：不得参与该容差。

### 9.4 blocker 生命周期回放

- A 已移动到 C 前方并使 C 遮挡；下一次无关操作中 A 仍在原位置且 C 未出现，C 必须
  继续 OCCLUDED，历史 `block_ids` 不得被清空；
- A 移走但 B 仍完全覆盖 C，C 继续 OCCLUDED，不产生 REVEALED；
- 最后 blocker 移走而 C 直接出现，C 保留原 `item_id` 并只产生一次 REVEALED；
- 最后 blocker 移走而 C 不出现，才重新启动既有 OUT 证据链。

### 9.5 低置信度假框回归回放

在一个已经稳定提交的库存前，注入一张只出现一帧或极短时间、置信度较低的食品框，
下一帧恢复为原始稳定画面。断言：

- 不创建可提交的正式 D；
- 不进入 `pending_in_ids_`；
- 不产生 `IN`；
- 不改变正式库存数量、`item_id`、`base_box` 或任何 `block_ids`；
- 不因为该短暂框而让已有旧 C 进入错误 OUT；
- 同一回放中的真实稳定新物，仍按原有连续确认帧数正常 IN。

### 9.6 轻微碰撞/检测抖动回归回放

在一个真实移动 A 的操作中，让相邻旧物 B 的检测框产生业务允许范围内的小平移、
宽高抖动或局部框变化；再提供 A 的正常移动终点。断言：

- B 保留原 `item_id` 和正式身份；
- B 的轻微变化不产生 `MOVED`；
- B 不因一两张变化框而产生 `OUT`；
- B 已有的原位/局部/静态恢复能力不被新的 A 候选图抢走；
- A 仍按既有真实移动证据和连续无手门槛确认 MOVED；
- 如果 B 的框确实是已确认 blocker 造成的局部框，只在“已确认遮挡上下文、双方唯一、
  不刷新不可靠 `base_box`”的受限条件下恢复 B，不能把普通小位移全局解释为遮挡。

## 10. 实施顺序和验收

严格按下列顺序实施，避免把多个根因混到一个大改动里：

1. 保存现有完整 replay、关键事件序列与实机日志作为基线；
2. 先固定第 9.5、9.6 节的低置信度和小位移回归基线，确认当前正确行为；
3. 新增第 9.1 节回放，只实现候选证据分级和双向预约；
4. 运行所有既有 HAND、CONTACT、D、alias、IN、OUT、MOVED、低置信度和微位移回放；
5. 再新增第 9.2 节回放，只实现窄 OUT 延迟保护和失败回退；
6. 再实现/验证 blocker 生命周期重算，不改变身份仲裁；
7. 最后新增第 9.3 节回放并实现边缘残余容差；如新增参数，同步更新
   `超参数位置与调节说明.md`；
8. 每一步均运行完整模块化 replay、ASAN/UBSAN、`git diff --check`；
9. 若任何已有的真实新 D、低置信度假入库防御、正常微位移、正常 OUT 或 alias
   回放失败，立即停止在上一个通过点定位原因，不能以调大阈值或删除保护来硬通过。

## 11. 完成条件

本轮只有同时满足下面条件才算完成：

- 相同稳定无手帧不会让 `op=11` 类场景永久 `defer-commit`；
- 真实同级歧义仍保持未决，未被 `item_id`、数组顺序或 timeout 强行收敛；
- 真实新 D 仍不被错误合并为旧 MOVED，也不产生假 IN；
- 低置信度单帧假框不产生 IN、不增加库存、不成为 blocker；
- 轻微碰撞/检测抖动不产生假 MOVED 或假 OUT，原有小位移容忍仍有效；
- 移动 A 对 C 的可靠遮挡不会因 A 晚一帧确认而把 C 先判 OUT；
- A 失败时 C 能正常恢复 OUT 流程，保护不会永久保留错误库存；
- 严格覆盖语义保留，边缘容差不接受内部空洞或未确认 blocker；
- `block_ids` 跨操作按已确认关系保留、更新和删除；
- 已有正式库存、事件、`item_id`、`base_box`、低置信度防御、微位移容忍、HAND、
  CONTACT、D、C-D alias、IN、OUT 和正常 MOVED 均没有回归；
- 完整 replay、ASAN/UBSAN 和 `git diff --check` 全部通过。

本文件的核心原则是：

```text
弱候选可以继续阻止草率入库，但不能永久否决更强且双方唯一的旧物归属；
临时移动证据可以短暂保护可能被遮挡的旧物不先 OUT，但不能提前创造 blocker；
只有身份和最终位置已确认，才允许用 base_box 写 block_ids、判断 OCCLUDED、提交事件。
```
