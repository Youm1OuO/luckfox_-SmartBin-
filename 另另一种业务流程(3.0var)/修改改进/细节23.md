# 遮挡与露出结算优化指导（细节23候选）

本文是下一次修改代码前的设计指导，不是本次代码修改记录。它把用户最新补充的业务定义与《遮挡优化.md》中关于工作库存、`base_box`、`block_ids` 和事件顺序的约束合并起来。

本次要解决的实机案例是：橙子 `#2` 从左侧移动到右上方，苹果 `#3` 原来可见，橙子移动后苹果没有 YOLO 框。期望正式结果为：

```text
橙子 #2: MOVED
苹果 #3: OCCLUDED
```

当前日志却出现：`#2` 已确认 `MOVED`，`#3` 的覆盖率约为 `0.898`，但 `edge=0/full=0`，随后可见数量缺口使整次操作 `defer-commit`。

## 1. 最新业务定义

### 1.1 什么叫遮挡

当物品 A 已确认移动到一个新位置，或者物品 A 已经确认是新进入的物品，并且 A 与物品 B 原来的位置有合理的空间重叠，同时满足以下因果关系：

1. B 在 A 到来前是已知且可见的；
2. A 到来后，B 在原位置不再有合法的 YOLO 直接观察；
3. B 没有自己的明确 `MOVED` 或 `OUT` 证据；
4. A 的当前位置能够解释 B 为什么看不见；

则 B 应判定为【遮挡】。

这里不要求 A 的框把 B 的 `base_box` 几何上覆盖到零残余。以下两种情况都属于【遮挡】：

- A 从肉眼看完全挡住 B；
- A 挡住 B 的大部分，肉眼还可以看到 B 的一点边缘，但 B 已经没有 YOLO 框。

因此，“遮挡”是一个由确认的前景事件和目标检测消失共同构成的因果结论，不是单纯的矩形差集面积结论。

### 1.2 什么叫露出

当物品 C 已确认移动离开或确认出库，C 原来作为 blocker 挡住了物品 D，并且：

1. D 之前处于【遮挡】状态；
2. C 的 blocker 关系被正式移除；
3. C 离开后，D 在原来位置重新获得合法 YOLO 直接观察；

则 D 应判定为【露出】。

如果 C 离开后 D 仍然没有检测框，但当前已经没有足够的遮挡解释，不能立刻判定 D 露出，也不能立刻判定 D 出库；应进入普通的无手缺失确认链。

### 1.3 业务定义与几何证明的关系

需要保留两种不同的遮挡证据：

```text
GEOMETRIC_FULL
    严格并集覆盖或受限的外边缘残余覆盖。
    用于已有几何覆盖证据、历史 proof 校验和兼容旧流程。

CAUSAL_FRONT_MISSING
    已确认 IN/MOVED 前景事件 + 与目标旧位置重叠
    + 目标由可见变为无合法观察。
    不要求 remaining 面积接近零。
```

`apply_cover()`、严格覆盖和 edge-residual 规则仍然有价值，但不能继续作为所有 `VISIBLE -> OCCLUDED` 结论的唯一入口。新的因果证据只在前景事件已确认、目标身份和缺失关系足够清楚时使用，不能把任意一帧重叠或任意漏检当遮挡。

## 2. 当前案例的根因

当前帧序说明：

1. 橙子 `#2` 最终被确认移动并放置到右上方；
2. 苹果 `#3` 在有手阶段进入 `HAND_FULL_BLOCKED/POSSIBLE_MOVED`；
3. 无手帧中苹果 `#1` 和 `#4` 的两个框分别被它们自己合法认领，苹果 `#3` 没有直接框；
4. `#2` 与 `#3` 的旧 `base_box` 覆盖率约 `0.898`，残余位于顶部外边界，约 `18` 像素；
5. 当前 edge-residual 容差为 `8` 像素，因此 `edge=0/full=0`；
6. 因为没有正式 full proof，后续 visible-count 把 `#3` 记为缺口，最终延期提交。

这里至少有两个实现层问题：

- 当前几何 full/edge 门槛过早阻断了“前景事件导致目标无法检测”的因果证据；
- `HAND_FULL_BLOCKED/POSSIBLE_MOVED` 和手部移动被过宽地当成了目标独立离开证据，阻止了橙子对苹果的遮挡解释。

上一次关于“正式 full proof 优先于同类身份歧义”的修改不是无效；只是本案例的 `edge=0/full=0/observation-conflict=0` 没有进入那条分支。本次应补齐另一条因果路径，不能把上次修改简单回退。

## 3. 不可破坏的现有功能

本次修改必须以当前已经有效的功能为基线，不能因为修一个遮挡案例而破坏其他场景：

- 正式库存 `inventory_` 与本次操作的 `working_inventory_` 必须继续隔离；手部操作中只修改工作库存，`replace_all()` 仍是唯一正式提交边界。
- `item_id` 仍是稳定库存身份；单帧 detection 不能直接创建正式库存，也不能直接删除正式库存。
- `base_box` 继续作为正式位置和 blocker 几何的主要基准；手框、预测框、轨迹中间点、低分临时框不能直接写成正式 `base_box`。
- `block_ids` 是目标侧“已确认位于目标前方的库存物品 id 集合”，不是每帧交叠缓存。当前漏检不能静默删除历史 blocker。
- 未确认的 D、quarantine D、HAND 框、预测框和路径中间点不能成为正式 blocker。
- 同类物品的 owner、C-D alias、D guard、claim grace 和 visible-count 保护仍必须保留。
- 普通 `OUT` 仍需要自身缺失证据；目标仅仅暂时看不见时，不能直接 `OUT`。
- `MOVED/OUT/IN` 等前景事件必须先于受影响目标的 `OCCLUDED/REVEALED` 事件发布。
- 多层遮挡必须支持：一个 blocker 离开后，如果还有其他 blocker，目标不能错误露出。
- 正常静态场景、手短暂擦过但物品未移动、真实整理、真实出库、入库和同类相邻场景不能退化。

本次不得通过全局放宽 YOLO/NMS、普通匹配、轨迹匹配、D/MOVED/OUT 帧数来解决问题。

## 4. 数据和证据的明确区分

实现时应把以下事实分开，不能用一个布尔值混合：

```text
observation
    当前帧是否看到一个 detection。

identity
    detection 是否已经唯一归属于某个 item_id。

front_event
    某个 item_id 是否已经确认 IN、MOVED 或 OUT。

block_relation
    某个确认前景 item_id 是否与目标旧 base_box 有正面积交集。

target_missing
    目标在前景事件之后是否没有合法直接观察。

independent_target_exit
    目标自身是否已有独立、唯一、足以解释其离开旧位置的证据。

formal_visibility
    最终的 VISIBLE/OCCLUDED 状态及其 proof。
```

建议在遮挡计划中增加或明确以下信息（名称可按现有代码风格调整）：

```cpp
struct CausalOcclusionEvidence {
    bool candidate = false;
    int target_id = -1;
    std::set<int> witness_blocker_ids;
    int front_event_frame = -1;
    int target_last_visible_frame = -1;
    BBox target_anchor_box;
    std::map<int, BBox> blocker_boxes;
    bool target_had_legal_observation_before = false;
    bool target_has_unique_exit = false;
};
```

正式 proof 至少要能回答：是谁在什么帧确认移动/入库、它覆盖了哪个目标旧位置、目标最后一次合法可见是什么时候、为什么不是目标自己的 `MOVED/OUT`。

## 5. blocker 关系的统一维护

### 5.1 关系方向

`target.block_ids` 的方向固定为：

```text
target B  --blocker A-->  B.block_ids contains A.item_id
```

A 是挡住 B 的前景物品，不要把“B 与 A 有交集”反向写成 A 被 B 挡住。

### 5.2 什么时候增加关系

只有确认的前景事件才可以增加关系：

- 新物品 D 已完成规定的身份确认链，并进入工作库存；
- 旧物品 A 已确认 `MOVED`，并且已经得到本轮可靠的放置框；
- 已确认的其他前景事件按照同一事务顺序处理。

对每个工作库存中的旧目标 B：

```text
if A.item_id != B.item_id
and A 的可靠 placed_box/base_box 与 B 的旧 base_box 有正面积交集:
    B.block_ids.insert(A.item_id)
```

这里使用工作库存和可靠 `base_box`/`placed_box`，不能使用尚未放下的 HAND 局部框作为正式关系。

业务语义是“交集大于零”。工程实现可以保留极小数值 epsilon 过滤浮点噪声，但不能再要求完整覆盖才能建立关系。

### 5.3 什么时候删除关系

只有 blocker A 已确认移动离开目标旧位置或已确认 OUT 时，才能从所有目标的 `block_ids` 中删除 A。

对 `MOVED` 必须按原子顺序处理：

```text
1. 先从所有旧目标删除 A 的旧位置关系；
2. 清除 A 自己在旧位置上的历史 blocker 解释；
3. 更新 A 的可靠新 base_box/placed_box；
4. 再根据 A 的新位置给受它遮挡的目标增加新关系。
```

不能因为当前一帧检测不到 A 就删除关系，也不能先加新边再按旧关系清理，避免迭代顺序误删新边。

## 6. VISIBLE -> OCCLUDED 的新结算规则

对每一个本轮开始时为 `VISIBLE` 的旧目标 B，先处理自己的独立移动，再处理前景 A 的遮挡解释。

### 6.1 可以采用因果遮挡结论的条件

以下条件全部满足时，可以生成 `CAUSAL_FRONT_MISSING`：

1. A 是本轮已确认的 `IN` 或 `MOVED` 前景物品，不是未确认 D、手框或预测框；
2. A 的可靠当前位置与 B 原来的 `base_box` 有正面积交集；
3. B 在 A 事件之前有可靠的旧位置观察或已确认的可见库存状态；
4. A 事件之后，B 没有合法的直接观察；
5. 该缺失不是一个已经唯一归属于 B 的新位置 detection；
6. B 没有 `MOVED_CONFIRMED`、唯一终点和足够分离证据组成的独立离开结论；
7. 没有另一个尚未解释的同类身份冲突使“B 消失”无法归属。

这里不再要求：

- `remaining.area <= COVER_REMAINING_AREA_EPS`；
- `edge_residual_full == true`；
- 目标框剩余区域必须小于固定像素值。

严格 full/edge proof 仍然可以优先使用；如果严格 proof 失败，只要上述因果证据成立，就可以使用 causal proof。

### 6.2 目标仍然被看到时

如果 B 仍有合法、唯一的直接 detection：

- 可以把 A 加入 B 的 `block_ids`；
- B 保持【可见】状态；
- 不因为有交集就强行变成【遮挡】。

用户定义中的“部分遮挡也算遮挡”针对的是“B 已经没有 YOLO 框”的情况，不是要求所有有交集的物品都显示为 OCCLUDED。

### 6.3 目标在 HAND_* 中时

`HAND_PARTIAL_BLOCKED`、`HAND_FULL_BLOCKED`、`POSSIBLE_MOVED` 和单纯的 `has_meaningful_hand_move` 不能单独作为 B 的独立离开结论。

如果 B 只是被同一只手短暂影响，后来没有唯一移动终点，而确认移动的 A 已经覆盖 B 原位置，则：

```text
保留 B 原来的 item_id 和 base_box
清理 B 的 HAND 临时候选/手代理状态
把 B 转为普通 OCCLUDED
把 A 写入 B.block_ids
不发 B 的 OUT
```

只有以下证据才应阻止 A 的因果遮挡解释，并优先结算 B 自己：

- B 已经 `MOVED_CONFIRMED`；
- B 有唯一且连续的非共享终点框，并满足既有放下/分离条件；
- B 的候选框明确不能归属于 A 的遮挡，而是 B 自己在其他位置重新出现；
- B 已有独立确认的 OUT 结论。

这一步是本次案例的关键：苹果 `#3` 的“手曾经移动过”不能自动等价于“苹果已经自己离开”，否则橙子 `#2` 永远无法把它解释为遮挡。

### 6.4 visible-count 的处理顺序

因果遮挡计划必须先于普通 visible-count 缺口结算：

```text
先生成并确认 A -> B 的 causal occlusion plan
    ↓
被 causal proof 保护的 B 不累计 visible-count OUT 缺口
    ↓
再对剩余未解释目标执行普通 visible-count / direct-missing 证据
```

如果同一帧已经通过 A 的确认移动和 B 的因果缺失证明，不能再因为同类物品数量少一框而把本次操作无限延期。

如果存在真正无法解决的 owner/alias 冲突，仍要保持未决；不能用 visible-count 强行挑身份，也不能用 causal proof 掩盖一个明确的 B 自己移动证据。

## 7. OCCLUDED -> REVEALED 的新结算规则

当确认 blocker C 移动离开或 OUT 时，先从工作库存所有目标的 `block_ids` 删除 C，再重新计算受影响目标的剩余 blocker 集合。

对曾经被 C 遮挡的目标 D：

1. 如果还有其他有效 blocker 能解释 D 被挡住，D 保持【遮挡】，不发 REVEALED；
2. 如果 C 离开后 D 在其原 `base_box` 附近获得合法、唯一直接观察，并且此前确实是由 C 的关系解释不可见，则 D 转为【可见】，产生 `REVEALED`；
3. 如果 blocker 关系已经失效但 D 仍没有合法观察，不能伪造 REVEALED，也不能立即 OUT，转入普通缺失确认；
4. 如果 D 重新出现在自己确认的移动终点，而不是旧位置，则按 D 自己的 MOVED 结算，不能把它当成旧遮挡的露出。

事件顺序必须是：

```text
C MOVED/OUT
    ↓
删除 C 的 blocker 关系
    ↓
D REVEALED（仅当 D 重新获得合法观察）
```

## 8. 目标自身移动与遮挡的优先级

建议采用以下优先级，而不是简单用一个 `target_has_independent_exit_evidence` 布尔值覆盖所有情况：

```text
明确的目标自身 MOVED/OUT 结论
    > 已确认前景造成的因果遮挡
    > 目标 HAND_* 的未决移动迹象
    > 单帧漏检、数量缺口或几何交叠推测
```

注意：第一行是“明确结论”，不是“曾经被手影响”。`HAND_*` 和手移动只能说明需要继续观察；如果它没有唯一终点，不能阻止一个已经确认的前景 A 对它产生遮挡解释。

## 9. 推荐的正式结算顺序

`settle_no_hand_frame_()` 应保持单向、可解释的阶段顺序：

1. 处理当前检测的身份归属、同类 owner、D/alias 和原位证据；
2. 结束本帧可以确认的 HAND/CONTACT 临时状态，但不把未决手移动直接变成 OUT；
3. 确认本轮 `IN`、`MOVED`、`OUT` 前景事件及可靠 `placed_box/base_box`；
4. 按事件先删除旧 blocker 关系，再增加新前景关系；
5. 对每个受影响目标生成几何 full/edge 或 causal front-missing proof；
6. 先应用 `VISIBLE -> OCCLUDED`、`OCCLUDED -> REVEALED` 计划；
7. 清除被正式遮挡 proof 保护的 visible-count 和普通 missing 证据；
8. 对仍无遮挡解释的目标执行原有普通 OUT/visible-count 结算；
9. 按 `MOVED/IN/OUT -> OCCLUDED/REVEALED` 顺序生成事件；
10. 只有所有未决状态已解决时，调用 `replace_all()` 原子提交，否则保留工作库存并延期。

同一无手帧不应因为多次 `refresh_confirmed_blockers_()` 重复增加同一种连续计数。若需要固定点重算，只允许重算关系和计划，不重复推进 frame evidence；每一类计数在本帧最多增加一次。

## 10. 建议的代码职责调整

不要把所有新逻辑塞进一个函数。可以按现有模块职责拆分：

### `include/session_internal.h`

- 扩展遮挡证据/计划类型，区分几何 proof 与 `CAUSAL_FRONT_MISSING`；
- 明确计划中的 blocker 事件帧、目标最后可见帧、目标独立终点和 causal witness；
- 保持纯函数接口，不让 `session_occlusion.cc` 直接读取 `SessionManager` 私有运行时。

### `src/session_occlusion.cc`

- 保留矩形差集、严格覆盖、edge-residual 和 proof witness 校验；
- 新增“确认前景 + 目标缺失 + 空间交集”的 causal occlusion evaluator；
- 集中处理 blocker graph 的加边、删边、旧位置关系失效和 proof 生命周期；
- 不再让 `full/edge` 成为所有可见到遮挡转换的唯一条件；
- 不在这里处理 detection owner、HAND 轨迹或 visible-count 细节。

### `src/session_settlement.cc`

- 负责把已确认的前景事件、目标合法观察、目标独立终点传给遮挡 evaluator；
- 将 causal occlusion plan 放在 visible-count 和普通 OUT 之前；
- 对被 proof 保护的目标撤回/暂停普通缺失证据；
- 保证事件顺序和 `replace_all()` 原子提交；
- 合并重复的遮挡刷新和计数推进路径，避免同一帧重复累计。

### `src/session_hand.cc`

- 保留 HAND/CONTACT 的既有证据链；
- 将“手移动过”与“目标已独立移动”分开；
- 不要因为目标进入 `HAND_FULL_BLOCKED` 就直接给 settlement 一个不可推翻的独立离开结论；
- 目标没有唯一终点、而被确认前景覆盖时，应允许统一释放为普通 OCCLUDED。

### `src/session_no_hand.cc`

- 继续维护原位观察、reappear、无手连续缺失和 OUT 证据；
- 在 causal occlusion plan 已确认后，不再为同一目标追加普通 visible-count/OUT 缺失；
- blocker 关系尚未解决时继续保留工作库存，不删除目标。

### `src/session_geometry.cc`

- 只提供正面积交集、可靠框、差集、边缘残余等纯几何工具；
- 不在全局修改 YOLO/NMS 或普通匹配阈值；
- 如果新增 causal overlap helper，只作为数值噪声过滤，不承担“完整遮挡”语义。

### 回放测试

为当前精确帧序补充独立回放断言，不要只检查最终库存数量，还要检查事件顺序和 proof：

```text
MOVED(#2) 先于 OCCLUDED(#3)
#3 保留原 item_id 和原 base_box
#3.block_ids 包含 #2
#3 不产生 OUT
操作最终能够提交，而不是 defer-commit
```

## 11. 超参数处理原则

第一版实现优先不改 YOLO/NMS、普通匹配和 D/MOVED/OUT 参数，也不直接把 `COVER_REMAINING_AREA_EPS` 调大。

现有参数的职责应保持：

- `COVER_REMAINING_AREA_EPS`：严格几何覆盖的面积容差；
- `FLOW3_CONFIRMED_OCCLUSION_EDGE_RESIDUAL_PX`：受限外边缘残余 proof 的像素容差；
- `FLOW3_CONFIRMED_OCCLUSION_DISAPPEARANCE_MIN_COVER_RATIO`：旧的受限 disappearance 支持路径；
- `BLOCK_OVERLAP_AREA_EPS`：正面积交集的数值噪声过滤。

新的 causal occlusion 规则不应通过把上述参数全局放宽来实现。若最终确实需要新增参数，例如：

```text
FLOW3_CAUSAL_OCCLUSION_MIN_INTERSECTION_AREA
FLOW3_CAUSAL_OCCLUSION_CONFIRM_FRAMES
```

必须同时更新：

1. `include/fridge_config.h`；
2. `另另一种业务流程(3.0var)/超参数位置与调节说明.md`；
3. `另另一种业务流程(3.0var)/完整操作流程说明.md`；
4. 对应回放测试和日志说明。

调参时一次只改一个参数，小步回放以下场景：严格完全遮挡、只露边缘但无框、普通部分遮挡仍有框、真实 MOVED、真实 OUT、REVEALED、多层 blocker、同类相邻和 HAND 短暂擦过。

## 12. 必须通过的回放场景

### A. 当前实机案例

```text
初始：苹果 #3 可见，橙子 #2 在左侧
操作：橙子 #2 移到苹果 #3 原位置
结果：MOVED(#2), OCCLUDED(#3)
```

即使 `remaining` 还有外边缘残余，也必须通过 causal proof，不得因为 `edge=0` 卡住。

### B. 严格完全覆盖

保留原有严格 proof 和事件结果，不应退化。

### C. 只遮住大部分、B 无 YOLO 框

只要 A 已确认移动、B 旧位置可知、空间关系合理且 B 无自身移动/出库证据，应得到 OCCLUDED。

### D. A 与 B 重叠但 B 仍有唯一直接框

B 保持 VISIBLE，只更新 blocker 关系；不能因为交集存在就误报 OCCLUDED。

### E. B 自己确实移动

B 有唯一终点或已确认 MOVED 时，先结算 B 自己；A 不能把 B 的旧位置缺失伪装成遮挡。

### F. blocker 离开后露出

C MOVED/OUT 后，D 重新在旧位置被识别，产生 `REVEALED(D)`；事件必须排在 C 之后。

### G. blocker 离开但仍有第二个 blocker

D 继续 OCCLUDED，不产生 REVEALED。

### H. blocker 离开但 D 仍未被看到

不产生 REVEALED，也不立即 OUT；走原有普通缺失证据。

### I. 手短暂擦过目标

目标被建立 HAND_* 但回到原位时，保持原有 STATIC/可见结算；不能因为新增 causal 规则误报遮挡。

### J. 同类身份歧义

没有足够 owner/alias 证据时继续未决；不能用数量缺口强行认领，也不能用 causal proof 删除 D 或 C。

## 13. 完成标准

完成修改后必须：

1. 先逐个对照本文件的阶段顺序审计代码；
2. 编译正式工程和主机回放；
3. 回放当前案例及上述 A-J 场景；
4. 检查 `MOVED/IN/OUT` 在 `OCCLUDED/REVEALED` 之前；
5. 检查没有重复推进同一帧的 missing/disappearance 计数；
6. 检查正常静态、OUT、D/IN、同类 alias 和历史 blocker 回归；
7. 有超参数修改时同步文档；
8. 最后才考虑实机验证。

本方案的核心不是把一个 `remaining` 阈值调大，而是把“确认前景事件导致目标检测消失”作为一种受约束的正式遮挡证据，并让它与现有严格几何 proof、身份仲裁、HAND 轨迹和普通 OUT 证据各自承担清晰职责。
