# 低覆盖率推、拉物品的处理思路

手没有握住物品、只是用手指推动或拉动物品时，手与物品的覆盖率可能低于 `e2`。
这类情况不能当作普通静态物品，也不能直接登记为新物品 D。

## 1. 状态与保存位置

遮挡状态仍按覆盖率判断：

```python
r >= e1       -> HAND_FULL
e2 <= r < e1  -> HAND_PARTIAL
r < e2        -> 普通可见
```

低覆盖率但手与物品相贴时，另记录一个运行时接触状态：

```python
NONE -> CONTACT_CANDIDATE -> CONTACT_MOVING
```

建议保存为 `OperationTrack.contact_state`，不放进 `InventoryItem`：

```text
InventoryItem.status       = VISIBLE / OCCLUDED
OperationTrack.state        = NORMAL / HAND_PARTIAL / HAND_FULL / PLACED
OperationTrack.contact_state = NONE / CONTACT_CANDIDATE / CONTACT_MOVING
```

普通物品以及 `HAND_PARTIAL/HAND_FULL` 物品的 `contact_state` 默认是 `NONE`。若覆盖率后来达到 `e2`，接触候选转换到对应的 `HAND_*` 流程，不同时运行两套流程。

不需要扩大手框；接触条件使用手框与物品的距离及少量交集判断。

## 2. 轨迹的含义

全局 `hand_track` 继续记录手框，供整次操作和手离开后的判断使用。

`HAND_*` 物品可以保存手移动量和估计框，但真实检测框优先，不能只凭手移动量确认物品移动。

`CONTACT_CANDIDATE/CONTACT_MOVING` 中，手腕移动量可能没有意义，因此物品应使用实际检测框形成 `observed_track` 和 `observed_move_values`。手移动量最多作为辅助记录，不能直接用于该物品的主要估计轨迹。

## 3. 低覆盖率候选的确认

`CONTACT_CANDIDATE` 只表示“可能被推、拉”，暂时不确认移动。

后续检测到 B 时，B 必须满足：

- 与 A 同类，宽高与 A 的完整框按相对比例接近；
- 没有被其他库存物品认领；
- 与 A 的上一观测框或已有 `observed_track` 连续；
- 实际移动量超过检测抖动阈值；
- 初次确认时 B 应与手相贴。

只有唯一的 A 能解释 B 时才累计证据；多个同类物品都可能解释时保持未决，不生成 D。

连续两次得到有效 B 后：

```text
CONTACT_CANDIDATE -> CONTACT_MOVING
已确认移动标志（现有 hold_and_move）置为 True
```

之后沿 B 的实际轨迹继续处理；不再强制要求 B 每一帧都与手相贴。

## 4. 两个证据计数

```text
找到唯一且确实移动的 B：
    hold_evidence_count += 1
    not_hold_evidence_count = 0

A 在原位置重新出现：
    not_hold_evidence_count += 1
    hold_evidence_count = 0

当前帧没有可靠 B：
    两个计数都暂停
```

当 `hold_evidence_count >= 2` 时进入 `CONTACT_MOVING`；当 `not_hold_evidence_count >= 2` 时清除接触候选并恢复 `NONE`。不能因为单帧漏检就判断未移动，也不能立即判定出库。

## 5. 手离开后的处理

`CONTACT_CANDIDATE` 可能因漏检或歧义暂时停留，不能假设它一定会在手离开前结束。手离开后按以下顺序收尾：

```text
1. 先检查 A 的原位置；
2. 原位置找到 A       -> 没有移动，释放候选；
3. 原位置没有 A，再查 A 的 observed_track；
4. 找到唯一合理的 B  -> 确认整理/移动；
5. 都找不到           -> 先保持未决；
6. 稳定无手帧持续缺失且没有遮挡解释 -> 才确认出库。
```

`CONTACT_MOVING` 也使用实际 B 轨迹寻找终点；不能用错误的手框移动方向替代物品终点。

## 6. 手框不动时的跳帧

手框严格匹配且没有活动的 `HAND_*` 或 `CONTACT_*` 轨迹时，可以跳过重复帧。严格匹配应允许少量检测抖动。

只要存在未决轨迹，尤其是 `CONTACT_CANDIDATE/CONTACT_MOVING`，就不能因为手腕或手框没有明显移动而整帧跳过；物品可能被手指移动。

## 7. 每帧处理顺序

```text
1. 更新已有物品的 HAND_* 与 CONTACT_* 候选；
2. 用真实检测框、轨迹和连续证据确认旧物品是否移动；
3. 处理手离开后的候选和稳定快照；
4. 最后才把无法被任何旧物品解释的检测登记为新物品 D。
```

低覆盖率接触候选在移动确认前保持旧物品身份，避免“只是推动旧物品却误登记新 D”。
