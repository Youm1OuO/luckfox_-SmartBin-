# 细节1-21核心总结（供新对话使用）

本文是《细节1.md》至《细节21.md》的压缩设计结论，不替代具体回放、参数或实现细节。
新对话应先以本文理解业务规则；只有需要追查某一历史案例时，再打开对应原文。

## 1. 系统目标与正式事务边界

目标是在一次开门、手部操作、关门后的视觉序列中，可靠维护冰箱库存，覆盖放入、取出、
整理、遮挡、漏检和同类物品。

```text
inventory_                 正式库存，只在一次操作完成后改变
working_inventory_         本次操作的工作视图
operation_start_inventory_ 本次操作开始时的正式快照
```

- 有手阶段只积累事实和候选，不能提前改 `inventory_` 或发正式事件。
- 无手结算完成后，`replace_all()` 是唯一原子提交边界；`IN`、`OUT`、`MOVED`、
  `OCCLUDED`、`REVEALED` 都只能随该提交发布。
- `item_id` 是稳定库存身份。`base_box` 是可靠的完整位置；`box` 可以是最近的直接或
  局部观察。手框、预测框、路径中间点、低分临时框都不能写成正式 `base_box`。

## 2. Detection、身份与新物品

```text
C = 已有正式库存物品
B = 当前 detection 候选
D = 可能的新物品
```

- detection 不是身份。一个未匹配 B 不能直接等价于新 D。
- 每个 B 先尝试归属旧 C（完整原位、合法轨迹、已有运行时记录），再尝试已有暂定 D，
  最后才可创建新的 suspect D；同一帧必须一对一归属。
- 旧 C 的身份优先于 D。同类多个旧 C 都合理时必须保留未决，不能按 `item_id`、检测数组
  顺序、map 顺序、超时或宽松几何强行选择。
- D 仅可来自 `HAND_VISIBLE_D`、`C_POSITION_REPLACEMENT_D`、`POST_HAND_REVEAL_D`；
  后者还要求真实手操作、短后手窗口、靠近操作轨迹、旧 C/已有 D 均无法合法拥有该 B，
  并有后续直接自匹配。D 必须经连续无手直接确认才可 `IN`，消失的弱 D 直接丢弃，绝不
  产生 `OUT`。
- suspect D 与旧 C 的冲突使用 C-D alias/quarantine：可实时跟踪，但在证据不足时不能成为
  正式所有者、blocker，或挤掉旧 C。跨类别低分重复框只能作为只读 identity hint，不能
  删除 YOLO 输入或反向决定库存身份。

## 3. HAND、CONTACT 与旧 C 的动作证据

- HAND_PARTIAL/HAND_FULL 的 `hold_and_move == false` 表示尚未确认，不表示“没移动”。
  只有清晰有效的物体证据才累计正/负结论，连续两帧确认；遮挡、漏检、歧义只暂停，不清零。
- `hold_and_move == true` 也不等于已完成 `MOVED`。仍要等待物体实际终点、与手分离、
  物体滞后于手或稳定无手确认。手离开后：原位合法观察可静态结算；唯一合法终点可 `MOVED`；
  仅在没有遮挡解释且满足普通无手缺失证据时才可能 `OUT`。
- 低覆盖接触另走 `CONTACT_CANDIDATE -> CONTACT_MOVING`；主依据是物体实际路径而非腕部位移，
  需要连续有效观察，单帧漏检不能把它变成 D 或 OUT。
- 有活动 HAND/CONTACT 运行时记录时，不能因手静止而跳帧。小碰撞、YOLO 抖动、近原位灰区
  必须走已有的稳定静态结算，不能误报 MOVED/OUT。

## 4. 无手结算的正确顺序

```text
当前 detection 的身份归属
    -> 已确认前景关系与遮挡/露出资格
    -> 普通 visible-count / direct-missing OUT 证据
    -> 一次性更新 working_inventory、排序事件、replace_all() 提交
```

- 可见数量只是在单摄像头同类合并/缺失下的保守回退：先一对一保留已归属 B，再结合连续无手帧；
  不能仅由“同类数量”决定身份，也不能绕过 D、alias、遮挡或正常 OUT 防线。
- 被静态邻居严格拥有的 B，不能再充当另一个旧 C 的 reappear 候选或假 D；旧候选失效后应继续
  正常回退搜索，不能提前终止旧 C 生命周期。
- 普通 OUT 保留“两帧直接无手缺失 + 自身退出证据 + 无合法遮挡解释”的门槛。C 自己确认
  MOVED/OUT 的证据优先于别人可能覆盖它的推测。

## 5. 遮挡的统一因果模型

必须区分四层事实：

```text
observation（看到框） != identity（框已归属）
identity              != front relation（前景关系）
front relation        != formal visibility（VISIBLE/OCCLUDED）
OCCLUDED              != 永久免于 OUT
```

`target_C.block_ids` 表示“已确认、当前位于 C 前方的库存物品 id 集合”，是目标侧有向关系，
不是每帧重算的交叠缓存，也不自动等于 `OCCLUDED`。

- 仅由确认的 `IN`、`MOVED`、`OUT` 更新关系：确认前景物进入/移动到相交位置可加边；确认
  移走或 OUT 才可删边；当前漏检不能静默清历史边。MOVED 必须在同一事务中先去掉旧位置关系，
  再加新位置关系，避免迭代顺序删除新边。
- 未确认 D、quarantine D、HAND 框、预测框、路径中间点、低分重复框都不能成为 blocker。
- `VISIBLE -> OCCLUDED`：目标没有合法直接 observation，且确认的前景关系在本次使可靠
  `base_box` 的覆盖并集从不完整变完整；不能只凭目标自身缺失或一帧重叠。
- `OCCLUDED -> REVEALED`：历史 blocker 已确认移动/OUT，使覆盖由完整变不完整，且目标现在
  有合法直接 observation。只看到目标、但 blocker 关系未合法变化时，禁止 REVEALED。
- 覆盖使用矩形差集得到真实并集，不能把多个交集面积相加。严格覆盖优先；历史与当前若使用
  已批准的 edge-residual 证据，before/after 必须采用兼容语义，否则 blocker 离开会留下
  `block_ids` 已清空但状态仍为 OCCLUDED 的悬空状态。
- 若 blocker 关系失效但目标尚无合法直接观察，不能伪造 REVEALED；转入新的正常 OUT 证据链。
  事件因果顺序必须是前景 `MOVED/IN/OUT` 在前，受影响目标 `OCCLUDED/REVEALED` 在后。

## 6. 不可退化边界与代码职责

- 不为单一苹果/橙子案例全局放宽 `strict_match_box()`、`partial_match_box()`、
  `track_match_box()`、YOLO/NMS、D/MOVED/OUT 帧数或 edge-residual 阈值。
- 不隐藏、删除、重排业务 detection，也不让 OSD 与业务仲裁使用不同的检测集合。
- 旧 C 的最终正式结果只能是 STATIC、MOVED、OUT 或有充分因果的 OCCLUDED，不能被无证据的
  暂定 D 永久阻塞。
- 按职责拆分，而不是继续堆进一个大函数：`session_geometry.cc` 管纯几何；
  `session_ownership.cc` 管归属/C-D；`session_hand.cc` 管 HAND/CONTACT/D 证据；
  `session_no_hand.cc` 管无手观察和恢复；`session_settlement.cc` 管正式计划与提交；遮挡规模
  增长时独立放入 `session_occlusion.cc`。每次修改都补窄回放并跑既有全量回归。
