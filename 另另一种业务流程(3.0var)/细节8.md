# 同类物品一对一归属与新物品 D 准入

本文件优先级高于细节7及此前所有冲突规则。

3.0 继续逐张有效帧直接处理：不使用 SnapshotBuffer，不做投票或框平均；连续帧只用于同一对象的直接自匹配、缺失计数和未决状态推进。

## 1. 要修复的问题

本次测试中 #2 apple 与 #4 apple 的库存中心只差约 2 像素。这表示同类空间身份已经失真：一个 apple 检测框不能同时证明 #2 与 #4 都可见。

最终库存表仍打印两个旧 apple 坐标，不等于手离开时真的检测到两个独立 apple 框。未绑定的旧库存可能只是保留了操作前 box；判断原因必须看原始检测和本帧的实际 owner。

当前代码可能发生：

    旧库存：#2、#4 都在中央 X
    当前帧：B0 在中央 X，B1 在右侧 Y

    检查 B1 是否为 D：
    #2 用 B0 证明自己存在
    #4 又用同一个 B0 证明自己存在
    B1 被错误当成新 D

根因是 register_post_hand_reveal_suspects_ 中逐个旧 C 扫描 independent_detection，同一个检测索引可被重复使用；有手阶段的“同类旧 C 未解决”也没有持续到无手阶段。

同样地，旧 #1 soda_can 最终仍打印在旧位置，不表示系统确认它还在旧位置；只表示它既没有被确认 MOVED，也没有满足 OUT 条件，结算保留了操作前记录。此时若左侧 soda B 又进入 D 链路，就会同时留下 #1 并生成 #11，造成数量膨胀。

## 2. 必须成立的规则

### 一帧内一对一

    一个 B 最多属于一个旧 C 或一个已有 D。
    一个 C 最多认领一个 B。
    有歧义时不按 item_id、map 顺序或检测顺序强行选择。

同一个 B 不能同时证明两个旧 item_id 存在，也不能一边属于旧 C、一边成为新 D。

### 每个旧 C 必须有结论

每个 operation_start_inventory_ 中的旧 C，在本次操作内只有以下结论：

    AT_ORIGIN              唯一 B 确认仍在原位
    AT_NEW_POSITION        唯一 B 确认在自己的新位置
    OCCLUDED_CONFIRMED     被已确认前景框的覆盖并集完全遮挡
    OUT_CONFIRMED          满足现有连续无手直接缺失规则
    UNRESOLVED             无法唯一证明

前四种才是已解决。UNRESOLVED 不得伪装成 VISIBLE、OCCLUDED 或 OUT。

PLACED 只表示“有放下候选”，不等于 AT_NEW_POSITION；还必须有无手直接帧中的独占 B 确认。

### 旧 C 未解决时禁止 D

一个 B 连续出现两帧，只证明它存在，不证明它从冰箱外放入。

只要有可能解释该 B 的旧 C 是 UNRESOLVED：

    B 保持未决
    不创建/提升 D
    不产生 IN
    不按数量变化猜身份

可能旧 C 包括原位置、HAND/CONTACT/reappear/placed 路径可匹配者，以及同类基线碰撞组成员。

## 3. 新增运行时数据

数据只存在于一段连续手操作，不写入 InventoryItem 或后端。

    enum class IdentityResolution {
        UNRESOLVED,
        AT_ORIGIN,
        AT_NEW_POSITION,
        OCCLUDED_CONFIRMED,
        OUT_CONFIRMED,
    };

    struct FrameOwnership {
        // 当前直接帧中唯一确认的旧 C <-> B。
        std::map<int, int> old_item_to_detection;
        std::vector<int> detection_to_old_item;

        // 尚未唯一确认的候选关系，供日志和未决处理使用。
        std::map<int, std::vector<int> > item_candidates;
        std::map<int, std::vector<int> > detection_candidates;
    };

    struct UnresolvedSameClassClaim {
        int cls_id;
        BBox first_box;
        BBox last_box;
        int direct_self_match_count;
        bool has_hand_source;
        bool first_seen_in_post_hand_window;
        std::set<int> possible_old_item_ids;
    };

SessionManager 保存：

    old_item_resolution_
    unresolved_same_class_claims_
    同类基线碰撞组

claim 表示“B 仍可能是旧 C，也可能是 D”，它不是 D。

## 4. 每张直接帧的处理顺序

这里的“当前帧”是当前有手或无手直接帧，不是快照。

### 1. 先建立 FrameOwnership

旧 C 与 B 同时建立候选边：

1. 未活动 C 的原位置严格匹配。
2. 已确认放下位置、已确认 reappear 候选。
3. CONTACT 的真实 observed_track。
4. HAND 的预计框与预计路径。
5. 原位置局部匹配，只作为弱候选。

再全局做一对一仲裁：

    C 和 B 两侧均唯一，或证据有明确领先差距，才正式绑定。
    静态原位严格匹配可优先于宽松 HAND 路径，
    但只有在所有候选中独占时才能锁定。

不能简单实现为：

    所有静态库存先抢框 -> 再处理 HAND/CONTACT

因为一个 B 可能同时是“静态 C 的原位框”和“活动 C 的移动终点”。这种冲突必须保持未决，不能由固定顺序决定。

现有 bind_mutually_unique 和 bind_mutually_unique_track_paths 的“双方唯一才绑定”原则应抽成统一 FrameOwnership，供有手、无手、最终结算共用。

### 2. 未决旧 C 必须先认领剩余 B

原位严格匹配已经唯一锁定的静态 C 不再参与后续竞争。随后对每个仍为 UNRESOLVED 的活动 CONTACT_* / HAND_* 旧 C，只检查 detection_to_old_item 中没有 owner 的 B：

    B 与 C 自己的 CONTACT observed_track 或 HAND 预计路径匹配；
    B 不严格属于其他旧 C；
    没有第二个旧 C 也能合理解释 B；
    C 原位置没有唯一 B，且没有完整遮挡解释。

满足时，B 必须先作为 C 的 reappear_candidate，而不是 D。下一张无手直接帧仍匹配同一个 B，才将 C 设为 AT_NEW_POSITION，并产生 MOVED C.item_id。

旧 C 一旦进入 CONTACT_* / HAND_*，单帧漏检或路径暂时中断都不能释放/删除其 OperationTrack；必须持续到原位、新位置、完整遮挡、确认 OUT 或本次操作放弃为止。

若 B 能被多个旧 C 解释、路径不可信、或下一张不能自匹配，则 C 与 B 保持 UNRESOLVED，不能转为 MOVED、OUT 或 D。

CONTACT_* 只使用物品真实检测形成的 observed_track；HAND_* 才使用完整旧框加 move_values 形成的预计路径。

### 3. 保存仍未解决的 B

未认领 B 若仍有可能旧 C，创建或更新 UnresolvedSameClassClaim。后续帧按同类和框连续性直接自匹配；B 消失则丢弃 claim，不产生 IN。

不能只打印“同类旧 C 未解决”后在下一阶段忘记它。

### 4. 最后才允许 D

HAND_VISIBLE_D、C_POSITION_REPLACEMENT_D、POST_HAND_REVEAL_D 都调用同一个门：

    can_start_new_d_for_claim(claim, frame_ownership)

仅当以下条件全满足时启动 D：

1. B 未被旧 C 或已有 D 占用。
2. B 有本次手操作来源：有手帧贴手/替代位置出现，或手离开窗口内首次出现且接触 hand_track。
3. possible_old_item_ids 中每个旧 C 都已解决。
4. 相关同类基线碰撞组已经解除。
5. 当前帧没有新的同类歧义。

旧 C 守卫未解除前，B 的连续出现只更新 claim，不能计入 D 的确认数。守卫解除的当前帧才算 D 第 1 张确认帧，下一张无手直接帧仍须自匹配。

### 5. 结算

has_unresolved_no_hand_state_ 必须包含：

    UNRESOLVED 旧 C
    未结束的 claim
    同类基线碰撞
    尚未完成直接确认的 D

任意一项存在时：

    不 replace_all 正式库存
    不 clear_runtime_after_commit_
    不产生 IN / OUT / MOVED

旧 C 成功绑定 B 时，只更新旧 C 并可产生 MOVED；同一个 B 绝不能再产生 IN。

## 5. 代码改动

### session.h

1. 增加 IdentityResolution、FrameOwnership、UnresolvedSameClassClaim。
2. 给 SessionManager 增加旧 C 结论表、未决 claim、基线碰撞组。
3. OperationTrack 保留“此 C 是否仍未解决”的运行时信息，不写入 InventoryItem。

### session.cc

1. reset_operation_runtime_ / begin_working_operation_：

       清空新状态；
       复制 operation_start_inventory_ 后检查同类基线碰撞；
       碰撞成员初始为 UNRESOLVED。

2. process_effective_hand_frame_ / observe_no_hand_frame_：

       每帧先生成 FrameOwnership；
       先锁定唯一原位静态 C；
       再让 UNRESOLVED CONTACT/HAND C 认领未占用且唯一的路径 B；
       之后才处理已有 D 和新 D；
       不允许各自独立遍历 detections 得出矛盾结论。

3. scan_or_update_suspects_：

       同类旧 C 未解决时写入/更新 claim；
       不再只有局部 unresolved_same_class_old 变量和 printf。

4. register_post_hand_reveal_suspects_：

       删除每个 old C 各自扫描 independent_detection；
       改读 FrameOwnership 与 old_item_resolution_；
       不再因 OperationTrackState::PLACED 直接跳过旧 C；
       D 守卫未通过时更新 claim，不创建 D。

5. settle_no_hand_frame_ / has_unresolved_no_hand_state_：

       使用同规则的一对一 owner；
       claim、碰撞组、UNRESOLVED 旧 C 必须阻止提交；
       全部旧 C 已解释且 D 已直接确认后才提交。

## 6. 损坏基线、日志和测试

在首张无手校验及 begin_working_operation_ 后检查同类基线碰撞。多个同类旧框只能对应同一个 B、却不能形成一对一分配时：

    不更新多个 item 到同一个 B；
    不因漏检判 OUT；
    不伪装为 OCCLUDED；
    保持 UNRESOLVED，并阻挡相关同类 D。

当前真实 5 件却错误增长到 7 件的库存不能继续用作基线。先从可信后端恢复 5 件，或受控校正去除错误 #11 / #12；再让两个 apple 分开、无遮挡地出现，用两个独立完整框重建基线。

日志至少输出：

    [OWNERSHIP] frame、B 索引、候选 C、owner 或 AMBIGUOUS
    [D-GATE] 被阻挡的旧 C 及其 IdentityResolution
    [INIT-IDENTITY] 同类基线碰撞组

主机回放至少覆盖：

1. #1 soda_can 的有手路径中断，但无手帧的剩余 soda B 唯一接上 #1 路径：下一张无手帧自匹配后只产生 MOVED #1，库存仍为 5，绝不生成 #11。
2. #2/#4 都能匹配同一个 apple B：B 不获得双 owner，无 apple IN、OUT 或错误位置更新。
3. 两个 apple 各有独立 B：建立两个不同 owner，解除碰撞。
4. 旧 C 未解决时出现同类真实 D：保持 claim，不提前 IN。
5. 旧 C 解决后 D 连续两张无手直接帧出现：只产生一次 IN。
6. 会话结束仍未决：不提交工作库存，正式库存保持操作前状态。

验收标准：

    单纯整理只产生 MOVED，库存数量不变。
    一个 B 永远不能证明两个 item_id。
    真实 D 可以延迟确认，但不能抢走旧 C 的身份。
