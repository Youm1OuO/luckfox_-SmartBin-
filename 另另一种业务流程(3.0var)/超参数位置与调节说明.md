3.0var 超参数位置与调节说明（3.0-r21 简明版）
====================================================

当前版本是 `3.0-r21`。r21 新增了只用于“确认前景 + 连续消失支持遮挡”的专用参数；
它不改变 YOLO 全局阈值、身份归属、D/MOVED 门槛，也不改变 OSD 输入。

调参原则：一次只改一项，小步改动；每次至少回放未移动、移动、取出、放入、遮挡、
相邻同类和 CONTACT 推动场景。普通无手状态只使用严格匹配；HAND_* / CONTACT_* 才能在
严格匹配失败后使用该物品自己的连续局部证据。这是固定业务规则，不是可调参数。

参数主要使用位置：

`src/yolov5n.cc`：候选阈值和 NMS 调用。
`src/postprocess.cc`：最终食品/手分数过滤和 NMS 结果整理。
`src/session_geometry.cc`：严格、局部、轨迹、手框和位移几何。
`src/session_ownership.cc`：同类 owner、CONTACT、D 和最终移动判定。
`src/session_hand.cc`：HAND/CONTACT、证据计数和放下。
`src/session_no_hand.cc`：无手连续确认、恢复和 OUT。
`src/session_settlement.cc`：可见数量、遮挡、IN/OUT/MOVED 提交。
`src/main.cc`：顶层门状态机和业务输入。
`src/app_door_state.cc`：暗帧/亮度测量。
`src/app_display.cc`：OSD 显示颜色和强手提示。

## 检测与显示

`CLASS_HAND = 33`
    作用：模型中“手”的类别 ID。
    调大：不是数值阈值；新模型时必须改成真实手类别。
    调小：任意改成错误 ID 都会把错误类别当作手。

`YOLO_CANDIDATE_SCORE_THRESH = 0.01`
    作用：RKNN 原始候选粗筛，由 `yolov5n.cc` 传给后处理。
    调大：候选更少、噪声更少，但遮挡低分框更易漏掉。
    调小：召回更多低分框，但噪声和后处理量更多。

`YOLO_OBJECT_SCORE_THRESH = 0.25`
    作用：NMS 后食品框进入业务层的最低分数。
    调大：假框更少，但遮挡物品更易直接漏掉。
    调小：召回更多，但状态机要处理更多噪声。

`YOLO_HAND_SCORE_THRESH = 0.30`
    作用：NMS 后手框的最低分数。
    调大：假手更少，但漏掉真手会过早进入无手收尾。
    调小：更容易保持 HAND，误手也会延迟收尾。

`HAND_CONTEXT_SCORE_THRESH = YOLO_HAND_SCORE_THRESH`
    作用：手框进入 `hand_boxes` 的门槛。
    调大：它是上项的别名，不应改成不同值。
    调小：同左。

`OSD_STRONG_HAND_SCORE_THRESH = 0.45`
    作用：只决定 OSD 是否把手显示为“强手”。
    调大：更少强手提示；不影响业务。
    调小：更多强手提示；不影响业务。

`OSD_STRONG_HAND_MIN_AREA_RATIO = 0.002`
    作用：只决定 OSD 强手所需的最小面积比例。
    调大：更少强手提示；不影响业务。
    调小：更多强手提示；不影响业务。

`OSD_LOW_CONFIDENCE_OBJECT_SCORE_THRESH = 0.50`
    作用：只决定业务有效框的 OSD 颜色。
    调大：更多框显示为低置信颜色；不影响输入或库存。
    调小：更少框显示为低置信颜色；不影响输入或库存。

`INFER_INPUT_BGR2RGB = false`
    作用：推理前是否转换 BGR 到 RGB。
    调大/开启：设为 `true` 会转换；当前模型实测识别变差，不建议开启。
    调小/关闭：设为 `false`，保持当前 BGR 输入。

## 库存身份与几何匹配

`INVENTORY_STRICT_CENTER_NORM = 0.26`
    作用：普通无手严格匹配的中心距离容差。
    调大：更抗框抖动，但相邻同类串身份风险更高。
    调小：身份更安全，轻微框变化也可能匹配失败。

`INVENTORY_STRICT_WIDTH_RATIO = 0.25`
    作用：普通无手严格匹配的宽度容差。
    调大：更宽松，框抖动更容易保持身份。
    调小：更严格，尺寸轻微变化也可能匹配失败。

`INVENTORY_STRICT_HEIGHT_RATIO = 0.25`
    作用：普通无手严格匹配的高度容差。
    调大：更宽松，框抖动更容易保持身份。
    调小：更严格，尺寸轻微变化也可能匹配失败。

`INVENTORY_PARTIAL_IOM = 0.84`
    作用：局部框与完整框的 IoM 要求。
    调大：更严格，局部框更难继承旧身份。
    调小：更宽松，遮挡召回更好，但误认邻居风险更高。

`FLOW3_HAND_PARTIAL_MIN_OBSERVED_COVER = 0.30`
    作用：手影响时，局部框至少落在旧框内的比例。
    调大：错误认领更少，也更易把旧物漏成 D。
    调小：遮挡更稳，也更易认领同类邻居。

`FLOW3_HAND_PARTIAL_MAX_AREA_RATIO = 1.35`
    作用：手影响局部框相对旧框允许的最大面积比例。
    调大：更宽松，减少遮挡下重复 D，也更易吸收邻居。
    调小：更严格，身份更安全，也更易漏局部框。

`FLOW3_HAND_PARTIAL_CENTER_NORM = 0.85`
    作用：手影响局部框相对旧框允许的中心偏差。
    调大：更宽松，遮挡下更易保住旧身份，也更易串邻居。
    调小：更严格，局部框偏移时更易漏掉。

`FLOW3_TRACK_PARTIAL_IOM = 0.50`
    作用：HAND/CONTACT 轨迹的局部重叠要求。
    调大：更严格，路径误配更少，快速/局部框更易断。
    调小：更宽松，轨迹更连续，邻居误配风险更高。

`FLOW3_TRACK_CENTER_NORM = 0.75`
    作用：HAND/CONTACT 预计位置的中心容差。
    调大：快动作更易保持身份，邻居串身份风险更高。
    调小：身份更安全，快动作更易保持未决。

`FLOW3_TRACK_WIDTH_RATIO = 0.65`
    作用：HAND/CONTACT 预计位置的宽度容差。
    调大：更宽松，尺寸变化更易连续匹配。
    调小：更严格，尺寸抖动时更易未决。

`FLOW3_TRACK_HEIGHT_RATIO = 0.65`
    作用：HAND/CONTACT 预计位置的高度容差。
    调大：更宽松，尺寸变化更易连续匹配。
    调小：更严格，尺寸抖动时更易未决。

`FLOW3_REAPPEAR_CANDIDATE_CENTER_NORM = 1.25`
    作用：C 暂不可见后，把 B 暂记为 `reappear_candidate` 的中心范围。
    调大：更容易把移动 C 接回，真实新 D 更可能延后确认。
    调小：更难串身份，快移动或模糊时更易走 D/未决路径。

`FLOW3_REAPPEAR_CANDIDATE_WIDTH_RATIO = 0.85`
    作用：`reappear_candidate` 的宽度容差。
    调大：更容易接回尺寸变化的旧 C，也更易吸收邻居。
    调小：更严格，尺寸变化较大时更易未决。

`FLOW3_REAPPEAR_CANDIDATE_HEIGHT_RATIO = 0.85`
    作用：`reappear_candidate` 的高度容差。
    调大：更容易接回尺寸变化的旧 C，也更易吸收邻居。
    调小：更严格，尺寸变化较大时更易未决。

`FLOW3_OLD_POSITION_OVERLAP_AREA = 16`
    作用：框算作占据旧位置的最小交集面积。
    调大：要求更明显的占位，抗边缘抖动，但可能漏局部露出。
    调小：对小交集敏感，也更易受框抖动影响。

## 跨类别重复身份提示（仅当前帧）

以下参数位于 `include/fridge_config.h`，由 `src/session_ownership.cc` 计算提示，
再由 `src/session_no_hand.cc` 在旧物无手原位仲裁的窄边界使用。它们不是 YOLO 过滤、
NMS、OSD 或 D 入库阈值：检测框不会被删除，仍保留为 D guard 的弱冲突边。只有低分
框与明显更高分的异类框几乎同框，且旧物已经有真实移动证据和可靠替代终点时，才会
在当前帧暂时降低该低分框对旧物原位身份的权威；普通异类部分重叠不会触发。

`FLOW3_CROSS_CLASS_DUPLICATE_LOW_SCORE_MAX = 0.45`
    作用：可疑跨类别重复框允许的最高分数。
    调大：更多低/中分框可进入重复提示，身份保护更积极，也可能压低真实静态低分物品的原位权威。
    调小：只处理更低分的可疑框，误抑制更少，但漏掉分数稍高的重复框。

`FLOW3_CROSS_CLASS_DUPLICATE_SCORE_GAP_MIN = 0.20`
    作用：异类竞争框相对可疑框必须高出的最低分数差。
    调大：要求更明显的高分竞争框，提示更保守。
    调小：分数接近时也可能提示，召回更高但普通异类重叠的误触发风险增加。

`FLOW3_CROSS_CLASS_DUPLICATE_IOM_MIN = 0.85`
    作用：两框几乎同一检测假设时的最小 IoM；IoM 是交集相对较小框的比例。
    调大：只接受更完全的同框重复，误触发更少。
    调小：允许更明显的框偏差，召回更高但真实重叠更容易被提示。

`FLOW3_CROSS_CLASS_DUPLICATE_CENTER_NORM_MAX = 0.16`
    作用：可疑框和异类竞争框的最大归一化中心距离。
    调大：容忍中心偏移，重复召回更高，也更易把相邻重叠当重复。
    调小：要求中心几乎一致，身份保护更窄。

`FLOW3_CROSS_CLASS_DUPLICATE_SIZE_RATIO_MAX = 0.20`
    作用：两框宽度和高度相对差的上限（宽、高分别检查）。
    调大：容忍尺寸变化，重复提示更容易触发。
    调小：要求尺寸更接近，减少真实不同物品被当成重复的机会。

不要通过调大 `YOLO_OBJECT_SCORE_THRESH` 来替代这组窄提示；因果遮挡门控本身没有新增
可调参数。调整这组参数后，必须回放跨类别同框、普通异类重叠、真实静态低分物品、
MOVED/REVEALED、D/IN 和历史 blocker 生命周期场景。

## 手、CONTACT 与有手轨迹

`HAND_MICRO_MOVE_SKIP_EPS = 6 px`
    作用：无活动轨迹时，近乎不动的手框可跳过业务处理。
    调大：跳过更多静止手帧，可能漏小手框变化。
    调小：更灵敏，处理和抖动影响更多。

`TRACK_HAND_MOVE_EPS = 12 px`
    作用：手移动到可作为移动/放下证据的最小距离。
    调大：过滤手抖，但慢速整理更难确认。
    调小：慢动作更易确认，手抖也更易累积证据。

`FLOW3_HAND_ATTACH_DISTANCE = 28 px`
    作用：手与新 D “相贴”的最大边缘距离。
    调大：更易发现手带入的 D，也更易误认手旁旧物。
    调小：D 更保守，检测间隙可能漏掉真实 D。

`FLOW3_HAND_NEAR_MAX_INTERSECTION_AREA = 900 px^2`
    作用：“相贴”时允许的手/物交集上限。
    调大：允许更大交集，更易把被压住物体视为相贴 D。
    调小：更符合相贴，但手框抖动可能漏 D。

`FLOW3_HAND_PARTIAL_COVER_RATIO = 0.30`
    作用：已有物品进入 HAND_PARTIAL 的最低手覆盖比例。
    调大：需要更多覆盖才跟踪，误触发少，也可能漏早期遮挡。
    调小：更早建立 HAND，手擦过更易触发。

`FLOW3_HAND_FULL_COVER_RATIO = 0.88`
    作用：从 HAND_PARTIAL 升为 HAND_FULL 的覆盖比例。
    调大：更接近真正全遮挡，也更易长期停在 PARTIAL。
    调小：更早判 FULL，也更易把深度部分遮挡当全遮挡。

`FLOW3_HAND_DETECTION_OVERLAP_AREA = 300 px^2`
    作用：新 D 与手相交/贴手的面积要求。
    调大：D 需更大交集，误建更少，真实 D 也可能漏。
    调小：D 更易取得贴手证据，误建风险更高。

`FLOW3_CONTACT_PATH_CENTER_NORM = 1.10`
    作用：CONTACT 中当前框到原框/观测轨迹的中心容差。
    调大：容忍快推拉，邻居串身份风险更高。
    调小：更安全，快移动时更易找不到 B。

`FLOW3_CONTACT_WIDTH_RATIO = 0.35`
    作用：CONTACT 的宽度容差。
    调大：更宽松，抗尺寸抖动，邻居更易被吸收。
    调小：更严格，框变化时更易未决。

`FLOW3_CONTACT_HEIGHT_RATIO = 0.35`
    作用：CONTACT 的高度容差。
    调大：更宽松，抗尺寸抖动，邻居更易被吸收。
    调小：更严格，框变化时更易未决。

`FLOW3_CONTACT_OBJECT_MOVE_EPS = 12 px`
    作用：CONTACT 中物品移动到可累计移动证据的最小距离。
    调大：过滤抖动，小幅整理更难确认。
    调小：小幅推拉更易确认，误移动风险更高。

`FLOW3_NEW_TRACK_CLAIM_GRACE_FRAMES = 2`
    作用：新 HAND/CONTACT 轨迹独占同类 B 前的保护帧数。
    调大：更保守，减少抢 B/重复 D，确认更慢。
    调小：更快认领，证据不足时更易抢错 B。

## 确认、放下与最终移动

`FLOW3_HOLD_EVIDENCE_REQUIRED = 2`
    作用：预计轨迹上的连续证据数，达到后确认“正在移动”。
    调大：更稳、更慢。
    调小：更快，更易被单帧误配触发。

`FLOW3_NOT_HOLD_EVIDENCE_REQUIRED = 2`
    作用：连续原位证据数，达到后释放 HAND/CONTACT 候选。
    调大：更能容忍一帧误匹配，释放更慢。
    调小：更快释放，也可能错过随后动作。

`NEW_ITEM_CONFIRM_FRAMES = 2`
    作用：D 连续自匹配次数，达到后可进入工作库存。
    调大：IN 更稳、更慢。
    调小：IN 更快，假 D 风险更高。

`FLOW3_NO_HAND_D_CONFIRM_FRAMES = 2`
    作用：无手恢复、灰区和 D 的连续直接观察要求。
    调大：无手结算更稳、更慢。
    调小：更快结算，更受单帧漏检/抖动影响。

`FLOW3_NO_HAND_OUT_MISSING_FRAMES = 2`
    作用：无手连续缺失多少帧才确认 OUT。
    调大：更抗漏检，OUT 更慢。
    调小：OUT 更快，也更可能误出库。

`FLOW3_REAPPEAR_CANDIDATE_CONFIRM_FRAMES = 2`
    作用：`reappear_candidate` 连续自匹配次数。
    调大：更抗单帧跳动，恢复身份更慢。
    调小：恢复更快，串身份风险更高。

`FLOW3_DROP_EVIDENCE_REQUIRED = 2`
    作用：放下组合证据的连续次数。
    调大：放下更稳、更慢。
    调小：放下更快，手框抖动更易误触发。

`FLOW3_DROP_FALL_BEHIND_RATIO = 0.45`
    作用：手继续移动时，物品移动多小才算“掉队”。
    调大：更容易判掉队/放下。
    调小：更难判掉队，更多依赖无手确认。

`FLOW3_DROP_FULL_BOX_IMPROVEMENT = 0.08`
    作用：框变得更完整时，算作放下辅助证据的最小改善量。
    调大：需要更明显改善，更安全也更易漏。
    调小：更易累计证据，也更受大小抖动影响。

`FLOW3_MOTION_REFERENCE_DIAGONAL_MIN_PX = 80`
    作用：最终归一化位移的最小参考尺度。
    调大：小物体需更大绝对位移才算移动。
    调小：小物体更敏感，也更受抖动影响。

`FLOW3_MOTION_REFERENCE_DIAGONAL_MAX_PX = 500`
    作用：最终归一化位移的最大参考尺度。
    调大：大物体更不敏感，可能漏小幅真实移动。
    调小：大物体更敏感，恢复抖动风险更高。

`FLOW3_STATIC_CENTER_SHIFT_NORM = 0.06`
    作用：最终移动的低位移静态参考线；本身不直接提交事件。
    调大：更多轻微变化按静态参考处理。
    调小：更早把变化送入灰区观察。

`FLOW3_FORMAL_MOVE_CENTER_SHIFT_NORM = 0.12`
    作用：最终 MOVED 的归一化位移资格线。
    调大：MOVED 更保守，可能漏小整理。
    调小：MOVED 更敏感，误移动风险更高。

`FLOW3_COMMIT_MOVE_CENTER_DISTANCE = 28 px`
    作用：旧版本兼容项，r19 不参与最终 MOVED 判定。
    调大：无当前业务效果，不建议调。
    调小：同左。

## D、遮挡与无手揭示

`FLOW3_D_REAPPEAR_MIN_PARTIAL_COVER = 0.35`
    作用：D 从局部框重现为完整框的最小覆盖比例。
    调大：关联更严格，误认少，也可能漏真实 D。
    调小：更易接回 D，也更易误关联同类邻居。

`FLOW3_D_REAPPEAR_MAX_CENTER_SHIFT_NORM = 0.45`
    作用：覆盖不足时，D 局部到完整框允许的中心偏移。
    调大：更宽松，召回更高，误关联风险更高。
    调小：更严格，偏移大时可能漏 D。

`FLOW3_C_REPLACEMENT_MIN_COVER_RATIO = 0.30`
    作用：无法认领的 D 覆盖 HAND 旧 C 原位置时，预登记 D 的覆盖要求。
    调大：更严格，路过框误登记更少，也可能漏真实替代 D。
    调小：更容易登记，也更容易产生未确认 D。

`FLOW3_POST_HAND_REVEAL_WINDOW_FRAMES = 2`
    作用：手离开后，允许创建 POST_HAND_REVEAL_D 的无手帧窗口。
    调大：漏检后新物更易被发现，也扩大假 D 窗口。
    调小：更保守，首帧漏检时更易漏新物。

`FLOW3_D_PARTIAL_COVER_RATIO = 0.30`
    作用：已确认 D 覆盖旧 C 时，把 C 视为遮挡保留的最低比例。
    调大：需要更多重叠才把它当遮挡。
    调小：更容易把 C 当作被遮挡保留。

`BLOCK_OVERLAP_AREA_EPS = 4`
    作用：遮挡矩形差集计算时的交叠面积误差。
    调大：更容忍小缝隙，更易视为覆盖。
    调小：更严格，边缘抖动更易破坏遮挡判断。

`COVER_REMAINING_AREA_EPS = 4`
    作用：全部遮挡框处理后，剩余面积是否可视为零的误差。
    调大：更容忍小缝隙，更易视为完全覆盖。
    调小：更严格，边缘抖动更易留下残片。

`FLOW3_CONFIRMED_OCCLUSION_EDGE_RESIDUAL_PX = 8`
    位置：`include/fridge_config.h` 的动态矩形遮挡参数附近。
    作用：严格矩形差集失败时，允许“已确认且当前直接出现的 IN/MOVED
    blocker”在旧 C 外边缘留下的窄条带被视为检测框边缘误差。
    该参数只在旧 C 未直接出现、至少一个当前 blocker 已完成既有身份确认、
    且所有参与框均为可靠 `base_box` 时调用；不参与身份匹配、MOVED、IN、OUT
    或 `block_ids` 预约，也不改变 `COVER_REMAINING_AREA_EPS`。
    调大：更能容忍目标外边缘的框偏差，但可能把较宽的边缘漏检当作完整遮挡。
    调小：更严格，实机框边缘残余较大时更容易保持未完全遮挡。

`FLOW3_CONFIRMED_OCCLUSION_DISAPPEARANCE_MIN_COVER_RATIO = 0.85`
    位置：`include/fridge_config.h` 的动态矩形遮挡参数附近。
    作用：`DISAPPEARANCE_SUPPORTED` 的专用近完整覆盖比例。只有已确认
    `IN/MOVED` 的当前前景与目标形成有效 `block_ids`，目标连续两张无手帧没有
    合法 direct observation，且残余只在目标外边界时才使用；它不参与身份、D、
    MOVED、普通 OUT、可见数量预约或关系建立。
    调大：更保守，较宽的检测残余不会被解释为遮挡，但真实遮挡边缘抖动更易进入
    OUT/未决链。
    调小：更容易保留高覆盖率的被遮挡目标，但可能把部分遮挡或漏检误认为完全遮挡。

`FLOW3_CAUSAL_OCCLUSION_MIN_COVER_RATIO = 0.30`
    位置：`include/fridge_config.h` 的动态矩形遮挡参数附近。
    作用：`CAUSAL_FRONT_MISSING` 的最低合理覆盖比例。仅当目标仍只有
    `HAND_*`/`POSSIBLE_MOVED` 等未决手部移动线索、没有自身已确认
    `MOVED/OUT`，且前景已确认 `IN/MOVED` 并造成目标无合法直接观察时调用。
    它不是建立 `block_ids` 的阈值：前景关系仍以正面积交集建立；也不改变严格
    full/edge、`DISAPPEARANCE_SUPPORTED` 的 0.85 比例、检测归属、普通 OUT、
    MOVED 或 IN。
    调大：更保守，较小的前景覆盖会继续走普通缺失/未决链。
    调小：更容易把部分覆盖解释为因果遮挡，必须重点回放同类相邻、擦边和漏检场景。

`DOOR_OPENING_CANDIDATE_BRIGHTNESS = 58`
    作用：进入开门候选的亮度门槛。
    调大：要求更亮才开门，误开少、延迟更多。
    调小：更易开门，也更易受亮度波动触发。

`DOOR_OPEN_LIGHT_THRESHOLD = 68`
    作用：确认开门的亮度门槛。
    调大：要求更亮才确认，误开少、漏开/延迟更多。
    调小：更易确认开门，也更易误开。

`DOOR_OPEN_CONFIRM_FRAME_COUNT = 5`
    作用：连续亮帧确认开门次数。
    调大：更稳、更慢。
    调小：更快，也更易误开。

`DOOR_CLOSING_GUARD_THRESHOLD = 42`
    作用：关门时允许的最高亮度。
    调大：关门条件更容易满足，也更易误关。
    调小：要求更暗，较安全但更慢。

`DOOR_CLOSING_DROP_RATIO = 0.62`
    作用：当前亮度相对开门参考亮度的最大比例。
    调大：更容易满足关门下降条件。
    调小：需要更明显变暗才关门。

`DOOR_DARK_PIXEL_THRESHOLD = 38`
    作用：单个像素被算作“暗”的亮度上限。
    调大：更多像素算暗，关门更容易。
    调小：更少像素算暗，关门更严格。

`DOOR_CLOSING_DARK_PIXEL_RATIO_THRESHOLD = 0.72`
    作用：关门所需的暗像素比例。
    调大：需要更多暗像素，关门更稳、更慢。
    调小：更快关门，也更易误关。

`DOOR_CLOSE_CONFIRM_FRAME_COUNT = 5`
    作用：连续关门证据次数。
    调大：更稳、更慢。
    调小：更快，也更易受瞬时暗帧影响。

`OPEN_REFERENCE_UPDATE_THRESHOLD = 72`
    作用：哪些亮帧可更新开门亮度参考。
    调大：只采更亮帧，参考更纯但更新更慢。
    调小：更新更快，也更可能混入不够亮的帧。

`OPEN_DARK_PIXEL_RATIO_LIMIT = 0.35`
    作用：可更新开门参考的最大暗像素比例。
    调大：允许更暗的帧更新，适应阴影但可能污染参考。
    调小：只用更亮帧，参考更稳定。

`OPEN_REFERENCE_WINDOW_SIZE = 20`
    作用：开门亮度参考的历史窗口长度。
    调大：更平滑、更慢响应。
    调小：更灵敏、更易抖动。

## 开关与非当前业务参数

`FLOW3_DEBUG_TRACE_LOG = false`
    作用：只控制 `[3.0-TRACE]` 日志，不影响业务结果。
    调大/开启：设为 `true`，方便复现问题，但日志很多。
    调小/关闭：设为 `false`，常规部署更安静。

`ALLOW_INITIAL_FRAME_BOOTSTRAP_WHEN_BACKEND_UNAVAILABLE = true`
    作用：后端库存不可用时，允许首张无手帧建立本地测试库存。
    调大/开启：允许本地测试建库。
    调小/关闭：接入可信后端后使用，避免冷启动画面建库。

`FRAME_W = 1280`、`FRAME_H = 720`
    作用：图像尺寸常量，必须与真实输入分辨率一致。
    调大：仅在真实输入分辨率更大时成对修改；不是识别容差。
    调小：仅在真实输入分辨率更小时成对修改；不能靠它改善识别。

`SNAPSHOT_N = 3`、`SNAPSHOT_S = 0.5`、`SNAPSHOT_MIN_SCORE = 0.5`、
`SNAPSHOT_MIN_BOX_WIDTH = 12`、`SNAPSHOT_MIN_BOX_HEIGHT = 12`、
`SNAPSHOT_VOTE_CENTER_NORM = 0.30`、`SNAPSHOT_VOTE_WIDTH_RATIO = 0.25`、
`SNAPSHOT_VOTE_HEIGHT_RATIO = 0.25`
    作用：只供独立 `snapshot.cc` 兼容代码使用，当前 r19 的 SessionManager 不使用。
    调大：`N` 更稳更慢；比例、最低分数和尺寸更严格；投票容差更宽松、更易合并邻居。
    调小：与上相反。不要用它们调 r19 的库存流程。

`HIGH_SCORE_THRESH = 0.5`、`LOW_SCORE_THRESH = 0.1`、`MATCH_IOU_THRESH = 0.30`、
`MATCH_IOU_THRESH_LOW = 0.20`、`MATCH_IOU_THRESH_UNCFM = 0.50`、
`TRACK_BUFFER_FRAMES = 60`、`NEW_TRACK_SCORE_THRESH = 0.6`
    作用：旧 ByteTrack-Lite 参数；当前主程序不编译 `tracker.cc`，不参与 r19 库存判断。
    调大：若日后恢复 ByteTrack，分数/IoU 更严格，buffer 会保留轨迹更久。
    调小：若日后恢复 ByteTrack，匹配更宽松，轨迹更快删除。

`CLOUD_ENABLED = false`
    作用：默认是否启动登录、心跳和事件上传；也可用环境变量 `FRIDGE_CLOUD_ENABLED` 覆盖。
    调大/开启：设为 `true`，启用云端上传和无事件截图上报。
    调小/关闭：设为 `false`，保持离线测试，不发网络请求。

`HEARTBEAT_INTERVAL_SEC = 30`

    调小：心跳更及时，网络请求更多。

## 无事件稳定截图与 JPEG

下列无事件截图参数只有在云端上传开启、当前没有手、且 `SessionManager` 已稳定时才生效。

`NO_EVENT_PIXEL_DIFF_THRESH = 2.0`
    作用：相邻缩小灰度帧的平均像素差不大于此值，才算“画面稳定”。
    调大：更容易判稳定，截图更频繁，也更可能在轻微变化时上传。
    调小：更严格，截图更少，轻微噪声可能一直阻止上传。

`NO_EVENT_STABLE_CONFIRM = 3`
    作用：连续稳定多少帧后才上传无事件整柜截图。
    调大：更稳、更慢，减少重复或偶发截图。
    调小：更快，也更易被短暂稳定误触发。

`NO_EVENT_SNAPSHOT_COOLDOWN_MS = 30000`
    作用：两次无事件截图上传之间的最小间隔，单位毫秒。
    调大：上传更少，节省网络和存储，画面变化后的新截图更晚。
    调小：上传更及时，也更可能产生大量重复截图。

`cv::IMWRITE_JPEG_QUALITY = 80`
    作用：IN、MOVED 和无事件截图的 JPEG 压缩质量。
    调大：图片更清晰、文件更大、上传更慢。
    调小：文件更小、上传更快，但 OCR/人工查看细节更差。

# [tools/luckfox_pico_rkmpi_example/example/luckfox_pico_rtsp_yolov5n/src/app_door_state.cc]

`cv::Size(64, 36)`
    作用：无事件画面差异计算前的灰度缩小尺寸；它决定 `NO_EVENT_PIXEL_DIFF_THRESH` 的测量粒度。
    调大：保留更多细节，对小变化更敏感，计算量略增，通常需要重新标定像素差阈值。
    调小：更平滑、计算更轻，但小变化更容易被忽略，通常也要重新标定像素差阈值。

# [tools/luckfox_pico_rkmpi_example/example/luckfox_pico_rtsp_yolov5n/include/cloud_uploader.h]

`UploadJob::max_attempts = 3`
    作用：单个上传任务在网络失败后的最大尝试次数。
    调大：成功机会更多，但失败任务占用队列和网络更久。
    调小：更快放弃失败任务，但临时网络故障更容易丢上传。

`CloudUploader::MAX_QUEUE = 16`
    作用：异步上传队列上限；满时丢弃最旧任务以保护内存。
    调大：突发时更少丢任务，但内存占用和延迟更高。
    调小：内存和延迟更可控，但网络慢时更容易丢旧任务。

`std::chrono::milliseconds(500)`
    作用：一次上传失败后、重新入队前的等待时间。
    调大：重试更慢，降低故障后请求压力，但恢复上传更慢。

# [tools/luckfox_pico_rkmpi_example/example/luckfox_pico_rtsp_yolov5n/src/cloud_http.cc]

`tv.tv_sec = 5`
    作用：HTTP socket 的发送和接收超时，单位秒。
    调大：慢网络更容易完成请求，但后台线程可能更久被单次请求占用。
    调小：失败更快、队列更容易继续处理，但慢网络下更容易误判失败。

最小验证清单：

1. 物品未移动，手经过后库存和 item_id 不变。
2. 同一物品移动、放回、取出，分别得到正确的 STATIC、MOVED、OUT 结果。
3. 放入新 D，必须经过连续证据后才产生 IN。
4. 前景物遮挡并再次揭示后，后方旧物不能误 OUT 或重复 IN。
5. 相邻同类有独立框时能区分；只剩一个共享框时保持未决，不伪造数量。
6. 手腕几乎不动、手指推动物品时，CONTACT 路径仍能保留原 item_id。

修改任一参数后都需要重新编译；保存“参数版本、测试视频、事件日志和回放结果”，便于
定位哪一项改动造成行为变化。
