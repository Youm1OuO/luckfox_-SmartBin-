# 删除固定成熟期，区分“当前帧暂归属”和“最终事件确认”

本文件优先级高于细节8及此前所有文件；与此前 `claim_grace` / “成熟期”规则冲突时，以本文件为准。

3.0 仍然逐张有效帧直接处理：不使用 `SnapshotBuffer`，不投票，不平均检测框。连续帧只用于同一对象的直接自匹配、缺失计数和最终事件确认。

## 1. 结论

删除固定的旧 C 成熟期。新建 `CONTACT_*` / `HAND_*` 轨迹后，不能因为“刚创建”而禁止它参与当前帧的一对一归属。

保留连续确认，但它只确认最终事件，不能阻止当前帧的唯一归属：

```text
当前帧唯一 C -> B：立刻把 B 暂归给 C，B 不能再成为 D。
下一张直接无手帧仍唯一匹配同一条 C -> B：才确认 AT_NEW_POSITION / MOVED。
```

“暂归属”不等于 `AT_NEW_POSITION`，更不等于 `MOVED`、`IN` 或提交库存。

## 2. 两层状态必须分开

### 当前帧归属：立即生效

`FrameOwnership` 表示当前直接帧的唯一关系。若 C/B 两侧都唯一：

```text
frame_ownership_.old_item_to_detection[C] = B
frame_ownership_.detection_to_old_item[B] = C
```

即使 C 的 `IdentityResolution` 仍为 `UNRESOLVED`，这个 B 也已经被旧 C 占用。后续 HAND、CONTACT、D、无手收尾的本帧 `claimed` / owner 表必须都读取同一份 `FrameOwnership`，不能只占用“已最终解决”的 C。

### 最终身份：连续直接帧确认

`IdentityResolution` 只表示已确认结论：

```text
AT_ORIGIN
AT_NEW_POSITION
OCCLUDED_CONFIRMED
OUT_CONFIRMED
UNRESOLVED
```

规则：

1. 唯一原位严格 B 可直接确认 `AT_ORIGIN`。
2. 唯一的路径 / reappear B 首次出现时，只形成 C 的暂归属并开始或更新 C 自己的直接自匹配计数。
3. 下一张直接无手帧仍唯一匹配同一 C 的同一条 B 链，且已有原有的有效移动证据时，才设为 `AT_NEW_POSITION` 并产生 `MOVED`。
4. B 消失、跳到另一条不连续路径，或变成多个 C 都可解释时，撤销该次暂归属/连续计数，回到 `UNRESOLVED`；不得产生 `MOVED`、`OUT`、`IN`。

现有 `FLOW3_REAPPEAR_CANDIDATE_CONFIRM_FRAMES`、移动证据、无手连续直接帧确认仍可用于第 3 步；它们不是“成熟期”。

## 3. 每张有效帧的顺序

有手和无手帧均按以下顺序处理：

1. 更新已有 `CONTACT_*` / `HAND_*` 的本地路径、真实 B 观测和手移动证据。
2. 对所有旧 C 和当前 B 同时建立候选边：原位置严格匹配、已确认放下位置、reappear、CONTACT 真实 `observed_track`、HAND 预计路径、原位置局部匹配。
3. 全局一对一仲裁。只有 C/B 两侧唯一或有明确证据领先时，写入当前帧 `FrameOwnership`；绝不按 `item_id`、map 或检测遍历顺序抢框。
4. 将所有当前帧 C owner（包括 `UNRESOLVED` 的暂归属）同步写入本帧 `claimed`。因此同一个 B 不能同时给旧 C、已有 D 或新 D。
5. 更新旧 C 的原位 / 新位置连续确认。首次唯一路径 B 只更新候选；满足下一张直接无手自匹配后才确认 `AT_NEW_POSITION`。
6. 对仍未归属的 B 计算 `possible_old_item_ids`，再决定 claim 或 D；不能以“轨迹刚创建”为理由跳过第 2 至第 5 步。
7. 无手阶段才推进 OUT 缺失计数、遮挡结论和提交门。`settle_no_hand_frame_` 不得重新匹配或创造 owner。

## 4. 同类歧义与 D 准入

### 旧 C 的同类 B

```text
一个 B 只可能唯一属于一个旧 C：立刻暂归该 C，禁止 D 使用。
一个 B 同时可能属于多个旧 C：不归任何 C，保留 claim，禁止 D 和提交。
```

“未最终确认的唯一 C -> B”与“多个 C 竞争 B”不同：前者可以暂归属，后者必须未决。

### D 的统一准入门

三种入口 `HAND_VISIBLE_D`、`C_POSITION_REPLACEMENT_D`、`POST_HAND_REVEAL_D` 都使用同一规则。只有同时满足以下条件，B 才能开始 D：

1. B 没有任何当前帧旧 C owner，也没有已有 D owner。
2. B 没有任何未解决旧 C 候选或同类基线碰撞候选。
3. B 具有本次手操作来源。
4. 当前帧不存在与其他同类未归属 B 的歧义。

旧 C 的暂归属足以阻止 D；不需要等待固定两帧成熟期。若旧 C 后来独立回到原位，原先另一个 B 从当前守卫解除帧起才可作为 D 第 1 帧，不能借用 claim 期间的计数。

## 5. 基线碰撞仍保留

两个同类旧 C 的基线框近到同一个 B 都能匹配时，不能靠删除成熟期解决：

```text
旧 #2 -> B，旧 #4 -> B 都合理
=> B 不得拥有两个 owner；#2/#4 保持 UNRESOLVED；
=> 不得 MOVED、OUT、IN 或提交。
```

只有两个旧 C 在同一直接帧各自获得不同 B，碰撞组才解除。损坏的重复库存基线必须从可信库存修正或用两个分开的完整检测框重建，不能让业务状态机猜 item_id。

## 6. 删除项与代码修改点

删除固定成熟期及其只为等待成熟而存在的分支：

```text
FLOW3_NEW_TRACK_CLAIM_GRACE_FRAMES
OperationTrack::claim_grace_remaining
is_claim_protected()
is_claim_mature()
advance_claim_grace_()
```

`tentative_b`、`reappear_candidate` 可以保留为 C 的本地路径和连续自匹配记录，但不得再因计时器禁止 C/B 的全局一对一归属。

重点检查：构建 `FrameOwnership` 后，所有 `old_item_to_detection` 都要占用本帧 B；不能仅在 `old_item_is_resolved_(C)` 为真时才写入 `claimed`。否则唯一但尚未确认移动的 C 会被错误看作“未归属 B”。

同步更新 `超参数位置与调节说明.txt`：删除成熟期参数及说明；保留并说明连续确认参数的作用是确认最终事件，不是延迟 C 的当前帧归属。

## 7. 日志和回放验收

补充结构化日志：

```text
[OWNERSHIP] frame=<n> B=<i> candidates=<C...> owner=<C|NONE|AMBIGUOUS> resolution=<...>
[D-GATE] frame=<n> B=<i> allow=<0|1> blocked_by=<C...|collision|existing-D>
[INIT-IDENTITY] collision_group=<item_id...>
```

回放至少覆盖：

1. 健康基线中，手从多个邻近物品旁经过、仅移动一个旧苹果：只产生一次 `MOVED`，库存数量不变，不残留未决操作。
2. 唯一旧 C 的路径 B 在有手阶段首次出现：B 当帧暂归旧 C，不能创建 D；下一张直接无手自匹配后才 `MOVED`。
3. 同一个 B 可属于两个旧 C：无 owner、无 D、无提交。
4. 两个近乎重叠的同类旧 C 各自出现独立 B：两个不同 owner，允许操作正常结束。
5. 唯一暂归属 B 在下一帧消失或变歧义：不产生 `MOVED` / `IN` / `OUT`。
6. 旧 C 已独立解决后，同类真实 D 从守卫解除的当前帧才开始 D 的确认计数。

验收标准：正常单物品整理不能因为“轨迹刚创建”而等待固定成熟期；有真实歧义时仍不猜身份、不增加库存数量。
