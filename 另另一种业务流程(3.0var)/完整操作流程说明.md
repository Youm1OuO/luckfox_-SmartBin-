# 2.0var：库存与快照对比的完整操作流程

本文把《问题.md》和 3.0var 版本中已经确定的思路，整理成一套完整的中文操作流程。这里的“快照”指某一帧 YOLO 输出的结果；库存更新仍然是“当前快照与库存的比较”，而手部移动、物品轨迹等信息则使用连续快照逐帧维护。

## 一、基本原则

系统同时维护两份库存：正式库存和工作库存。
正式库存是上一段操作已经确认的结果, 只有在本次手部操作结束、所有未决物品完成最终判断后才修改。
手进入后, 先把正式库存复制为工作库存；手还在画面中时，所有暂时确认的遮挡、移动、疑似入库和疑似出库都只写入工作库存。
这样一次手部操作连续整理多个物品时，后续帧能够使用前面已经得到的临时结果，但中途误判不会立即破坏正式库存。

库存物品具有唯一的 item_id。
当前检测框没有自己的正式库存身份，不能因为某个检测框暂时和某件物品相似就直接生成新的正式库存物品。
但与手相贴、且无法匹配任何已有库存的检测框 D，可以先建立“疑似新物品”临时对象，并分配一个只用于跨帧连续匹配的 `suspect_id`。
这个临时对象不是只有一个 box：它同样保存 `box`、`first_hand_block_box`、`last_hand_block_box`、`track`、移动值列表、证据计数、`hand_track_start_index` 等 HAND_PARTIAL 所需信息，另有初始为空的 `placed_box`；初始状态为“被手部分遮挡”、`hold_and_move=False`。
在下一张有效观察（下一张有效手帧，或手离开后的第一张收尾无手帧）中，如果 D 仍然可见、能与自己的上一帧观测连续匹配，并且仍然无法匹配已有库存物品，就把同一个临时对象提升到工作库存，分配正式 `item_id`，保留已有的全部轨迹和状态；它此时仍然是“被手部分遮挡”，不等于已经放下。
由于 D 初次出现时没有被手遮挡前的完整框，它的初始 `box` 只是首次局部观测的临时参考框，不能直接拿来判断它在新位置遮挡了谁。D 仍在手中时，遮挡判断使用本帧与 D 匹配到的当前检测框（或最新的 `last_hand_block_box`）；D 出现放下证据时，把当时用于表示放置位置的检测框写入 `placed_box`，之后用 `placed_box` 判断 D 对 C 的覆盖。手离开后得到稳定、较完整的 D 框时，再同时更新工作库存中的 `box` 和 `placed_box`，并重新计算 D→C 的遮挡关系。正式库存和正式 IN 事件仍在整段操作最终提交时产生。

每个库存物品的状态分为“可见”“遮挡”“被手部分遮挡”和“被手完全遮挡”。
“遮挡”表示物品仍在原位置，只是被其他物品挡住；
“被手部分遮挡”和“被手完全遮挡”表示当前手部正在影响这个物品，但此时还不能据此认定它被拿起或移动。

本次手操作中还允许存在“疑似新物品 D”。
D 在提升到工作库存前没有正式 `item_id`，不能直接写入正式库存或正式 `block_ids`；
但它可以临时记录自己遮挡了哪些旧库存物品 C。这个临时遮挡关联用于解释“C 为什么暂时看不见”。
D 的身份确认和 D 是否已经放下是两件事：D 即使已经进入工作库存，只要仍被手部分遮挡，就只能保留临时遮挡关联；
等 D 出现掉队/与手分离或手离开后框稳定，再把关联转成正式遮挡关系。
D 的一次漏检不能清空它的临时对象；若后续出现 D 与旧 C 的身份冲突，先保持冲突未决，不同时让同一检测框被两个物品认领，也不自动把 D 删除。
在 D 尚未形成正式遮挡关系期间，C 的遮挡计算也必须使用 D 当前实际观测框（D 在手中时）或 `placed_box`（D 已放下时）作为前方遮挡框传给 `apply_cover`，不能把仍被 D 遮住的 C 错判为“可见”。


## 二、开始一段连续手部操作

当连续帧中第一次识别到手时，系统开始一段新的手部操作。
如果当前没有工作库存，就先复制正式库存。第一张检测到手的快照作为本段操作的基准帧：保存它的手框为 `old_hand`，并以它建立公共 `hand_track`。这张首帧需要正常处理，不因“没有上一张手帧可比较”而跳过。

手刚进入画面时，默认只认为手在造成遮挡，不能在第一帧就认为手已经拿走了物品。
在处理任何未被跳过的手部快照时，先逐个检查检测框是否能可靠认领给工作库存中的已有物品。若某个检测框 D 无法与任何库存物品可靠匹配，且 D 与当前手框相贴，就立即新建或更新“疑似新物品 D”记录，供本帧后续的遮挡、移动和入库判断使用。这里的“相贴”允许检测框因 YOLO 误差与手框有少量重叠；它表示 D 正在随手出现，而不是普通远处的未匹配检测。
第一帧中手附近的检测框可能是库存中原有的物品，也可能是手从画面外带进来的新物品；因此 D 只能先进入疑似新物品记录，不能马上判定入库。一个未匹配框若并未与手相贴，也不能仅凭它未匹配就新建疑似入库记录。

对已有可靠完整框的库存物品 A，HAND 状态只由手对完整框的覆盖率决定：`r = intersection_area(hand.box, A.box) / area(A.box)`。设 `e2 < e1`，当 `r < e2` 时，手不影响 A，不新建 HAND_* 候选；当 `e2 <= r < e1` 时，A 为“被手部分遮挡”（HAND_PARTIAL）；只有 `r >= e1` 时才是“被手完全遮挡”（HAND_FULL）。当前 YOLO 是否还能检测到 A、以及当前检测框是否变小，都不能改变这条状态分类；检测框只用于更新局部观测历史。这里的 A.box 必须是进入 HAND_* 前保存的可靠完整框（或完整估计框），不能用已经被遮挡后缩小的 `last_hand_block_box` 代替。初始建议 `e2=0.30`、`e1=0.88`，后续按相机实际框误差标定。

如果库存中的物品按上述规则进入“被手部分遮挡”，就把它改为该状态。把这一帧被手挡住后仍然识别到的局部框同时记录为 `first_hand_block_box` 和 `last_hand_block_box`，并保留物品原来的 `box`。即使 `e2 <= r < e1` 但这一帧没有 A 的 YOLO 检测框，也仍然要进入 HAND_PARTIAL；此时只是不更新这两个局部框。
`first_hand_block_box` 是刚被手挡住时的第一个局部框，只在进入该状态时记录一次，后续保持不变；
`last_hand_block_box` 是最近一帧实际识别到的手遮挡局部框，每次成功匹配当前帧物品后都要更新。它们只保存局部可见部分的历史，用于辅助局部连续性或判断掉队；物品的主估计轨迹不以它们为基准。物品恢复“可见”或结束本次手部处理时，两者都清空。

如果库存中的物品按上述规则达到 `r >= e1`，就把它改为“被手完全遮挡”，同样保留它被遮挡前的原位置，不因为当前看不到就修改 box。即使 YOLO 因模型误差仍返回一个局部框，只要覆盖率达到 e1，状态仍是 HAND_FULL；该局部框最多用于历史记录。
上一帧手框 `old_hand` 是所有物品共用的帧级数据，不属于某个物品；它始终指向最近一张**已完整处理**的手部快照，而不是最近到达的相机帧。
每一张通过微小移动筛选、被完整处理的手部快照，才根据当前手框与 `old_hand` 计算一次手部位移，然后把这次位移分别追加到当时已被手影响的每个物品自己的移动值列表中。
需要估计某个物品的新位置时，把它自己的位移列表相加得到净位移向量；如果要统计手实际经过的总路程，则把每个向量的长度相加。不能让多个物品共用一个累计列表。

完整的手框轨迹只保存一份公共 `hand_track`，不在每个物品中重复保存；其中只写入首帧和后续已完整处理的手部快照，不写入被忽略的微小移动帧。某个物品开始进入“被手部分遮挡”或“被手完全遮挡”时，只记录当前手框在公共轨迹中的下标 `hand_track_start_index`。以后需要这个物品对应的手轨迹时，从公共列表的这个下标开始读取即可。因此，不同物品从不同时间开始被手遮挡也不会混淆，同时每个物品只额外占用一个整数。


## 三、每一帧的总体顺序

每得到一张新的快照，先判断当前是否检测到手。当前没有检测到手时，不能按微小移动帧跳过，而应直接进入“手离开”的收尾流程；收尾时仍以最近一张已完整处理的手帧及其状态为准。

若当前和 `old_hand` 都有手，先仅计算一次两者的手框位移，作为极轻量的筛选。
若位移未达到“有效手移动”阈值，则当前 B 帧整体丢弃：不追加 `hand_track`，不更新 `old_hand`，不更新任何物品的移动值、track、状态、遮挡关系或证据计数，也不扫描、创建、更新疑似新物品 D。
下一张快照 C 仍直接与 B 之前最近的已处理帧 A 比较；也就是说此时 `old_hand`、库存和所有临时信息仍保持 A 帧的结果。若 C 仍是微小移动帧，则按同样规则继续跳过。
这种“完全跳过”是明确的算力与稳定性取舍：如果一个新物品从出现到放下的全部关键变化都恰好发生在被跳过的微小移动帧中，系统可能看不到它的首次贴手证据。实现时必须把有效移动阈值设在不会吞掉一次真实取放动作的范围；不能在 B 帧偷偷补做一部分 D 扫描，否则就不再是“B 帧不存在”。

只有首帧或通过上述筛选的有效手移动帧才进入完整处理。
首帧只建立基准、预登记 D 并初始化遮挡/HAND_* 状态；因为它没有可比较的上一张手帧，所以不累计移动值、不累计正反证据，也不进行轨迹移动判断。
对于后续[有效移动帧]，先把当前手框追加到公共 `hand_track`，再用当前手框与 `old_hand` 计算本次位移，并把同一个位移分别追加到所有已经处于“被手部分遮挡”或“被手完全遮挡”的物品自己的移动值列表中；随后才在本帧处理结束时把 `old_hand` 更新为当前手框。
当前帧才刚进入手部遮挡状态的物品从下一张有效移动帧开始记录位移。
需要估计某个物品的新位置时，再把该物品列表中的位移逐项相加；物品结束手部影响状态或手离开后，清空它自己的列表。

在每一张进入完整处理的手部快照的一开始，先预扫描当前检测框。
对每个 D，先尝试与工作库存的已有物品认领；
若 D 无法可靠认领给任何库存物品，且 D 与当前手框相贴，就新建或更新疑似新物品记录。
这里的“无法认领”必须是在适用的身份判断都完成后仍没有唯一来源：先分别检查已有物品的严格匹配，再检查当前 HAND_* 物品适用的局部/轨迹连续匹配；有唯一来源的检测框不能创建 D，来源同样合理而无法唯一选择的检测框才保持冲突并按贴手条件建立候选 D。
D 可能是手从外部拿进来、此前一直被手完全遮挡、现在才第一次露出的新物品。
如果已有疑似 D，则在本次预扫描中先尝试用类别、局部外观、位置连续性和前后框变化把当前检测框与 D 自己匹配；
下一张有效帧仍能自匹配且仍未匹配库存时，就把 D 提升到工作库存，保留它已经积累的 HAND_PARTIAL 全部信息。
预登记/提升都不立即等价于“已经放下”：D 在手中时仍保持“被手部分遮挡”，只在后续出现放下证据后形成正式遮挡关系。

预扫描到 D 后，先检查 D 是否与任一被手影响物品 C 的旧框 `C.box` 相交，并记录临时遮挡关联。
若本帧是经过位移筛选的后续有效移动帧，且 D 与当前手框的并集能够完整覆盖 `C.box`、C 又没有在[他自己的候选轨迹]的其他位置被唯一找到，则“D 放在 C 原位置、手和 D 暂时遮住 C”可作为 C 没有跟手移动的一次有效反向证据。
首帧只记录关联，不增加证据。这里必须使用 `apply_cover(C.box, [hand.box, 当前与 D 匹配的检测框])` 或等价的并集覆盖计算，不能把两个交集面积直接相加；不能误用 D 初次出现时保存的临时 `D.box`。

完成未知 D 的预登记和遮挡关联后，先把所有已经存在的疑似 D 临时对象也加入本帧的 HAND_PARTIAL 处理集合。D 即使尚未进入工作库存，也必须像普通“被手部分遮挡”的物品一样：从它建立后的下一张有效手帧开始追加自己的移动值，更新当前局部框、`last_hand_block_box`、`track`、证据计数，并判断是否出现掉队/与手分离的放下证据；D 提升到工作库存时只改变身份，不重置这些历史。
然后才处理之前已经处于“被手部分遮挡”或“被手完全遮挡”的库存物品。
对其中 `hold_and_move=False` 的物品，执行旧位置与估计位置的两类证据判断；
对 `hold_and_move=True` 的物品，跳过这类证据判断，只更新 `track` 并尝试确认放下。
若 C 的旧位置被预登记的 D 覆盖，必须先使用这层遮挡解释，不能把 C 的暂时消失直接当成正向移动证据。

其他没有被手影响的物品不参与复杂的移动判断，避免把手臂遮挡、检测漏检或普通物品抖动误认为整理。
除“手离开”的收尾处理外，本文后续所说的“本帧”或“每帧”均指首帧或已通过微小移动筛选、进入完整处理的手部快照；
被整体丢弃的 B 帧不属于任何后续步骤。

同一帧中，一个检测框最终只能被一个物品认领。
D 在提升前通过 `suspect_id` 作为临时对象和潜在遮挡物保留；提升后沿用同一个对象并获得正式 `item_id`，不能因为一次漏检就重新创建第二份 D。
如果旧 C 的轨迹也指向同一个检测框，则先记录为身份冲突；已经完成“贴手出现→下一次有效观察自匹配→仍无法认领库存”链路的 D 对这个检测框暂时拥有优先认领权，C 不能重复使用同一检测框。C 仍依据自己的旧位置、候选 track 和 D 的遮挡解释继续判断；若这些证据不能唯一解决冲突，就保持 C 未决并等待后续有效帧，不能仅凭冲突自动删除已经提升到工作库存的 D，也不能因此直接 OUT C。
完成 C 的处理后，再处理与库存可见物品的局部匹配、被手完全遮挡物品的匹配，以及仍未被任何旧物品认领的检测框。
若一个检测框有多个同样合理的来源，或者一个物品对应多个同样合理的检测框，则暂时保持未决，不强行选择。
(移动值和物品估计框由每个被手影响的物品分别保存；手框轨迹只公共保存一份，每个物品通过自己的 `hand_track_start_index` 取得相应片段。因此可以暂时保持未决，在后续帧继续判断，而不会混淆不同物品开始被遮挡的时间。)

**注意**
> 在本帧刚刚被改成【被手部分遮挡】与【被手完全遮挡】的物体, 他们的 shelter_or_hold=True, hold_and_move=False
> 他们只是被认为是被手遮挡而已, 目前还没有确认是否被手握住并移动。HAND_* 状态下的 `hold_and_move=False` 始终表示“待确认”，不是“已确认没有移动”。
> 每个待确认物品保存 `hold_evidence_count` 和 `not_hold_evidence_count`。连续两次有效证据支持随手移动，才把 `hold_and_move` 设为 `True`；连续两次有效证据支持仍在旧位置，才释放该候选并恢复为正常状态：C 已露出时为“可见”，仍被候选新物品 D 遮挡时为普通“遮挡”。相反方向的有效证据会清零另一个计数；无法得出结论的模糊帧不增加、也不清零任何计数。
> 连续确认“没有移动”后，该 `item_id` 暂时进入 `released_hand_candidate_ids`。在手仍然遮挡该物品时，不要每帧反复把它建立为 HAND_* 候选；手真正移开后解除这个抑制，因此以后手再回来拿它时仍能重新判断。
> 无论 C 是因“两次反向证据”还是因“D 已放下并完整覆盖 C”而退出 HAND_*，都要执行同一套释放清理：保留 C 原来的 `box`，清空 `first_hand_block_box`、`last_hand_block_box`、候选 `track` 和本轮移动值，重置两类证据计数，并把 C 的 `item_id` 加入 `released_hand_candidate_ids`。之后 C 只按普通【可见】/【遮挡】规则处理，不能在同一段手操作中被重复建立为 HAND_* 候选。


## 四、处理被手部分遮挡的物品

设库存物品 C 在手移动前处于“被手部分遮挡”,。
先查看 `C.hold_and_move` 再分支。`hold_and_move=False` 时，C 仍是待确认物品，才需要检查旧位置和估计位置并累计两类证据；`hold_and_move=True` 时，C 已经完成“跟手移动”的确认，不再重复做是否被握住的判断，只维护 `track` 并寻找放下证据。


### 4.1 `hold_and_move=False`：仍处于待确认

旧位置判断以 C 被手影响前保持不变的 `C.box` 为基准；`last_hand_block_box` 只表示局部可见部分，不能替代旧位置。此处先处理未知 D 的覆盖，再判断 C 本身是否仍在旧位置、是否可能跟手移动。


#### 4.1.1 先预登记库存中没见过的 D，并判断 D 是否遮挡 C

在本帧开始时，先找出暂时无法可靠认领给任一旧库存物品的检测框。
只有该检测框 D 同时与当前手框相贴时，才登记为“候选疑似新物品”：它可能是手从外部带进来、此前一直完全被手挡住、直到放下时才第一次被看到的新物品。
未匹配但不贴手的检测框只保持未决，不以此新建疑似入库记录。
D 的登记不会因为一次漏检自动清除；若后续 D 与旧 C 产生身份冲突，则保持冲突未决并继续收集连续证据，不允许同一检测框同时被 D 和 C 认领。

若 D 与 C 的旧框 `C.box` 相交，则把 D 记录为 C 的临时疑似遮挡物。必须先区分“D 只是已经确认身份但仍在手中”和“D 已经确认放下”：身份确认不等于放下。

- 如果 D 仍处于【被手部分遮挡】，即使它已经进入工作库存，也只保留 D→C 的临时遮挡关联。此时若 `apply_cover(C.box, [hand.box, 当前与 D 匹配的检测框])` 的并集完整覆盖 C.box，且 C 没有在自己的候选轨迹其他位置唯一出现，可以增加一次 `not_hold_evidence_count` 并清零 `hold_evidence_count`，但不能仅凭 D 入工作库存就把 C 变成【可见】或直接退出 HAND_*。
- 如果 D 已经确认放下，且 `D.placed_box` 单独完整覆盖 `C.box`，则这是足够强的“C 仍在原位置、只是被 D 遮住”证据。立即清零 `hold_evidence_count`，把 `not_hold_evidence_count` 置为足以释放 HAND_* 的结果，并执行上述统一释放清理；保留 C 原来的 `C.box`，把 C 改为普通【遮挡】，并把 D 加入正式 `block_ids`；不发 OUT。
- 如果 D 已经确认放下、只部分覆盖 C，但当前仍能在 C 原位置唯一看到 C 的局部或完整框，则同样释放 C 的 HAND_* 状态。C 实际没有被挡住的部分可记为【可见】；若系统把部分遮挡单独记录，则保持普通遮挡状态并记录 D 的 blocker 关系。
- 如果 D 已经确认放下、只部分覆盖 C，而 C 仍因手与 D 的并集看不见，则本帧只记一次反向证据，不能直接把 C 标成【可见】。后续每张有效帧如果仍满足同一并集完整覆盖、且 C 没有在自己的候选轨迹其他位置唯一出现，可以继续累计反向证据；如果手移开并重新看到 C，也记一次反向证据。达到释放阈值后释放 C；若并集不能解释 C 的消失，则保持待确认，不能立即出库。

因此，C 的 HAND_* 释放条件不是“发现 D”或“D 获得 item_id”，而是“D 已放下并且覆盖关系或旧位置重新出现已经解释 C”。
释放后 C 的状态由实际可见性决定：没有被遮挡才是【可见】，仍被 D 挡住就是普通【遮挡】。


#### 4.1.2 旧位置仍然是 C

若没有上述 D+手完整覆盖的特殊解释，旧位置检测到的框仍能唯一与 C 匹配，说明 C 很可能只是被手短暂遮挡，实际上没有被拿起。
只有在手本帧明确移动时，才把这当作一次有效反向证据，令 `not_hold_evidence_count += 1` 并清零 `hold_evidence_count`。连续两次有效判断都确认旧位置是 C，才把 C 释放出 HAND_* 判断；若没有其他遮挡则恢复为“可见”，若有 D 的临时遮挡关联则保持普通“遮挡”。手没有明确移动时不增加计数。


#### 4.1.3 旧位置露出一个已知库存物品

如果旧位置不再匹配 C，但出现了一个已经存在于库存中的物品 D，并且此前 D 确实位于 C 后方、被 C 遮挡，那么说明 C 可能已经离开旧位置，D 只是重新露出。此时不能仅凭 D 露出就立即确认 C 出库，还要继续根据手的移动量寻找 C 的新位置。


#### 4.1.4 旧位置没有 C，也没有 D+手完整覆盖的解释

如果旧位置既没有重新看到 C，也没有出现能够与手共同完整覆盖 C 的候选新物品 D，只能说明 C 当前没有被看见。它可能被手拿走，也可能仍在原处但被手臂、手掌、其他物品或 YOLO 漏检遮住。因此这一帧只能保留“疑似被手带着移动”的状态，不能立即发出库事件。


#### 4.1.5 根据移动量寻找 C 的新位置

只有在“旧位置露出已知库存物品”或“旧位置没有 C 且没有 D+手完整覆盖解释”的情况下，才尝试为 `hold_and_move=False` 的 C 寻找新位置。
使用被手影响前保持不变的完整框 `C.box`，加上 C 自己从进入 HAND_* 后累计的全部移动值，计算这一帧的主估计位置：`expected_box = move_box(C.box, total_item_move_value(C))`。
这个框是完整物品坐标系中的候选位置，也是后续候选 `track` 的统一来源。
不能以 `last_hand_block_box` 作为主估计基准：上一帧可能没有可靠检测，局部框也会随手遮挡面积变化而漂移；完全遮挡物品更没有有效的局部框。
`first_hand_block_box` 与 `last_hand_block_box` 只保留作局部连续性或掉队判断的辅助信息，不参与主位置计算。

然后在手框附近寻找检测物品 B，并先排除能严格匹配其他库存物品的 B，再用允许少量抖动和偏移的[局部匹配]检查 B 是否仍然是 C。(因为这时估计框是C的完整框的基础上估计的, 而B可能是被手遮挡了的小框, 只能用[局部匹配])
若 B 匹配成功，同时 C 的旧位置已看不到 C、也不存在候选新物品 D+手完整覆盖 C 的解释，就累加一次 `hold_evidence_count` 并清零反向计数。
连续两次有效判断都满足这组条件后，才设置 `hold_and_move=True`。
在正式确认放下以前，`C.box` 继续保留本段 HAND_* 前的旧位置；当前 B 只更新局部观测 `last_hand_block_box`，候选 `track` 始终追加由 `C.box + 总移动值` 得到的主估计框。

若没有找到唯一匹配的 B，则这是模糊帧，不能立即把 C 判为出库，也不能直接恢复为“可见”。
两个证据计数都暂停，保留 C 的待确认状态与候选轨迹，等待后续有效帧。
移动量累计误差、手臂遮挡、YOLO 漏检以及 C 尚未露出都可能造成这种情况。


### 4.2 `hold_and_move=True`：只跟踪并确认放下

一旦 C 的 `hold_and_move` 已经为 `True`，就不再检查旧位置来累计“没有移动”的证据，也不再修改两种证据计数。
后续每张完整处理的有效手帧只继续更新 C 的 `track`；track 仍由 `C.box + C 自己累计的全部移动值` 生成，并用轨迹估计框寻找检测物品 B。这里的 B 必须先排除能严格匹配其他库存物品的情况；
若 B 仍被预登记为覆盖 C 旧位置的候选新物品 D，也先保留其 D 身份，除非 C 有足够强的轨迹身份证据把它重新认领。即使 B 与 C 的 track 匹配，也只能说明 B 很可能是 C。

只有在手继续移动而 C 的框明显掉队，或者已经出现 C 与手分离的证据时，才确认 C 被放下并完成整理，随后用终点框更新 C 的工作库存位置。单独的 track 匹配不能确认放下。


## 五、处理手附近但尚未解释的检测框

本节处理的是完成“未知 D 预登记”和被手影响物品 C 的判断后，仍然没有最终归属的手附近检测框 B。
也就是说，未知 D 的发现不能等到本节才开始；本节只继续更新、重新认领或确认此前已预登记的 D。

如果手附近的 B 没有匹配到任何被手部分遮挡的物品，再拿它与工作库存中当前可见的物品 A 做局部匹配。
局部匹配只说明 B 与 A 可能是同一物品的不同可见部分或不同遮挡程度，不能单凭局部匹配就判定发生了入库或整理；
匹配成功后继续跟踪 A/B 的后续位置。若 B 属于已经提升到工作库存的 D，继续沿用 D 的 `item_id`；若它同时与旧 C 的轨迹相符，记录身份冲突并等待连续帧解决，不能只因为空间相交就强行改认领，也不能自动删除 D。

如果仍然匹配不上，再检查被手完全遮挡的库存物品。
若 B 的类别与某个被手完全遮挡物品一致，且当前的空间关系合理，则把 B 归还给该库存物品。
若该物品 `hold_and_move=False`，B 只作为待确认阶段的候选正向证据；若已经 `hold_and_move=True`，则跳过握持判断，只把 B 用于 track 匹配，并继续寻找掉队或与手分离的放下证据。

如果 B 仍然无法与任何库存物品对应，先检查它是否已经是预扫描阶段建立的疑似新物品 D：若是，则继续更新它的记录，即使它此刻已经不再贴手也不能丢失这条候选轨迹；若不是，只有 B 此刻与手相贴时才新建疑似新物品记录，不贴手时只保持该检测框未决。新建 D 后，下一张有效帧若仍能与 D 自己连续匹配且仍无法匹配库存，就立即把同一个 D 提升到工作库存，分配 `item_id`，并保留其 HAND_PARTIAL 状态、轨迹、移动值和证据计数。D 的一次漏检不能删除它；若它与旧 C 发生身份冲突，保持冲突未决，不自动撤销 D。若 D 长时间没有后续支持，才在收尾阶段将其标记为未确认并清理临时记录，不能因此反向生成 C 的出库判断。

手进入第一帧就贴近手出现的未匹配检测框与手移动过程中后来贴手出现的未匹配检测框要区分记录。第一批疑似物品可能只是手带来的旧物品，也可能是原库存物品被重新检测到；后续批次则可能是手放下的新物品。两者都必须通过连续观察确认，不能只按出现时机直接判定。

## 六、处理被手完全遮挡的物品

对于被手完全遮挡的库存物品 C，因为看不到物品本身的框，不能根据“手移动了而 C 仍然看不见”就认定 C 被拿走。手臂没有被 YOLO 完整框出时，C 可能只是一直处于手臂阴影或遮挡区域。

先查看 `C.hold_and_move`：

对于 `hold_and_move=False` 的 C，先应用前文“未知 D 预登记”的规则。
若本帧手明确移动，候选新物品 D 与手框的并集完整覆盖 C.box，且没有在候选轨迹其他位置唯一找到 C，这本身就是一次“没有跟手移动”的有效证据；若 D 只部分覆盖 C、C 又暂时看不见，则 C 的两个计数保持不变，但 D 继续跟踪。除上述特殊情况外，只有手本帧明确移动时才进行普通判断：旧位置唯一看到 C，是一次“没有跟手移动”的有效证据；根据 C 的估计轨迹找到一个与 C 唯一匹配、且不能严格匹配其他库存物品的 B，是一次“跟着手移动”的有效证据。两种证据分别累计，连续两次支持同一方向才采取对应动作；相反方向的有效证据会清零另一边计数。手没有明确移动、B 匹配不唯一、当前没有找到 B 或存在尚未解释的遮挡时，都是模糊帧，两个计数都不增加也不清零。

对于 `hold_and_move=True` 的 C，已经确认它跟着手移动，不再重复检查旧位置，也不再修改上述两个计数。后续只继续维护 C 的 `track`，并将轨迹估计框与快照中的 B 匹配；B 必须先排除其他库存物品的严格匹配。只有结合 C 掉队或已经与手分离的证据，才确认 C 被放下、整理成功；单独的 track 匹配不能证明已经放下。

## 七、遮挡关系和物品状态更新

每张完整处理的帧完成物品认领后，再处理剩余库存物品的遮挡关系。D 在提升到工作库存但仍处于 HAND_PARTIAL 时，只保存“D 临时遮挡 C”的关联；D 虽已有 `item_id`，但尚未放下，不能因此立即把 C 退出 HAND_* 或写入最终遮挡关系。D 出现掉队、与手分离或手离开后框稳定时，记录当前放置位置到 `D.placed_box`，才视为已经放下；这个判断不要求 D 自己的 `hold_and_move` 已经为 True，因为新物品可能在凑齐两次握持证据前就被放下。D 放下后先处理 D 自己：把稳定的 `D.placed_box` 写入工作库存 `D.box`，结束 D 的 HAND_PARTIAL 状态，清空 D 的手部局部框、移动值和手轨迹索引，并按新的遮挡关系把 D 标为普通【可见】或【遮挡】。随后再处理 D→C：对于 `hold_and_move=False` 的 C，把临时关联转为正式 `block_ids`，并用 `D.placed_box` 按 4.1.1 的覆盖规则释放 C：D 单独完整覆盖 C 时，C 直接转普通【遮挡】；D 部分覆盖但 C 在原位置重新出现时，C 转【可见】或普通部分遮挡；D 部分覆盖且 C 仍被手+D 并集遮住时，只累计反向证据，等待后续露出。对于 `hold_and_move=True` 的 C，必须先根据 C 自己的候选 track 结算它的最终位置；只有 D 覆盖该最终位置时才能建立正式 D→C 遮挡，若 C 已经移动到其他位置则移除这条旧位置临时关联。所有情况下都保留 C 原来的 `C.box`（直到 C 自己被确认整理），不发 OUT。手离开后若 D 的稳定框使 `placed_box` 改变，必须先重新计算所有 D→C 覆盖关系；失去覆盖解释的 C 回到待确认检查，不能直接据此 OUT。整理后重新放置的物品以及本轮确认入库的新物品，视为位于发生重叠的旧物品前方。

如果一个库存物品不再被手直接影响，但被其他物品遮挡，则状态为“遮挡”，保留原位置和库存身份；如果重新露出，则恢复为“可见”。这里“退出 HAND_*”与“变为可见”是两件事：D 放下后被 D 挡住的 C 应退出 HAND_*、进入普通“遮挡”，不能标成“可见”；只有 C 实际露出时才恢复“可见”。`hold_and_move=False` 的物品不能仅因消失就记录为“已整理/已移动”；`hold_and_move=True` 的物品也必须等到掉队或分离证据出现后，才把轨迹终点写入工作库存。

### 7.1 已确认前景导致旧物缺失

手离开后的收尾阶段，若已确认移动或入库的前景物品 A 以可靠的 `placed_box`/`base_box` 与旧物 B 的旧 `base_box` 有正面积交集，而 B 在 A 的确认事件后没有合法、唯一的直接观察，可以把 A 写入 `B.block_ids`。若 B 没有已确认的自身 `MOVED`、唯一终点或 `OUT`，则 A 的确认事件可以作为 `CAUSAL_FRONT_MISSING` 证明：B 保留原 `item_id` 和原位置，转为普通【遮挡】，不累计 B 的普通缺失或 visible-count OUT 证据。仅有 `HAND_*`、`POSSIBLE_MOVED` 或手部位移迹象不等于 B 已经独立离开，不能否决这条因果解释。

前景关系本身仍只要求正面积交集；它不要求严格完全覆盖。为了不把仅擦边的偶然重叠解释为“整件物品消失”，当 B 只有未决的 HAND/POSSIBLE_MOVED 线索时，`FLOW3_CAUSAL_OCCLUSION_MIN_COVER_RATIO` 规定 causal proof 的最低合理覆盖比例。严格 full/edge proof 和原有 `DISAPPEARANCE_SUPPORTED` 路径仍使用各自的阈值，普通检测归属、MOVED、IN、OUT 和已有遮挡关系的判定都不因此放宽。B 仍有合法、唯一直接框时，B 保持【可见】，即使 A 已被写入 `block_ids`。

B 已经确认自身移动或出库时，先结算 B 自己，A 不能将其旧位置缺失解释成遮挡。若事务尚未提交而 A 又离开、覆盖关系消失，必须撤销这次仅用于当前事务的【遮挡】投影，让 B 回到原有的缺失/OUT 证据链，不能永久卡在未决状态。事件发布顺序保持 `MOVED/IN/OUT` 在 `OCCLUDED/REVEALED` 之前。

## 八、整理的确认

整理判断必须先看 `hold_and_move`。`hold_and_move=False` 的物品还没有确认跟手移动，不能在手还在时直接标记为整理；只能继续累计正、反向证据。只有 `hold_and_move=True` 后，才进入“跟踪并寻找放下证据”的整理分支。

对于已经 `hold_and_move=True` 的部分可见物品，如果它露出的框在手移动过程中与手同步移动，并且在手继续移动时出现明显的“掉队”，再结合新框与旧框的包含关系和局部匹配，才确认它被放下。若露出部分大小和形状明显改变，或重新回到旧位置，则优先认为只是遮挡。单独与 `track` 匹配不能确认放下。

对于已经 `hold_and_move=True` 的完全遮挡物品，只有在手附近或估计轨迹附近重新出现一个 B，B 先排除能严格匹配其他库存物品的情况，再与 C 的 `track` 估计框匹配，并且同时有掉队或与手分离的证据，才确认整理。仅仅因为它一直没有被看到，或单独因为 B 与 track 匹配，都不足以确认整理，更不足以确认出库。

一旦某物品在工作库存中确认完成整理，就更新它的工作位置并结束这次 HAND_* 临时状态，让后续帧使用这个新位置进行比较。正式库存仍然等到整段手部操作结束后统一提交。

## 九、入库的确认

新物品只能通过“与手相贴地出现、无法认领给库存、下一张有效观察仍能自匹配、之后继续稳定存在”这一链路确认。在每张进入完整处理的手部快照开始时，若检测框 D 暂时无法可靠认领给任何库存物品、且 D 与手相贴，就在处理 C 之前建立或更新疑似记录；第一张手帧同样执行此规则。这里的“下一张有效观察”既可以是下一张有效手帧，也可以是手刚离开后的第一张收尾无手帧：只要该帧仍能与 D 自己连续匹配且仍无法匹配库存，就把同一个 D 提升到工作库存，分配 `item_id`，但仍保持“被手部分遮挡”状态，直到确认放下。微小移动而被整体跳过的帧不创建、提升或更新 D。

D 提升到工作库存后，后续帧直接使用它的正式 `item_id` 更新 HAND_PARTIAL 的轨迹、移动值和证据；不需要等到手离开才第一次确认身份。D 的放下确认仍采用掉队/与手分离或无手稳定框，但不要求 D 自己先把 `hold_and_move` 变为 True：新物品可能在获得两次握持证据前就已经被放下。手离开后的收尾负责把最终稳定框写入 `placed_box` 和 `box`，重新计算 D→C 覆盖关系，并在确认放下后把临时关联转为正式 `block_ids`。

单摄像头存在无法解决的情况：如果 D 与旧 C 类别、大小和位置都完全相同并重合，视觉上可能无法彻底证明两者不是同一物品。本流程采用已经确定的业务策略：只要 D 已完成“贴手出现 → 下一张有效观察自匹配 → 仍无法唯一认领给库存”的入库链路，就保留 D 为新物品，同时保留 C 在原位置（必要时由 D 遮挡），不因为这层歧义删除 D、合并 D/C 或判 C 出库；若检测框没有完成这条手带入链路，则不能仅凭静态未匹配框增加库存数量。

## 十、出库的确认

出库只能在手离开后的收尾阶段确认。手还在画面中时，任何“看不见 C”的结果都只能记为疑似出库，不能直接删除工作库存；只要还没有找到足够证据，C 就保留为未决。

手离开后进行最终检查，并按 `hold_and_move` 解释结果。收尾前必须先处理 D 的最终状态：如果 D 还只是疑似对象，先确认它是否已经通过连续自匹配进入工作库存；如果 D 已有 `item_id` 但仍处于 HAND_PARTIAL，则先用无手帧确认它的最终稳定 `box` 和放下状态。只有完成这一步，才能把 D→C 的临时遮挡关联转成正式 `block_ids`，并按覆盖程度释放 C；D 稳定存在并遮住 C 时，C 保留在旧位置，绝不能判出库。

对于 `hold_and_move=False` 的 C，不能把 False 当成“没有移动”：在原位置(A.box)看到 A，就确认没有移动；在候选 `track` 的其他位置看到 A，就补确认整理；只有在 D 已完成最终处理、没有仍有效的 D 覆盖关联时，旧位置和整条候选轨迹上都没有重新找到 A，才补确认出库。若 D 已放下并覆盖 C，则先按 4.1.1 判断 C 是释放为【可见】/普通【遮挡】还是继续待确认；在这个判断完成前不进入 OUT 判断。对于 `hold_and_move=True` 的 C，不再重新进行两次握持证据判断；手离开本身提供了分离条件，若候选 `track` 的其他位置找到未被其他库存物品认领的 A，就确认整理，若旧位置重新找到 A，则按终局结果恢复没有移动，若不存在有效 D 覆盖关联且两处都找不到 A，则确认出库。没有明确出库证据的缺失物品继续保留在正式库存，不直接删除。

## 十一、手离开和本次操作结束

当连续快照中不再检测到手时，先不要立刻清空所有临时状态，而是进入本次手部操作的收尾阶段，并继续接收若干张无手快照，用于确认 D 的最终稳定 `box`、放下状态和临时遮挡关系。每张收尾无手帧仍要执行检测框与工作库存、已有疑似 D 的匹配：可以更新已有 D 的自匹配、把首次贴手时已建立的 D 提升到工作库存、更新 D 的 `placed_box`/`box`，以及检查 C 的旧位置和候选 track；但不能凭一个远离手的全新未匹配框创建 D，也不再追加手部移动值或新建 HAND_* 状态。此时根据每个物品的 `hand_track_start_index` 读取公共 `hand_track` 中属于它的轨迹片段，再结合各物品的 track、旧位置以及最后几帧快照，对所有疑似移动、疑似入库和疑似出库物品做最终确认。收尾顺序先完成 D 的身份提升/最终放下判断及其对 C 的遮挡处理，再处理 C 的整理和出库；这样 D 挡住 C 时不会把 C 误删。收尾列表不能只包含 `hold_and_move=True` 的物品；所有仍在 HAND_* 中的 `False` 物品也必须进入收尾，因为它们是待确认而不是已否定。True 物品不再做握持证据判断，但仍要完成放下、没有移动或出库的终局判断。

收尾结束后，确认没有移动的物品恢复为正常可见或遮挡状态；确认整理的物品保留新的位置；已经提升到工作库存的 D 同时更新最终稳定 `placed_box` 与 `box`，重新计算覆盖后再把有效的临时遮挡关联写入 `block_ids`；确认出库的物品从工作库存移除。没有明确出库证据或仍有未决 D 遮挡关联的物品保持未决并继续留在工作库存。

若仍有候选新物品 D 需要通过连续无手帧确认其身份或最终放下，则继续保留工作库存、D 的临时遮挡关联和 C 的未决状态；在 D 的状态解决前，不得提交本次操作，也不得仅因 C 暂时看不见而判它出库。若 D 已经完成贴手出现与自匹配链路、只是与旧 C 存在无法消除的身份歧义，则按“D 是新物品、C 保留在原位”的既定策略收尾，不自动删除 D、合并 D/C 或发出 C 的 OUT。

只有全部候选 D 都已完成上述处理并通过最终检查，才把工作库存整体提交为正式库存，并统一产生 IN、OUT、MOVED 等正式事件。提交完成后清空本次手部操作的疑似新物品、待出库记录、手轨迹、物品移动值和临时状态。若操作异常中断，则丢弃工作库存，正式库存保持不变。

## 十二、整个流程的核心判断顺序

整个系统始终遵循以下优先级：先判断有手帧是否达到有效移动阈值；不足阈值的手帧整体忽略，所有状态继续沿用最近的已处理帧。对首帧和达到阈值的有效手帧，先预登记或提升“无法认领给库存且与手相贴”的候选新物品 D，并判断它是否与手共同遮挡旧物品 C；再按 `hold_and_move` 分支处理 C：False 的物品用有效移动帧判断“仍在旧位置”或“跟着手移动”，True 的物品跳过握持判断、只维护 track 并寻找掉队或分离证据；随后再处理手附近检测框与可见库存、完全遮挡库存的匹配，最后确认 D 的放下状态并按实际覆盖程度释放 C。任何单帧的消失、出现或遮挡，都不能直接等价为出库、入库或整理，必须结合 D 的临时遮挡解释、对应分支、物品轨迹、旧位置和手离开后的最终结果共同确认。
