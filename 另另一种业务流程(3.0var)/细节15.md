# 代码审查后的修改指导

## 审查基线

- 以 `细节14.md` 为最新规则，细节 8 至 13 为前置不变量。
- 本次确认 r15/r16/r17 的主状态机、正式库存与工作库存分层、C-D alias 收尾，以及 OSD/业务输入同源关系已落地。
- 本文件只记录下一轮修改的边界；本轮不修改业务源码。

## 优先级 0：修复同类旧 C 串位，以及被撤销 MOVED 的残留状态

对应实测记录：`讨论用/测试后的结果与发现的问题.md`。

### 现场因果

本次不是 soda_can 实际遮挡苹果。现场手框在中段过大，旧苹果 `item#2` 暂时漏检，而另一颗旧苹果 `item#3` 始终有自己的原位检测。`item#2` 在保护期内把严格属于 `item#3` 的框记成自己的 B 候选，并累计 `hold_evidence`；随后在有手帧被错误 `confirm-rearrange`。真实的 `item#2` 原位框之后又被带入 D/alias 链路，最终连锁产生错误的 `OCCLUDED item#2` 与 `IN item#9`。

这属于同类旧 C 的动态候选所有权问题；遮挡和 IN 是后果，不应先靠调整遮挡阈值处理。

### 0.1 保护期内不得借用另一旧 C 的严格框

涉及位置：

- `src/session.cc` 中 `update_existing_hand_tracks_()` 的 `is_claim_protected(track)` 分支（约 3367 行）
- 现有可复用判断：`detection_strictly_matches_other_item()`（约 734 行）

现状：保护期分支在 `old_position_index < 0` 时会直接 `record_tentative_b()`，并可能累计 `hold_evidence_count`。这里没有排除“该 detection 已严格属于另一件 operation-start 旧 C”的情况。相邻同类旧物品因而会按 `track_buffer_` 的遍历顺序互相借用 B 证据。

修改要求：

1. 为保护期内 C 的本地 B 候选增加旧 C 所有权门槛：若 detection 严格匹配另一件 operation-start 旧库存的可靠参考框，当前 C 不得把它写为 tentative/reappear B，不得据此累计 hold 或进入 `hold_and_move`。
2. 此时保持当前 C 未决，并让该检测框留给真正的旧 C、后续一对一仲裁或无手结算；不能因为拒绝候选就创建 D。
3. 该判断只解决“旧 C 借另一旧 C 的直接严格框”，不要把 pending D、`C_POSITION_REPLACEMENT_D` 或普通同类邻近 D 一并视为阻塞者。
4. 不能依赖 map 遍历顺序决定两个旧 C 的身份。

### 0.2 有手阶段的 MOVED 必须能被原位直接证据完整撤销

涉及位置：

- `src/session.cc` 中 `confirm_rearrange_()`（约 2810 行）写入 `confirmed_moved_ids_` 和 `placed_box`
- 同文件 `release_not_held_()`（约 2843 行）在 `ORIGINAL_DETECTION` 后改回 `STATIC_CONFIRMED`
- 无手结算仍把 `confirmed_moved_ids_` 作为高优先级前景/事件依据（约 5851、5973、5983 行）

现状：现场 `item#2` 在 312 帧被错误确认 MOVED，314 帧已经用自己的原位直接检测释放回 `STATIC_CONFIRMED`；但 `release_not_held_()` 没有撤销 `confirmed_moved_ids_`、`has_placed_box`、`placed_box` 与 `drop_confirmed`。未提交的旧 MOVED 因此仍污染无手绑定、前景遮挡和最终事件。

修改要求：

1. 在同一次操作尚未正式提交时，`ORIGINAL_DETECTION`（及等价的原位静态释放）若撤销了此前 `MOVED_CONFIRMED`，必须同步清除该 item 的临时 MOVED 标记与放下终点。
2. 工作库存的 `box/base_box` 应恢复为当前原位直接证据，保留正常的 YOLO 框微小抖动，不硬写死成旧矩形。
3. 已被撤销的 item 不得继续作为无手绑定优先级、前景遮挡物或 `MOVED` 事件来源。
4. 已正式提交后的历史事件不回写；本条只针对当前 operation 的可撤销工作状态。

### 必补回放

1. 用本次日志的最小化几何构造两颗相邻同类苹果 A/B，以及一个实际移动的 soda_can。手框短暂大范围覆盖 A，A 暂时漏检，B 仍持续严格出现在自己的原位。
2. 断言最终只产生 soda_can 的 `MOVED`；两颗苹果均保持可见、原数量不变，绝不产生苹果 `MOVED`、`OCCLUDED` 或 `IN`。
3. 单独覆盖“先错误进入临时 `MOVED_CONFIRMED`，再在提交前直接见到原位框”的回滚：最终不能保留 `confirmed_moved_ids_`、旧 `placed_box` 或任何前景遮挡资格。
4. 保留细节14的 `HAND_VISIBLE_D` 回放。该测试覆盖 D 借静态旧 C 框；本条覆盖旧 C 借另一旧 C 框，两者不能互相替代。

## 优先级 1：修正遮挡差集的残片处理

涉及位置：

- `tools/luckfox_pico_rkmpi_example/example/luckfox_pico_rtsp_yolov5n/src/session.cc` 中 `subtract_cover()`（约 499 行）
- 同文件 `fully_covered_by()`（约 519 行）

现状：`subtract_cover()` 在每一次矩形差集后，按 `COVER_REMAINING_AREA_EPS` 丢弃单个小残片；而 `fully_covered_by()` 最后才按剩余总面积判断。多个各自不超过阈值、但总面积超过阈值的残片会被提前全部丢弃，可能把部分遮挡误判成 `OCCLUDED`。

修改要求：

1. 差集过程中保留所有正面积残片，仅去除零面积或纯浮点噪声残片。
2. 全部遮挡框处理完成后，再在 `fully_covered_by()` 以剩余总面积唯一应用 `COVER_REMAINING_AREA_EPS`。
3. 不改变现有阈值，不把覆盖并集退化为逐框相交面积相加。
4. 先补最小失败回放：未覆盖区域分成多个各自不大于 `4 px^2`、但总和大于 `4 px^2` 的残片时，目标必须保持 `VISIBLE`，不得转为 `OCCLUDED`。

保留既有覆盖并集回放（`session3_replay_test.cc` 约 1703 行），以防重叠遮挡框被重复计面积。

## 优先级 2：调整 r17 静态预约的候选过滤顺序

涉及位置：

- `tools/luckfox_pico_rkmpi_example/example/luckfox_pico_rtsp_yolov5n/src/session.cc` 中 `build_mutually_unique_hand_static_owner_by_detection_()`（约 2679、2718、2731 行）

现状：helper 先把所有严格匹配 C 放入 detection 的候选集，之后才在写入 `best_detection_for_item` 时排除 `hand_affects(hand_box, reference)` 的 C。已被手覆盖的 C 仍能以更低成本占据竞争位，阻止真正静态的 C 获得双方唯一预约，这与细节14中“手已覆盖的 C 不参与静态预约”的定义不一致。

修改要求：

1. 在构造 `candidates_for_detection` 前过滤掉 `hand_affects(...)` 的 C。
2. 保留真正静态 C 之间的严格匹配、唯一最低成本、平局未决和迭代预约语义。
3. 不扩大到 `C_POSITION_REPLACEMENT_D`、无手仲裁或全局匹配阈值。
4. 先补最小失败回放：一个被手覆盖的同类 C 和一个未被手影响的静态 C 都严格接近同一检测框时，前者不得阻止后者成为静态预约；`HAND_VISIBLE_D` 仍必须让渡该框，不累计认领、不增加 `self_match_count`、不提升 D。

## 优先级 3：独立清理死代码

涉及位置：

- `src/session.cc` 中同名空实现（约 5622 行）

该函数没有调用点且实现为空。可在独立、无行为变化的提交中同时删除声明和定义；不要与上述两项状态机修复混在同一变更中。

## 暂缓的非功能性同步项

- `include/fridge_config.h` 的版本标识仍为 `3.0-r16`，而 r17 代码和回放已经存在。待 r17 实机验证后再决定是否更新。
- `FLOW3_DEBUG_TRACE_LOG` 当前默认开启。常规部署前应评估日志量并考虑关闭，但不要混入正确性修复。

## 本轮不纳入修改范围

- 多手并行归属：属于 `后续修改主方向.md` 的后续阶段，当前代码只选择主手不是细节14缺陷。
- 单手连续多动作的完整逐物品生命周期：同属后续阶段，不能借本轮 r17 或遮挡修复扩大改造范围。

## 建议执行顺序

1. 先为优先级 0 补现场问题的最小失败回放，并先修复旧 C 串位与可撤销 MOVED 回滚。
2. 再为优先级 1 和 2 各补一条最小失败回放，分别实施对应 helper 的最小修改。

4. 在独立提交中移除死代码。
5. r17 实机验证完成后，再处理版本和默认调试日志配置。
