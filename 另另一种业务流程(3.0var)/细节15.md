# 细节15：先确认旧物体原位置所有权，再允许移动路径匹配

## 0. 本文件的用途

本文件是下一轮业务代码修改的唯一实施指导。此次修改的目标是修复
《讨论用/测试后的结果与发现的问题.md》记录的实测错误：

    只实际移动一罐 soda_can，
    却额外产生了 apple 的 OCCLUDED 和 IN。

本轮不是泛化地重写整理、遮挡、入库或出库流程，也不是通过调整阈值
“压住”这一条日志。必须在错误身份确认的源头修复，并把该实测过程
固化为可重复的回放。

当前代码已经具备并通过了许多重要能力，包括正常 MOVED、IN、OUT、
C-D alias、无手收尾、工作库存隔离、细节14的 HAND_VISIBLE_D 防护等。
本次只添加必要的所有权优先级和可撤销状态回滚；不得为了通过本例而
破坏原先已经正确的代码与回放。

## 1. 实测问题的准确描述

### 1.1 物体记号

为避免把代码中的 D suspect 与讨论用的检测框记号混淆，本文件中：

- 旧苹果 A：现场日志的 item#2。
- 旧苹果 B：现场日志的 item#3。
- C(A)：当前帧中真实属于 A 的检测框；本例中曾暂时漏检。
- D(B)：当前帧中真实属于 B 的检测框；这里的 D(B) 只是讨论记号，
  不是代码里的“疑似新物品 D”。

初始时 A、B 是两件不同的 operation-start 旧库存，原位置不同。
本例中真正需要识别的动作只有 item#1 soda_can 的 MOVED。

### 1.2 现场时间线

1. 手框在中段变得很大，A 被建立为 HAND_FULL；YOLO 暂时没有输出 A。
2. B 仍有原位检测框 D(B)。在关键帧中该框甚至接近完整框；在更一般的
   遮挡场景中，它也可能只剩 B 的局部小框。
3. 当前实现先让 A 的 HAND_* 更新路径用估计框或局部路径找到 D(B)，
   并把 D(B) 记为 A 的 tentative/reappear B，累计了 A 的 hold 证据。
4. A 因此被错误 confirm-rearrange；这不是 A 的真实移动，而是 A 借用了
   B 的原位观测。
5. 随后真正的 A 原位框被错误地带入 suspect / C-D alias 链路，最后生成
   item#9 apple。
6. 无手结算基于已经污染的工作库存，将 item#9 视作前景，错误输出
   OCCLUDED item#2 和 IN item#9。
7. 日志中 A 后来已经被自己的原位直接框释放回 STATIC_CONFIRMED，
   但此前写入的临时 MOVED 标记和 placed 状态没有完整撤销，继续污染
   无手绑定、前景遮挡物和最终事件。

因此，本例的根因顺序是：

    同类旧 C 的原位置所有权未先建立
        -> A 借用 B 的框形成假移动
        -> 假移动污染 D / alias 与无手结算
        -> 错误 OCCLUDED 与 IN

遮挡和 IN 是后果，不是本轮首先应调整的遮挡算法问题。

## 2. 必须实现的业务规则

### 2.1 原位置证据优先于移动路径猜测

对同一帧检测框，优先级必须是：

    旧物体自己的原位置严格证据
        > 旧物体自己的局部连续证据
        > 另一旧物体的估计移动路径 / 局部路径猜测

若 D(B) 能解释为 B 的原位观测，A 即使能用 estimated_box、track 或
其他宽松路径匹配到 D(B)，也不得把它作为 A 的移动证据。

“D(B) 归 B”首先只是本帧所有权结论，不等于单帧就最终认定 B 没移动。
B 是否只是被遮挡、是否最终恢复静态，仍沿用现有的有效帧计数和无手收尾。

### 2.2 不同状态允许的匹配方式

普通状态指既不处于 HAND_*，也不处于 CONTACT_* 的旧物体。

1. 普通状态：
   - 只允许用 original/base_box 做严格匹配。
   - 严格匹配失败就是本帧未匹配；不得退化成局部匹配，也不得因此直接
     创建 D、确认移动、确认出库或修改正式库存。
   - 严格阈值本来就应容纳正常 YOLO 的小幅抖动；超出该范围时等待后续帧。

2. CONTACT_*、HAND_PARTIAL_*：
   - 先尝试与自己的 original/base_box 严格匹配。
   - 严格失败后，允许局部匹配。
   - 局部匹配优先使用该物体自己的 last_hand_block_box 的连续性；它表示
     “上一帧已经看到的同一块局部区域仍连续存在”。
   - 若没有可靠的 last_hand_block_box，才可把“当前小框被旧完整框包含”
     作为较弱的原位局部候选；这只能保护所有权或保持未决，不能单帧确认 MOVED。

3. HAND_FULL_*：
   - 看不见物体不是移动证据，也不是出库证据。
   - 重新出现的框仍先走自己的原位置严格匹配；严格失败时可作为局部原位
     候选或路径候选，但必须受本文件第 2.3 节的所有权门槛约束。
   - 没有可唯一归属的框时，两个证据计数保持模糊，不增加也不清零。

### 2.3 同一框必须先得到全局的旧 C 原位置归属

不能再按 track_buffer_ 的遍历顺序，让某个 A 先尝试移动路径，再让 B
检查自己的原位置。每一张有手帧中，在任何旧 C 使用 estimated_box、
track、tentative B 或 reappear candidate 之前，必须先完成一次无副作用的
“旧 C 原位置所有权计划”。

建议新增纯 helper，名称可为：

    build_mutually_unique_hand_direct_old_owner_by_detection_()

输入为当前帧 detections、operation-start 旧库存、运行时 track、当前 claimed
种子；输出至少包括：

    detection_index -> 唯一旧 item_id 的直接所有权
    无法唯一决定的 detection_index 集合
    每个所有权的强度（STRICT 或 LOCAL_CONTINUOUS / LOCAL_WEAK）

该 helper 不修改 claimed_detection_indices、known_item_owner、工作库存或
任何计数；它只生成本帧计划。

构建计划时：

1. 对每个 operation-start 旧 C，用本文件第 2.2 节规定的顺序生成
   “原位置直接候选”。
2. 严格原位置候选优先于局部候选。
3. 局部连续候选优先于只有单帧包含关系的弱局部候选。
4. 若一个检测框只对应一个旧 C，记录唯一 owner。
5. 若多个旧 C 竞争同一框：
   - 严格候选中存在唯一更低 strict_match_cost 的，才可选出 owner。
   - 严格与局部同时存在时，严格候选优先。
   - 多个局部候选时，只有一个具备显著更强的自身局部连续性才可选出 owner。
   - 仅靠局部小框中心距离更近不能强行裁决；手遮住一侧会改变局部框中心。
   - 仍有平局或无法唯一解释时，标记为“原位置歧义”。

原位置歧义的框不能被任一旧 C 用作 HOLD / MOVED 正向证据，也不能在本帧
被新 D 用作 self_match、promote 或 placed 证据。它只保留为未决观测，
等待下一张连续帧或无手直接帧。

### 2.4 再处理移动路径匹配

原位置所有权计划完成后，才进入每个 HAND_* / CONTACT_* C 的动态路径更新。

对当前 C：

1. 如果当前检测框已唯一归另一旧 C：
   - 当前 C 不得使用它作为 observed_index、tentative_b、reappear_candidate、
     last_seen_box、hold_evidence 或 drop_evidence 的来源。
   - 当前 C 保持未决；不得因为拒绝该框而创建 D。

2. 如果当前检测框属于当前 C：
   - 用作当前 C 的原位置/局部连续观测。
   - 是否累计“未被拿起”的反向证据，仍按现有手是否有效移动、确认帧数和
     HAND_* / CONTACT_* 状态规则执行。

3. 如果当前检测框是原位置歧义：
   - 所有旧 C 都不得把它当移动正向证据。
   - 不得按 map 顺序选 A 或 B。

4. 只有未被任何旧 C 原位置计划占用、也不属于原位置歧义的框：
   - 才允许参与 estimated_box、last_hand_block_box、track 等移动路径匹配。
   - 仍须保留当前已有的唯一仲裁、claim grace、连续候选确认和无手直接证据。

这条规则也应提供给 scan_or_update_suspects_()。HAND_VISIBLE_D 或其他 suspect
不得使用已被直接旧 C 所有权计划保留、或标为原位置歧义的检测框升级自己。
细节14的“静态旧 C 预约让渡”保持原样；本细节补的是“活动 HAND/CONTACT 旧 C 的
直接原位置所有权”，两者不能互相替代。

### 2.5 原位置替代 D 的边界

真实的新 D 可能被放在一个已经被带走的旧 C 原位置，现有
C_POSITION_REPLACEMENT_D 链路必须保留。

本细节的保守规则是：

1. 若旧 C 尚无独立、可靠的被带走/放下证据，而当前框可解释为该旧 C 的
   原位置严格或局部连续观测，则优先保留旧 C，不把当前框急于升级为 D。
2. 若旧 C 已有独立且未被撤销的真实移动证据，现有 C_POSITION_REPLACEMENT_D
   和无手仲裁仍可处理原位置的新 D。
3. 单摄像头下，旧 C 与同类新 D 从视角上完全重合且没有独立手持过程证据时，
   本来就不可可靠区分；按既有保守原则宁可不新增库存，不得伪造 IN。

## 3. 临时 MOVED 必须完整可撤销

confirm_rearrange_() 在有手操作期间写入的是工作状态，不是正式不可逆事件。
只要本次操作尚未无手提交，后续独占的原位置直接证据就可以推翻此前的临时 MOVED。

当某旧 C 曾为 MOVED_CONFIRMED / PLACED，随后被本帧唯一的原位置所有权计划
归回自身，并按 ORIGINAL_DETECTION 或等价原位静态释放处理时，必须同步：

1. 从 confirmed_moved_ids_ 移除该 item。
2. 清空 has_placed_box、placed_box 和 drop_confirmed。
3. 清除只为旧 MOVED 终点保存的路径/候选残留，保留当前原位直接观测作为新的
   working box/base_box；允许正常 YOLO 小幅抖动，不硬写死历史矩形。
4. 保证该 item 不再是无手绑定优先级、confirmed_front_ids、遮挡 blocker 或
   MOVED 事件的来源。
5. 只回滚当前 operation 尚未提交的工作状态；已经正式提交给 inventory 的历史
   事件不回写。

“原位置直接证据”必须是本文件第 2.3 节的唯一 owner，不能因为任意同类框接近
original_box 就错误撤销一个真实的已放下物品。

## 4. 必须新增的回放

### 4.1 现场问题最小回放

构造：

- 两颗相邻同类苹果 A、B，几何位置使用现场日志同量级的相邻关系。
- 一罐 soda_can，从原位置移动到新位置。
- 手框中段短暂大范围覆盖 A、B；A 暂时漏检。
- B 连续出现在自己的原位置。
- 无手后 A、B 都重新完整可见，soda_can 在新位置稳定可见。

断言：

1. 最终仅产生 soda_can 的 MOVED。
2. 苹果 A、B 均为 VISIBLE，库存数量保持初始数量。
3. 不产生苹果 MOVED、OCCLUDED、IN、OUT 或 REVEALED。
4. 结果不得随 item_id、检测数组顺序或 map 遍历顺序改变。

### 4.2 B 只露出局部框的变体

构造与 4.1 相同，但 B 在 HAND_PARTIAL_* 期间只输出一个被 B 的 original_box
包含、并与 B.last_hand_block_box 连续局部匹配的小框；它与 B 的完整框严格匹配失败。
A 的 estimated_box 可以宽松匹配该小框。

断言：

1. B 的局部连续观测优先于 A 的移动路径猜测。
2. A 不得用该小框累计 hold、进入 hold_and_move 或 confirm-rearrange。
3. 无手后不产生额外苹果事件。

### 4.3 原位置冲突和纯路径歧义

1. 一个检测框同时与两个旧 C 的原位置候选同级且无法唯一裁决：
   保持原位置歧义，不得按最近中心或 map 顺序产生 MOVED / IN。
2. 一个检测框只同时匹配两个旧 C 的移动路径，不匹配任何旧位置：
   保持路径歧义，谁都不得把它作为本帧移动正向证据。
3. 严格原位候选与局部原位候选竞争时：
   严格候选优先。

### 4.4 MOVED 回滚回放

构造一个旧 C 在有手帧暂时进入 MOVED_CONFIRMED / PLACED，随后在同一 operation
正式提交前出现属于自己的唯一原位直接框。

断言：

1. 最终没有该 C 的 MOVED 事件。
2. confirmed_moved_ids_ 不再包含该 C。
3. placed_box、drop_confirmed 和前景遮挡资格均已清除。
4. 当前无手结算不能据此产生错误 OCCLUDED、IN 或 blocker。

### 4.5 必须持续通过的既有回放

至少覆盖并保留：

- 细节14：HAND_VISIBLE_D 必须让渡给双方唯一静态旧 C。
- 正常同类相邻 D 入库。
- C_POSITION_REPLACEMENT_D。
- C-D alias 的 shared、distinct、stale-missing 无手收尾。
- r16 遮挡灰区旧 C 的两帧无手结算。
- 正常 MOVED、IN、OUT、遮挡和揭示。

## 5. 严格禁止的修改方式

不得：

1. 修改全局 YOLO 分数阈值、NMS 阈值、手接触阈值、手移动阈值、严格/局部
   匹配阈值或既有确认帧数，只为让本例不再复现。
2. 把所有局部匹配禁掉。HAND_PARTIAL_* / CONTACT_* 必须能追踪真实的局部框。
3. 把所有原位局部匹配都立刻当作“未移动”终态。它们首先是所有权和观测证据，
   最终静态结论仍受现有确认规则约束。
4. 仅在最终事件生成处删除 OCCLUDED / IN。错误身份必须在有手阶段阻止。
5. 仅靠 map 遍历顺序、item_id 更小或局部框中心更近强行决定同类身份。
6. 重写整个 process_effective_hand_frame_() 顺序，或把静态预约全面提前，
   从而破坏已有 HAND_*、CONTACT_*、C_POSITION_REPLACEMENT_D 的优先级。
7. 修改或删除细节14的 D-GUARD、C-D alias、无手独立 D 仲裁，以换取本例通过。
8. 把多手并行归属或完整多动作生命周期混入本次补丁。

## 6. 建议实施顺序

1. 先在 session3_replay_test.cc 写出第 4.1、4.2、4.4 的最小失败回放；
   先验证当前代码确实失败，再开始改 session.cc。
2. 新增无副作用的“旧 C 原位置所有权计划” helper，并只在当前有手帧中接入。
3. 将 update_existing_hand_tracks_、CONTACT 路径和 suspect 扫描中会使用
   移动候选的入口，统一接入该计划的 owner / ambiguous 结果。
4. 实现第 3 节的临时 MOVED 回滚，确保只在唯一原位证据推翻当前操作内的
   provisional MOVED 时触发。
5. 每一个小步骤都运行完整 session3_replay_test；最终复跑 Sanitizer 版本。
6. 最后使用现场“只移动 soda_can”的实际操作复测，确认只输出一条 MOVED，
   库存仍为初始数量且所有苹果可见。

4. 被原位证据撤销的 MOVED 不遗留任何工作状态、遮挡资格或最终事件。
5. 既有 3.0 回放全部通过，且不改变原先已经正确的业务行为。
