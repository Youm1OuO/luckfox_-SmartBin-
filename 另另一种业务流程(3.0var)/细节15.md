# 细节15：处理间接移动和同类移动簇，避免错误结算或未决卡住

## 1. 目标与范围

一次手操作中，手直接移动 A 时，旁边旧物品 B/C 可能被碰撞、推挤或滚动而移动；
它们不一定被手框覆盖。当前状态机主要以“手直接影响”建立活动轨迹，因此 B/C 的框
偏移较小时可能被按静态收尾，偏移达到正式 MOVED 门槛后又因缺少直接手持证据而保持
未决，阻塞整轮提交。

本次只补充 **operation-start 旧库存的间接移动结算**。目标是：

```text
真实被带动的旧物品 -> 保持原 item_id，确认后更新自己的位置；
密集摆放造成的稳定 YOLO 框边界偏移 -> 可收敛，不永久卡住；
同类物品一起移动且每个物品都有独立框 -> 不交换身份、不互锁；
身份确实无法判定 -> 保守保持未决，不猜 MOVED / OUT / IN。
```

不修改 D 的身份、创建、提升、隔离或最终 IN 语义；本补丁不是通用阈值重构。

## 2. 绝对不能破坏的现有能力

不得修改全局 YOLO/NMS、手覆盖、移动距离、匹配或确认帧数阈值。尤其必须保留：

1. 正常直接拿取、低覆盖率推拉、放下、IN、OUT、MOVED、遮挡和恢复流程。
2. 细节9至细节14的同类一对一认领、claim grace、C-D alias 与假 D 防线。
3. 细节14：不可靠 D 不能借 operation-start 静态旧 C 的检测框增加 self-match 或入库。
4. 真实新物品仍可按既有 D 链路入库；同类相邻但静止的旧物品仍应优先保护自己的框。
5. 直接被手影响的 A 继续使用已有 HAND_* / CONTACT_* / reappear 路径，不能被本次
   的间接移动逻辑替换、放慢或重复结算。

不得通过调大 `FLOW3_COMMIT_MOVE_CENTER_DISTANCE`，或把超过该门槛的框一律当作静态，
来解决本问题。

## 3. 位置更新与业务事件必须分开

对已经确认身份的旧物品，库存位置更新和是否产生 `MOVED` 事件不是同一件事：

```text
确认发生间接位移
    -> 用该物品自己的最终直接检测框更新 box / base_box。
    -> 只有位移达到既有正式 MOVED 门槛，才产生 MOVED 事件。
    -> 位移较小但已确认时，仍更新 base_box，但不额外制造 MOVED。

未证明真实间接位移，但最终框连续、唯一、稳定
    -> 允许做 STABLE-REBASE：更新 base_box、解除未决、不产生 MOVED。

身份竞争、漏检、候选不连续或证据矛盾
    -> 保持 UNRESOLVED；不更新 base_box，不猜事件。
```

因此，不能只调用 `update_seen()` 后便视为位置已经完成业务更新；只有已经确认的
`INDIRECT-MOVE` 或 `STABLE-REBASE` 才可写入 `base_box`。实现可增加一个仅用于
最终写回位置的已确认集合/标志；它不能等同于 `confirmed_moved_ids_`，否则小位移会
被错误地产生 `MOVED`。

## 4. 间接移动候选的证据

间接移动候选必须是 operation-start 的旧库存，并且始终使用它**自己的**检测框和
观测轨迹。不得复制 A 的手位移、预测框或检测框给 B/C。

候选至少需要同时满足：

1. B/C 有当前直接检测框，且该框在同类旧库存中可唯一归属；不能使用共享框。
2. B/C 与直接活动的 A，或已确认的间接移动成员，存在操作期间可解释的推动链：
   物体框/短时真实轨迹相邻或相接，且 B/C 的位置变化在时间和方向上能接上前一个成员。
   仅因最终两个物品靠近，不能建立推动链。
3. B/C 自身有连续观察：其运动过程或最终无手位置由自己的直接框支持。无手最终框
   仍必须经过既有连续直接帧确认，不得单帧确认。
4. 同类候选必须先完成全局一对一身份分配；一个框可合理属于多个旧物品时，不能确认
   任意一个候选的间接移动。
5. 候选不得与未解决的 C-D alias、真实新 D、OUT 或遮挡证据发生冲突。冲突时保留
   原有保守仲裁，不以“推动关系”覆盖它。

表示方式可以是 `OperationTrack` 上的局部字段，也可以是独立的临时移动簇结构；但它
必须是可撤销的，不能把未确认 B/C 直接升级为 HAND_*、MOVED 或工作库存新物品。

## 5. 同类 A-B-C 排成一行并一起被推动

用户已确认：即使多个同类物品相贴，YOLO 仍持续输出每个物品的独立框。因此本次的
核心不是处理合并框，而是防止同类身份在集体移动中交换。

对于沿同一方向的接触链：

```text
操作前：A -> B -> C
推动后：a -> b -> c
```

物品可能平移、间距可能改变、B/C 的位移可能与 A 不同；但在普通推挤中它们不会穿过
彼此。实现优先使用 A 的**自身真实观测位移方向**建立投影轴；若 A 在有手阶段完全被
遮住，只可用 A 的原位置、自己的最终候选位置或手方向缩小候选范围，不能用手位移直接
给 A/B/C 分配身份或位置。最终映射仍必须由各自的直接检测框确认，并在该轴上保持顺序：

```text
sort(start members along axis) == A, B, C
sort(final direct detections along axis) == a, b, c

只允许：A -> a，B -> b，C -> c
禁止：A -> b，B -> c，C -> a 等循环或跨越映射
```

镜像画面或从右向左推不影响该规则：按推动向量投影排序，不按固定的屏幕左右方向判断。
YOLO 每帧 detection 的输入顺序也绝不能作为身份依据。

对于非共线、滚动导致每个物品位移不同的情形，成员各自的连续真实框优先；推动链和
共同方向只用于验证“它属于这次操作”，不能替代最终位置。若无法得到唯一且不交叉的
全局分配，保持未决，不能用 `item_id`、detection index 或逐个就近贪心来决定身份。

这条规则只适用于物理上不穿越的推挤链。若物品真的绕行、交换先后顺序，且中间轨迹又
无法保持连续，则当前 `cls_id + BBox` 信息不足，仍应等待后续帧，不得伪造身份。

## 6. 批量分配和无手结算顺序

同类移动簇必须作为一个批次做一对一分配，不能让 B 等 C、C 又等 B 的逐项认领形成
逻辑未决。建议顺序如下：

```text
1. 保持既有 D-GUARD、C-D alias 和普通静态旧 C 的保护规则。
2. 标记有可靠推动链的旧 C 为间接移动候选。
3. 普通静态预约/静态灰区 release 不得抢占这些候选成员的框；
   非候选静态旧 C 仍按原规则优先预约自己的唯一严格框。
4. 在未被非候选静态 C 或确认 D 占用的框中，对移动簇一次性做全局、顺序不交叉的分配。
5. 连续无手直接帧确认后，分别更新每个成员的 final box / base_box；达到既有门槛的
   成员分别确认 MOVED。
6. 只有没有可靠推动链的旧 C，才可进入 STABLE-REBASE 兜底。
```

现有“同类可见数量不足”的 `VISIBLE-COUNT` 最小成本/稳定 item_id 决胜，只适用于
该既有 OUT 兜底，不能复用为间接移动簇的身份决策。间接移动簇遇到完全打平时必须保持
未决，而不是按 item_id 或检测索引选一个。

`try_release_stable_near_original_no_hand_()` 及其调用点需要检查：已经具有可靠间接
移动证据的 B/C，不能被细节13/14的静态灰区提前释放为 STATIC。

## 7. STABLE-REBASE：抵御密集摆放下的框边界偏移

这条路径只处理“没有可靠推动链”的 operation-start 旧 C，避免将真实间接移动吞掉。
它可在最终框越过一般 MOVED 距离门槛时仍解除未决，但必须同时满足：

1. C 在每张无手帧都有自己的直接、唯一检测框，且可见库存状态正常。
2. 最终框连续自匹配，并满足既有的类别、形状、IoM/尺度一致性要求；不得把不同帧的
   不同同类框拼成证据。
3. C 没有直接手持移动证据、没有间接推动链、没有 reappearance/claim/alias 歧义，
   也不是待 OUT 或已确认遮挡对象。
4. 使用现有无手连续确认帧数；不为本路径新增全局魔法数。

确认后记录 `STABLE-REBASE`，更新 `base_box`，不产生 `MOVED`。它不是“所有大位移
都是静态”的规则，也不能覆盖已经成立的 `INDIRECT-MOVE`。

仅靠单摄像头的检测框，无法百分之百区分“无可见推动链的真实轻微位移”和“稳定框边界
偏移”。这里的优先级是：有推动链则按真实间接移动处理；没有推动链但证据稳定则重同步
位置；身份不唯一则不提交。

## 8. 建议修改位置与诊断日志

- `include/session.h`：为旧 C 的间接候选/移动簇/位置重同步保存必要的临时状态；不得
  扩散到 `InventoryItem` 的长期业务状态。
- `src/session.cc` 的有手处理：建立 A 的直接活动轨迹后，观察可见邻居的自身框和推动链；
  不把间接成员伪装成 HAND_*，也不复制手位移。
- 无手结算、静态预约和 `try_release_stable_near_original_no_hand_()`：按第6节控制候选
  优先级，完成移动簇确认或 STABLE-REBASE。
- 最终库存写回：已确认位置更新的 B/C 必须写入 `base_box`；只有正式满足 MOVED 条件的
  id 才进入 `confirmed_moved_ids_` 和事件输出。

新增追踪日志至少包括：

```text
INDIRECT-MOVE:
  item、cluster、前驱 item、自己的 detection、自己的原始/最终框、连续计数、推动链依据

CLUSTER-ASSIGN:
  轴方向、开始顺序、最终顺序、每个 item -> detection 映射、拒绝的交叉/歧义映射

STABLE-REBASE:
  item、唯一归属、连续计数、原始/最终框、为何不存在推动链

UNRESOLVED:
  缺失、共享同类框、顺序冲突、alias 冲突或证据不连续的具体原因
```

## 9. 必须新增的回归测试

1. A 直接移动并带动可见、不同类 B；B 未被手覆盖，B 位移超过既有 MOVED 门槛：A、B
   都正确更新并产生应有的 MOVED，操作提交，无伪 IN/OUT。
2. 同场景但 B 的确认位移较小：B 的 `base_box` 更新，不产生伪 MOVED、IN 或 OUT。
3. A 推动多个可分别检测的不同类旧物品：每个唯一可确认成员都用自己的最终框更新。
4. 三个同类 A-B-C 排成一行，A 推动 B、C；每帧三个框独立，检测输入顺序可变化：
   A/B/C 的 item_id 不交换，三者正确更新，操作提交。
5. 上述同类链在镜像方向/反方向推动：仍按运动轴保持顺序，不依赖固定左右方向。
6. 同类移动簇旁有一个未参与推动的同类静态旧 C：静态 C 的唯一框仍受保护，不能被簇
   成员或 D 抢走。
7. 同类成员的最终框存在多个候选但无法得到唯一、顺序不交叉的映射：保持未决，不按
   item_id、detection index 或最近距离强行提交。
8. 密集摆放下 B 实际未移动，但其唯一直接检测框连续稳定地偏离旧框：走 STABLE-REBASE，
   提交且不产生 B 的 MOVED。
9. 保留并运行全部既有 `session3_replay_test`，特别是正常 IN/OUT/MOVED、CONTACT、
   同类邻居、VISIBLE-COUNT、C-D alias 和细节13/14相关用例。

## 10. 验收标准与超参数

在“同类 A-B-C 一列、每个都有独立框、A 推动 B/C”的场景中，系统必须在连续无手确认
后收敛：不交换身份、不把 B/C 误当静态、不出现 A/B/C 循环映射、不因相互等待卡住。

真实间接位移、稳定框边界偏移和真正身份歧义必须分别落入第3节的三个结果；正常直接
操作及既有假 D 防线全部回归通过。

本次原则上不新增或修改超参数。若实现确实需要新增 `constexpr`，必须说明为何不能复用
现有尺度感知/连续帧规则，并同步更新 `超参数位置与调节说明.txt`。12/28 像素门槛的
长期尺度/抖动重构另见 `待处理.md`，不属于本次实现。
