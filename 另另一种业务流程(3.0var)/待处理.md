# 待处理：将 12/28 像素门槛升级为尺度与抖动感知的移动判定

## 1. 状态与边界

这是一个**延期处理的长期改进项**，不属于细节15的当前修复范围。

细节15先使用现有阈值、连续帧和身份/推动证据，解决：

```text
间接移动旧物品无法结算；
同类物品组成移动簇时身份可能交换或互相等待；
密集场景下稳定框偏移导致操作未决。
```

本文件只讨论以后是否要重新设计“原位/移动”的尺度判定，不得被用来提前修改
细节15正在保护的正常 IN、OUT、MOVED、CONTACT、遮挡、同类仲裁或 D 防线。

## 2. 现有数字的准确含义

当前代码中有几个数值相同但语义不同的参数，不能合并理解：

```text
FLOW3_CONTACT_OBJECT_MOVE_EPS = 12px
    CONTACT 路径中，物品相对上一真实观测框移动多少才算有效推/拉证据；
    也参与“当前检测是否仍可明确视作原位”的判断。

FLOW3_COMMIT_MOVE_CENTER_DISTANCE = 28px
    原始 base_box 与最终 base_box 的中心距离达到多少，才允许产生 MOVED 事件。

FLOW3_HAND_ATTACH_DISTANCE = 28px
    手框与物品框的边缘接近距离；它不是物品移动门槛。

约 14px / 14.4px
    只是过去实机或回放中的实际观测距离，不是配置阈值。
```

因此，未来即使改造移动判定，也必须分别评估 CONTACT 原位、正式 MOVED 和手接近三条
语义，不能把三个参数合成一个“通用移动阈值”。

## 3. 什么时候才启动本待办

本待办默认延期，不是细节15或当前代码运行的前置条件，也不要求现在额外采集一整套
数据，更不要求修改训练集或重新训练 YOLO。

只有在以下情况出现时，才考虑启动：

1. 细节15和既有回归已经通过；
2. 同一类问题在实际测试中重复出现，并且已经排除身份匹配、遮挡、推动链和 D 所有权等
   原因，确认确实是 12/28 绝对像素门槛造成的；
3. 能先用主机回放比较旧规则和候选新规则。

时间有限时，最低限度只需从现有测试视频/日志中挑选几个典型案例，人工记录“物品是否
真的移动”和期望业务结果即可。小/中/大、远/近、空旷/密集等完整覆盖是理想校准方案，
不是必须完成的任务；案例不足以支持可靠结论时，只做诊断，不修改阈值。

只有一次偶发日志，或问题实际来自同类身份/推动链时，不应启动本待办；调阈值会掩盖
真正根因。

## 4. 期望的长期判定方向

未来不应把“中心距离是否超过一个固定像素”作为唯一结论，而应把下面的证据组合起来：

```text
身份唯一
    + 自己的连续直接检测框
    + 直接手持/CONTACT/间接推动链证据
    + 最终框连续稳定
    + 相对物品尺度的位移
    + 相对该物品历史检测抖动的位移
    -> MOVED 或位置更新
```

没有真实移动因果证据、但有稳定唯一最终框时，仍可使用细节15的 `STABLE-REBASE`；
本待办不能把所有几何偏移都升级为 MOVED。

## 5. 建议的尺度与抖动模型

### 5.1 保留绝对安全下限

不建议完全删除绝对像素下限。很小的框在归一化后会放大一个或两个像素的检测噪声，
因此应保留一个经过数据校准的最小像素安全值，用于防止微小抖动触发事件。

### 5.2 增加尺度归一化

对原始框 `before` 和最终框 `after` 记录：

```text
d_px   = center_distance(before, after)
d_norm = d_px / max(diagonal(before), diagonal(after))
```

未来移动事件的相对尺度建议使用现有 `normalized_center_shift()` 的思路，即用较大框
对角线作分母，避免局部/缩小的检测框把正常边界变化夸大。不要直接把用于“附近匹配”
的较小框分母 `normalized_nearby_distance()` 原样当成最终 MOVED 阈值。

### 5.3 建立每个物品的抖动基线

在稳定无手状态下，为每个可见物品记录若干帧的中心和框尺寸，使用中位数与 MAD 等
稳健统计得到 `noise_px`。正式移动候选至少应同时考虑：

```text
d_px   >= 绝对安全下限；
d_px   >= noise_px 的若干倍；
d_norm >= 经数据校准的相对尺度门槛。
```

具体倍数、相对门槛和基线帧数不能凭经验直接写入；必须由分尺寸实机数据校准，并在
更新 `超参数位置与调节说明.txt` 时说明适用范围。

### 5.4 使用滞回和时间确认

若位移在门槛附近来回抖动，单一边界会造成状态在 STATIC/MOVED 间反复切换。未来应
考虑：

```text
进入 MOVED 使用较高门槛；
维持已确认 MOVED 使用较低回退门槛，或直接锁定本次结论；
仍需连续直接帧确认，不能单帧触发。
```

滞回只用于已经明确身份的移动结论，不能绕过同类冲突、C-D alias 或 D 确认链。

## 6. 判定优先级

长期规则仍须按业务证据优先，而不是按数字优先：

1. 先做 C/D 身份、同类一对一、遮挡和推动簇仲裁。
2. 再判断该物品是 `INDIRECT-MOVE`、`STABLE-REBASE` 还是仍然 `UNRESOLVED`。
3. 最后才用尺度/抖动模型判断是否输出 `MOVED` 事件。

不能出现下面的反向流程：

```text
先看到中心差超过阈值
    -> 直接确认 MOVED
    -> 再尝试补身份和同类关系
```

同类 A-B-C 移动簇仍必须使用细节15规定的全局一对一、运动轴顺序和各自直接最终框；
尺度阈值只能决定“是否显著移动”，不能决定“这个框属于谁”。

## 7. 实施步骤

未来实际处理时按以下顺序，不要一次性重写所有判断：

1. 先只增加诊断字段和离线统计，不改变业务结果。
2. 回放同一批数据，输出每个物品的 `d_px`、`d_norm`、框对角线、IoM、宽高比例、
   `noise_px`、推动证据和最终人工标签。
3. 先在“正式 MOVED 事件”分支试用混合判定；CONTACT 原位和 HAND 接近规则暂时保持
   原语义，避免一次改动影响多个状态机。
4. 通过旧回放后，再单独验证 CONTACT、小尺寸物品、遮挡恢复、同类移动簇和 STABLE-REBASE。
5. 最后才考虑是否把同样的尺度模型推广到 CONTACT 原位门槛；若没有足够数据，不推广。

## 8. 启动后的最低诊断记录

只有实际启动本待办时才需要记录数据。每个入选案例至少记录：

```text
物品/类别、原始框和最终框、框宽高与对角线
d_px、d_norm、IoM、宽高比例差
历史抖动基线和使用的安全门槛
直接手/CONTACT/间接推动证据
同类全局分配结果与是否存在歧义
旧规则结果、新规则结果、人工真实结果
```

完整字段便于后续分析，但没有足够案例时不得根据某一次“看起来更合理”的结果直接调整
数字。

## 9. 验收标准

完成本待办后，至少要同时满足：

- 不同尺寸物品的真实直接/间接移动都能稳定判断，不依赖同一个绝对像素比例。
- 纯 YOLO 框抖动不产生伪 MOVED，也不污染 `base_box`。
- 小幅但真实、已被推动链确认的位移能更新位置；是否产生 MOVED 由明确的业务规则决定。
- 同类 A-B-C 的身份分配不受尺度阈值影响，不能交换或互锁。
- 正常 IN、OUT、MOVED、CONTACT、遮挡、D 防线和细节15全部回归通过。
- 新增或修改的每个 `constexpr` 都同步写入 `超参数位置与调节说明.txt`，并记录校准数据。

## 10. 明确不属于本待办的内容

模型重新训练、NMS 类别策略、实例分割、同类合并框的视觉身份恢复，以及细节15的间接
移动簇本身，均不在本文件的阈值改造范围内；它们应另立问题和回归目标。
