3.0var 超参数位置、作用与调节说明
====================================

一、参数代码位置
----------------

3.0 业务状态机和显示层的大多数配置位于：

tools/luckfox_pico_rkmpi_example/example/luckfox_pico_rtsp_yolov5n/include/fridge_config.h

YOLO 后处理的 NMS IoU 阈值位于：

tools/luckfox_pico_rkmpi_example/include/rknn/postprocess.h

实际将这些参数送入 RKNN 后处理的位置位于：

tools/luckfox_pico_rkmpi_example/example/luckfox_pico_rtsp_yolov5n/src/yolov5n.cc

3.0 的会话状态机实现位于：

tools/luckfox_pico_rkmpi_example/example/luckfox_pico_rtsp_yolov5n/src/session.cc

修改参数后必须重新交叉编译。建议一次只改一项，并保存“参数版本 + 视频 +
事件日志”；多个阈值一起放宽，出现误匹配时会无法判断是哪一项造成的。

当前版本（3.0-r18）的固定规则（不是超参数）：同一张有手帧里，若旧物品已经拥有
自己的唯一最近严格检测框，该 item_id 会先占用该框；旁边同类、贴手且尚未被占用
的框才有机会进入疑似 D 链路。若某个 HAND_* 旧 C 没有自己的检测框，而同类贴手
B 又能唯一落在 C 的候选轨迹附近，B 会先作为 C 的 `reappear_candidate` 暂存，不能
立刻建立 D。多个 C 都合理时保持未决；单摄像头无法区分时不会凭类别相同强行增加数量。
新建的旧库存 CONTACT_* / HAND_* C 还会经历两张后续有效帧保护期：保护期内仍
逐帧匹配自己的原位置、预计位置和真实轨迹并累计本地 tentative/hold/not_hold 证据，
但不能把同类 B 写入排他认领表；保护期结束后才参加 B 的唯一归属仲裁。保护期内的
同类未认领框暂不创建 D，避免手路过造成库存数量膨胀。
若保护期结束后仍有多个成熟 C 能解释同一个 B，有手阶段及同类可见数量没有减少的
无手阶段仍保持未决；不会按 item_id 顺序强行把 B 认成 MOVED，更不会据此建立 D。
但这是单摄像头，若手已经离开、同一 cls_id 的旧可见物品数量持续大于当前可靠可见
框数量，则最终无手结算改按“一框一个可见物品”处理：先把每个框一对一保留给旧 C
（独立原位框优先、上一帧保留关系次之、最后才稳定成本/item_id 决胜），未保留的
同类旧 C 经过当前 FLOW3_NO_HAND_OUT_MISSING_FRAMES 连续直接无手帧后 OUT。
已保留给邻居 B 的框对 A 是“排除证据”，不能再永久阻止 A 的 OUT；这条数量规则
不在有手阶段使用，也不用于同类数量相等的换入换出，后两者继续走原有身份/D 链路。
同类数量不足时未认领框也不得趁机创建新的同类 D，避免旧 C OUT 与伪 D IN 同时发生。

本版本还明确区分“有手阶段暂时看到 C 在原位”和“无手阶段已经完成静态结算”：
前者即使运行时状态为 NORMAL，仍保留 `needs_no_hand_settlement`。若同一只手在
离开前再次有效移动、且 C 的原位独立框消失，C 会恢复 HAND_* 路径。

无手阶段的同类框若严格属于另一件旧库存 B，必须再区分两种情况：若当前帧中 B
和该框是双方唯一的严格原位匹配，该框已独立属于 B；它对移动中的 A 是“排除证据”。
若 A 的旧 `reappear_candidate` 恰好指向该框，程序会清除这个过期候选，并在同一帧
继续检查 A 的预计位置、真实路径和剩余唯一框；A 的真实新框仍须走原有连续无手确认，
不会单帧强认 MOVED。若 B 没有上述独立原位证据，或一个框仍可同时属于多个旧 C，
则保持未决，不会强认 MOVED、OUT 或新 D。

r18 继续保留 r14 增加的仅限当前手操作的 C-D alias 隔离层，并只在最终位置变化
判定处增加了归一化位移参数；既有身份几何范围、CONTACT 短时路径和 IN/OUT/MOVED
的确认帧数均保持不变。若一个操作开始前的
同类旧 C 仍处于活动且未结算状态，即使该 C 本帧已经暂时认领了另一个检测框，
第二个未认领同类框也会立刻建立为可追踪的 `PROVISIONAL_D` runtime track；它和 C
记录 `C_D_ALIAS` 关系，但在有手阶段不得写入 `working_inventory_`、不得获得 staged
item_id、不得作为“其他旧库存”排除 C。普通、无冲突 D 仍使用原有的提前 staged
入库链路，不受此规则影响。

手离开后仍先执行旧 C 的独立静态框/细节10 fallback，再对 alias 做连续直接无手
仲裁：同类最终只有一个共享框时，第 1 张无手帧只等待，第 2 张连续直接帧将框归回
旧 C 并丢弃重复 D，不产生 IN；旧 C 与真实 D 在两张无手帧各自拥有不同检测框时，
才解除 D 的隔离并按原有流程提交 C 的 MOVED 和 D 的 IN。隔离 D 始终保留逐帧位置、
贴手和路径更新，所以这不是“等手离开后才识别”。

r18 补全并保留第三个、同样只限隔离 alias 的终态：若关联的所有 operation-start old C
已经由原有无手证据独立结算，而 runtime-only 的隔离 D 连续两张有效无手帧既没有
自己的直接检测框、也没有与 C 共用检测框，就只解除 alias 并删除该 runtime D。它
不写入 working_inventory_ 或 pending_in_ids_，不产生 IN/OUT；随后仍由原有 settlement
提交旧 C 的既有 STATIC/MOVED 等结果。这不是对普通 D 的删除规则，真实独立 D、共享框
重复 D、入库、出库、遮挡、CONTACT 和同类邻居规则均保持不变。

3.0-r18 继承的固定身份规则（r17 引入，本次继续保留；不是超参数）
------------------------------------------------

每一张包含 HAND_* 或 CONTACT_* 旧 C 的有手帧，会先生成一次无副作用的“旧 C 原位置
所有权计划”，再进入移动路径和疑似 D 扫描。计划只使用 operation-start 旧库存，
不提前修改 claimed、库存或证据计数；同一检测框的所有权按以下优先级决定：

    自身原位置 STRICT
        > 自身 last_hand_block_box 的 LOCAL_CONTINUOUS
        > 旧完整框包含当前小框的 LOCAL_WEAK

STRICT 只允许原位置几何阈值通过；普通（非 HAND_*、非 CONTACT_*）状态严格匹配失败
就保持未匹配，不退化成局部匹配。LOCAL_CONTINUOUS 可以继续服务于它自己的连续
HAND/CONTACT 观测，但不能被另一个旧 C 或 D 借用。LOCAL_WEAK 只用于保护原位置所有权
和保持未决，不能单独累计 MOVED、HOLD、DROP 或 D 的正向证据。一个检测框若同时被
多个旧 C 以同级证据解释，标记为原位置歧义：本帧不作为任何 C 的移动、HOLD、MOVED、
D、placed 或遮挡正向证据，等待后续连续帧。

静态预约会在候选写入阶段先排除实际被手影响的旧 C，避免它以较低几何成本阻挡真正
静态旧 C；该规则与活动 HAND/CONTACT 的原位置计划相互独立。若活动 C 先出现临时
MOVED_CONFIRMED/PLACED，随后又获得唯一严格原位置证据，而本次操作尚未无手提交，
程序会撤销 confirmed_moved_ids_、placed_box、drop_confirmed 及相关临时终点状态，
恢复当前原位工作状态。已经正式提交到 backend 的历史事件不会回写。

遮挡矩形差集会保留每个正面积残片，只有全部遮挡框处理完后才把残片面积汇总，并
只在总面积上应用 COVER_REMAINING_AREA_EPS；因此多个各自很小但合计超过阈值的缝隙
不会被误判为完全遮挡。r18 没有修改既有身份匹配几何范围、确认帧数、NMS 阈值或
YOLO 分数阈值；新增的四个归一化位移参数只用于最终位置变化/静态灰区的尺度判断，
不改变 HAND、CONTACT、D、遮挡、IN/OUT 的入口和确认规则。

检测输出、NMS、业务输入与 OSD 显示
--------------------------------------

以下数值都属于检测/显示配置，但它们的含义不同，不能混为“同一个 YOLO 阈值”：

YOLO_CANDIDATE_SCORE_THRESH（当前 0.01）
    代码位置：fridge_config.h；实际传入 post_process 的位置：yolov5n.cc。
    它是 RKNN/YOLO 原始候选的粗筛阈值。低于它的 anchor 不会进入后续候选集合。
    调大：后处理计算更少、原始噪声更少，但可能在 NMS 前就漏掉部分遮挡或低分物品。
    调小：召回候选更多，但会增加后处理负担；它不是业务层物品确认阈值。

NMS_THRESH（当前 0.60）
    代码位置：tools/luckfox_pico_rkmpi_example/include/rknn/postprocess.h。
    这是同类候选框的 NMS IoU 重叠阈值，绝不是置信度分数阈值。两个同类候选框高度
    重叠时，NMS 会保留较强候选、抑制较弱候选。
    调大：只有重叠更高时才压掉重复框，因此更容易保留多个相近框；相邻/遮挡物品的
    召回可能更高，但同一物品的重复框也更容易进入后续。
    调小：更积极地压掉重叠框，重复框更少；但相邻、部分遮挡的两个真实物品更可能被
    错误合并。不得为了单次假 D 现象盲目调低。

YOLO_OBJECT_SCORE_THRESH（当前 0.25）
    代码位置：fridge_config.h；在 postprocess.cc 的 NMS 后最终输出阶段按类别使用。
    它是食品框的最终置信度下限：达到该值的 NMS 后食品框才会进入 od_results，随后被
    main.cc 放进 food_dets 并传给 SessionManager::process_frame()。
    因此它不是 NMS，也不是“库存已确认”的门槛。达到 0.25 只表示该框是本帧业务状态机
    必须看见并谨慎处理的 YOLO 输入；是否成为正式库存仍由后续轨迹、C-D alias、无手
    证据和 settlement 决定。
    调大：假框、重复框更难进入业务层，但手遮挡下真实物品的低分框也会被直接丢掉，
    可能退化现有整理、遮挡与入库能力。
    调小：低分证据更容易保留，召回更高，但状态机需要处理更多短暂候选。任何调整都
    必须同时回放正常 IN/OUT/MOVED、CONTACT_*、遮挡和相邻同类场景。

YOLO_HAND_SCORE_THRESH / HAND_CONTEXT_SCORE_THRESH（当前均 0.30）
    代码位置：fridge_config.h。手框达到该值后进入 hand_boxes，业务状态机将该帧视为
    HAND，而不是继续无手收尾。
    调大：手的误触发减少，但低分真手可能被漏掉，造成过早无手提交。
    调小：更早/更稳定地暂停无手提交，但低分误手框也会让操作保持 HAND。

OSD_LOW_CONFIDENCE_OBJECT_SCORE_THRESH（当前 0.50；r18 继承的显示颜色分界）
    代码位置：fridge_config.h。此名称取代了 r14 的 OSD_OBJECT_SCORE_THRESH，避免把它
    误解为第二道业务或显示过滤阈值。

    r18 的 main.cc 继续直接遍历当帧实际传入 process_frame() 的 food_dets，以及使用与
    hand_boxes 完全相同 HAND_CONTEXT_SCORE_THRESH 条件生成的 hand_dets_for_display。
    因此每一个业务有效食品/手框都会画在 OSD 上；分数低于 0.50 的框仅改为黄色/橙色，
    并带有 input-index、类别和分数，分数达到 0.50 的框使用常规类别/手框颜色。

    这个值不参与原始候选粗筛、不参与 NMS、不改变 food_dets、hand_boxes、库存匹配或
    提交。它也不是“库存已确认”的门槛。不要通过把 YOLO_OBJECT_SCORE_THRESH 从 0.25
    提升到 0.50 来实现“看到即所得”，那会改变业务证据而非修复显示不一致。

看到即所得的准确范围
    应显示：经 NMS 和最终类别阈值后、已进入 food_dets / hand_boxes 的业务有效框。
    不要求显示：原始 anchor、低于最终类别阈值的候选、或已被 NMS 抑制的候选；它们没有
    进入业务状态机，显示它们会把“模型原始猜测”和“实际业务输入”混为一谈。
    画面中的低分业务框也不是正式库存或 IN 事件，只是提醒“状态机正在观察这个输入”。

诊断追踪开关（不是匹配超参数）
----------------------------------

FLOW3_DEBUG_TRACE_LOG（当前 true）
    代码位置：fridge_config.h。它只控制诊断输出，不参与匹配、计数或结算判断。
    实机复现异常时改为 true 后重新编译；常规部署保持 false，避免逐帧日志过多。

    开启后输出统一的 [3.0-TRACE] 前缀，每条记录都有 operation_id、frame_id、
    HAND/NO_HAND 阶段和事件标签。日志会记录旧 C / 疑似 D 的状态转换、原始框、
    预计框、最近观测框、reappear candidate、保护期、hold/not_hold/缺失计数；
    `RELEASE` 还会带 release_reason、调用分支 caller、原位检测索引和 BBox（若存在）。

    常用标签：STATE（状态转换）、LIVE-STATE（逐帧运行时状态；会给出
    owner-kind、runtime key、正式 item_id、`provisional=0/1` 和原因）、MATCH（C->B 接受或拒绝原因；若出现
    `exclude-independent-static-neighbor-and-fallback`，表示过期候选已被独立静止
    邻居排除，程序正继续搜索当前 C 的真实框；其中
    `other-owner-evidence=direct-original-mutually-unique` 表示邻居在当前帧和该框
    双方均只有一个严格原位匹配，`result=fallback-selected` 表示已找到 C 的独立
    后备框，`result=excluded-static-neighbor-then-no-a-candidate` 表示本帧确实没有
    C 的新框，后续交由原有连续 OUT 规则处理；`real-*-ambiguity` 才表示排除后
    仍有真实同类身份歧义）、D-GUARD（新 D
    防线及每个同类旧 C 的结论）、NO-HAND（无手匹配/OUT 证据）、VISIBLE-COUNT
    （同类可见框数、框到旧 C 的一对一保留、数量差额 OUT、框跳变清除及撤销）、SETTLE（拒绝或
    提交结算、库存变化和最终事件）。排查一次异常时，应按 operation_id 再按 item_id
    过滤，查看第一个不符合预期的 STATE/MATCH/VISIBLE-COUNT 转换。

    r18 还会输出 D-GUARD 和 C-D-ALIAS。`D-GUARD action=quarantine-pending-d` 表示
    同类未结算旧 C 与新框发生了身份冲突：D 已建立 runtime track，但
    `formal-owner-authority=0`，不会在有手阶段 promote。C-D-ALIAS 会说明关系是
    `shared-detection`、`distinct-detections` 还是尚未获得直接配对，并记录
    `wait-second-no-hand`、`discard-duplicate`、`confirm-independent-d` 等仲裁动作；
    `discard-duplicate-settled-old-c` 表示 D 只命中已经独立结算的 C 的同一直接
    检测框，或在 C 本帧未再参与认领时与其结算框高度重合，因此 D 被按重复身份
    回收而不会产生 IN。相邻但各自拥有不同 detection index 的同类 C、D 不会走
    这条回收分支。
    若 MATCH 出现 `reject=strict-owner`，后面的 `owner-kind` 可明确区分
    `start-old-c`、`pending-d`、`quarantined-pending-d`、`confirmed-d`；只有
    `start-old-c` 或已确认库存才具有“其他旧物品”的正式排除权限。

    r18 继承的新增诊断：每个实际传入 process_frame() 的食品框都会输出
    `[FOOD-DETECTION] input-index=<n> cls=<...> score=<...> box=<...>
    business-input=1 osd-business-visible=1`；每个实际传入 hand_boxes 的手框都会在调用
    前输出同格式的 `[HAND-DETECTION]`。若 `foods=4` 而物理上只有 3 个物品，应先用
    这两类日志确认额外框的分数、位置和重叠关系；不能仅凭 OSD 看见的框数推断业务输入。
    C-D stale alias 清理日志还会包含 `all-conflicting-old-settled` 与
    `missing-count=<n>/<threshold>`，以区分“等待真实 D”和“所有旧 C 已结算后回收消失的假 D”。

    同类数量不足跨帧累计时，`VISIBLE-COUNT` 会复用既有 `FLOW3_TRACK_*`
    匹配范围确认保留框仍连续；若保留框明显跳变，会清除未提交的数量不足
    计数并从新位置重新开始。这里没有新增或调整数值超参数。


二、无手稳定快照
------------------

SNAPSHOT_N（当前 3）
    连续多少张无手帧合成一份稳定快照。
    调大：抗 YOLO 漏检和框抖动更强，手离开后的确认更慢。
    调小：响应更快，但单帧误检/漏检更容易影响提交。

SNAPSHOT_S（当前 0.5）
    物品在 N 帧中出现比例必须严格大于 N*S 才进入快照。
    调大：更保守，误检更难进入快照，但部分露出物品可能被过滤。
    调小：更容易保留暂时可见物品，也更容易让噪声进入快照。

SNAPSHOT_MIN_SCORE、SNAPSHOT_MIN_BOX_WIDTH、SNAPSHOT_MIN_BOX_HEIGHT
    快照投票前的最低置信度和最小框尺寸。
    调大：去除小框噪声更有效，但远处、小物品或部分遮挡物品更容易丢失。
    调小：召回率更高，但错误检测也更多。

SNAPSHOT_VOTE_CENTER_NORM、SNAPSHOT_VOTE_WIDTH_RATIO、
SNAPSHOT_VOTE_HEIGHT_RATIO
    同一稳定快照内部，跨帧 YOLO 框是否属于同一候选的容差。
    调大：容忍抖动，但相邻同类物品可能被错误合并。
    调小：物品之间更容易区分，但同一物品可能因抖动被拆成多票。


三、库存身份匹配
------------------

INVENTORY_STRICT_CENTER_NORM、INVENTORY_STRICT_WIDTH_RATIO、
INVENTORY_STRICT_HEIGHT_RATIO
    严格匹配：稳定位置上的同一物品判断。
    调大：框抖动时更容易保持同一 item_id，但同类相邻物品误认风险上升。
    调小：身份更保守，但轻微移动也可能匹配失败。

INVENTORY_PARTIAL_IOM
    正常局部匹配阈值。用于物品部分露出、但仍在原位置时。
    调大：只有高度重叠才认同一物品，安全但容易漏掉遮挡后的局部框。
    调小：局部框更容易继承旧 item_id，但同类邻居更可能误配。

FLOW3_HAND_PARTIAL_MIN_OBSERVED_COVER、
FLOW3_HAND_PARTIAL_MAX_AREA_RATIO、FLOW3_HAND_PARTIAL_CENTER_NORM
    这三项只用于“手正在影响物品”时，把 YOLO 的局部框优先认领给已有库存
    物品，避免移动旧物品时被错误建成新的 D。它们不参与无手稳定快照匹配。
    MIN_OBSERVED_COVER 调大：局部框必须更多地落在旧框内，较安全，但遮挡较深
    时容易把旧物品漏成 D；调小：更能容忍局部框偏移，但相邻同类物品误认风险升高。
    MAX_AREA_RATIO 调大：允许局部观测框比旧框略大，容忍 YOLO 抖动，但真正的新
    物品更可能被旧物品吸收；调小：更保守，但框变大时可能误建 D。
    CENTER_NORM 调大：允许局部框中心偏离更远，减少遮挡下的重复 IN；过大则会
    增加同类邻居被错误认领的风险。

FLOW3_TRACK_CENTER_NORM、FLOW3_TRACK_PARTIAL_IOM、
FLOW3_TRACK_WIDTH_RATIO、FLOW3_TRACK_HEIGHT_RATIO
    HAND_* 期间的轨迹匹配容差。它比普通严格匹配宽，用于“旧框 + 该物品自己的
    累计移动值”所得到的预计位置。
    调大/调小的影响与严格匹配相同，但这里过大尤其危险：会把相邻同类物品当成被手
    拿着移动的那个物品。

FLOW3_REAPPEAR_CANDIDATE_CENTER_NORM、
FLOW3_REAPPEAR_CANDIDATE_WIDTH_RATIO、FLOW3_REAPPEAR_CANDIDATE_HEIGHT_RATIO
    只用于 C 曾暂时看不见后，判断一个同类 B 是否足够接近 C 的完整候选路径，从而
    暂记为 `reappear_candidate`。它比普通 FLOW3_TRACK_* 略宽，但候选还必须连续
    自匹配，且最终仍要通过无手稳定快照，所以它不会单帧产生 MOVED 或 IN。
    调大：更能抵抗手框/YOLO 在相邻有效帧间的大跳动，减少“移动 C 被误建成 D”；
    过大：较远的同类新物品也更可能被保守地暂认给 C，导致真实 IN 延后或保持未决。
    调小：同类身份更严格，但快速手移动或运动模糊时更容易重新落入 D 链路。

FLOW3_OLD_POSITION_OVERLAP_AREA
    判断某个检测是否占据旧位置的最小交集面积。
    调大：只有明显占位才影响旧位置判断，较抗边缘抖动；过大可能漏掉真实局部露出。
    调小：对小面积占位敏感，但更容易被框边缘误差干扰。


四、手框与有效帧
----------------

HAND_MICRO_MOVE_SKIP_EPS（当前 6 像素）
    没有任何未决 HAND_* / CONTACT_* 轨迹时，连续两帧手框四条边的差异都小于该值，
    当前帧才会跳过。存在活动轨迹时，即使手框不动也继续检查物品检测框，避免漏掉
    手指推动。该跳过只减少业务层计算；如果上游已经先完成 YOLO 推理，不会减少推理本身。
    调大：普通静止手帧计算更少，但可能吞掉小幅手框变化。
    调小：更灵敏，但普通手框抖动会带来更多业务层处理。

FLOW3_CONTACT_PATH_CENTER_NORM（当前 1.10）
    CONTACT_* 中，当前物品框相对 A 的原框或 observed_track 某一点的最大归一化中心
    距离。仍需同时满足类别和宽高比例条件。
    调大：能容忍快速推拉或 YOLO 框跳动，但相邻同类物品串身份风险上升。
    调小：身份更安全，但快速移动时容易暂时找不到 B。

FLOW3_CONTACT_WIDTH_RATIO、FLOW3_CONTACT_HEIGHT_RATIO（当前均 0.35）
    CONTACT_* 的 B 与 A 完整框/历史真实框的相对宽高差容差。
    调大：容忍视角和检测框尺寸变化，但同类邻居更容易被吸收。
    调小：形状约束更严格，但框抖动或轻微尺度变化可能使候选保持未决。

FLOW3_CONTACT_OBJECT_MOVE_EPS（当前 12 像素）
    CONTACT_CANDIDATE 中，物品相对上一真实观测框的最小中心移动量；超过它才累积
    hold 证据。它也用于 CONTACT 路径中判断当前真实观测能否作为“仍在原位置”的
    反向证据；它不再是无手恢复阶段的全局候选过滤器。找到属于某个 HAND/CONTACT
    旧 C 的原位置候选后，即使中心偏移超过 12 像素，也必须保留候选交给静态灰区或
    正式移动判断，不能在入口处丢弃。
    调大：更能过滤 YOLO 抖动和手指微动，但小幅整理可能无法确认。
    调小：小幅推拉更容易确认，但误移动和原位判断抖动风险上升。

FLOW3_NEW_TRACK_CLAIM_GRACE_FRAMES（当前 2）
    新建旧库存 CONTACT_* / HAND_* 轨迹的 B 认领保护期长度，单位是“后续已实际
    处理的有效帧”。新建帧本身记为 t0，不递减；当前值 2 的时间线是 t0 建立、t1
    第一张后续帧、t2 第二张后续帧，t3 才允许把连续且唯一的 tentative B 升级为
    排他候选。保护期内不禁止本地匹配，也不禁止保存 observed_track/轨迹，只禁止
    抢占全局 B；无手收尾帧同样会推进计数，微小手框被跳过的帧不会推进。
    调大：同类物品多、手框跳动大时更保守，能减少路过物品抢 B 和重复 D，但确认
    整理/取出会变慢，并可能让短操作在快照前仍保持未决。
    调小：响应更快，但新建 CONTACT/HAND 更容易在证据不足时抢占同类 B；设为 0
    等于关闭保护期，不建议在同类物品较多的画面使用。

CONTACT_* 的固定规则（不是单独超参数）：接触状态保存在 OperationTrack.contact_state，
不写入 InventoryItem。CONTACT_* 只保存物品真实 observed_track/observed_move_values；
手部 hand_track 和 hand_move_values 仅作辅助，不用手腕位移计算物品终点。首次有效 B
需要与手相贴，连续两次真实移动证据才进入 CONTACT_MOVING；没有可靠 B 时两个证据计数
都暂停；新建 CONTACT_* 的两帧保护期内仍累计本地证据，但不排他认领 B。手离开后先查原位置，再查 observed_track；两者都没有时先保持未决，稳定无手
帧持续缺失且没有遮挡解释后才允许 OUT。若接触候选后来达到 e2/e1 转入 HAND_*，
会把接触阶段最后一次真实 B 保存为 HAND_* 的估计锚点，但仍保留 original_box 作为
最终原位置比较基准，避免“已推开但仍与旧框局部重叠”被释放为未移动。

FLOW3_HAND_ATTACH_DISTANCE
    手与新物品 D 的边缘最大距离；用于“相贴”而不是“遮挡”。除有手阶段的
    HAND_VISIBLE_D 外，它也用于 POST_HAND_REVEAL_D：手离开后，完整 B 必须
    与本次公共 hand_track 中至少一段手框相贴/接近，才可作为“全程被手遮住的
    新物品”候选。
    调大：更容易发现手带入的新物品，也更容易把手旁边的旧物品误当 D。
    调小：D 判断更保守，但新物品和手之间有检测间隙时可能漏掉。

FLOW3_HAND_NEAR_MAX_INTERSECTION_AREA
    hand_is_near 允许的手/物品最大交集面积。相贴时理论上应几乎无交集，YOLO
    抖动会造成少量交集，所以保留这个容差。
    调大：更容易把实际被手压住的物品当成“相贴 D”。
    调小：更符合“相贴”定义，但手框抖动时可能漏掉真实 D。

FLOW3_HAND_PARTIAL_COVER_RATIO（e2，当前 0.30）
    已有库存物品进入 HAND_* 的最低覆盖率。对进入 HAND_* 前的可靠完整框 A.box
    计算 r = intersection_area(hand.box, A.box) / area(A.box)：r < e2 时不进入
    HAND_*；e2 <= r < e1 时进入 HAND_PARTIAL。
    调大：只有手实质遮住更多物品面积才建立候选，手从旁边经过更不容易误触发；
    但手刚压住物品、覆盖尚浅时可能漏掉候选。
    调小：更早开始跟踪手影响的物品，但手框抖动或手臂边缘擦过时更可能产生候选。

FLOW3_HAND_FULL_COVER_RATIO（e1，当前 0.88）
    手覆盖已有完整物品多少比例后，才从 HAND_PARTIAL 升为 HAND_FULL。它必须大于
    e2 且接近 1；r >= e1 为 HAND_FULL，中间区间始终是 HAND_PARTIAL。当前是否还能
    检测到物品不参与这一分类，局部 YOLO 框也不能作为分母。
    调大：更接近视觉上的“完全遮挡”，避免把普通交叠误视为 HAND_FULL；但 YOLO
    手框偏小或边缘不准时，真实完全遮挡可能长期停在 HAND_PARTIAL。
    调小：更早建立 HAND_FULL，但会将较深的部分遮挡误当作完全遮挡。

FLOW3_HAND_DETECTION_OVERLAP_AREA（当前 300 像素²）
    只用于“新物品 D 是否贴手/与手相交”及其放下判断，不能用于已有库存物品的
    HAND_PARTIAL/HAND_FULL 分类。POST_HAND_REVEAL_D 检查 B 与历史 hand_track
    的每一段关系时也会使用它。D 初次出现时没有可靠的被遮挡前完整框，因而不能
    套用 e1/e2 覆盖率规则。
    调大：D 必须与手有更大交集才被认为贴手，误建 D 更少，但可能漏掉手框与物品框
    之间只有少量重叠的真实新物品。
    调小：D 更容易获得贴手证据，也更容易把手旁的旧框误当成 D。

FLOW3_D_REAPPEAR_MIN_PARTIAL_COVER（当前 0.35）
    仅用于 D 的“局部框 → 手离开后完整框”路径重现。若最终完整检测框 B 覆盖
    D 路径中某个预测局部框的比例达到该值，可作为重现候选；C 不使用此规则。
    调大：要求 B 与预测局部位置重叠更多，身份更安全，但手持偏移或 YOLO 框抖动时
    可能漏掉真实 D。
    调小：更容易接回局部→完整的 D，但同类物品靠近路径时更可能产生误关联。

FLOW3_D_REAPPEAR_MAX_CENTER_SHIFT_NORM（当前 0.45）
    当 B 没有足够覆盖预测局部框时，允许的最大归一化中心偏移；分母使用 B 和局部
    框中较大的对角线。它同样只用于 D 的局部→完整重现。
    调大：容许手中物品相对手框发生更大偏移，召回率更高，但同类邻居误关联风险更高。
    调小：路径重现更严格，安全但可能遗漏“放下后完整框偏移较大”的 D。

TRACK_HAND_MOVE_EPS
    手明确移动的距离阈值；主要用于判断物品是否可能掉队放下。
    调大：过滤慢速手抖，慢速整理可能难确认。
    调小：慢速动作更容易确认，但手抖也可能累积成移动证据。


五、hold_and_move 与放下
-------------------------

FLOW3_HOLD_EVIDENCE_REQUIRED（当前 2）
    连续多少次有效“物品出现在自己的预计轨迹上、旧位置干净”的证据后，才把
    hold_and_move 设为 True。
    调大：更谨慎，减少误判拿起；确认整理/出库更慢，短动作可能不够证据。
    调小：响应更快，但一次误匹配就可能变成移动候选。CONTACT_CANDIDATE 也使用
    此门槛；只有达到后才把 contact_state 设为 CONTACT_MOVING。

FLOW3_NOT_HOLD_EVIDENCE_REQUIRED（当前 2）
    连续多少次有效“物品仍在旧位置”的证据后，释放 HAND_* 候选。
    调大：更能容忍一帧错误旧位置匹配，但候选持续更久。
    调小：很快释放，可能错过随后真正拿起或推拉的动作。CONTACT_CANDIDATE 只有在
    A 真实回到原位置时才增加该计数；漏检或歧义帧不会增加。

FLOW3_DROP_FALL_BEHIND_RATIO
    手继续移动而物品框移动明显较少时，“掉队”的比例。它只是放下证据的必要条件；
    还必须同时满足 B 已与手脱离或 B 的宽高更接近完整 C.box，并连续达到
    FLOW3_DROP_EVIDENCE_REQUIRED 次才会进入 PLACED。
    调大：更容易累积放下证据，可能把手持但慢速移动的物品提前放下。
    调小：更严格，放下确认更慢，更多依赖无手稳定快照。

FLOW3_REAPPEAR_CANDIDATE_CONFIRM_FRAMES（当前 2）
    `reappear_candidate` 首次出现后，需要连续多少次能匹配到同一个 B，才可把 B
    作为旧 C 的已确认重新出现位置。若 B 是在无手第一帧才首次可见，也同样使用
    这个门槛；稳定快照仍是正式提交的最后一步。
    调大：对一帧误检、同类串身份更稳，但快速操作后确认整理更慢。
    调小：更快恢复 C 的身份，但单帧 YOLO 跳动更容易造成错误整理。

FLOW3_DROP_EVIDENCE_REQUIRED（当前 2）
    连续多少帧出现“手继续走、B 基本停住、且 B 脱手/更接近完整框”的组合证据后，
    才确认放下并进入 PLACED。
    调大：避免单帧手框跳动触发整理，代价是放下确认更慢。
    调小：实时性更高，但单帧误差可能提前确认放下。

FLOW3_DROP_FULL_BOX_IMPROVEMENT（当前 0.08）
    B 相对完整 C.box 的宽高差至少改善多少，才把“框逐渐变完整”视为辅助放下证据。
    调大：只有明显从局部框变完整时才计入，较安全但可能漏掉轻微改善。
    调小：更容易把框大小变化计入放下，适合局部框变化小的模型，但更容易受抖动影响。

FLOW3_MOTION_REFERENCE_DIAGONAL_MIN_PX（当前 80 像素）
    最终位置变化归一化时，操作开始时完整原框对角线允许使用的最小尺度。实际
    reference_scale = clamp(diagonal(operation_start_complete_box), MIN, MAX)。
    它只防止极小物体的像素位移被比例过度放大，不改变 STRICT、LOCAL 或 CONTACT
    的身份匹配范围。
    调大：小物体需要更大的绝对位移才达到同一归一化比例，误报较少但可能漏掉小物体
    的真实整理；调小：对小物体更敏感，但 YOLO 抖动更容易接近移动阈值。

FLOW3_MOTION_REFERENCE_DIAGONAL_MAX_PX（当前 500 像素）
    最终位置变化归一化时使用的最大参考对角线。大框超过该尺寸时不再继续扩大分母，
    避免大物体的真实位移被固定比例过度稀释。分母始终来自操作开始的完整原框，不能
    使用手遮挡后的局部框或临时 reappear 框。
    调大：大物体的归一化位移更小，较不易把框恢复抖动报成 MOVED，但可能漏报大物体
    的小幅真实移动；调小：大物体更敏感，但边界恢复变化的风险上升。

FLOW3_STATIC_CENTER_SHIFT_NORM（当前 0.06）
    归一化中心位移的低位移静态参考线。低于该值的候选更像普通 YOLO 抖动；它本身
    不会跳过唯一所有权、连续无手帧或静态释放条件，也不会让候选在单帧立即结算。
    该值用于静态灰区诊断与调参，灰区候选仍按现有 `FLOW3_NO_HAND_D_CONFIRM_FRAMES`
    连续无手规则处理。
    调大：更多轻微变化落入低位移参考范围；调小：更早把变化视为需要重点观察的灰区。
    不能把它当作 CONTACT 的 12 像素门槛或最终 MOVED 门槛。

FLOW3_FORMAL_MOVE_CENTER_SHIFT_NORM（当前 0.12）
    最终正式 MOVED 判定的归一化中心位移门槛：归一化位移达到该值才具备正式位置
    变化资格。达到门槛仍须通过已有的 HAND/CONTACT 连续证据、唯一所有权、路径和
    无手结算条件；它不会单帧强制产生事件。
    调大：更保守，能过滤更多框抖动和轻微碰撞，但可能漏掉真实小幅整理；调小：更
    容易记录真实移动，但同类误配或检测抖动更可能进入 MOVED 候选。

FLOW3_COMMIT_MOVE_CENTER_DISTANCE（兼容保留，当前 28 像素）
    旧版本的固定像素最终移动阈值。r18 的 `boxes_differ_as_move()` 已改用上面的
    完整原框对角线归一化公式，因此这个参数不再负责最终 MOVED 或 `base_box`
    迁移判定。保留它是为了兼容旧配置/日志和避免无关接口断裂；不要继续用它推断
    当前版本的正式移动边界。CONTACT 短时推拉仍只看
    `FLOW3_CONTACT_OBJECT_MOVE_EPS`。


六、D、新入库、遮挡
--------------------

NEW_ITEM_CONFIRM_FRAMES（当前 2）
    suspect D 连续有效自匹配次数达到该值后，才提升为工作库存物品。
    调大：更难误入库，但手快速放下物品时确认会变慢。
    调小：实时性更高，但一帧误检更容易成为候选 D。

    说明：D 在第二次有效观察达到该值后进入工作库存；正式 IN 仍要再等连续
    SNAPSHOT_N 张无手稳定帧完成结算。若感觉“手已离开但一直不提交”，先看画面
    左上角是否仍是 HAND / rawH>0；只要仍检测到手，稳定快照会被重置。

    疑似 D 的发现入口有三个：贴手出现的 HAND_VISIBLE_D、无法认领且替代 C 原位置
    的 C_POSITION_REPLACEMENT_D、以及手离开后首次完整出现的 POST_HAND_REVEAL_D。
    前两者从有手帧开始计数；第三者以首张无手完整 B 记为第 1 次，下一张有效无手帧
    必须自匹配才可提升。三者都不能绕过稳定快照直接正式 IN。

    r18 不改变这个数值或普通 D 的提升时机。唯一例外是 `C_D_ALIAS` 中的
    QUARANTINED_PENDING_D：它仍从首次有手帧建立并实时更新，但要等旧 C 与 D 在
    连续直接无手帧中获得不同检测框，或旧 C 已独立结算，才允许进入原有的
    `NEW_ITEM_CONFIRM_FRAMES -> working_inventory_ -> IN` 链路。该例外是身份
    所有权隔离，不是放宽或降低 D 的确认要求。

    r18 的 stale alias cleanup 也不改变这个数值或普通 D 的提升时机：它只会删除一个
    从未提升、没有 item_id、且所有关联旧 C 已独立结算后连续两张无直接无手证据的
    QUARANTINED_PENDING_D。只要 D 有独立或共享直接证据，计数立即清零并继续原有流程。

FLOW3_C_REPLACEMENT_MIN_COVER_RATIO（当前 0.30）
    有手阶段，若已有库存 C 已进入 HAND_*、本帧又没有自己的检测框，而一个未被
    库存认领的 D 覆盖 C 的原始完整框达到该比例，则将 D 以
    C_POSITION_REPLACEMENT_D 预登记；即使 D 已经不贴手也一样。
    调大：只有 D 明显盖住 C 才会记录，误把路过框当 D 的风险更低，但部分遮挡的
    “放下 D 覆盖 C”可能漏掉。
    调小：更容易保护 C 不被误判 OUT，并更早记录 D；但框边缘轻微交叠也更可能生成
    无法确认的 D 候选。

FLOW3_POST_HAND_REVEAL_WINDOW_FRAMES（当前 2）
    手离开后，允许从“库存无法认领、且贴近本次 hand_track”的完整 B 创建
    POST_HAND_REVEAL_D 的最早无手帧数。它必须留出至少一次后续无手自匹配，才可能
    在当前稳定快照中正式 IN；当前 SNAPSHOT_N=3、NEW_ITEM_CONFIRM_FRAMES=2，因此
    设为 2。
    调大：手离开稍晚才被 YOLO 看到的真实新物品更不容易漏掉；但会扩大“旧物重现或
    误检被误建 D”的时间范围，而且过大时本轮稳定快照没有足够帧完成二次确认。
    调小：入库来源更紧贴手离开时刻，安全性更高；但首帧漏检时更容易漏掉全程被手
    遮挡的真实 D。

FLOW3_D_PARTIAL_COVER_RATIO
    已确认的新 D 放下后，对一个旧 HAND_* 物品达到多少覆盖比例时，可作为
    “C 先保留、不能判 OUT”的遮挡证据。
    调大：更严格，部分遮挡下 C 更可能保持未决。
    调小：更容易把 C 判为遮挡，可能隐藏真实取出。

BLOCK_OVERLAP_AREA_EPS、COVER_REMAINING_AREA_EPS
    矩形差集遮挡计算的面积误差。代码使用 apply-cover 思路计算多个框的并集覆盖，
    不直接把交集面积相加。
    调大：更容忍 YOLO 框边缘缝隙，容易把接近完整覆盖当成完整覆盖。
    调小：几何判断严格，但边缘抖动可能导致遮挡关系无法确认。


七、调参顺序
--------------

1. 先调 SNAPSHOT_*：确保没有手时同一物品的稳定框不会乱跳。
2. 再调 INVENTORY_STRICT_* 与 INVENTORY_PARTIAL_IOM：确保静态库存不产生
   新 item_id，也不合并相邻同类物品。
3. 调手框参数与 HAND_MICRO_MOVE_SKIP_EPS：先让“手经过但没拿”不产生移动。
4. 最后调 FLOW3_TRACK_*、FLOW3_CONTACT_*、两类 evidence 阈值、放下与遮挡参数。
   若“移动旧 C 却误报 IN”，先检查/小幅调大 FLOW3_REAPPEAR_CANDIDATE_*；若
   “真正相邻同类 IN 长期保持未决”，再小幅调小它们，并保留回放验证。

每次验证至少回放以下操作：

- A 移动后放回；
- A 移动到 B 前方，B 遮挡；
- 再移开 A，B 露出；
- 取出 A；
- 放入新 D；
- 同类物品无法唯一判断时，库存数量不得增加，状态应保持未决。
- 手腕基本不动、手指推动物品时，旧 item_id 不得变成新的 D；应先出现
  CONTACT_CANDIDATE，连续真实框移动后才变为 CONTACT_MOVING。

重要原则：稳定快照中“没有绑定 item_id 的框”不会自动入库。只有具有 D 的
“有手阶段已发现（贴手或替代 C 原位置）→ 连续自匹配 → 稳定存在”，或
“手离开后首次显现且贴近本次 hand_track → 连续无手自匹配 → 稳定存在”证据链，
才允许产生正式 IN 事件。

同类相邻验证应分两种情况：

- 旧物品和新物品各自都有独立检测框时，应保留旧 item_id，并让新框完成 D→IN；
- 两者已经完全重叠，只剩一个同类检测框时，单摄像头没有足够证据区分数量，系统
  应保持未决，不应伪造新的 item_id。
