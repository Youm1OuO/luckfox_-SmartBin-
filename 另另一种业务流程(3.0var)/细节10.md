# 修复未决旧 C 被误建为新 D

本文件优先级高于细节9及此前所有文件。3.0 仍逐张有效直接帧处理：不使用
`SnapshotBuffer`、投票或检测框平均；不重新引入固定成熟期。

## 问题

仅移动旧苹果时，旧 C 的路径可能因一帧检测框跳动而暂时没有当前帧 owner。
手离开后，该 B 又落在手路径上，当前代码只看“这一帧是否还能找到旧 C 候选”，
于是错误创建 `POST_HAND_REVEAL_D`，下一帧再提升为新的库存 item。

`UnresolvedSameClassClaim` 已记录“该位置的 B 仍可能属于旧 C”，但 D 门没有读取
这条历史未决关系。这是实现缺口，不是固定成熟期应恢复的理由。

## 必须成立的规则

`FrameOwnership` 仍只表示当前直接帧的唯一 C -> B；当前帧无法唯一归属时，不得
强行把 B 给 C，也不得直接给 D。此时由空间连续的 claim 保持未决。

对任何 `HAND_VISIBLE_D`、`C_POSITION_REPLACEMENT_D`、`POST_HAND_REVEAL_D`，统一按下列顺序判断：

```text
1. 当前 B 已被旧 C 或已有 D owner 占用：禁止 D。
2. 当前 B 与某条历史 claim 同类且直接自匹配连续：
   - claim 的 possible_old_item_ids 中任一旧 C 仍为 UNRESOLVED：
     更新 claim，禁止 D，D 的确认计数不得增加。
   - 所有相关旧 C 已独立得到 AT_ORIGIN / AT_NEW_POSITION /
     OCCLUDED_CONFIRMED / OUT_CONFIRMED：claim 守卫解除；当前帧才可作为 D 第 1 帧。
3. 没有匹配的未决 claim 时，才继续现有的手操作来源、同类碰撞和当前帧歧义检查。
```

claim 的“匹配”只能按同类和相邻直接帧的框连续性（如 `track_match_box`）判断，
不能按检测数组索引 `B=<i>` 判断。一个位置的 claim 不能阻止远处无关的新 D。

## 代码修改点

1. 在 `can_start_new_d_for_detection_()` 中，在 `possible_old_owners_for_detection_()`
   为空后、允许 D 前，查询与当前 B 匹配的 `UnresolvedSameClassClaim`。
2. 若匹配 claim 含未解决旧 C：保留并更新 claim，返回 `false`；日志输出
   `D-GATE allow=0 blocked_by=claim:C#...`。不得创建 D，也不得删除该 claim。
3. 只有匹配 claim 的所有旧 C 已独立解决时，才删除/释放该 claim，并让当前 B
   从本帧开始 D 的确认链；不得借用 claim 期间的帧数。
4. claim 仅可在以下情况删除：
   - 匹配的旧 C 已在当前帧独立且已解决地认领该 B；
   - B 未能在下一张直接帧连续自匹配，`refresh_unresolved_same_class_claims_()` 丢弃它；
   - 上述“所有相关旧 C 已解决”后，当前 B 合法开始 D。
5. 无手阶段的顺序保持：先建立/更新 `FrameOwnership` 与 claim，再调用
   `register_post_hand_reveal_suspects_()`。后者必须经过同一 D 门，不能绕过 claim。

不新增超参数；`超参数位置与调节说明.txt` 无需修改。

## 回放验收

新增主机回放：旧苹果移动时，路径 B 曾一帧唯一、下一帧变歧义或暂时失去当前候选；
手离开后同一位置的 B 再出现。结果必须是：

```text
不创建 POST_HAND_REVEAL_D
不提升新的 item#
不产生 IN
旧 C 后续唯一接回时只可能形成其自身的 MOVED；接不回则保持未决/丢弃，不猜新物品
```

再覆盖：旧 C 已在其他 B 上独立解决后，远处真实同类 D 出现，D 可从守卫解除的
当前帧开始正常确认，避免 claim 永久阻止真实放入。
