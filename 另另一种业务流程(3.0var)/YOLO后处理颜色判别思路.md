# YOLO后处理颜色判别思路

这份说明只记录“后处理二次判别”的思路，不修改 YOLO 模型本身。

核心原则：先相信 YOLO，再用颜色和几何特征修正少量容易混淆的结果。

## 触发条件

- 只对少数容易混淆的类别对生效：`apple / onion`、`egg / orange`
- 只在 YOLO 的 top-1 与 top-2 分数很接近时触发
- 如果 YOLO 本身已经很确定，就不做人工修正

## 判别顺序

1. 读取 YOLO 输出的类别、置信度和框位置
2. 先看是否落在需要二次判别的类别对里
3. 截取 bbox 中心区域，不用整框平均，尽量减少背景干扰
4. 提取颜色特征，优先看 HSV / Lab，而不是直接看 RGB
5. 再结合框面积、长宽比、圆度做辅助判断
6. 输出最终类别时，保留 YOLO 分数作为基础，再叠加手动规则

## 苹果 / 洋葱

- 洋葱如果偏紫、偏暗、亮度低，倾向判为洋葱
- 苹果如果更红、更亮、颜色更鲜，倾向判为苹果
- 如果颜色特征不明显，优先保留 YOLO 原结果

## 鸡蛋 / 橙子

- 鸡蛋通常偏黄白、饱和度低、框面积偏小
- 橙子通常更偏橙红、饱和度更高、框面积偏大
- 如果颜色接近，再用面积和长宽比辅助判断

## 纠正后的同类去重（补一次 NMS）

**为什么需要：** YOLO 的 NMS 是「逐类」进行的，只压制同一 cls_id 的重叠框。所以 YOLO 会
对同一个物体同时给出 `apple` 框和 `onion` 框（cls_id 不同，NMS 互不压制，两个都放行）。
我们把 `onion` 改成 `apple` 后，同一位置就出现两个 cls_id 相同且高度重叠的框，而 NMS 早已
在 postprocess 阶段跑完，不会再来清理 → 一个物体被两个框框住。egg/orange 同理。

**做法：** 在类别纠正「之后紧跟」补做一次同类去重（相当于对纠正结果再跑一次小 NMS）：

1. 先对每个框做类别纠正（颜色/面积规则），同时记录哪些框被改过。
2. 再两两检查：若两框 **cls_id 相同** 且 **IoM 超过阈值**，只保留置信度更高的那个。

**判据用 IoM（交集 / 较小框面积），不用纯 IoU：** 一个框基本被另一个框「包住」时 IoM 更
敏感，正是「同一物体两个框」的典型形态（两框大小可能不同，纯 IoU 会偏低）。

**安全边界（做法 A，重要）：** 只在「这一对框里至少有一个是被纠正改过类别的」时才去重。
**绝不碰 YOLO 原生就给出的同类框**——那是 YOLO 自己的 NMS 已经放行的结果，二次删除可能
误伤两个真实相邻的同类物体（例如挨在一起的两个苹果），造成漏检。

**实现与阈值：** 逻辑在 `reclassify.cc` 的 `reclassify_detections()`（纠正后调用
`dedup_after_reclassify()`）。开关与阈值在 `fridge_config.h`：
`RECLS_DEDUP_ENABLED`、`RECLS_DEDUP_IOM_THRESH`（默认 0.75，可按实测调）。

## 注意点

- 这个方法只适合演示和短期修正，不是通用分类方案
- 规则要尽量保守，宁可不改，也不要大范围覆盖 YOLO 的原判断
- 后续如果要继续优化，优先从真实场景照片里调阈值，而不是先改模型结构
- 去重是独立、稳健的补丁：即使颜色阈值没调好、把某个苹果误判了，去重逻辑仍能正常工作
  （它只看「纠正后有没有同类重叠」，不关心纠正得对不对）
