# YOLO后处理颜色判别思路

这份说明只记录“后处理二次判别”的思路，不修改 YOLO 模型本身。

核心原则：先相信 YOLO，再用颜色和几何特征修正少量容易混淆的结果。

## 触发条件

- 只对少数容易混淆的类别对生效：`apple / onion`、`egg / orange`
- 只在 YOLO 的 top-1 与 top-2 分数很接近时触发
- 如果 YOLO 本身已经很确定，就不做人工修正

## 判别顺序

1. 读取 YOLO 输出的类别、置信度和框位置
2. 先看是否落在需要二次判别的类别对里
3. 截取 bbox 中心区域，不用整框平均，尽量减少背景干扰
4. 提取颜色特征，优先看 HSV / Lab，而不是直接看 RGB
5. 再结合框面积、长宽比、圆度做辅助判断
6. 输出最终类别时，保留 YOLO 分数作为基础，再叠加手动规则

## 苹果 / 洋葱

- 洋葱如果偏紫、偏暗、亮度低，倾向判为洋葱
- 苹果如果更红、更亮、颜色更鲜，倾向判为苹果
- 如果颜色特征不明显，优先保留 YOLO 原结果

## 鸡蛋 / 橙子

- 鸡蛋通常偏黄白、饱和度低、框面积偏小
- 橙子通常更偏橙红、饱和度更高、框面积偏大
- 如果颜色接近，再用面积和长宽比辅助判断

## 苦瓜 / 卷心菜（bitter_gourd → cabbage，单向，按长宽比）

**问题：** 卷心菜(cabbage)有时被误判成苦瓜(bitter_gourd)。这两者形状差异大：
苦瓜是**长条形**、卷心菜是**圆球状**，正好可以用长宽比区分。

**判据（单向）：** 一个被识别成 `bitter_gourd` 的框，若其**短边/长边 ≥ RECLS_SQUARE_ASPECT_MIN
（默认 0.75，即接近正方形）**，说明它其实是圆的 → 改成 `cabbage`。
只做 bitter_gourd → cabbage，**不反向**（cabbage 不会因形状被改成苦瓜）。

**为什么这里长宽比有效、而 lettuce/cabbage 不行：** 苦瓜(长条) vs 卷心菜(圆)形状差异明显，
长宽比能分开；而生菜/卷心菜**都是圆团状、长宽比都接近 1:1**，长宽比分不开——所以
lettuce↔cabbage 的区分暂不做，若业务必须精确区分，应补数据重训模型（后处理无可靠特征）。

**实现与阈值：** `reclassify.cc` 的 `apply_bitter_gourd_cabbage()`，开关/阈值
`RECLS_BITTER_GOURD_TO_CABBAGE_ENABLED`、`RECLS_SQUARE_ASPECT_MIN`。

## 假 orange 过滤（两个鸡蛋拼成的长框被误判成 orange）

**问题：** 两个 egg 挨在一起，YOLO 有时把这个长矩形整体误判成一个 orange（分数多在 60 左右）。
这个错误没法靠「egg/orange 颜色转换」解决——即便按颜色把它从 orange 改回 egg，**那个错误的
框依然存在**（只是换了类别）。所以关键是让这个框**根本不出现（直接删掉）**。

**判据（三条同时满足才删框，宁可漏过、不可误删真 orange）：**

1. 是 **YOLO 原生 orange**（`cls_id == CLS_ORANGE`）；
2. 分数 **< `RECLS_ORANGE_FILTER_SCORE_MAX`（默认 0.63）**——高分的真橙子直接保留；
3. 框内中心区域平均色相**不在橙色区间** `[RECLS_ORANGE_H_MIN, RECLS_ORANGE_H_MAX]`（默认 8~25）。
   两个 egg 拼的框是蛋壳色（偏白/黄），不橙；真橙子橙色，会落在区间内被保留。
   采样失败（拿不到颜色）时**保守不删**。

**为什么只过滤 orange、不给 egg 加过滤：** egg 的置信度时高时低，若给 egg 也加分数/颜色门槛，
很容易把真 egg 误删（漏入库比多一个假 orange 更糟）。所以只对 orange 这一个方向下手。

**顺序（关键）：这个过滤必须在 `egg<->orange` 面积互转【之前】执行。** 因为判据看的是
`cls_id==orange`；若先转换，一个面积偏大的真 egg 可能先被转成 orange，再撞上这个过滤而被
误删（等于间接过滤了 egg）。先过滤、只作用于 YOLO 原生 orange，就绝不会误伤 egg。
也因此，`egg<->orange` 转换本身**保持纯面积、不加颜色**，避免给不稳定的 egg 引入颜色风险。

**顺序（重要）：** 过滤放在【所有逐框转换之后、去重之前】。因为这个假 orange 往往不是 YOLO
原生输出的，而是**两个 egg 拼成的大框被 egg->orange 面积规则转出来的**——所以必须等
egg->orange 转换跑完，再对“最终是 orange 的框”统一过滤，才能把这种转换产生的假 orange 也
删掉。流程：逐框转换(含 egg->orange) → 假 orange 过滤(删框) → 同类去重。
（早期版本把过滤放在转换之前、只拦原生 orange，导致 egg 转来的假 orange 漏网，已修正。）

**实现与阈值：** 逻辑在 `reclassify.cc` 的 `is_bogus_orange()`，在 `reclassify_detections()`
的逐框转换之后逐框判断并从检测列表移除（同步移除其 changed 标记，保持与去重对齐）。
开关/阈值在 `fridge_config.h`：
`RECLS_ORANGE_FILTER_ENABLED`、`RECLS_ORANGE_FILTER_SCORE_MAX`、`RECLS_ORANGE_H_MIN/MAX`。

**局限（如实说明）：** 若某次假 orange 分数恰好 ≥0.63，仍会漏过（阈值法固有局限）；配合
「不橙」双条件已能滤掉绝大部分，真漏的高分误判只能靠后续去重/数量逻辑兜。

## 统一去重（最后一步，补一次 NMS）

**为什么需要：** YOLO 的 NMS 是「逐类」进行的，只压制同一 cls_id 的重叠框。所以 YOLO 会
对同一个物体同时给出**不同类别**的两个高度重叠框（如同一位置一个 `apple` + 一个 `onion`，
cls_id 不同、NMS 互不压制，两个都放行）。类别纠正也可能制造同类重叠框。这些 NMS 都不会
再清理 → 一个物体被两个框框住、甚至被算成两个物品。

**做法（当前）：** 作为过滤 + 转换之后的**最后一步**，做一次**统一去重**，去重完直接交业务：

- 两两检查任意两个框（**不分类别、不分是否被纠正改过**）：若 **IoU ≥ 阈值**（默认 0.90，很高），
  判为「同一物体的重复框」，只保留**置信度更高**的那个（同分保留前者）。

**为什么用 IoU（交 / 并）而不是 IoM：** 关键是避免误删「小物品挡在大物品前面」这种前后遮挡
——那种情况 IoM 会很高（小框基本被大框包住）导致误删前面的小物品；而 IoU 低（并集大），
不会误删。IoU 只在「两框几乎完全重合、大小也相近」时才高，这正是「同一物体重复标签」的
典型形态（如同位置 apple+onion，IoU≈0.95）。

**为什么阈值要高（0.90）：** 高门槛保证只杀「几乎完全重合」的真重复；**挨着但不重合的相邻
真实物体**（例如并排两个鸡蛋、两个苹果）IoU 达不到 0.90，不会被误删——这对「数对个数」很关键。

**实现与阈值：** 逻辑在 `reclassify.cc` 的 `reclassify_detections()`（转换后调用
`dedup_overlapping()`）。开关与阈值在 `fridge_config.h`：
`RECLS_DEDUP_ENABLED`、`RECLS_OVERLAP_DEDUP_IOU`（默认 0.90，可按实测调）。
（早期「只对改过类别的框做同类 IoM 去重」的做法 A 已废弃，统一成这一条更通用的规则。）

## 注意点

- 这个方法只适合演示和短期修正，不是通用分类方案
- 规则要尽量保守，宁可不改，也不要大范围覆盖 YOLO 的原判断
- 后续如果要继续优化，优先从真实场景照片里调阈值，而不是先改模型结构
- 去重是独立、稳健的补丁：即使颜色阈值没调好、把某个苹果误判了，去重逻辑仍能正常工作
  （它只看「纠正后有没有同类重叠」，不关心纠正得对不对）
