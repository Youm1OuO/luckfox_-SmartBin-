# YOLO 类别、颜色、框大小融合方案（讨论稿）

> 状态：仅用于后续讨论和设计，不代表当前代码已经实现，也不修改现有 YOLO、训练流程或板端后处理。

## 1. 要解决的问题

当前 49 类模型中，部分外观相近的类别容易混淆，尤其是：

- `apple` 与 `onion`
- `egg` 与 `orange`

YOLO 已经能够检测出物体的位置和主要语义，但单靠原始分类分数时，容易在这些相近类别之间犹豫。颜色、亮度、框面积和宽高比是额外有价值的信息：

- 苹果通常更偏红、较明亮；部分洋葱更偏紫、暗。
- 鸡蛋通常框较小、偏黄白；橙子通常更大、偏橙红。

目标不是在 YOLO 输出后写死一条“颜色像什么就强制改成什么”的规则，而是让模型从训练数据中学习：在什么情况下，颜色和框大小应该帮助某个类别增加或减少置信度。

## 2. 核心目标

希望模型学习的是：

```text
P(class | YOLO feature, color, size)
```

其中：

```text
YOLO feature  = YOLO 对物体外观、形状、纹理、位置等的深层特征
color         = 该物体局部区域的颜色、饱和度、亮度等特征
size          = 预测框面积、宽高比等几何特征
class         = 49 个类别之一
```

更适合的分类形式是：

```text
old_logits   = 原始 YOLO 的 49 类分类分数（未取最大值前）
DeltaLogits  = 根据 YOLO 特征、颜色和大小得到的 49 维修正量
final_logits = old_logits + DeltaLogits
new_cls_id   = argmax(final_logits)
```

最终仍然只有一个类别输出，只是它不再完全由原始 YOLO 分类分支单独决定。

## 3. 为什么不能只用 old_cls_id

不推荐：

```text
new_cls_id = Model(old_cls_id, color, size)
```

因为 `old_cls_id` 是已经取最大值后的硬类别，丢失了 YOLO 的犹豫程度。

例如下面两种预测的 `old_cls_id` 都是 `apple`：

```text
A: apple 0.99, onion 0.01
B: apple 0.47, onion 0.45
```

对于 A，颜色和大小不应该轻易推翻 YOLO 的强判断；对于 B，颜色和大小很适合帮助模型决定。

因此小模型至少应看到 `old_logits`（或 49 类置信度），而不是只看到一个 `old_cls_id`。最理想的输入是：

```text
[YOLO local feature, old_logits, color feature, geometry feature]
```

## 4. 推荐的模型内部结构

概念结构如下：

```text
输入图像
  |
  +-- 原 YOLO backbone / neck
  |      |
  |      +-- 局部检测特征 f
  |      +-- 原始框 box = (x, y, w, h)
  |      +-- 原始 49 类 logits z
  |
  +-- 轻量 ColorStem（从 RGB 图像提取颜色特征）
         |
         +-- 与检测头同一位置的颜色特征 c

几何特征：
g = [log(box_area / image_area), log(w / h)]

分类修正：
DeltaLogits = MLP([f, z, c, g])
final_logits = z + alpha * DeltaLogits
```

其中：

- `f`：YOLO 本身已经学习到的物体语义、形状、纹理等特征。
- `z`：原始 49 类 logits。它包含 YOLO 对每个类别的完整判断和犹豫程度。
- `c`：颜色特征，例如综合色相、饱和度、亮度和局部颜色分布。
- `g`：框面积、宽高比等几何特征。
- `DeltaLogits`：小型 MLP 输出的 49 个修正值。
- `alpha`：限制修正幅度的系数，避免新的分支一开始就推翻原 YOLO 的判断。

这个结构中，YOLO 依然负责找框和主要分类；小分支只在它本来不确定时，利用颜色和大小帮助拉开类别差距。

## 5. 类别如何和颜色、大小建立联系

不需要人工写规则，例如“不需要写苹果加红色分、洋葱加紫色分”。关系由权重自动学习。

最简单的概念形式可以写为：

```text
c = 颜色特征，维度为 d
g = 几何特征，例如面积和宽高比

DeltaLogits = W_color * c + W_size * g + W_feature * f + b
```

其中：

```text
W_color 的形状为 49 x d
W_size  的形状为 49 x 几何特征维度
```

每一行对应一个类别。因此模型会自动学到：哪些颜色特征和大小特征会提高或降低该类别的 logit。

实际实现时可将上式换为两层很小的 MLP，使关系不止是线性的；但思想相同：输出的 49 个修正值各自与类别绑定。

## 6. 颜色特征怎样得到

### 方案 A：直接按预测框从输入图裁剪

概念上最直观：

```text
预测框 -> 在原始 RGB 图中裁剪该区域 -> 小型 CNN / HSV 特征 -> color feature
```

优点：颜色特征与框内物体直接对应，直观且准确。

难点：若要端到端训练，需要在 NMS 之前基于连续预测框做动态裁剪（例如 ROIAlign）。这类动态操作在 PyTorch 中可做，但 ONNX 到 RKNN 的兼容性和部署风险较高。

### 方案 B：ColorStem 颜色分支（更适合未来 RKNN）

从输入 RGB 图像增加一条很浅的卷积分支，产生与 YOLO P3/P4/P5 特征图对齐的颜色特征图。检测头每个位置直接取同位置的颜色特征。

优点：

- 只包含卷积、拼接、激活等常规算子，更容易导出 ONNX/RKNN。
- 不需要在模型内动态裁剪原图。
- 可以保持最终检测输出形状不变。

缺点：颜色特征是“与候选框相邻的局部颜色特征”，不如真正按框裁剪那样精确。但 YOLO 检测头的感受野本身已覆盖物体区域，通常足够用于第一版验证。

如果未来真的实现模型内部融合，优先考虑方案 B。

## 7. 框大小特征怎样得到

对输入尺寸固定为 `704 x 704` 的训练和推理，可以使用：

```text
area_ratio = (box_w * box_h) / (704 * 704)
aspect     = box_w / box_h

g = [log(area_ratio), log(aspect)]
```

可选地加入框中心位置：

```text
[center_x / 704, center_y / 704]
```

在固定冰箱、固定镜头、比赛演示场景中，位置和尺度可能确实有帮助；但位置不是物体本身的属性，依赖它会降低换摆放位置后的泛化能力。若只追求当前展示效果，可在后续实验中单独评估是否加入。

几何特征应使用预测框的连续宽高，而不是 NMS 后的硬结果。这样才能在训练中参与计算，也保证训练与推理一致。

## 8. 训练方式

现有 49 类标签已经包含了训练所需的类别和框信息，不需要额外人工标注“红色苹果”“紫色洋葱”等颜色标签。

可以概念性地使用：

```text
L_total =
    L_yolo_detection
  + lambda_base  * L_class(old_logits)
  + lambda_final * L_class(final_logits)
  + lambda_pair  * L_confusion_pair
```

含义：

- `L_yolo_detection`：原 YOLO 的框、目标置信度和分类损失。
- `L_class(old_logits)`：保留原始分类分支的能力，避免修正分支过度依赖颜色和大小。
- `L_class(final_logits)`：让最终融合后的类别结果对真实标签负责。
- `L_confusion_pair`：对容易混淆的类别对增加额外约束。

例如真实标签为苹果时，可额外鼓励：

```text
final_logit[apple] > final_logit[onion] + margin
```

真实标签为洋葱时则相反；鸡蛋和橙子也可建立同类约束。

这不是固定规则或固定偏置。它只是让模型知道“把苹果错成洋葱”这类错误比一般错误更值得被重点拉开。

训练可从当前 49 类 `best.pt` 继续，而不是从零开始。新增的颜色/融合分支可以初始化为接近零，使训练刚开始时的行为尽量接近当前 YOLO，再逐步学习修正。

## 9. Prototype（类别原型）方案是什么

Prototype 是另一种明确表示“类别与颜色/大小关系”的方法。

对于训练集中每一个标注框：

```text
图像 + bbox + class_id
```

提取：

```text
color feature = HSV/Lab 直方图、亮度、饱和度，或小型 CNN embedding
size feature  = 归一化面积、宽高比
```

然后按类别自动统计：

```text
proto_color[apple] = 所有苹果颜色特征的分布
proto_size[apple]  = 所有苹果大小特征的分布

proto_color[onion] = 所有洋葱颜色特征的分布
proto_size[onion]  = 所有洋葱大小特征的分布
```

它们不应由人工写死。可以是：

- 每类一个均值和方差；
- 每类 `2~4` 个 K-Means 聚类中心；
- 或训练过程中可学习的多个 prototype 向量。

单一原型不适合颜色变化较多的类别。例如苹果可能有红、黄红、暗处三种模式；洋葱也可能有紫皮、黄皮、阴影下等模式。因此若采用原型，更合理的是每类多个中心，而不是一个平均颜色。

原型可产生对每个类别的兼容度：

```text
compatibility[k] =
    color 像第 k 类的程度
  + size 像第 k 类的程度

final_logit[k] = old_logit[k] + beta * compatibility[k]
```

### Prototype 是否必须保留到推理阶段

- 若 Prototype 直接参与 `final_logit` 的计算：必须保留。颜色提取、大小特征和 prototype 表都要在推理时存在。
- 若 Prototype 只作为训练时的约束，例如让同类颜色特征靠近、混淆类特征远离：训练完成后可移除。此时它只间接改善 YOLO 特征。

Prototype 的优点是类别关系很明确，缺点是多颜色模式、光照变化和部署实现会使它比第一眼看起来复杂。

## 10. 三种思路的关系

这三种不是互斥选择，而是不同层次的设计：

| 层次 | 对应方案 | 作用 |
| --- | --- | --- |
| 主结构 | `final_logits = old_logits + DeltaLogits(...)` | 决定最终如何融合 YOLO、颜色和大小 |
| 训练约束 | 颜色/大小辅助损失、类别对间隔损失 | 让融合分支真正学会利用相关信息 |
| 类别关系表达 | MLP 或 Prototype | 决定 `DeltaLogits` 如何知道“什么颜色/大小更像什么类” |

因此可以有如下组合：

```text
推荐第一版：
YOLO feature + ColorStem + geometry -> MLP -> DeltaLogits
并加入 apple/onion、egg/orange 的间隔损失

后续可选增强：
再加多 prototype 或 prototype 约束，帮助颜色特征形成更清晰的类别结构。
```

## 11. 为什么不建议一开始只做固定后处理规则

固定后处理可能类似：

```text
若预测为 onion，且与 apple 分数接近，则直接改成 apple
```

这种做法会牺牲真正的洋葱。它不能表达“同样接近时，紫暗色更像洋葱、红亮色更像苹果”这一条件。

学习式 `DeltaLogits` 的不同点是：

- 它同时看到 YOLO 的全部类别分数；
- 它同时看到局部颜色和预测框大小；
- 它由真实标注样本训练；
- 它可只对 YOLO 犹豫的样本做小幅修正；
- 它不需要人为给苹果、洋葱、鸡蛋、橙子写固定阈值。

## 12. 颜色训练的注意事项

如果颜色被作为重要判别依据，训练增强不能把颜色关系破坏得太厉害。

YOLO 默认的 HSV 色相、饱和度、亮度增强如果过强，可能把红苹果增强成接近紫色，或把紫洋葱增强成接近红色。这样网络会学到“颜色不可靠”，与本方案的目标相冲突。

对于固定冰箱、固定镜头、以比赛展示效果为目标的场景，后续实验时更适合：

- 保留现实中可能出现的亮暗变化；
- 控制过强的色相变化；
- 使用与现场灯光、摆放方式接近的训练数据；
- 单独检查苹果/洋葱、鸡蛋/橙子的颜色分布是否真的可区分。

## 13. 推荐的后续验证顺序（尚未执行）

1. 先统计训练集和验证集中苹果、洋葱、鸡蛋、橙子框内的颜色、面积和宽高比分布，确认这些信息是否真的能分开。
2. 先在 PyTorch 中验证轻量融合头是否降低这两对类别的混淆。
3. 从当前 49 类 `best.pt` 初始化，新增分支从零或近零开始训练。
4. 对比原模型和融合模型的苹果/洋葱、鸡蛋/橙子混淆情况，而不只看总 mAP。
5. 确认 ONNX 导出正常后，再验证 RKNN 是否支持全部算子。
6. 只有在原始 YOLO、ONNX、RKNN 三者的输出趋势一致后，才考虑部署到板端。

## 14. 当前结论

最符合目标、也最值得后续研究的方向是：

```text
保持 YOLO 负责检测和初始分类，
在模型内部增加轻量颜色/几何条件分支，
输出对 49 类 logits 的小幅、可学习修正。
```

也就是：

```text
final_logits = old_logits + MLP(YOLO feature, old_logits, color feature, size feature)
```

它不是放弃 YOLO，也不是手动补丁；而是在 YOLO 原有判断的基础上，学习类别与颜色、尺寸之间的条件关系。
